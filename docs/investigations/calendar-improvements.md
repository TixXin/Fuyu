# 日历：节假日标记之后还能补什么

2026-11-19。起因是上游 `flyl1u/fly-island` 的 PR #99（日历标记：节假日、节气、纪念日、农历）。本仓库已脱离上游，不合它的代码；这份文档对照它看我们缺什么，再列出日历和待办里值得做的改进。

## 现状：PR #99 的功能我们大多已有

| PR #99 做的 | Fuyu 现在 | 在哪 |
|---|---|---|
| 农历 | 有，1900–2100 数据表，同一套 | `src/features/calendar/lunar.ts` |
| 二十四节气 | 有，公式加修正表，2000–2099 | `lunar.ts` 的 `solarTerm` |
| 传统节日、公历节日 | 有（春节、元宵、端午、中秋、除夕、元旦、国庆等 24 个） | `lunar.ts` 的 `festival` |
| 法定节假日「休」、调休「班」 | 有，来自订阅的苹果节假日日历（ICS），每年自动更新 | `monthView.ts` 的 `dayMark`、`utils/workday.ts` |
| 周末标色 | 有 | `CalendarMonth.tsx` 的 `--weekend` |
| 待办重复跳过节假日 | 有（「工作日」重复按休 / 班算） | `todos/recurrence.ts`、`useHolidayMarks.ts` |
| 纪念日（不放假的） | **没有** | — |
| 待办里的月历带标记 | **没有**：待办的日期选择器是纯数字 | `todos/TodoDateCalendar.tsx` |

PR 自己写死了 2025–2027 年的节假日表，每年 11 月要手动更新；我们用订阅，这一点不学它。

## 发现的缺口

1. **没加日历时看不到月历。** 日历页要先加一个日历才显示，否则整页都是「添加日历」的说明。农历、节气、节日都是本地算的，不需要任何日历。
2. **待办日期选择器不知道节假日。** 给待办挑日期时看不出哪天放假、哪天调休上班。
3. **「休 / 班」只在三个月内可见。** 节假日 ICS 是整份下载的，但和别的日历一样只保留上个月到下下个月；往后翻月就没有标记，远期「工作日」重复的待办也会排错。
4. **少了几类节日。** 按星期算的节日（母亲节＝5 月第二个周日，父亲节＝6 月第三个周日）、不放假的纪念日（国家公祭日 12-13、抗战胜利纪念日 9-3 等）都没有。
5. **调休没有提醒。** 周末要上班这件事最容易忘，现在只在月历角上有个「班」。
6. **待办没有「每年」重复。** 重复只有每天、工作日、每周、每月；生日、纪念日（尤其是农历生日）记不了。

## 方案

按「改动小、收益大」排序。每一项都能单独做、单独提交。

### P1：小改动，先做

**A. 没有日历也显示月历**（缺口 1）
- 日历页没有日历时：右边照常显示月历（农历、节气、节日），左边的议程栏换成现在的说明和「订阅中国节假日」按钮。
- 只改 `CalendarPanel.tsx` 的分支，`CalendarEmpty` 从整页变成议程栏里的一块。
- 「没加日历时不联网」保持不变。
- 回归页 `calendar` 补一个「没有日历」的快照。

**B. 待办日期选择器标出休 / 班**（缺口 2）
- 复用 `useHolidayMarks()`：放假的日子数字标红、右上角写小「休」；调休的周末写「班」；周末颜色和月历一致。
- 格子太小，不放农历。中文界面以外不显示「休 / 班」角标（这个订阅只有中国的）。
- 改 `TodoDateCalendar.tsx` 和 `TodoDatePicker.css`；文案复用 `t.calendar.off` / `work`，不新增 key。

**C. 补节日和纪念日**（缺口 4）
- `lunar.ts` 加按星期算的节日（母亲节、父亲节）和一组纪念日（国家公祭日、抗战胜利纪念日、国际劳动妇女节已有等）。
- 优先级维持「节日 > 节气 > 农历」，纪念日排在节气之后，不抢节日。
- 同步 `CHINESE_DAY_NAMES`，订阅里同名的全天条目照样不算日程；`calendar-month.test.mjs` 补用例。

### P2：中等改动

**D. 调休和放假前一晚提醒**（缺口 5）
- 订阅了节假日时，前一天晚上（默认 20:00）在岛上提醒一次：「明天调休，要上班」「明天起放假，共 N 天」。
- 走 `reminders/v1`，每个日子只提醒一次；设置 → 日历加一个开关，默认开。
- 依赖 E（要知道整段假期有几天）。

**E. 节假日日历保留整年**（缺口 3）
- 识别为节假日订阅的 ICS（`hasChinaHolidays` 已经能认），读取范围放宽到今年 1 月 1 日至明年 12 月 31 日，其余日历不变。
- 这样往后翻月也有「休 / 班」，`useHolidayMarks` 给待办重复用的数据也够远。
- 改 Rust `src-tauri/src/calendar/` 的读取范围，要跑 `cargo test` 和 `build:exe`。

**F. 下一个假期倒计时**
- 日历页标题现在写「13 天后小雪」。有节假日订阅时，在它后面或换成「距国庆还有 N 天 · 放 7 天」，也就是最近的一段「休」。
- 依赖 E。

### P3：大一点，单独立任务

**G. 每年重复和农历每年重复的待办**（缺口 6）
- `TodoRecurrenceKind` 加 `yearly`、`lunarYearly`。农历用 `lunarDate` 反查；闰月出生的按常规月份算；三十那天不存在时（小月）挪到廿九。
- **对外契约**：重复规则存在待办数据里。旧版本读到新的 kind 会丢掉重复（`normalize` 返回 `undefined`），等于降级后变成一次性待办。要在 `contracts.md` 记一笔，并在发布说明里写清楚。
- 待办标签菜单加两项，中英文案都要有（英文写 Yearly / Yearly (lunar)）。

### 不建议做

- **内置一份节假日表做离线兜底**：就是 PR #99 的做法，每年要手动更新，忘了就静默出错；订阅更省心。
- **黄历宜忌**：受众窄、数据来源杂，适合做成第 3 版插件，不进核心。
- **周视图、Microsoft Graph、会前弹窗**：已经在任务 C5b 里，不重复列。

## 建议顺序

A → B → C 可以一起做成一批（都是前端，一两个提交）；然后 E → D → F（E 是 Rust，D、F 依赖它）；G 单独开任务，先确认契约变化。
