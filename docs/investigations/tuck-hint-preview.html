贴边隐身时的「还在运行」提示（C132 / #864）

「贴边隐身」（C111，露出 0px）收起后岛完全看不见，用户以为软件关了。这里比较三种提示样式：无 / 小圆点 / 光晕，以及提示画在哪。上面的开关会同时作用于下面所有画面。2026-11-19。

一、隐身时有没有像素能画提示

有，不用另开窗口。岛的窗口（舞台）比岛本身大得多：逻辑尺寸约 820 × 岛高 + 上下留白。贴边隐身时 Rust 只把窗口往上推「岛的高度」（geometry.rs 的 tucked_top_offset：-(height × scale).ceil()），岛整个出了屏幕，但舞台下面那一大块透明区域还在屏幕里，紧贴屏幕顶边的那一行像素正好就是「岛原来的位置的下沿」。底边贴靠时对称，窗口往下推。

鼠标穿透是按「岛的形状」判断的（passthrough.rs → geometry.rs 的 cursor_on_island）：隐身档里只有贴边那条 2px 的唤醒热区算「在岛里」，舞台其余部分都穿透。所以提示画在舞台里、热区之外的部分天然穿透，不用改穿透逻辑；和 2px 热区重叠的那一点本来就是唤醒用的，不算新挡住东西。Mac 上隐身时原生玻璃已经关掉（glass_macos.rs 的 tucked_hidden），提示画在网页层里，Windows 和 Mac 是同一份 CSS。

现在隐身是给 .island 整个设 opacity: 0（IslandShell.css 的 .island--tucked-hidden），所以提示要做成岛外壳的兄弟元素，不能放在 .island 里面。

放在哪好处坏处
A. 画在现有岛窗口里，贴着屏幕边（推荐）不加窗口、不加契约；穿透逻辑不用改；位置和收起、露出、换边、换屏天然同步；收起时岛滑走、提示淡入可以在同一个窗口里接上提示被限制在舞台范围内（够用）；顶边有刘海的 Mac 不走隐身档（notch.is_none()），那时不显示提示，和现在一样
B. 另开一个很小的穿透窗口和岛完全解耦，想画在屏幕任何位置都行多一个窗口 label（对外契约）、多一套置顶 / 多屏 / DPI / 托盘隐藏的处理，和岛的滑动不同步，Windows 上置顶顺序也要再调；收益只有「位置更自由」，这里用不上
C. 不隐身，岛留几像素零开发这就是已有的「极简细线」（4px），用户选隐身就是嫌它挡浏览器标签页（#849），不解决问题

顺带发现（不在本任务里修）

贴左右侧边时，收起后岛变成 12×72 的小把手，窗口不推出屏幕。选了「贴边隐身」时把手只是 opacity: 0，但 Rust 的穿透判断里侧边没有走隐身分支，整个 12×72 的把手区域仍然接鼠标：屏幕侧边有一块看不见、却点不穿的地方。本任务可以顺手让侧边隐身时只保留 2px 热区（改 geometry.rs 的侧边分支），或者另开任务，请一起定。

三、三种样式

样式长什么样尺寸
无和现在一样，什么都不画—
小圆点贴边居中一个实心小圆点，离屏幕边 3px；侧边时在原把手的位置直径 7px，最多占边缘 10px
光晕贴边一条短白条，带一圈柔光（用户提的「带光晕的小白条」）38 × 3px，光晕向外约 18px，光晕本身不接鼠标

颜色两种都给了：「白芯 + 描边」是白色本体加一圈半透明深色描边，深浅壁纸都看得见；「跟随岛色」用岛的底色（Windows 玻璃 / Mac 黑），描边反过来，和岛的外观更一致但在同色壁纸上弱一些。动画：收起时岛滑出（沿用现有收起），提示在 --motion-medium 后用 --motion-ease-out 淡入；呼吸是 2.8s 一个来回、--motion-ease-in-out，和 Agent 卡片的呼吸同节奏；系统开了减少动画时不呼吸，常亮。按 motion.md「底线」第 4 条，循环只给表示状态的东西，「隐身中、还在运行」算状态，但它会一直挂着，所以默认建议常亮，呼吸做成可选或不做。

四、请用户定

  1. 默认样式：无 / 小圆点 / 光晕？（建议：小圆点。选了隐身的老用户升级后会多出一个 7px 的点，正好解决「以为关了」；不想要可以选「无」。）
  2. 呼吸还是常亮？（建议：常亮。一直挂在屏幕边上的东西一直闪会分心；也可以加一个「呼吸」开关，默认关。）
  3. 颜色：白芯 + 描边，还是跟随岛色？（建议：白芯 + 描边，深浅壁纸都稳。）
  4. 画在哪：A 画在现有岛窗口里（建议），还是 B 另开小窗口？
  5. 侧边的「看不见但点不穿」：本任务顺手修（会动 geometry.rs），还是另开任务？
