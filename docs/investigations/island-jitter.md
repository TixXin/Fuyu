# 岛屿展开 / 收起时的元素抖动排查

日期：2026-11-09。代码基线：`c955d76`。

## 结论

展开和收起的 560ms 过程中，岛屿上的文字会左右（以及上下）来回抖动 0.5–1 个设备像素，字形也在逐帧变形。**直接原因是整个岛屿外壳在 `transform: scale(...)` 下同时做宽高过渡**：

- 外壳 `.island` 的宽高在动画中逐帧取小数值；内容层 `.island__collapsed` / `.island__expanded` 用 `left: 50%` 居中，它们在外壳**局部坐标**里的偏移也是小数，被浏览器先在局部坐标里对齐到整像素，再乘以缩放系数（例如 0.89 / 0.91）投到屏幕上。对齐误差被缩放后不再落在设备像素上，每帧取整方向不同，于是文字在理论上静止的位置附近来回跳。
- 缩放系数是否在过渡（F14 的改动）不是关键：收起态和展开态缩放相同（都为 0.91）时抖动依旧；缩放为 1 时同样的宽高动画完全不抖。
- 受影响的是收起或展开缩放不为 1 的用户。新装的默认缩放自 `cea5168`（11-06）起是 1，不会遇到；在那之前保存过设置的用户保留旧值（例如 0.89 / 0.91），以及在设置里调过缩放的用户都会遇到。（本文最初写成「默认缩放都不是 1」，是看了 Rust 侧 `DEFAULT_COLLAPSED_SCALE` 等常量误判，已更正。）

把缩放从 `transform: scale` 改成 `zoom` 后，布局直接在缩放后的尺寸里进行、在设备像素上对齐，抖动基本消失（见下表）。已按这个方向修改，见「处理」。

## 测量方法

- 最小复现页：[island-jitter-fixture.html](island-jitter-fixture.html)，复制 `IslandShell.css` 中外壳和两层内容的过渡规则（宽、高、圆角、`--island-scale` 560ms；内容层 `top` 的 6px 滑动），各放一行中英文混排文字。为只看位置，内容层的透明度固定为 1。
- 用 Playwright 的 Chromium，视口 820×460，`deviceScaleFactor: 1.5`（与此前展开掉帧排查的设备像素比一致），收起宽度 300px（按 `alignCollapsedIslandWidth` 的规则，在 1.5 倍下左缘落在整设备像素上）。
- 切换 class 后暂停全部动画，每 8ms 用 `currentTime` 定位一帧并截图，计算文字墨迹（亮度 > 60 的像素）的加权中心，与 `getBoundingClientRect` 给出的理论中心相减，得到「渲染偏差」。理论位置平稳时，偏差应保持不变；偏差来回跳就是抖动。
- 统计区间：展开取 320ms 之后（此前内容被尚未展开的外壳裁掉一部分，中心不可比），收起取 120ms 之后。

## 结果

| 条件 | 方向 | 偏差范围（设备 px） | 相邻帧跳动 > 0.3px 的次数 | 字形墨迹总量波动 |
| --- | --- | ---: | ---: | ---: |
| 现状：`transform: scale` 0.89 → 0.91 | 收起 | 1.60 | 19 / 61 帧 | 2.99% |
| 现状：`transform: scale` 0.89 → 0.91 | 展开 | 0.66 | 6 / 36 帧 | 0.54% |
| `transform: scale` 两态都为 0.91 | 收起 | 1.10 | 17 / 61 帧 | 0.78% |
| `transform: scale` 两态都为 0.91 | 展开 | 0.72 | 5 / 36 帧 | 0.60% |
| 缩放为 1（对照） | 收起 | 0.00 | 0 | 0.01% |
| 缩放为 1（对照） | 展开 | 0.02 | 0 | 0.04% |
| `zoom` 0.89 → 0.91 | 收起 | 0.27 | 0 | 0.97% |
| `zoom` 0.89 → 0.91 | 展开 | 2.05 | 1 | 2.50% |
| `zoom` 两态都为 0.91 | 收起 | 0.72 | 1 | 1.55% |
| `zoom` 两态都为 0.91 | 展开 | 0.01 | 0 | 0.04% |

同期理论中心在统计区间内只移动约 0.02 设备像素，所以表中的偏差范围几乎全是渲染误差。逐帧数据里还看到：现状展开在 528ms 处文字纵向一次跳 0.8 设备像素，与缩放的最后一点插值落定同时发生。

`zoom` 0.89 → 0.91 展开那一行的 2.05px 不是来回抖，而是一次单向变化：`zoom` 过渡时字号随之逐帧变化，字号的取整让文字在某一帧整体跳一下。缩放不过渡、或两态缩放相同时没有这个问题。

## 相关提交

- `e1e1163`（11-04）`alignCollapsedIslandWidth`：把收起宽度微调到「居中后左缘落在整设备像素」。它的计算没有考虑 `--island-scale`：缩放不为 1 时，真正落在屏幕上的左缘是 `410 − 宽度 × 缩放 / 2`，这次微调在缩放不为 1 时基本无效。它的前提（合成器在动画结束时把图层对齐到整像素）在下一条提交后也不再成立。
- `cfeaed4`（11-07，F14）：缩放的过渡从合成器上的 `transform` 改到主线程逐帧插值 `--island-scale`，解决动画中的文字模糊。主线程逐帧重绘让上面的取整误差每帧都直接画出来。本次测量里暂停后定位的帧都在主线程绘制，所以**无法用这一方法比较 F14 之前合成器动画的实时表现**；但「两态缩放相同仍抖」说明宽高动画加非 1 缩放本身就足以产生抖动。

## 修复方向

1. **用 `zoom` 代替 `transform: scale`（推荐先试）**。测得的抖动基本消失，文字仍是逐帧按实际尺寸绘制，不会回到 F14 之前的模糊。需要核对：
   - Rust 命中测试（`island/passthrough.rs`）假定「基准尺寸 × 缩放、顶部居中」的盒子；`zoom` 的视觉盒子相同，但 `transform-origin: top center` 不再起作用，要确认居中仍然成立（外壳是舞台 flex 居中的，`zoom` 后的布局宽度本身就缩放了）。
   - Chromium 128 起 `zoom` 按标准化语义计算，`getBoundingClientRect`、`offsetWidth` 等返回值要逐一确认：收起栏插槽宽度、Agent 提醒行高、消息新到行高这些用测量结果算岛屿尺寸的地方（`useCollapsedSlots`、`expandedHeight.ts` 的输入）不能被重复缩放。
   - `zoom` 过渡会让字号逐帧变化（上表展开那一行）。可以让 `zoom` 不过渡，只在两态缩放不同的瞬间切换；或保留过渡、接受一次整像素跳动。两种都要在 `pnpm tauri dev` 里实际看。
2. **只在缩放为 1 的层上做宽高动画**：例如外壳形状用 `clip-path` 或单独的背景层做动画，内容层固定在舞台坐标里不随外壳宽度重新布局。改动面大于方案 1，只在 `zoom` 行不通时考虑。
3. 不论选哪种，`alignCollapsedIslandWidth` 都应按最终屏幕上的左缘（考虑缩放）计算，或在方案 1 之后重新核对它是否还需要。

## 验证边界

- 测的是最小复现页，不是完整岛屿；液态玻璃的模糊、阴影和光斑层没有包含，它们不影响文字位置，但会影响观感。
- Playwright 的 Chromium 不等于 WebView2，但两者的布局与像素对齐逻辑相同；最终结论要在 `pnpm tauri dev` 或 lane 预览里，在 125% / 150% / 175% 缩放下用逐帧录屏复核。
- 最初只做排查；后续修改见「处理」。

## 处理

`.island` 改用 `zoom: var(--island-scale)`，去掉 `transform` 和 `transform-origin`，并加 `isolation: isolate` 保留原来由 `transform` 形成的层叠上下文。核对结果：

- **命中测试**：舞台是顶部居中的 flex 容器，没有内边距，`zoom` 后岛屿的盒子仍是「基准尺寸 × 缩放、顶部居中」，与 `island/passthrough.rs` 的假设一致，Rust 不用改。
- **测量接口**：在 Chromium 156 实测，`zoom` 下 `getBoundingClientRect` 返回缩放后的视觉尺寸，`offsetWidth`、`scrollHeight`、`getComputedStyle` 返回未缩放的布局尺寸，与 `transform: scale` 下一致，依赖测量的代码不会重复缩放。区别只有滚动条厚度也随 `zoom` 缩放。
- **固定定位**：岛屿里的 `position: fixed` 元素（悬浮卡片、插件右键菜单）都经 portal 挂在 `body` 上，不在岛屿内，不受影响。
- **缩放过渡**：保留 `--island-scale` 的过渡。两态缩放不同时，展开过程中字号随缩放变化，可能有一次整像素的跳动（上表 `zoom` 0.89 → 0.91 展开那一行），比原来每帧来回抖轻得多。
- `alignCollapsedIslandWidth` 未改：缩放不为 1 时它基本不生效，缩放为 1 时仍然有用。

## 第二轮：Agent 列表仍上下轻微抖动（2026-11-09）

改用 `zoom` 后用户反馈抖动减轻，但 Agent 列表展开、收起时仍上下轻微抖动。

### 测量

这次直接测真实组件：临时回归页挂载 `IslandShell` 和 `AgentSessionsPanel`（3 个会话，列表视图），设置 `--island-scale` 等变量后切换展开态，方法同上（暂停后每 8ms 定位一帧截图，1.5 倍设备像素比）。统计 160–600ms 之间：

- **逆向移动**：某一行的渲染位置移动超过 0.5 设备像素，而方向与它的理论位置相反（或理论位置没动）。
- **间距反复**：标题栏与某一行之间的距离变化超过 0.5 设备像素，且变化方向来回反转。

| 条件 | 逆向移动 | 间距反复 |
| --- | ---: | ---: |
| `zoom` 0.89 → 0.91（上一轮的修复） | 第 3 行 1 次 | 3 次 |
| `zoom` 1 → 1 | 0 | 0 |
| `zoom` 0.91 → 0.91 | 0 | 0 |
| `zoom` 0.89 → 0.91，去掉 6px 滑入 | 每行 1 次 | 1 次 |
| `zoom` 0.89 → 0.91，去掉滑入，缩放不过渡 | 0 | 0 |
| 本轮修复后 0.89 / 0.91 | 0 | 0 |
| 本轮修复后 1 / 1 | 0 | 0 |

### 原因

两态缩放不同时，`--island-scale` 的过渡让 `zoom` 每帧取一个新值，整个岛屿内容每帧按新的缩放重新排版。列表的行高、行间距在每个缩放下各自取整，误差逐行累积，越靠下的行越明显：第 3 行在 272ms 下移 1 设备像素、292ms 又上移 1 像素，理论位置却几乎没动。这就是「Agent 列表上下轻微抖动」。

内容层 6px 的 `top` 滑入只产生单向的整像素台阶，各行同步，不是这一轮抖动的来源（但见第三轮）。

### 处理

外壳和内容分开缩放：

- 外壳 `.island` 不再缩放，直接按「基准尺寸 × 当前模式的缩放」设定宽、高和圆角（`--island-shell-radius*`），宽高和圆角照常过渡。外壳上没有文字，逐帧变化的只是背景和圆角。
- 收起层 `.island__collapsed` 固定用收起缩放、展开层 `.island__expanded` 固定用展开缩放（`--island-collapsed-scale` / `--island-expanded-scale`，`stageStyle.ts`）。开合过程中它们的缩放不变，不再逐帧重排。
- `--island-scale` 不再注册、不再过渡，只表示当前模式的缩放，供外壳尺寸、顶部圆角过渡（`IslandTopEdge.css`）、插件权限提示条（它在内容层之外）和消息横幅使用。
- 内容层仍用 `left: 50%` 加负的半宽外边距居中：`zoom` 同时缩放外边距，百分比按外壳计算，内容层比外壳宽时也居中（`margin: auto` 在这种情况下会退成左对齐，试过后放弃）。

静止时的几何与之前一致（0.89 / 0.91，280px 收起宽度、316px 展开高度）：收起 249.2 × 33.81、圆角 19.58px，展开 509.59 × 287.55、圆角 27.3px，外壳和两层内容的中心在开合全过程都是 409.99。Rust 命中测试的假设（基准尺寸 × 缩放、顶部居中）不变。

未覆盖：会话数据在展开过程中变化（轮询刷新、用量行出现）导致的高度变化不在本次测量范围内；那会是一次跳动而不是来回抖。

## 第三轮：「刚刚」先在上方，再落到正常位置（2026-11-09）

用户反馈：展开面板时，Agent 第一行右侧的「刚刚」先显示在偏上的位置，随后跳到正常位置。

### 测量

真实组件，一个刚更新的运行中会话（模型、权限模式标签和「刚刚」都在标题行）。实时播放时逐帧读 `getBoundingClientRect`：「刚刚」与标题的垂直中心差始终为 0，展开过程中行内 DOM 也没有变化，所以不是布局跳动，而是绘制位置。暂停逐帧截图，比较两者墨迹的上下边（设备像素）：

| 缩放 | 408ms（滑入尾声） | 420ms（滑入结束） |
| --- | --- | --- |
| 1 / 1，有滑入 | 「刚刚」124–142，标题 122–143 | 「刚刚」125–143，标题 124–145 |
| 0.89 / 0.91，有滑入 | 不变 | 不变 |
| 1 / 1 和 0.89 / 0.91，去掉滑入 | 全程与最终位置相同 | 同左 |

### 原因

滑入用 `top` 从 −6px 过渡到 0。最后一帧 `top` 从约 −0.01px 变成 0，几乎没动，但两段文字按设备像素取整的方向不同：14px 的标题下移 2 设备像素，12px 的「刚刚」只下移 1 像素。整个滑入过程中「刚刚」相对标题偏上 1 像素，结束时才落到最终位置。是否出现取决于缩放和行的位置，所以只在某些行、某些缩放下看得到。

### 处理

两层内容去掉 6px 的 `top` 滑入，只保留淡入淡出；动感来自外壳的尺寸变化。改用 `transform` 滑入会在动画中模糊文字（F14），所以不考虑。

## 第四轮：宽度回弹时内容左右跳（2026-11-12）

用户反馈：开合动画中，尤其是宽度变化时，岛内的元素抖动。这时外壳宽度已改成官网的回弹曲线（`cubic-bezier(0.34, 1.36, 0.5, 1)`，冲过约 3% 再回落）；用户的设置是缩放 1、面板宽 800、屏幕缩放 150%。

### 测量

- **浏览器（不复现）**：Playwright 的 Chromium，按用户的窗口（820 宽）和面板宽度，在 125% / 150% / 175% 下暂停动画逐帧截图，文字墨迹位置全程不变。注意截图框要固定：按每帧文字位置取整的截图框会跟着挪 1 个 CSS 像素，测出假的 1–2 设备像素跳动（本轮一开始就被它误导过）。
- **真实窗口（复现）**：在 lane 预览岛屿里临时加一个每 2.5 秒自动开合的循环，用 `Graphics.CopyFromScreen` 逐帧录屏（70–120 帧/秒），按固定区域算墨迹中心。展开时「今天还很轻」在 515.8 和 516.8 设备像素之间来回跳，顶部图标、输入框也一样；只发生在展开层淡入的 250ms 里，淡入结束后静止。

### 原因

淡入期间，WebView2 把展开层放到单独的合成层里绘制，合成层的位置要取整到设备像素。展开层按外壳的 `left: 50%` 加负半宽外边距居中，外壳自己又在舞台里居中；外壳宽度每帧是小数时，这两次居中按布局单位（1/64 设备像素）分别取整，合起来的位置每帧差 ±1/64，落在像素边界附近时就整像素来回翻。暂停逐帧截图时不走合成层，所以浏览器里测不出来。回弹让宽度在终点附近来回慢慢变，翻得最密。

### 处理

`IslandShell.css`：外壳过渡注册过的 `--island-shell-width`，左边距 `--island-shell-left` 取整到整设备像素（不小于 0，回弹不超出窗口），宽度由左边距推出；两层内容不再按外壳 50% 居中，而是放在各自静止时（舞台居中、取整到整设备像素）的位置，再减去外壳左边距。舞台设为容器（`container-type: inline-size`），宽度用 `100cqw`。这样内容层在屏幕上的位置每帧都是同一个整设备像素。1/1.5、1/1.75 不是精确小数，取整结果可能比整像素差一丝，加 0.001px 让它落在同一侧。

真实窗口重录：展开、收起全程，文字只有淡入时亮度变化带来的 ±0.2 像素浮动，没有整像素跳动。第一次修改时还剩宽度顶到窗口边缘（原来的 `max-width: 100vw` 截住宽度、内容层位置没跟着截）的那几帧跳 1 像素，左边距限制为不小于 0 后消失。代价是静止时外壳宽度可能比设定差 1 个设备像素。

## 第五轮：面板里切换页面时文字抖（2026-11-12）

用户反馈：开合不抖了，但展开的面板里切换页面时还会抖。

### 原因

切换页面时 `usePageFadeIn`（`src/windows/island/usePageFadeIn.ts`）用 Web Animations 给新页面放 220ms 的淡入，同时 `transform: translateY(6px)` 上滑。这正是前几轮说要避免的位移动画：图层每帧停在小数设备像素上，文字按像素一级级挪动，结束时再落一下。开合时的滑入在第三轮已经去掉，切换页面的这一处没跟着改。切换页面时外壳的宽高不变（C27 起所有页面同一个面板尺寸），所以不是第四轮的外壳宽度问题。

### 测量

方法同第四轮（实时 BeginFrame 截图），把操作换成在展开的岛上点页面按钮，在点击之后收集新页面的文字和图标。设备像素比 1 / 1.25 / 1.5 / 1.75，切到日历、待办、音乐、Agent。

| 条件 | 1.5 倍下新页面出现之后的跳动次数 |
| --- | --- |
| 改之前（淡入 + 上滑） | 日历 461、Agent 114、待办 84、音乐 51；每个节点按 2.25 → 1.36 → 0.78 … 设备像素一帧帧上移 |
| 只淡入 | 四个页面、四种设备像素比都是 0 |

（新页面出现的那一帧，分析脚本拿它和旧页面同位置的墨迹比，记成一次大跳动，那是测量的假象，两种条件下都有，不计。）

### 处理

`usePageFadeIn` 只做透明度 0 → 1，不再位移。
