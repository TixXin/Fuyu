## 出过的问题

1. **默认关闭的新内置插件让第 2 版迁移测试挂了**。写代码的会话提交前跑了 `pnpm test:changed`，但改 `src/features/builtins.json` 没挑出 `plugin_kernel` 的 Rust 测试，到推前验证才发现，多一轮验证。
2. **只在 Windows 挂的脚本测试**。Windows 上 `pnpm heavy` 经 cmd 跑命令，测试里的 `node -e "…"` 被拆坏。Mac 上的验证查不出，开 PR 后才挂，多一轮 CI（约 10 分钟）。
3. **回归页互相影响**。CI 的一个分片在同一个浏览器里依次跑几十页，前一页留下的 localStorage 改了 settings 页的起点。拆分 builtins-off 后分片和顺序变了才暴露；本机验证三个浏览器并行、顺序不同，所以本机过了。CI 重跑照样挂，两轮 CI，最后由别的会话修好。
4. **同一段对话两个副本**。会话中断后桌面端的副本和另一个客户端里的副本各自往下做，两边都启动了 `pnpm release`，后启动的一份停在「另一个构建在跑」的排队里，看上去像卡住。两边权限模式不同，会话之间的消息被扣住直到过期。
5. **官网导入失败**。有会话在已停用的旧站仓库部署，把 `fuyu-site-api` 容器当孤儿删掉。`pnpm release` 到最后一步才发现，重试三次；那段时间官网的更新接口 404。旧仓库的部署已经改成默认拒绝（fuyu-site bf828f2）。

本机验证在 beta.1 挂了两个 Rust 测试，都和改动无关：锁屏时 `macos::session` 的测试断言屏幕没锁；开着系统代理（127.0.0.1:7890）时，翻译「连不上」的测试的请求被代理接住、返回了状态码。用户同意后用 `--unverified` 推的；代理那个之后改成连本机地址时不走代理。

D121.4 试过 Defender 排除，没有收益；再要快只能换更大的 runner、换链接器或调 LTO，用户定不做。

### 第二轮（D121.6–.8）的效果

- **一个 PR**（D121.6）：省掉了推的 PR 那一轮 CI（约 6 分），但总时间没有变短。新流程里从开 PR 到公开的关键路径是「Windows 预构建 → 下载 → 上传」，beta.2 这次 Windows 预构建慢了约 2:43（12:20，上次 9:37），下载和上传也比上次慢（编完后又下了约 4 分钟，上传 2:22，0.3.12 是 0:33），把省下的时间吃掉了。这几段受 GitHub runner 和网络影响，一次的数字波动大，换一次再比才说明问题。
- **提前冒烟测试**（D121.7）：生效了。冒烟测试在 Windows 编完时就开始，`pnpm release` 走到这一步只等了 0:07（beta.1 1:21）。
- **官网导入并行**（D121.8）：和收尾几步同时跑了，但这次官网本身慢：第 1 次下载失败重试、再等官网构建，共 15:54，`pnpm release` 总共 30:40，并行只省下收尾那不到 1 分钟。GitHub 公开在 +13:43，不受官网影响。官网慢在下载重试和官网构建，属于官网项目那边。

现在决定总时间的是 Windows 预构建（10–12 分钟），其次是下载和上传安装包的网络。
