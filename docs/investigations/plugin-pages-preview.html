和现在相比改了什么

需要你定的问题

每题第一项是我的推荐。

1. 插件市场放哪？ 推荐：侧栏单独一页

  • 侧栏「扩展」下单独一页「插件市场」（11-07 你选过这个，D10）
  • 插件页里的标签「已安装 | 插件市场」（现在的做法，和「外观 → 主题市场」一致）

对比和理由见下面「市场放哪」，预览窗口上方能直接切。

2. 运行诊断（插件进程、内存、CPU、全部模块的运行表、二分排查）放哪？ 推荐：方案 C

  • C：平时不显示，出问题时插件页顶上出提示条，点进诊断子页；⋯ 菜单里常驻「运行诊断」
  • A：插件页最下面一个折叠的「高级」
  • B：挪到「关于」页的「高级」

三个方案并排见下面「诊断放哪」。

3. 已装列表：一行一个，还是保留两列卡片？ 推荐：一行一个

  • 一张卡片里的列表行：插件不多时一眼看完，要处理的事有整行宽度写清楚，和设置窗口其他页一致（VS Code、Obsidian 也是列表）
  • 两列卡片（11-07 定的、11-13 收紧过）：好看，但插件少时右边常常空一格，提示条只有半宽要截断

4. 代码里的内部名字要不要跟着改？ 推荐：改代码名，不改契约

  • 改：组件 PluginsV3SettingsPage、PluginMarketV3Tab，CSS class plugins-v3__*，文案文件 pluginsV3.ts 和它的 key，作为实现最后一个单独的 refactor 提交（搬迁和改写分开）
  • 不改（对外契约）：设置分类 key pluginsV3（fuyu-settings-focus、事件 plugin-package-open 用它）、数据目录 plugins-v3/、环境变量 FUYU_PLUGINS_V3 / FUYU_PLUGINS_V3_SAFE
  • 也可以全都先不改，只改界面上显示的字

5. 架构历史文档里的「第 3 版」留不留？ 推荐：留

  • 留：docs/architecture/plugins/v3-*.md 讲的就是那次改版，是历史记录；只改面向用户和插件作者的文档（docs/features/、docs/plugins/、docs/design/settings.md）
  • 全改成「插件平台」，文件也改名

6. 插件页要不要提一句「自带功能在哪开关」？ 推荐：要，页底一行脚注

  • 页底一行灰字「浮屿自带的功能（待办、音乐、剪贴板……）不算插件，在『概览』里开关」，点「概览」跳过去；免得以前在这里关过内置模块的人找不到
  • 不提

7. 两个新操作要不要做？ 推荐：都做

  • 插件行上的「重启」：现在没有单个插件重启，实现上等于停用再启用（不改配置）
  • 「查看日志」：现在只有「最近一次出错」一段文字；新设计把它放进详情「运行情况」，加「复制」按钮。要不要再接插件自己的日志输出，可以以后再说

诊断放哪：三个方案

诊断里有：插件进程（连接、进程号、Node 版本、开发模式）、内存、累计 CPU、已运行时长，全部模块（你装的插件 + 22 个内置模块）的运行表（状态、CPU、启动耗时、活跃资源、出错数），二分排查。普通用户几乎用不上，出问题时又必须找得到。
