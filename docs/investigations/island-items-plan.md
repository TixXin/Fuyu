# 岛上内容的排列：清单、放哪、放不下怎么办（方案）

起因（用户，2026-11-19）：「插件安多了后，岛屿上会显示很多内容，但又没有一个地方快捷设置显示或关闭和先后顺序；mac 刘海的情况，多出来的直接就不显示出来了。应该加个选择，比如时间在右上角、歌词展开小面板显示。」

状态：**已定**（用户 2026-11-19：「按建议定」），分四步做，任务 C139。预览页：[island-items-preview.html](island-items-preview.html)。下面标「待定」的几项是当时给用户挑的，结果见「定下来的」。

## 问题归到三条

1. **清单不全**：插件项不能单独隐藏、不能排序。
2. **放不下没有规则**：刘海屏上谁显示、谁消失看的是渲染顺序，用户不知道也改不了。
3. **只有「左 / 右 / 隐藏」三档**：文字类内容在刘海屏上没有去处，不常看的内容没有「收起来但随时能看」的去处。

## 方案

### 1. 一张清单管所有上岛内容

- 岛把此刻注册的全部项目（id、名字、所属插件）写给设置窗口，设置里的「收起条上的项目」列出全部，包括计时器和市场插件。
- 名字：插件给插槽项加可选的 `label`（字符串或 `{ "zh-CN", en }`），没给时用插件的 `displayName`；一个插件多个项目时必须给。
- 插件详情里加「显示在岛上」开关，和清单是同一个值。
- 位置仍然只在这一处调，插件自己不设位置选项（沿用 2026-11-09 的决定）。

### 2. 「放哪」从三档扩成五档

| 位置 | 能放什么 | 说明 |
|---|---|---|
| 左侧 / 右侧 | 图标、环、读数这类短内容 | 现有 |
| 文字位 | 歌词、Agent 标题、待办、会议 | 非刘海形态是中间；刘海形态见第 4 节 |
| 小面板 | 全部 | 不占岛上的位置，停在「+N」上看 |
| 不显示 | 全部 | 现有 |

不做自由网格，不做中间区放图标。

### 3. 放不下的规则（待定 A）

- **靠屏幕外侧的优先，靠近刘海（中间）的先收。** 左侧从最后一个开始收，右侧从第一个开始收；这样状态灯和会话数这两个最靠外的最后才动。
- 收掉的项目进小面板，岛上留一个「+N」。刘海形态下它放在更空的一侧、靠刘海那头（默认布局下左侧只有状态灯，所以在左边，不占右边的位置）；没有刘海时放在最右。设置里给收掉的行标上「刘海屏放不下」。
- 新装的插件：放得下就上岛，放不下进小面板，安装提示里说一句，不挤掉原有的。
- 刘海和非刘海**共用一份顺序**，各自按容量截断，不存两套布局：Mac 接外接屏会自动切形态，这份设置还会跨设备同步。
- 两翼最宽另外做成滑块（100–170，默认 100 不变）：调宽能多放两三个，代价是盖住应用菜单，预览页里用 Chrome 的菜单做了对比。
- 两翼 100 本身很紧：悬岛样式的状态灯自己 54 宽（24 高的 2.25 倍），左侧只剩约 26；一个带读数的项目（图标加四五个字符）约 50。只做「+N」不调宽，刘海屏上每侧仍然只放得下一两个。两翼是 2026-11-13 用户反馈太宽后从「72 起、按文字加宽」改小的，要不要放宽由用户定。
- 新装的插件默认放到更空的一侧（现在全都进右侧，左侧通常只有状态灯）。

### 4. 小面板和刘海下一行（待定 B）

- **小面板**：停在或点「+N」时，在岛正下方出一张卡片，上面是文字类内容，下面是收进来的图标（带名字），点一项打开它的页面。做法同新消息横幅：画在岛外、算进原生点击区域；停在「+N」上不触发悬停展开（同用量环）。
- **刘海屏的文字**四选一，按项目设：
  - 不显示（现状，默认）
  - 刘海下常驻一行：歌词适合，但会一直盖住窗口的标题栏或标签栏
  - 有变化时出现 4 秒：Agent 一轮跑完、切歌时
  - 只在小面板
- 这一行复用现有的刘海下一行（消息预览在用），消息和长提示仍然优先。
- 选了常驻或出现 4 秒，就改掉了 2026-11-13「刘海不放常驻文字」的决定，所以默认不变，由用户自己打开。

### 5. 快捷入口（待定 C）

- 右键收起的岛，弹一张勾选清单：每个项目一行，勾掉就是不显示；底部「排列…」打开设置的这一节。
- 岛上直接拖动排序先不做：和拖岛手势冲突，要单独的编辑模式。

### 6. 文字位的先后（待定 D，建议最后做）

插件也能往文字位放内容，写死的顺序会遇到同样的问题。做成和图标一样的可排序列表（会议、歌词、Agent 标题、待办、插件的文字），临时提示仍然排在最前、不参与排序。这会推翻 2026-11-09「不做通用排序」，现有的「歌词优先 / Agent 优先」开关并进这张列表。

## 数据和契约

- `fuyu-collapsed-items`：版本不变，项目多一个可选字段 `shelf: true`（收进小面板），`zone` 仍然只有 left / right。旧版本读到会忽略它，旧版本保存时会丢掉它（退回到在岛上显示），可以接受。
- 新 key `fuyu-collapsed-text`：文字类内容的顺序、是否显示、刘海屏上的方式。不往旧 key 里塞新的 `zone` 值：旧版本的校验会把整项丢掉。
- 新 key（不同步、不备份）：岛写给设置窗口的项目清单。
- 两个要同步的 key 加进同步和备份的清单，写进 [contracts.md](../architecture/contracts.md)。
- 插件接口：`island.collapsed/v1` 多一个可选的 `label`；市场规则加一条「上岛项目宽度不超过 64，超过的要提供更窄的形态或默认收进小面板」（数值待定）。

## 分阶段

| 阶段 | 内容 | 大小 |
|---|---|---|
| 1 | 清单补全：设置列出全部插件项、插件详情的开关、`label`；右键勾选清单 | 小，只动前端 |
| 2 | 溢出：外侧优先的截断、「+N」、小面板、设置里的「放不下」标记、安装提示 | 中，小面板要加原生点击区域（Rust） |
| 3 | 文字去处：`fuyu-collapsed-text`、刘海下一行的四种方式、文字进小面板 | 中 |
| 4 | 文字位排序；拖动排序 | 视需要 |

每个阶段单独能用，做完一个再看下一个要不要做。

## 不做

- 自由拖放的网格、中间区放图标。
- 刘海和非刘海各存一套布局。
- 插件自己选位置。

## 没核实的

- 两翼可用宽度「约 80、放 2–3 个图标」是按 `notch.ts` 的常量和样式里的边距算的，没在真机上量。
- 预览页的图标宽度是示意，和真实项目有出入；英文文案的宽度没做。
