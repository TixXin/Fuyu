用户 2026-11-19 选了 C，并要求「把更新日志放在单独 tab，设置和帮助也是」，标签放在关于页顶部、和其他页面的标签一致。之后又说「设置还是放在首页里」。这一版：标题下面一排下划线标签 概览 / 更新日志 / 帮助，概览是首页，放居中名片和更新设置。上面的开关能比较重置与退出的三个位置；A、B 已放弃，留着对比。

第一版的问题清单和三套方案对比（已定，折叠）
  1. 双栏不齐：右栏长，左栏「更新日志」下面空一大块。

  3. 日志藏着：更新日志是主要内容，却只列版本号，要点开才看到。

  5. 危险操作：「重置与退出」要和别的区分，但不要太醒目。
  6. 状态：三种通道和检查中 / 下载中 / 有新版本 / 已下载 / 失败时横幅怎么变。
  7. 适配：最小宽 580、浅色深色、中英文、Win 和 Mac。

拟定的做法（实现时要写进文档）

标签就是页名

  • 概览 about（名片 + 更新设置）、更新日志 aboutChangelog、帮助 aboutHelp，和外观、AI Agent 的标签一样，每个标签一个页名。
  • 设置搜索的索引按页名记，结果显示「关于 › 概览 › 更新通道」，点了切到那个标签、滚到那一行、强调色铺底 1.8 秒（现有做法）。
  • 旧页名 updates 照样能打开关于，落在概览。

记住上次的标签

  • 新 key fuyu-about-tab：字符串 "overview" / "changelog" / "help"；没有或认不得时按 "overview"。只是界面状态，不进设置备份（不加进 BACKUP_KEYS）。写进 contracts.md。
  • 从侧栏点「关于」、关掉设置窗口再打开，都回到上次的标签。
  • 预览页真的在写这个 key：当前值 （刷新页面能看到被记住）。

跳转请求

  • 沿用 fuyu-settings-focus，section 还是 "updates"；像 E60.12 给插件加 plugin 那样，加一个可选的 tab（"changelog" / "help"）。不带 tab 时落在概览，因为更新状态、主按钮和更新设置都在概览。
  • 跳转打开的标签也会被记住（待定问题 2）。

待你定的问题

  1. 重置与退出放哪：推荐概览最底下，和更新设置一起（重置的是设置，找起来顺），中间隔开一段、只有按钮是红字；也可以放「帮助」底下，或收进名片右上角的「⋯」菜单（最不显眼，但第一次找的人可能找不到）。上面「重置与退出」开关能切。
  2. 跳转要不要改写记住的标签：推荐改写（简单：最后看的就是记住的）；另一种是只有自己点标签才记，跳转只是这一次。
  3. 第一次打开停在哪：推荐「概览」；也可以第一次直接停在「更新日志」，因为日志是主要内容。
  4. 其他页的标签要不要也记住上次：现在外观、AI Agent 等页每次都从第一个标签开始，只有关于页记，行为不一致。推荐先只做关于页，以后要统一再说。
  5. 概览里的海面横幅和戳一戳问候：这版名片是素的（淡光 + Logo 位），没有海面、浮动小岛和问候彩蛋。要不要把小岛和戳一戳放回名片里？
  6. 有新版本时新版本的说明放哪：这版在概览名片下面直接展开「v… 更新内容」，更新设置被挤到下面。也可以收成一行「查看更新内容 ›」，点了跳到更新日志标签最上面。
