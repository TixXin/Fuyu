分级：

- **挡发版**：不修就会伤到正式版用户。
- **最好发版前修**：风险明确，改动不大。
- **以后再说**：设计上的取舍，或者影响小。

「确定」是读代码或实际跑过；「推测」是没实测。

## 挡发版

### B1 六个内置插件升级后从关变成开，旧配置也丢了（确定，已抽查）

- **涉及**：用量环 `claude-usage`、`cc-connect`、会话环 `session-ring`、本机接口 `local-api`、SSH 隧道 `ssh-tunnel`、中心图案 `center-pattern`。
- **原因**：
  - v0.3.10 的迁移表只有计时器一项（`git show v0.3.10:src-tauri/src/plugin_kernel/v2_builtins.rs` 第 40 行）。
  - 「没开过就写成关闭」的规则 `off_without_grant` 是 v0.3.10 之后才加的（`fcf96486^:src-tauri/src/plugin_kernel/v2_builtins.rs:102-108`），后来在 fcf96486（E36.6.5）里随 `v2_builtins.rs` 一起删掉了。
  - 现在启动只跑 `v2_migration::migrate_and_scan`（`builtins.rs:342`），`plugins.yml` 里没有的内置插件一律当作开着；`src/features/builtins.json` 也没有「默认关」的字段。
  - `contracts.md:230` 说这段迁移「已跑满一个发版周期」，这只对测试版用户成立，正式版用户一次都没跑过。
- **后果**：
  - 正式版用户升级、新装用户首次启动，这六个都会开着。本机接口开着就会起服务（`local_api/background.rs:18-19`）。
  - 用过它们的老用户会丢掉 cc-connect 的路径和「由岛启动」、用量环设置、中心图案的选择。
  - 从 0.3.9 或更早升上来的用户，计时器也一样。
- **改法**：从 `fcf96486^` 拿回迁移表，在 `builtins::init` 里跑一次；至少要做到「没有旧授权就写成 `disabled`」。另外给 `builtins.json` 加上「默认关」，让新装用户也不会默认开。

### B2 卸载接口能删掉全部已装插件（确定，已抽查）

- `market/v1` 服务不检查调用方是谁（`services.mjs:141-180,229-231`），任何插件或窗口都能调 `uninstall`、`installFile`、`setManualAllowed`。
- 卸载时插件 id 只过一道正则 `/^@([a-z0-9-]+)\/([a-z0-9._-]+)$/i`（`packages/plugin-cli/src/installer.mjs:13`），`@x/..` 也能通过，拼出来的路径就是 `packages/` 本身。勾了「同时删数据」时，整个 `data/` 也会被删。
- **改法**：卸载只接受已装列表里的 id，名字部分拒绝 `.` 和 `..`；安装和 `setManualAllowed` 只接受设置窗口发来的调用。

### B3 市场插件装上后看不到页面，也找不到设置（确定，已在修）

- 岛的页头只显示带 `headerDot` 的页面，而且只认内置页的标题；设置窗口没有渲染 `pluginsV3` 这一组设置分节；命令也没有「运行」按钮。
- 12 个官方插件里，9 个注册了岛页面，9 个注册了设置分节，用户装了等于看不到。
- 正在修：E60.5（#936）、E60.6（#937）、E60.7（#938）。要么等它们合入再发，要么在发版说明里写明「市场插件的页面和设置下个版本才能用」。

## 最好发版前修

### 升级迁移

- **M1 旧开关迁移先写标记、后切开关**（确定）：`useLegacySwitches.ts:20-24`。切换失败或中途崩溃后不会再迁，原本关掉的功能会变成开着。应该每切成功一项再写那一项的标记。
- **M2 同步白名单里留着已删的键**（确定）：`settings_whitelist.json:10,199-200` 里还有 `fuyu-plugin-pages` 和 `fuyu-plugin-market-favorites`，同步设置里还显示「插件岛上页面顺序与隐藏」这个开关（`src/i18n/sections/sync.ts:267`），但它已经不起作用。
- **M3 文档写错**（确定）：`data-storage.md:42` 说「本机接口的设置第一次启动时搬过来」，现在已经不是这样。

### 第三方插件和市场

- **M4 `replaces` 不看插件是否真在运行，也没有白名单**（确定）：`builtins.mjs:113-133`。插件被安全模式拦下、出错停用或被二分排查暂时关掉时，它要替换的内置服务照样关着。第三方插件还能替换必需的 `market/v1`。
- **M5 市场包不核对包名和版本**（确定）：安装目录按包自己清单里的名字定（`installer.mjs:115`），不和索引条目比对；市场来源一律按官方身份校验（`installer.mjs:74`），所以第三方包也能叫 `@fuyu/*`。
- **M6 撤销名单出问题会拖垮整个市场刷新**（确定）：撤销名单过期（上限 90 天）、取不到或被拒时，`market.mjs:166-187` 直接抛错，索引不更新，自动更新和撤销都不执行。设计（`v3-market.md:156`）写的是只提示。撤销密钥是离线的，忘了重签就会一直失败。
- **M7 更新后宿主里跑的还是旧代码**（推测，把握高）：宿主代码按不带版本号的地址 `import()`（`sources.mjs:138`），装完只刷新配置，不重启宿主（`market.mjs:348-353`）；窗口部分带 `?v=版本`，会加载新版。结果新旧两半一起跑，安全修复要等下次启动浮屿才生效。
- **M8 装到一半失败会留下半装的包**（确定）：先删旧目录再逐个写文件（`installer.mjs:116-122`），依赖先装（`market.mjs:65-78`）。应该先写到临时目录再改名，失败时还原旧版。
- **M9 撤销执行不完整**（确定）：被撤销停用的插件，用户拨一下开关就能重新打开（`InstalledPluginRow.tsx:87`、`market.mjs:318-333`）；「提示」级的撤销在界面上从不显示。
- **M10 自动更新不比较权限**（确定）：`market.mjs:88-96` 只排除换了作者密钥的版本，新版本多要了 `nodeApis`、`network`、`replaces` 也会静默装上；也没有关自动更新的开关。索引里有已装版本的清单，可以直接比对。

## 以后再说

- **S1 第三方插件没有隔离**（确定，设计如此）：
  - 宿主部分和内置插件跑在同一个 Node 进程里，能读别的插件的 `data/` 和 `plugins.yml`。
  - 窗口部分和岛在同一个 JS 环境里运行（`loader.mjs:5,22`），能直接调 `__TAURI_INTERNALS__.invoke`。
  - 岛窗口的 CSP 放行任意 `http:`/`https:`（`tauri.conf.json:149`），清单里的 `network` 白名单在窗口里不起作用。
  - `ctx.rust` 只给内置插件，这只是约定，插件可以直接写 fd 1。
  - 和设计文档「审核是唯一防线」（`v3-everything-plugin.md:485`）一致，但文档第 410 行说「页面的 CSP 只放行这些域名」，要改。
- **S5 作者签名不覆盖包内容**（确定）：只签了 name、version、repository、commit（`plugin-market/src/author.mjs:6,40-43`），设计表里「作者签名能防市场被攻破」这一条不成立。
- **崩溃隔离**：一个插件卡死，所有内置功能会一起中断约 2 秒。插件跑满 60 秒后才卡死的，失败计数会清零，可能无限重启（推测）。宿主没设堆内存上限。
- **启动细节**：
  - 用户设的 `NODE_OPTIONS` 会传给宿主（`supervisor.rs:239-240`）。
  - 正式版找不到打包的宿主时，会退回到编译机上的仓库路径（`mod.rs:77-85`）。
  - 系统里的 Node 只在启动时选一次。
  - `runtime.ts:48-49` 里有一条提示只有中文。
- **备份**：内置插件的开关和配置不进同步，也不进完整备份（`backup.ts:38-49`）。
- **卸载残留**：快捷键改键记录和固定的作者密钥会留下；卸载时不检查有没有别的插件依赖它。
- **测试缺口**：第 2 版迁移卡片和岛上的升级提示没有回归页。

## 已确认正常的

- **启动**：正式版一定会启动宿主，只有 `FUYU_PLUGINS_V3=0` 能关（`mod.rs:45-59`）。插件相关的代码里已经没有按版本号判断的残留。
- **宿主没起来时**：22 个内置功能照常能用，界面和服务都在窗口里，开关归 Rust 管。受影响的只有第三方插件和插件市场；设置 → 插件页会显示下载进度、失败原因和「重试」。
- **打包**：发布脚本带上了宿主和内置插件，打包后的路径和 Rust 里的 `BUNDLED_HOST`、`BUNDLED_BUILTINS` 一致；用发布脚本打到临时目录后 `release-resources --verify` 通过，按正式版的参数启动，22 个插件全部到了 running。
- **市场校验**：
  - 哈希不符、平台不支持、需要更新浮屿、被撤销的版本，都会挡下来不让装；
  - 索引 7 天过期，序号只增不减；
  - 更新冷静期 3 天，紧急修复可以跳过。
- **停用和卸载时的释放**：定时器、命令、快捷键、服务、Rust 事件都会释放。
- **老版本直接升上来**：从 FocuSD、0.2.x 直接升，改名迁移和旧 key 复制的链路是通的，但同样会遇到 B1。
- **测试**：`node --test "packages/*/test/**/*.test.mjs"` 360 个全部通过；升级迁移相关的单元测试 36 个全部通过。
- **issue 和提交**：没有用户或外部报的插件 bug 还开着；最近 3 天插件相关的提交里没有 WIP 或 revert。
