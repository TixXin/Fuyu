剪贴板预览：要你定的 5 件事

用户原话：按住空格打开预览后，鼠标移到预览窗口，松开空格应该预览继续显示；预览要能放大缩小图片、窗口放大（中等、全屏），支持修改。每件事 2–3 个方案，蓝框是组长推荐。2026-11-15，[任务] 剪贴板预览。

用户已定（2026-11-15）

① A+B+C 都要 · ② A · ③ A+C · ④ A · ⑤ A，类型 1（先文字，图片第二批）。计划见 docs/architecture/clipboard-preview-plan.md。

现在是怎么工作的

  • 标准宽度、搜索框为空时按空格：剪贴板窗口旁边弹出 clipboard-preview 窗口（宽 420，与剪贴板窗口同高，右边放不下放左边）。点按空格 = 一直开着，再按空格或 Esc 关；按住超过 350ms 再松开 = 关（useSpacePeek.ts）。
  • 预览窗口从不拿焦点：Windows 是 WS_EX_NOACTIVATE + SW_SHOWNOACTIVATE；Mac 是一种不能成为 key window 的 NSPanel（PreviewPanel，G1.18 修过：以前一出来剪贴板窗口就失焦关掉）。
  • 所以键盘始终在剪贴板窗口里，↑↓ 换条时预览跟着换；鼠标点预览里的链接、颜色照常能粘贴（点击不需要焦点）。
  • 剪贴板窗口失焦就关（除非「固定」），预览跟着关。已有「编辑后粘贴」Ctrl+E：在剪贴板窗口里编辑，Ctrl+Enter 只粘贴这次，Ctrl+S 另存新记录，原记录不变。没有「改原记录」的命令。

① 松开空格后预览怎么留住、怎么关 按住时剪贴板窗口仍有焦点，所以松开的按键它收得到

推荐

A. 松开时鼠标在预览上 → 留住

剪贴板
留住了×
🖱️ 松开空格时指针在预览里：变成和「点按空格」一样的常开状态

预览窗口把鼠标进出（pointerenter / leave）发给剪贴板窗口；松开空格时看最后一次状态。之后再按空格、Esc、点右上角 × 关，剪贴板窗口关时一起关。鼠标不在预览上时松开照旧关，按住看一眼的习惯不变。

代价：小。纯前端加两个事件。提示文字「松开即关」在鼠标进入后改成「松开后留住」。
Windows无激活窗口照样收 pointer 事件Mac非 key 面板里 WebView 的鼠标进出要实测（可能要开 tracking area 的 activeAlways）

B. 按住期间鼠标进过预览 → 留住

只要按住时指针进过预览，哪怕又移出来再松开，也留住。

代价：和 A 一样小。容易「误留」：鼠标只是路过也会留住，用户得多按一次关。

C. 预览上加一个图钉

松开空格照关；想留住就在按住时点预览右上角的图钉。

代价：最小，但不符合用户原话（他要的是「移过去松开就留着」）。

② 鼠标移进预览后，焦点怎么交接 绿框 = 有键盘焦点的窗口

推荐

A. 平时不拿，进入编辑才拿

剪贴板
滚轮缩放 · 拖动 · 按钮
看、缩放、换尺寸都不要焦点；点「编辑」时预览才拿焦点，Esc / 保存后还给剪贴板窗口

点击、滚轮、拖动在两个平台的无激活窗口里都能用，所以浏览阶段保持现状：↑↓ 照常换条，缩放的键盘快捷键（+-0）由剪贴板窗口转发。只有编辑文字时预览拿焦点，这段时间剪贴板窗口失焦不关。

代价：中。失焦就关的逻辑加一个「焦点给了自己的预览」例外；两个平台各写一段「临时可激活」。自动粘贴的目标窗口不受影响（弹出前记下的）。
Windows已有 set_no_activate(hwnd, bool)，编辑时关掉再 SetForegroundWindow；本进程已在前台，前台锁一般不拦MacPreviewPanel 现在写死不能成为 key，要换成能切换的（编辑时允许 + makeKeyAndOrderFront），不能回到 G1.18 以前的样子

B. 鼠标移进就拿焦点

指针进预览，焦点跟过去；移出还给剪贴板窗口。预览里能直接用键盘（选文字 ⌘C、方向键平移图片）。

代价：大。焦点来回跳，剪贴板窗口的 ↑↓、搜索框输入会被鼠标位置打断；Windows 频繁抢前台可能闪任务栏；Mac 每次 key 切换都要绕开 G1.18 的坑。两个平台行为最难做成一样。

C. 永远不拿，编辑放回剪贴板窗口

预览里点「编辑」= 剪贴板窗口打开已有的编辑器（Ctrl+E 那个），预览只负责看。

代价：最小，零焦点代码。但编辑框挤在 380 宽的窗口里，旁边大预览却不能改，和「预览支持修改」对不上；全屏预览时编辑不方便。

③ 中等 / 全屏两档怎么切、放在哪

推荐

A. 三档按钮 + 一个键循环

标准中等全屏×
剪贴板
全屏时剪贴板窗口叠在预览上面，键盘还在它那，↑↓ 换条照常

预览顶上三个按钮：标准（现在的 420 宽）、中等（剪贴板窗口所在屏幕工作区的约 60%×75%，靠剪贴板窗口一侧摆）、全屏（那块屏幕的整个工作区，不盖任务栏 / 菜单栏）。剪贴板窗口里 F 循环三档（搜索框为空时，和空格同样的条件）。剪贴板窗口始终在预览上层。

多显示器：跟着剪贴板窗口所在的那块屏幕。记不记：每次打开从标准开始（不加新的存储 key）。

代价：中。Rust 加尺寸档位和摆放函数（可单测）；层级要让剪贴板窗口压在预览上：Windows 两个都置顶，按 z 序插入；Mac 预览面板的 level 比剪贴板窗口低一级。

B. 中等贴边长大，全屏时剪贴板窗口隐身

中等：预览朝远离剪贴板窗口的方向变宽变高，两个窗口并排。全屏：预览铺满，剪贴板窗口隐到后面但保留焦点，↑↓ 盲换。

代价：中。全屏时看不到列表、不知道选的是哪条；Windows 上「隐藏但保留焦点」做不到（隐藏的窗口会丢焦点），只能挪到屏幕外，Mac 可以 alpha 0。

C. 拖边自由缩放 + 记住尺寸

预览可以拖边改大小，双击顶栏在「全屏 / 上次大小」切换，尺寸存进设置。

代价：大。无激活窗口在 Windows 上拖边改大小会激活它（要自己画拖拽区）；Mac 非 key 面板拖边也得自己处理；要新存储项（对外契约）。

④ 图片缩放的操作

推荐

A. 滚轮缩放 + 拖动 + 缩放条

−135%+适应1:1

滚轮以指针为中心缩放（触控板双指捏合在 WebView 里也是 Ctrl+滚轮，一并支持），放大后拖动平移，双击在「适应窗口 / 100%」之间切。底部悬停出现缩放条。键盘 +-0 由剪贴板窗口转发。换条时回到「适应」。

代价：小，纯前端组件。长截图要先放大才能看下半截。

B. Ctrl+滚轮缩放，滚轮滚动

像浏览器看图：普通滚轮上下滚（长截图友好），按住 Ctrl / ⌘ 再滚才缩放。

代价：小。但键盘焦点在剪贴板窗口，预览收到的滚轮事件里 Ctrl 状态在 Windows 上是准的，Mac 非 key 窗口里 ⌘ 修饰要实测。

C. 只有档位按钮

适应 / 100% / 200% 三个按钮，没有滚轮和拖动。

代价：最小，但不能看局部细节，用户说的「放大缩小」做得很弱。

⑤ 编辑：改这条还是另存，编辑哪些类型

推荐

A. 两个都给：保存 = 改这条，另存 = 新一条

预览里点「编辑」（或剪贴板窗口 CtrlE），内容区变成编辑框。CtrlS 改这条：来源、复制时间、收藏、标签、固定键都保留，第二行多一个「已编辑」，底栏「已保存 · Ctrl+Z 撤销」6 秒（和删除一样）。Ctrl⇧S 另存一条放最上面。CtrlEnter 只粘贴这次。

代价：中。Rust 新增「改记录文字」命令（重算预览文字、类型识别、打码判断，带 HTML 的条目改完变纯文字）。要改一条已确认的设计：现在编辑器里 Ctrl+S 是「另存」，统一后变成「改这条」，剪贴板窗口里的 Ctrl+E 编辑器同步改。

B. 只改这条

编辑就是改原记录，带撤销。不提供另存。

代价：和 A 差不多，少一个按钮；想保留原文的人只能先复制一份。和现有 Ctrl+S 冲突同 A。

C. 只另存（和现在一样）

编辑后存成新记录，原记录永远不动。

代价：最小，不改已确认的设计。历史里会堆出很多相似的条目。
推荐

类型 1：先做文字，图片编辑第二批

第一批：文字（含链接、JSON、颜色这类识别出来的文字；JSON 打开编辑时先格式化）。打码的条目要先点「显示原文」才能编辑。文件列表不编辑。第二批：图片的裁剪、旋转、标注（标注复用截图的标注绘制代码，先评估能不能直接用），改这条 = 替换图片文件、重做缩略图和文字识别。

代价：分两批，第一批就能用；图片那批 Rust 量大（图片文件替换、OCR 重跑、撤销要留旧文件）。

类型 2：文字 + 图片一次做完

代价：一批里同时改文字和图片的存储，任务会话要编译的时间长，晚很多才能用上。

类型 3：只做文字

代价：最省；图片只能看和缩放，标注还得去截图里做。
