# 市场规则

> 适用于上架官方市场 [`TixXin/fuyu-plugins`](https://github.com/TixXin/fuyu-plugins) 的插件。**向市场提交插件，就是同意这一页的规则。**

插件和浮屿同权，浮屿没有技术手段拦住一个插件去读文件、联网或运行程序。用户能依靠的，主要是维护者读过这个版本的源码。所以这些规则都为了一件事：**让审核的人看得懂、看得全你的插件会做什么。**

## 代码

- **不混淆。** 提交的源码要是人能读的源码。压缩和打包由市场构建时的 `fuyu-plugin build` 来做，不用你做。第三方库通过 npm 依赖引入并写进锁文件，不要把别人压缩过的代码拷进自己的源码：审核看不了，审核分析器也会标出来（见[审核看什么](review.md)）。
- **不在运行时下载代码来执行。** 不用 `eval`、`new Function`、字符串形式的 `setTimeout`；不下载 JS、WebAssembly 或脚本再加载、运行；界面里不加载远程脚本。从网上取数据（JSON、图片）没问题，取回来的东西不能当代码跑。
  - 浮屿在技术上挡住了一部分：宿主的 Node 带 `--disallow-code-generation-from-strings` 启动，`eval` 和 `new Function` 用不了；界面的 CSP 不允许 `eval` 和远程脚本。但「下载一个文件再 `import()` 它」技术上拦不住，靠审核。
- **不自己更新自己。** 新版本只走市场。不下载新文件覆盖插件目录，不让用户去别处下载新版本替换。
- **不带可执行程序和 Node 原生扩展（`.node`）。** 它们没法从源码审核。包里出现就会被拒，按扩展名和文件头认（`.exe`、`.dll`、`.so`、`.dylib`、`.wasm`、`.jar` 等，完整列表见[清单和安装包](package.md#包里不能有的)）。要用系统自带的程序，可以在宿主部分用 Node 的 `child_process`，审核时会逐项看，在 PR 里写清为什么要用。
- **不用实验接口。** 清单的 `fuyu.experimental` 不为空的插件，市场不收。实验接口只给内置插件和开发模式用。
- **声明和代码对得上。** 要连的域名写进 `fuyu.network`，用到的服务写进 `fuyu.inject`，提供和替换的服务、放界面的插槽、命令都写进清单（见[清单和安装包](package.md)）。`fuyu.network` 不是沙箱，技术上拦不住宿主里的代码连别的地方；它的作用是让「把数据发到一个陌生的服务器」必须先在审核里露面。代码连了没声明的域名，这个版本不会被批准。

## 名字

- 第三方插件的名字必须是 `@<源码仓库的所有者>/<名字>`。所有者就是 GitHub 上放源码的那个用户或组织，不区分大小写：仓库在 `github.com/SomeOne/weather`，插件可以叫 `@someone/weather`。
- 作用域里的名字可以带 `fuyu`：`@someone/fuyu-weather` 可以。
- `@fuyu/*` 留给官方插件。不带作用域的名字不收。
- 只能用小写字母、数字、`-`、`.`、`_`、`~`，最长 214 个字符。
- 名字是插件的唯一标识，也是它在用户电脑上的安装目录和数据目录的名字。改名就是另一个插件，已经装了的用户不会自动换过去。

## 开源和许可证

- 源码仓库必须公开：市场从这个仓库构建，维护者审核读的也是它。
- `package.json` 的 `license` 必填，写 SPDX 标识，例如 `MIT`、`Apache-2.0`、`GPL-3.0-only`。`UNLICENSED` 不收。
- 仓库里放上 `LICENSE` 文件，它会跟着进包。市场详情页显示许可证和仓库链接。

## 作者签名

- **第三方插件的每个版本都要作者签名。** 签的是这个版本的**提交号**（不是标签名：标签能被移动），连同插件名、版本、仓库一起签，算法 Ed25519。旧版插件用过的作者签名密钥可以继续用。
- 公钥登记在市场的提交文件里，第一次上架时由维护者核对。用户第一次安装时，浮屿记下签名的密钥和仓库；之后换了密钥或仓库的版本要用户确认才装（见下一节）。
- 在自己的电脑上签，私钥不要放进仓库或 CI，并且备份好：丢了只能换新密钥，换密钥按下一节处理。
- 官方插件（`@fuyu/*`）不用私钥。它的作者证明是「这个提交在 `TixXin/fuyu` 受保护的 `main` 上」，同样走市场构建、审核和冷静期。

生成密钥和签名的命令见[命令行](cli.md#密钥)，提交给市场的流程见[发布](publish.md)。

## 换密钥、换人、换仓库

这三种情况**一律当作重新上架**：

- 维护者按第一次上架重新审核，通读源码。
- 已经装了这个插件的用户会看到「这个插件的作者或签名密钥已更换」，要重新确认，这次更新**不会自动安装**。
- 换密钥时旧密钥还在、用它给新密钥签了证明的，用户确认一次；没有证明（旧密钥丢了），或者仓库变了，用户要确认两次。

所以没有必要就别换密钥，换之前先备份好旧的。

## 所有权转移

把插件交给别人维护（转让仓库、卖掉插件、换人发版）之前，**先在 `fuyu-plugins` 开 issue 告知**，按重新上架处理（见上一节）。

名字的作用域跟着仓库的所有者：仓库转到别的账号后，旧名字和新所有者对不上，新版本要用 `@<新所有者>/<名字>` 上架，在浮屿看来是另一个插件。已经装了旧名字的用户怎么换过去，[还没定](#还没定的)。

作者签名管不住「作者把插件和密钥一起交给了别人」，这一条只能靠规则。不告知就转手的，被发现时维护者可以拒绝之后的版本、撤销已上架的版本。

## 违反规则会怎样

- 还没上架的版本：不批准，PR 里写明原因，改好后重新提交。
- 已经上架的版本：撤销（见下一节），原因公开。

## 下架、撤销和申诉

**撤销**用来处理已经上架、可能已经有人装了的版本，分两级：

| 级别 | 用户那边 |
|---|---|
| `warn`（提示） | 插件页和岛屿上提示原因；这个版本不再自动更新到用户那里，也不再是新安装的默认版本，只能手动装；有修复版时优先推修复版 |
| `disable`（停用） | 这个版本被停掉、不能再启用，插件的数据保留；用户可以卸载，或者换到没被撤销的版本 |

- 撤销可以针对一个版本，也可以针对一个插件的所有版本。
- 撤销的原因用中英文公开显示。
- 撤销名单由维护者用一把单独的、离线保管的撤销密钥签名，市场日常构建用的密钥签不了。
- 对手动安装的同名同版本插件同样生效。
- 不会删除用户电脑上的插件目录。

**谁能申请撤销**：作者自己（发现某个版本会删数据、会泄露信息）、用户、任何发现问题的人，都到 `fuyu-plugins` 开 issue。安全问题按下文[报告安全问题](#报告安全问题)走。

**申诉**：作者对拒绝或撤销有异议，在 `fuyu-plugins` 开 issue 写明理由，维护者复核。确认是误撤销的，维护者把那一条撤销**收回**；收回的撤销以后不会再生效，要再撤销就另开一条。

**作者主动下架**（不再维护、不想让人再装）：在 `fuyu-plugins` 开 issue。下架后市场里怎么显示、已经装了的用户怎么处理，[还没定](#还没定的)。

## 报告安全问题

发现某个插件有安全问题（会泄露数据、有恶意行为、能被别人利用）：

- **不要在公开的 issue 里写细节和利用方法。** 在 `fuyu-plugins` 开 issue，只写插件名、版本和「有安全问题，需要私下联系」，维护者会联系你拿细节。GitHub 的私密漏洞报告（仓库 Security 页的 Report a vulnerability）现在还没打开，打开后改用它。
- 问题看起来是作者无意的、作者还在维护，也可以同时私下告诉作者；看起来是作者故意的，只报给市场。
- 维护者确认后按问题的轻重撤销（`warn` 或 `disable`），原因公开。

## 每项保护管什么、不管什么

市场和浮屿的界面上不会说一个插件「安全」或「已验证」，只说具体的事：哪个版本被人审过、作者签了没有、上架了多久。「已验证」只用在发布者身份上，并写明怎么验证的（GitHub 组织或域名），它说明发布者是谁，不说明插件没有问题。

| 保护 | 管得住 | 管不住 |
|---|---|---|
| 审核 | 审过的那个版本里看得出来的问题 | 没审的版本；审核的人没看出来的 |
| 市场构建 | 「源码干净，发布包里另外塞了东西」 | 源码本身有问题：作者作恶、作者账号被盗、依赖被投毒 |
| 作者签名 | 市场或下载渠道被攻破 | 作者的电脑被攻破（密钥会一起丢）；作者把插件卖给别人 |
| 冷静期 | 给别人留出发现问题的时间 | 潜伏期比冷静期长的 |
| 联网白名单（`fuyu.network`） | 让偷偷联网必须先在审核里露面 | 宿主里的代码能直接用 Node 的网络接口，技术上拦不住 |
| 安装确认 | 告知用户、划清责任 | 用户习惯性点掉 |
| 撤销名单 | 事后清理 | 发现之前的损失；也可能误伤 |
| 出错或占用过高时自动停用 | 有 bug 的插件 | 恶意插件：它们不报错、不占 CPU |

手动安装的 `.fuyu` 文件不经过市场：审核、市场构建、冷静期都管不到它，只剩安装时那一次确认和撤销名单。浮屿会在安装确认和插件页上写明「这个插件没有经过浮屿市场的审核」，见[清单和安装包](package.md#三种装法)。

## 还没定的

- 仓库转给别的账号后，已经装了旧名字的用户怎么换到新名字。
- 作者主动下架后，市场怎么显示、已经装了的用户怎么处理。
- 私密报告安全问题的入口：等 `fuyu-plugins` 打开 GitHub 的私密漏洞报告。
