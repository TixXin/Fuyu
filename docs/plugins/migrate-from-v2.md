# 从旧版插件迁移

> **提纲。** 2026-11 之前的旧版插件（清单是 `fuyu-plugin.json`、用 `fuyu-plugin` 1.x 开发的那一套）已经随 E36.6 下线，宿主和 SDK 都从浮屿里删了。旧接口到现在的服务的对照表还没写，缺的列在[待补](#待补)。旧版的作者文档只留在 git 历史里：[删除前的最后一版](https://github.com/TixXin/fuyu/tree/82c16e4027/docs/plugins)。

## 先知道的

- **旧版插件在现在的浮屿里不能用**，没有兼容层。装过的旧版插件升级后都不能再用，浮屿会给一次性的提示。
- 旧版的命令行 `fuyu-plugin` 1.x、`create-fuyu-plugin` 0.x 和 PowerShell 模块停止更新；npm 上的 `fuyu-plugin` 2.0 起是现在的命令行。
- 迁移基本等于重写：插件从「浮屿启动的一个独立程序」变成「浮屿里加载的一个模块」，界面从模板变成 React 组件。

## 差别一览

| | 旧版 | 现在 |
|---|---|---|
| 插件是什么 | 浮屿启动的独立程序，用浮屿的接口要先申请权限 | 在浮屿的 Node 宿主里加载的 ES 模块，和浮屿同权 |
| 用什么写 | PowerShell、`.exe`，或用本机 Node 运行的 JS | TypeScript 或 JavaScript：后台跑在 Node 里，界面用 React |
| 清单 | `fuyu-plugin.json` | `package.json`，浮屿的字段放在 `fuyu` 下（见[清单和安装包](package.md)） |
| 标识 | 插件 id，例如 `dev.example.todo-sync` | `@<源码仓库的所有者>/<名字>`（见[市场规则](market-rules.md#名字)） |
| 和浮屿通信 | 标准输入输出上的 JSON-RPC | 经 `ctx` 用服务、收发事件 |
| 权限 | 清单申请、用户授权，敏感权限第一次用时再问 | 没有权限表；靠市场逐版审核 |
| 界面 | 页面模板（list、detail、form）、收起条、自定义网页 | React 组件，放进插槽 |
| 安装包 | zip，可以带 `.exe` | `.fuyu`（内容是 zip），不能带可执行程序和 `.node` |
| 上架 | 作者在自己的 Release 里放 zip，市场定时去取 | 作者交提交号，市场从源码构建 |
| 审核 | 第一次上架，和申请新权限这类版本 | 每个版本 |
| 作者签名 | 可选，签 zip | 必须，签提交号 |
| 自动更新 | 签了名、不加权限的版本 | 上架 3 天后，见[冷静期](review.md#冷静期) |
| 撤销 | 停用或卸载 | 提示或停用，不删插件目录 |

## 迁移的步骤

1. **换名字。** 插件 id 改成 `@<源码仓库的所有者>/<名字>`。在浮屿看来这是一个新插件，已经装了旧版的用户要重新装。
2. **新建项目。** 用 `npm create fuyu-plugin@latest` 生成 TypeScript 项目。PowerShell 和 `.exe` 写的插件要改写成 TypeScript。
3. **改写后台逻辑。**
   - 插件不再是自己的进程：逻辑写在插件的入口函数里，后台部分跑在浮屿的宿主里。
   - 旧版的 JSON-RPC 方法改成 `ctx` 上的服务（对照表待补，现有的服务见[服务、接缝与插槽参考](services-and-slots.md)）。
   - 要运行外部程序，在宿主部分用 Node 的 `child_process`；不能再把 `.exe` 放进包里。用了 `child_process` 的版本会落进黄档，在 PR 里写清为什么要用。
   - 宿主卡死或崩溃时浮屿会重启它，所以状态不能只放在内存里。
   - 定时器、事件监听、样式用内核提供的受管版本，插件停用时才撤得掉。
4. **权限改成声明。** 删掉权限表，改成：用到哪些服务写进 `fuyu.inject`，要连的域名写进 `fuyu.network`。用到的 Node 模块（`fuyu.nodeApis`）由构建时扫出来，不用写。
5. **改写界面。** 页面模板、收起条、设置页、自定义网页都改成 React 组件，放进对应的插槽；设置项改成 `fuyu.config` 指向的 schema，设置窗口据此生成表单。
6. **签名。** 旧版的作者签名密钥可以直接用：`fuyu-plugin` 2.0 读的是同一个密钥文件（`~/.fuyu-plugin/signing.key`），见[命令行](cli.md#密钥)。旧版签名可选，现在上架必须签，签的是提交号，见[市场规则](market-rules.md#作者签名)。
7. **重新上架。** 按[发布](publish.md)的流程提交，按第一次上架审核。

## 待补

- 旧版的接口（`todos.*`、`clipboard.*`、`island.notify`、`storage.*`、`secrets.*`、事件……）到现在的服务的对照表。
- 旧版的页面模板、收起条、命令、菜单、音效包到插槽的对照表。
- 旧版插件保存的数据（`plugins-data/<id>/`、凭据管理器里的秘密）能不能搬、怎么搬。
