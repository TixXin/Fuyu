# 发布

> **提纲。** 第 3 版的市场还没开放上架：命令行 `fuyu-plugin` 2.0（[#483](https://github.com/TixXin/fuyu/issues/483)）和市场 CI（[#484](https://github.com/TixXin/fuyu/issues/484)）还在做。这一页先写已经定下的流程，具体命令、提交文件的格式等它们做完后补，缺的列在[待补](#待补)。

插件进浮屿有三条路：从市场装、手动装一个 `.fuyu` 文件、开发时从文件夹加载，区别见[清单和安装包](package.md#三种装法)。这一页讲前两条。

## 上架之前

- 读一遍[市场规则](market-rules.md)：提交就是同意。
- 源码仓库在 GitHub 上、公开，清单写了 `license`。
- 插件名是 `@<源码仓库的所有者>/<名字>`。
- 用审核分析器看一下自己落在哪一档（[提交前先自查](review.md#提交前先自查)）。
- 有一把作者签名密钥。第 2 版的密钥可以继续用。

## 市场怎么上架一个版本

作者**不用自己打包**：交一个提交号，市场从这个提交的源码构建出 `.fuyu`，用户装的就是市场构建的包。所以维护者看过的源码和用户装上的代码是同一份。

1. **作者**：在自己的仓库给这个版本打标签，用自己的密钥给**提交号**签名（签的是插件名、版本、仓库、提交号四样，不签标签名，因为标签能被移动），向 `TixXin/fuyu-plugins` 开 PR，提交这个版本的提交号和签名。计划由 `fuyu-plugin publish` 一条命令完成打标签、签名、开 PR。
2. **市场 CI，检查**：取这个提交的源码，核对作者签名；在一个没有任何密钥的任务里按锁文件安装依赖（**不运行依赖的安装脚本**），用统一的 `fuyu-plugin build` 和市场提供的构建配置构建、打包；跑审核分析器，把报告贴进 PR。
3. **维护者**：看报告和源码差异，点批准（见[审核看什么](review.md)）。
4. **市场 CI，上架**：合入后重新构建，把 `.fuyu` 发到 `fuyu-plugins` 的 Releases，由另一个任务签名并更新市场索引。这个时间就是上架时间。
5. **用户那边**：上架 3 天后自动更新到已经装了的用户那里；手动更新、新安装的规则见[冷静期](review.md#冷静期)。

对作者有影响的几条：

- 构建配置由市场提供，不用作者仓库里的打包配置；现在只支持统一的 `fuyu-plugin build`，有特殊构建需求的插件暂时上不了架。
- 依赖要写进锁文件（`package-lock.json` 或 `pnpm-lock.yaml`），安装时不运行安装脚本，靠安装脚本才能用的依赖在市场构建里用不了。
- 提交号要是完整的 40 位，不能是标签名或分支名。

## 第一次上架

除了上面的流程，第一次还要在 `fuyu-plugins` 登记：

- 发布者（GitHub 账号）和作者的签名公钥；
- 市场分类等市场自己要核实的信息。

第一次上架至少是黄档，维护者通读全部源码。

## 以后的版本

- 提高 `version`，按上面的流程交新的提交号。
- 每个版本都审，和上一个审过的版本比。
- 换密钥、换人、换仓库当作重新上架，见[市场规则](market-rules.md#换密钥换人换仓库)。

## 预发布版和旧版浮屿

- 版本号带预发布标记（`1.3.0-beta.1`）的是预发布版，浮屿默认跳过，不自动更新到它。
- 每个版本有自己的 `engines.fuyu`：浮屿只装满足范围的版本，所以用户的浮屿没升级时，会拿到它能用的最新版本。

## 官方插件

`@fuyu/*` 的官方插件在 `TixXin/fuyu` 仓库里。它们不用私钥签名：作者证明是「这个提交在 `TixXin/fuyu` 受保护的 `main` 上」，由市场 CI 核对。其余和第三方插件一样：市场构建、逐版审核、冷静期。

## 手动分发一个 `.fuyu`

不上架，只想发给几个人用：

1. `fuyu-plugin pack` 打出 `<作用域>-<名字>-<版本>.fuyu`。
2. 可以用作者密钥签名，对方安装时会看到是谁签的；不签也能装，确认里写「没有签名」。
3. 对方要先在浮屿的设置里打开手动安装，再双击这个文件。安装确认会写明「这个插件没有经过浮屿市场的审核」，以后也不会自动更新。

## 用户那边会看到什么

市场详情页和安装确认里的信息来自三处：

| 来源 | 信息 |
|---|---|
| 清单 | 名字、介绍、图标、截图、分类、作者、许可证、主页和仓库、兼容的版本和系统、会用到浮屿的什么、会不会读写文件 / 运行程序 / 联网、要连的域名、依赖的插件、提供和替换的服务、插槽、命令和快捷键、设置项、是否预览版 |
| 包里的文件 | README、CHANGELOG |
| 市场 | 发布者和它的身份怎么核实的、作者签了没有、哪个版本被人审核过、包大小、上架时间、历史版本、是否被撤销 |

安装确认写明「这个插件拥有和浮屿一样的权限，能读写你的文件、运行程序」。浮屿里的这些界面还在做。
