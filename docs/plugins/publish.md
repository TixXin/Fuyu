# 发布

> 第 3 版，实验。**第 3 版的市场还没开放上架**：市场 CI 在 `TixXin/fuyu-plugins` 的草稿 PR [#25](https://github.com/TixXin/fuyu-plugins/pull/25) 上，合入后才能提交。下面是那个 PR 定下的流程，开放前细节还可能改。内部设计见 [v3-market-ci.md](../../architecture/plugins/v3-market-ci.md)。

插件进浮屿有三条路：从市场装、手动装一个 `.fuyu` 文件、开发时从文件夹加载，区别见[清单和安装包](package.md#三种装法)。这一页讲前两条。

命令行 `fuyu-plugin` 2.0 还没发到 npm，下文的 `fuyu-plugin` 怎么运行见[命令行](cli.md#怎么运行)。

## 上架之前

- 读一遍[市场规则](market-rules.md)：提交就是同意。
- 源码仓库在 GitHub 上、公开，清单写了 `license`。
- 插件名是 `@<源码仓库的所有者>/<名字>`。你要拥有这个仓库，或者是拥有它的那个组织的公开成员。
- **依赖只能用 `package-lock.json` 锁定**（`lockfileVersion` 2 或 3）。每个依赖都要来自 `https://registry.npmjs.org/` 并带 `sha512` 校验；git、本地路径、`link` 的依赖和别的锁文件（包括 `pnpm-lock.yaml`）市场构建都不收。市场用 `npm ci --ignore-scripts` 安装，**不运行依赖的安装脚本**，你的 `.npmrc` 也不生效。没有依赖的插件不用锁文件。
- 本地先跑一遍：
  - `fuyu-plugin check --market`：会被市场拦的东西提前报出来；
  - `fuyu-plugin review <上一个上架版本的提交> <这次的提交>`：看到的就是 PR 上的报告（见[审核看什么](review.md)）。

## 市场怎么上架一个版本

作者**不用自己打包，也不用发 Release**：交一个提交号，市场从这个提交的源码构建出 `.fuyu`，用户装的就是市场构建的包。所以维护者看过的源码和用户装上的代码是同一份。

1. **只做一次**：`fuyu-plugin keygen`，记下它打印的公钥 `{ "keyId", "publicKey" }`。私钥留在你自己的电脑上（见[命令行](cli.md#密钥)）。
2. **提交并推送这个版本**：`package.json` 的 `name`、`version` 是这个版本，`repository` 指向这个仓库。打不打标签随你，市场只认提交号。
3. **签名**：`fuyu-plugin sign --commit <提交号>`。它读这个提交里的 `package.json`，签下插件名、版本、仓库、提交号四样，打印一段 JSON（见[命令行](cli.md#sign)）。
4. **开 PR**：向 [`TixXin/fuyu-plugins`](https://github.com/TixXin/fuyu-plugins) 开 PR，只新增或修改**一个文件** `plugins/v3/<作用域>/<名字>.json`，在 `versions` 末尾加一行（格式见下一节）。从 fork 开 PR 也可以。
5. **PR 检查**：在没有任何密钥、只读权限的任务里，按提交号取你的源码，用市场的构建设置和固定版本的工具构建，和上一个上架的版本对比审核，把报告贴到 PR 上：
   - 🟢 绿：和上一版比没有值得注意的变化，维护者看一眼就能批准；
   - 🟡 黄：多了 Node 模块、域名、子进程、依赖变化这类，报告逐条列出，维护者看过源码再批准，必要时请你说明；
   - 🔴 红：不会上架。改好后发新提交、新版本号再提交。
   - 构建失败，或者源码里扫出遗留的密钥（令牌、API 密钥、私钥），检查直接失败。
6. **批准**：维护者读报告、批准并合入。
7. **上架**：市场在合入后重新构建这个版本，发到 `fuyu-plugins` 的 Releases（标签 `v3.<作用域>.<名字>@<版本>`，附件是 `.fuyu`、图标和截图），几分钟后签过名的市场索引 `index.v3.json` 更新。发 Release 的时间就是上架时间。
8. **用户那边**：上架 3 天后自动更新到已经装了的用户那里；手动更新、新安装的规则见[冷静期](review.md#冷静期)。

## 提交文件

`plugins/v3/<作用域>/<名字>.json`，作用域是仓库所有者的小写：`@someone/weather` 放在 `plugins/v3/someone/weather.json`。

```json
{
  "name": "@someone/weather",
  "path": "plugins/weather",
  "authorKeys": [{ "keyId": "…", "publicKey": "…" }],
  "versions": [
    {
      "version": "1.0.0",
      "repository": "https://github.com/someone/fuyu-weather",
      "commit": "<40 位提交号>",
      "authorSignature": { "keyId": "…", "signature": "…" }
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `name` | 插件名，和清单的 `name` 一样 |
| `path` | 插件在仓库里的文件夹；在仓库根目录时不写 |
| `authorKeys` | 作者的签名公钥，第一次提交时写 `keygen` 打印的那一把 |
| `versions` | 每个版本一行：`version`、`repository`、`commit`、`authorSignature` 照抄 `sign` 打印的四项；`name` 和 `publicKey` 不用抄进这一行 |

**谁能改什么**：

| 改动 | 谁能做 |
|---|---|
| 加版本、加作者密钥 | 仓库所有者，或拥有仓库的组织的公开成员 |
| 已经上架的那一行改任何字段 | 谁都不行 |
| 删版本、删作者密钥、删文件、标 `urgent` | 只有维护者 |
| 提交官方插件 `@fuyu/*` | 只有维护者 |

所以**已经上架的版本不能替换**：同一个版本号不能换一个提交号再交一次，有问题就发新版本号。

## 市场构建时会核对什么

- 按提交号取源码，符号链接不展开。`package.json` 的 `name`、`version`、`repository` 必须和提交文件里那一行一致。
- 依赖的规则见[上架之前](#上架之前)。安装前会删掉你的 `.npmrc` 这类配置。
- 用市场自己的构建设置（`nodeTarget: node22`、`browserTarget: es2022`）和钉在固定提交上的 `fuyu-plugin` 构建，不读你仓库里的构建配置，不许用实验接口。
- 审核和上一个上架的版本比；同一个 PR 里加了几个版本时，后一个和前一个比。
- 源码再过一遍密钥扫描，扫出遗留的令牌或私钥就不上架。

## 第一次上架

- 新建提交文件，`authorKeys` 写上你的公钥，`versions` 只有第一行。
- 第一次上架至少是黄档，维护者通读全部源码。

## 以后的版本

- 提高 `version`，提交并推送，`sign`，在 `versions` 末尾加一行，开 PR。
- 每个版本都审，和上一个上架的版本比。
- 换作者密钥：在 `authorKeys` 里加新密钥，最好带旧密钥签的换密钥证明（`endorsedBy`）。没有证明的新密钥会在报告里标出来，浮屿会把它当成换了作者，要用户确认两次；有证明的确认一次。换密钥、换人、换仓库都当作重新上架，见[市场规则](market-rules.md#换密钥换人换仓库)。命令行还没有生成换密钥证明的命令。
- 紧急的安全修复：在 PR 里说明，维护者决定要不要在这一行标 `urgent`（见[冷静期](review.md#冷静期)）。

## 预发布版和旧版浮屿

- 版本号带预发布标记（`1.3.0-beta.1`）的是预发布版，浮屿默认跳过，不自动更新到它。
- 每个版本有自己的 `engines.fuyu`：浮屿只装满足范围的版本，所以用户的浮屿没升级时，会拿到它能用的最新版本。

## 官方插件

`@fuyu/*` 的官方插件在 `TixXin/fuyu` 仓库里，由维护者提交。它们不带作者签名：仓库必须是 `https://github.com/TixXin/fuyu`，提交号必须在它受保护的 `main` 上，由市场 CI 核对。其余和第三方插件一样：市场构建、逐版审核、冷静期。

## 手动分发一个 `.fuyu`

不上架，只想发给几个人用：

1. `fuyu-plugin pack` 打出 `<作用域>-<名字>-<版本>.fuyu`。
2. 可以加 `--sign` 用作者密钥签名，对方安装时会看到是谁签的；不签也能装，确认里写「没有签名」。
3. 对方要先在浮屿的设置里打开手动安装，再双击这个文件。安装确认会写明「这个插件没有经过浮屿市场的审核」，以后也不会自动更新。

## 用户那边会看到什么

市场详情页和安装确认里的信息来自三处：

| 来源 | 信息 |
|---|---|
| 清单 | 名字、介绍、图标、截图、分类、作者、许可证、主页和仓库、兼容的版本和系统、会用到浮屿的什么、会不会读写文件 / 运行程序 / 联网、要连的域名、依赖的插件、提供和替换的服务、插槽、命令和快捷键、设置项、是否预览版 |
| 包里的文件 | README、CHANGELOG |
| 市场 | 发布者和它的身份怎么核实的、作者签了没有、哪个版本被人审核过、包大小、上架时间、历史版本、是否被撤销 |

安装确认写明「这个插件拥有和浮屿一样的权限，能读写你的文件、运行程序」。浮屿里的这些界面还在做。
