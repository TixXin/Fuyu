## 顶边贴合

- 岛屿贴住显示器顶边时，顶边与屏幕上沿齐平，上方两角向外做反向圆弧，与屏幕边框连成一体，底部两角保持外凸圆角；离开顶边后恢复四角圆角。（用户确认：参考截图）
- 折叠态与展开态都保持这一造型。（用户确认）
- 拖放时距离顶边 16 逻辑像素以内会吸附到顶边；顶部任务栏存在时以任务栏下沿为顶边。反向圆弧半径默认 8px，可在设置"外观"中用"贴边圆角"滑块（原名"贴顶圆角"，2026-11-15 改名）调成 0–12px（0 为直角，随样式预设保存），不进入点击区域，鼠标在那里会穿透到桌面。（Agent 推断）
- 多显示器（C1）：设置"位置 → 显示在"可选主显示器（默认，和以前一样）、鼠标所在的显示器、前台窗口所在的显示器。跟随时，收起的岛（含贴边收起）在目标换到另一块屏幕并停留约 0.6 秒后，移到那块屏幕的顶部中间；展开或正在拖动时不移，等收起后再移；前台是岛屿自己时不算换屏。移屏会清掉拖动保存的位置。只有一个岛，不做每屏一个。（用户确认：跟着走）
- 岛屿圆角可在设置"外观 → 尺寸与位置"中调成 16–40px（默认 24px，随样式预设保存；旧版本保存的设置里没有这一项时按 30px 显示），调的是展开态底角；折叠态底角按原 30 / 22 的比例跟随，原生点击区域同步缩放。默认值 2026-11-20 从 32 改成 24：折叠条底角随之约 17.6px 方圆，量 Mac 截图后和刘海的底角弧度一致（32 时明显比刘海圆）；已保存的设置不改。（用户要求 2026-11-20）拖离顶边后四个角一样圆：顶角取同一形态的底角（折叠 22、展开 30 的比例），不再用更小的顶角，悬浮的胶囊上下对称。（用户确认 2026-11-13：离开顶边后上方圆角和下方不一致，看起来像歪了）内层面板（待办、音乐、剪贴板）与岛边缘相距 20px，圆角按同心原则取"岛屿圆角 − 20px"，最小 8px，默认 10px。贴顶描边与侧边描边同宽同样式（液态玻璃为 1px 加向内淡出）。（用户确认）描边的画法见下一条「一条轮廓」。
- **一条轮廓**（C106，2026-11-17）：岛的外形用 CSS `clip-path: shape()` 画成一条路径，贴边时两侧反向弧和本体是同一条路径（`src/windows/island/islandOutline.ts` 生成，`IslandOutline.css` 使用），不再是本体圆角矩形加两块弧拼起来。描边是这条路径和它往里缩一个描边宽度的路径用 `evenodd` 相减得到的环，顺着反向弧走到屏幕边，在弧尖渐隐，贴着屏幕的那条边不画；经典、液态玻璃、油膜边都用这一圈，原来 `box-shadow` 里的描边线和 refraction 的边框在支持 `shape()` 时关掉。面也是一整块：贴边时液态玻璃的流动色块、高光铺进反向弧，岛的内容层按整条轮廓裁剪（不再按本体长方形），否则反向弧只有底色、和本体交界处像一道棱；折射内发光画不了弧线，贴边时不画。（用户 2026-11-17 在开发版上指出两侧还有棱）贴顶、贴底、贴左右侧、刘海、悬空药丸都一样。路径只引用 `--island-shell-*`、`--island-top-fillet`，展开收起的过渡照常由 CSS 驱动。方圆角用三次贝塞尔近似（控制点系数 0.9192，误差约为半径的 0.45%），圆角用 0.5523。不支持 `shape()` 的 WebView（Safari 18.4 以前的 Mac）用 `@supports` 退回原来的拼法。原生点击区域不变。预览页 `docs/investigations/island-one-outline-preview.html`。（用户确认 2026-11-17：岛的形状是拼起来的，油膜边在本体上一圈、和贴顶圆角分开，要画成一个整体）
- 岛屿圆角默认为"方圆"（CSS `corner-shape: squircle`），在"尺寸与位置 → 圆角样式"中可切回"圆角"，随样式预设保存；旧版本的设置也按方圆显示。岛屿外框、继承其圆角的玻璃与描边层、内层面板都用同一形状，原生点击区域按超椭圆 |x|⁴ + |y|⁴ ≤ r⁴ 判断。没有采用苹果的连续曲率圆角：同半径下它与普通圆角相差不到 1px，CSS 无法直接表达，只能整体裁剪，代价是重做阴影和描边。调研与对比页见 `docs/investigations/corner-shape-compare.html`。（用户确认）
- 展开方式可选"点击"（默认）或"鼠标悬停"。悬停时光标在岛上停留满"悬停延迟"（0–1000ms，默认 300ms）才展开；延迟内按下鼠标会取消，拖动和点击不受影响；停在小岛上的消息预览、邮件、音乐按钮上不展开。小岛正在显示 QQ / 微信 / 邮件预览时暂停悬停展开，点击预览照常打开对应应用；预览结束时光标仍停在岛上的，需移开再回来才会悬停展开。（用户确认：悬停与点击预览冲突）悬停模式下，面板无论是悬停还是点击打开、在里面点过什么，只要光标进入过面板再移开，就在"移开后收起延迟"（0–2000ms，默认 400ms）后收起；正在文本框里输入、或鼠标仍按住（如拖出面板的拖动）时暂不收起，结束后照常收起。光标从未进入过的面板（快捷键、设置预览打开）不按此规则收起。失焦收起照旧。（用户确认：点过后不收起不符合预期）悬停不抢占输入焦点：光标停在展开的岛上也不拿键盘焦点，翻页键要点一下岛或用快捷键打开后才生效。设置 → 页面切换里的「悬停时接管键盘」（`hoverTakesKeyboard`，默认关）打开后，光标停满 160ms 拿焦点，移开还给原来的窗口；收起的岛也一样，这样光标停在小岛上按 ↓ 就能展开（2026-11-23 起，之前只在展开的岛上拿）。（2026-11-14 用户确认：默认拿焦点会打断正在做的事）收起时光标仍在岛上的，需移开再回来才会再次悬停展开。光标进出岛形状由原生端判断（事件 `island-hover-changed`），不依赖网页的 mouseleave。（用户确认）
- **悬停预览层与页头滚轮切页（C76，用户确认 2026-11-15）**：
  - 展开方式第三项为「悬停预览」（`expandTrigger: "preview"`，和点击、鼠标悬停并列，读到不认识的值按 `"click"` 降级）。（用户确认）
  - 预览层形态为 `86px` 高 × `max(收起宽 + 40, 400)` 宽（不超过面板宽），圆角按 `24 / 30` 比例跟随，收起条留在上方、摘要文字淡出、下方长出 `48px` 卡片区；底边吸附时上下翻转；原生端增加 `IslandMode::Preview` 命中区域，不抢焦点。（用户确认）
  - 预览卡片按优先级排序（Agent 等你 > 15 分钟内会议 > 正在放歌 > 未读 > 下一个日程 > 待办 > 时间日期兜底），紧急卡片钉住不轮换，其余每 4 秒轮换并显示右侧小圆点；点击卡片直达对应页面，向下滚展开、向上滚缩回，光标移开 200ms 收回。（用户确认）
  - 预览时继续停留自动展开默认关（`previewAutoExpandMs: 0`，可选 1 / 1.5 / 2.5 秒，开启时卡片底部显示 2px 主题色进度条）。（用户确认）
  - 侧边竖向岛不出预览，保持点击展开。（用户确认）
  - 页头滚轮切页为独立开关（`wheelSwitchPage`，默认关），仅在展开面板顶部图标栏生效，不干扰内容区滚动；累计 50px（行模式按 40px/行）切一页、到头不循环，切后 450ms 吞掉触控板惯性（期间有新滚动续 150ms），200ms 无滚动清零。（用户确认）
- 点击不抢焦点（2026-11-14，Windows）：收起的岛被点击时不激活窗口，点消息预览、音乐按钮、Agent 环时，正在用的窗口保留键盘焦点。点击展开面板时岛才拿焦点（面板里要打字、要按翻页键），并记住原来的前台窗口；面板收起时岛还是前台窗口的，把焦点还给它，失焦收起（点了别的窗口）时不动。原来的前台窗口是管理员权限的程序时岛拿不到焦点，面板照常打开，点一下面板里面就有焦点。拖动岛和以前一样会激活它。启动时显示岛也不拿焦点；托盘点击、再次启动、插件打开页面照常拿。macOS 不变。（用户确认：岛的启动和消息会抢走焦点、打断正在做的事；具体规则为 Agent 推断）
- **翻页箭头和方向键**（2026-11-23，用户按预览页 [panel-page-arrows-preview.html](../investigations/panel-page-arrows-preview.html) 里的推荐定）：
  - 箭头：展开面板左右两边各一个只有 ‹ › 的箭头，放在面板原有的 20px 左右留白里、内容区竖向居中，不压内容、不改各页排版。平时看不见，鼠标进面板淡淡出现（28%），放到箭头上全亮并出现浅色底，悬停名称是「上一页：日历」这样的去向。点了切到上一页 / 下一页，顺序和 Ctrl+Tab 一样、到头循环；被点的箭头往那边推 4px 再回来（箭头没有文字，可以动）。只有一个页面、弹出页开着、调整布局中、竖着的侧边岛不显示。箭头不进 Tab 顺序。设置 → 页面切换「面板两侧显示翻页箭头」（`pageArrows`，默认开）。
  - 方向键：面板里 ← → 翻页（屏幕上对应的箭头闪一下），↑ 收起；内容往下滚过时 ↑ 先回到顶部，在顶部再按才收起。收起的岛有键盘焦点时 ↓ 或回车展开，打开的页面和点岛一样。按住只翻一页。光标在有字的输入框里（空的不算：翻译页一打开光标就在原文框里，用户 2026-11-23 反馈那里按不了）、焦点在自己处理方向键的控件上（列表框、网格、滑块、菜单、下拉，以及 Agent 会话列表这类已经处理了按键的）、输入法组词中、按着 Ctrl / Alt / Shift / Win 时都不处理；弹出页开着、调整布局中只有 ↓ / 回车照常。设置 → 页面切换「方向键翻页和展开收起」（`pageArrowKeys`，默认开）。
  - Esc 由里往外退（2026-11-23）：菜单、下拉、日期选择这类弹出的东西开着时（`role=menu` / `dialog`，或 `aria-haspopup` 的按钮展开着），Esc 只关它，不收起面板；里面的控件已经处理了这个 Esc（`preventDefault`，比如取消编辑）时也不收起。开没开着在按键的捕获阶段就记下，因为 React 的处理在事件冒泡到窗口之前就把菜单关掉了（`useIslandKeyboard.ts`）。
  - 触控板左右滑动（2026-11-23）：面板上两指往左滑是下一页、往右是上一页，一次滑动只翻一页：两次滚轮事件间隔不超过 300ms 算同一次，惯性也算；翻过一页后，事件先慢下来（降到这次最快时的 20% 或 3px 以下）再连着两次变快，或者反过来往另一边滑，就算新的一次滑动（2026-11-23，用户反馈 Mac 触控板只有第一次滑动生效：惯性要一秒多才停，接着再滑一直被当成同一次）；横向累计 80px、而且横向是纵向的 1.5 倍以上才算，按着修饰键（含 Shift 横滚）不算。指针下面有能左右滚动的区域（比如 Fuyu 页的多页组件）时不翻，照常滚动。弹出页开着、调整布局中不翻。翻页时对应的箭头闪一下。设置 → 页面切换「触控板左右滑动翻页」（`pageSwipe`，默认开）。参数（300ms、80px、1.5 倍）是 Agent 推断。
  - 焦点规则不变：收起的岛没有焦点时按不到 ↓，不为它抢焦点；开着「悬停时接管键盘」时光标停在小岛上就有焦点。收起的岛上不显示「↓ 展开」这类提示（用户定）。
- "收起到边缘时，收到新消息自动露出"（默认开启，在"通用 → 展开与收起"）：岛贴边收起时仍接收 QQ / 微信 / 邮件预览，有新预览时滑出并显示；预览显示期间暂停闲置计时，预览结束后重新完整计时再收回。关闭后保持旧行为：贴边时丢弃预览。（上游 issue #28，用户确认）
- "外观 → 尺寸与位置"中的"最大面板高度"（306–546px，默认 490px，随样式预设保存）限制会滚动的页面：待办随条目增高到此为止后列表开始滚动，剪贴板和消息页也不超过它；音乐、归档等固定布局的页面不受影响。字号不单独设置，由"展开面板大小"整体缩放；面板宽度起初不开放（需要原生窗口宽度随之变化）。（用户确认）新消息和 Agent 的弹出提醒例外：只显示卡片、岛宽 400（见 collapsed-bar.md、agent.md）；窗口本身是固定 820 宽的透明舞台，岛宽由 CSS 决定，Rust 只用 `expandedWidth` 算鼠标命中区域。
- 面板宽高（C25，2026-11-10）："最大面板高度"改名"面板高度"，下面加"面板宽度"（480–800px，默认 560，随样式预设保存；大缩放下以能放进 820 宽的岛窗口为限）。宽度用于普通页面，日历（680）和要求更宽的插件页取两者中较大的。展开时按住 Alt 拖动面板左右边缘（12px 以内）调宽度、拖动底边调高度、拖动底角两者都调，岛保持居中所以左右一起变；拖动高度时面板临时显示到正在设的高度，松开后回到页面自己的高度。按住 Alt 时展开的岛不因鼠标离开或切到别的窗口而收起。移动岛屿从 Ctrl + 拖动改为 Alt + 拖动。（用户确认：Alt 拖动、Alt 改宽高、按住 Alt 不收起、外观加宽高条；拖边缘的方式、宽度范围为 Agent 推断）

## 灵动岛视觉规范（2026-11-06）

下列条目除注明"用户确认"外，均为 Agent 推断，依据一轮岛屿界面的设计审阅。圆角形状见上文"顶边贴合"。设置窗口不在这一轮范围内。

- **清晰度**：新用户默认折叠 / 展开缩放都是 1.0（老用户保留已存值）。`.island` 不再常驻 `will-change: transform`，内容层只保留 `will-change: opacity`（不常驻 will-change、进场用 `backwards` 填充是通用规矩，见 [motion.md](motion.md)「哪里可以动」）；缩放仍用 `transform`（不用 `zoom`），因为原生点击区域（`island/passthrough.rs`）按"基准尺寸 × 缩放、顶部居中"计算，`zoom` 会改变布局盒、打断缩放过渡，还会让展开高度测量换算。
- **字体**：全岛一个字体栈 `--font-ui`（`Segoe UI Variable Text`、`Segoe UI`、`Microsoft YaHei UI`…），写在 `tokens.css`，`base.css` 引用；不再有私有字体栈和 `font-synthesis: weight`（像素字体主题除外）。字重只用 400 / 600，≥15px 的标题可用 700；不用 800 / 900。
- **文字 4 级**：`--text-1/2/3` 与 `--text-placeholder`，同一色相（`--color-text` 的 248,246,240）取 .96 / .68 / .54 / .42。在岛 `#030303` 与内层面板 `#1e1e22` 上分别为 17.5 / 14.2、8.7 / 7.8、5.7 / 5.4、3.8 / 3.8：前三级用于可读文字（≥4.5:1），placeholder 只给输入框占位。岛上中性灰文字一律用这 4 级，主题色（`--color-accent`）不在此列。
- **图标**：岛上 lucide 图标只用 16px（顶栏、折叠条、列表）和 14px（行内、插件页按钮），统一 `strokeWidth={1.5} absoluteStrokeWidth`；品牌图标 16px。
- **颜色语义**：颜色只给数据和状态用，其余黑白灰。黄色只表示"需要注意"（Agent 状态）。Agent 弹出通知另有规矩：橙色只给「等你确认」，等你回复用灰蓝，见下面「Agent 通知」。
- **一个主题色**（C39，2026-11-10）：各页面、当前页按钮、玻璃面板的色调、剪贴板窗口、翻译窗口、设置窗口只用一个强调色 `--color-accent`，就是「设置 → 主题 → 强调色」选的那个（默认深色 `#74d6ff`、浅色 `#0a7fd1`，可以跟随 Windows 或自选）；原来各页自己的颜色（音乐紫、日历橙、剪贴板粉、文件中转薄荷绿、日期按钮紫）都去掉了。主题色上的文字用 `--color-on-accent`，按主题色的亮度取深字或白字。表示状态的颜色不跟主题色：Agent 状态灯和会话灯、删除的红、完成的绿、日历的「休 / 班」、警告色、SSH 隧道的「已连接」、设备提示的绿和橙、文件类型和插件分类的图标色。（用户要求：每个页面的主题色花里胡哨，统一成设置窗口的蓝色，并且可以设置）会话列表里仍有运行中会话时，状态灯显示蓝色运行，不再出现"绿灯 + 蓝色数字"。
- **顶部栏的页面按钮**：状态灯右边的待办、音乐、日历、剪贴板、文件中转是图标按钮，图标和设置窗口侧栏同一套（`ListTodo`、`Music`、`CalendarDays`、`ClipboardList`、`Inbox`），不再是彩色圆点。没打开的是灰色单色图标、没有底；当前页的图标用主题色，垫一层主题色的淡底。右边的设置、消息、翻译等操作按钮带圆形底，和左边的页面按钮区分开。插件页按钮同样大小。最左边的 Agent 入口也是图标（`Bot`），不再是圆点，但颜色照旧跟着 Agent 状态（空闲、运行、需要注意），打开 Agent 页时垫一层浅底。（用户确认 2026-11-09：圆点看不出是哪一页，改成图标、单色、当前页上色；Agent 的圆点也改成图标）
- **纯色模式是一整块底色**（2026-11-09）：收起的岛和展开的岛一样只画底色，不再叠上下明暗渐变；纯黑的岛（默认）因此能和屏幕黑边、刘海融在一起。焦点描边和内发光只在用键盘切到岛上的按钮时出现（`:focus-visible`），鼠标点过后不再亮起。液态玻璃不变。（用户反馈：纯色模式下有高光渐变）

- 碰到弹一下（2026-11-21，新装的默认悬停效果）：照 NookX 录屏量的，鼠标碰到岛的当帧就开始，没有延迟；宽 +18px、高 +2px，欠阻尼弹簧（阻尼 0.54、response 0.24s），约 120ms 冲到最宽（多出约 10%），回落一下，约 350ms 停稳。只在碰到岛时鼓（range 0），离开按同一个弹簧弹回。`islandHover.ts` 的形状多了可选的 `damping`，其他悬停效果不写，仍是临界阻尼。回弹多少跟「弹动幅度」走（见下面「弹动幅度」），这里的数是常规档。已经存过别的悬停效果的老用户不变。（用户要求）

## 液态玻璃：流动彩色（C87，2026-11-15）

方向由用户在调研和预览页之后定下（[liquid-glass.md](../research/liquid-glass.md)「用户决定」、[预览页](../investigations/liquid-glass-preview.html)）。（用户确认 2026-11-15：按推荐来，设置里要有丰富的外观选项，可以高度自定义）

## 音乐页（2026-11-09）

- 和 Agent 页同一种做法：内容直接放在岛的底色上，没有自己的卡片、描边和投影；文字颜色跟随岛的底色（`--island-ink-rgb`），只有鼠标悬停的按钮亮起一层浅底。顶部一行是 56px 封面、歌名（大、亮）和「歌手 · 播放器」（小、暗），歌词偏移和音乐设置在这一行最右、悬停才出现；中间是占满整宽的歌词（没有歌词时是波形）；下面是进度条或估算说明；最下面是上一首、下一首两个只有图标的按钮，中间的播放 / 暂停是跟随文字颜色的实心小圆。液态玻璃外观下也不再给音乐页单独画一块玻璃面板。（用户确认 C17）
- 有歌词时，歌词占波形的位置，不再在歌词下面留一条看着像进度条的细波形；没歌词时仍是大波形。（用户要求：全面优化音乐页 UI）
- 歌词三行：上一句、正在唱的、下一句（有翻译时是翻译）。正在唱的那句太长时换成两行完整显示，不再用省略号截断。（Agent 推断）
- 播放器报告进度和时长时，下面是一条带「已播放 / 总长」的细进度条。网易云这类不报告进度的播放器没有进度条，换成一行说明：歌词按切歌时间估算，拖了进度就点正在唱的那句对齐；岛屿没看到这首歌开头时（比如岛屿启动时歌已在放）说「可能没对齐」。播放器是网易云时附一个「装 InfLink-rs 精确同步」的链接。（调研：网易云自带的 SMTC 不报告进度和歌曲 id，见会话 2026-11-09）

## 插件的列表页面（2026-11-09）

- 用列表模板的插件页面（GitHub Issue、开发任务看板等）和 Agent 页、音乐页同一种做法：不套卡片，行不加底色，靠字号和明暗区分，只有鼠标悬停的行亮起一层浅底；文字颜色跟随岛的底色（`--island-ink-rgb`），外链图标悬停才出现。详情、表单、状态模板暂时保留卡片。（用户要求 E16）

- 悬停切换页面只认光标真的移动：页面宽度不同（系统监控 800、日历 680、其他 560），岛居中变宽时顶部图标会整体平移，图标滑到静止的光标下面不算悬停；切换页面后约 0.45 秒（岛变宽的动画）内也不响应悬停，之后光标要再动一下。点击不受影响。（用户反馈：悬停系统监控图标时页面来回跳）

- 闲置贴边收起时这些情况不收起（C32，issue #29，2026-11-10）：设置 → 行为 →「闲置时贴边隐藏」下面三个开关：有正在进行的待办时（点了「开始」、待办还在且没完成，默认开）、Agent 在等你时（有会话等审批或回答，默认开）、音乐播放中（默认关）。对应的功能关着时不算。这些情况期间闲置计时暂停，都结束后从头计时，和消息预览结束后一样；只是不收起，已经收起的不会因此露出。「有待办」不按「列表不为空」算：列表里总有没做完的事，那样岛就永远不收。（用户确认：两个默认开、音乐默认关）C63（issue #314，2026-11-15）加第四个开关「有未读消息时不收起」（默认开）：微信有待看提醒、QQ 有未读通知、开着的邮箱有新到的未读邮件都算，对应来源没打开的不算；音乐设置页也放了「音乐播放中不收起」，和行为页是同一个设置（`autoTuckHoldMusic`）。邮箱不按收件箱的未读总数算（很多人收件箱常年几十上百封未读，那样岛就永远不收）：每个邮箱记一个基线，展开消息页时基线跟到当前未读数（邮件预览只弹几秒、常被忽略，不算看过，和微信、QQ 一直挡到被看或被清一致），别处读掉邮件时基线跟着降；未读数比基线多才算。（用户确认：未读默认开、音乐页放同一个开关；只算新到的邮件是主 agent 审查时定的）
- 拖动过位置的岛贴边后再出来（鼠标碰到那条边、新消息、托盘「显示」）时，在屏幕顶边滑出，横向位置用拖动时的 x，这样岛正好在鼠标下面；面板关掉回到收起、或再拖一次后，回到拖动时的高度。托盘「显示」会把贴边的岛滑出来。（issue #37，用户选定 2026-11-11）
- 悬停切换要先停稳（C35，2026-11-10）：光标在页面图标上停约 0.12 秒才切换（设置的悬停时间更长时按设置），划过的图标不切换；以前悬停时间为 0（默认）时，从左往右划过去会把经过的每一页都打开一遍，每次都重排页面、改原生窗口大小、重启岛的宽高动画，划到目标时还卡在上一条的 0.45 秒等待里不动。岛还在改宽度时移到的图标不再被丢掉，等岛停稳后若光标仍在那个图标上就切过去。（用户反馈：左上角图标悬停切换卡顿）
- 悬停切换不再来回跳（2026-11-23）：光标要在图标上停稳（0.12 秒内移动不超过 4px，悬停时间设得更长时按设置），斜着划过某个图标去下面的内容区时不切页。切页后岛改宽度（约 0.6 秒）期间不响应悬停；停稳时光标下面若是滑过来的另一个图标（两页宽度不同，图标整体平移了），这个图标要等光标离开再回来才算悬停，宽度相同的两页照常能一个接一个悬停切换。判断光标动没动用屏幕坐标。（用户反馈：Mac 上从 Fuyu 页往下移经过待办图标，切到待办后岛变窄，Fuyu 图标滑到光标下又切回去）
- 点展开面板的空白处收起，但卡片里面不算空白（2026-11-23）：从点到的元素往上到面板，只要有一层有底色或背景图（卡片、输入框外框、组件），这一下就不收起；卡片之间的间隙、列表下面的空处照旧收起。翻译页的原文卡片整张是输入区：光标是文字光标，点卡片里的空处（底部字数那一行）聚焦输入框。（用户反馈：Mac 上点翻译原文框左下角，岛收起了）

## Fuyu 面板的调整布局（2026-11-20）

参照 Nook X 的编辑态重做，预览页 [panel-edit-mode-preview.html](../investigations/panel-edit-mode-preview.html)。（用户定）

- **入口**：页头设置按钮左边只有图标的按钮，只在 Fuyu 页面显示（2026-11-20 起，原先在面板里单独占一栏），平时是布局图标，编辑中变成强调色底的 ✓，不写「编辑」「完成」文字；名称「调整布局 / 完成调整」放在 `aria-label`，悬停名称照常显示。长按面板空白处也能进入；长按某个组件（避开它里面的按钮、输入框、滑块）进入编辑并直接拿起它，手不松开就能拖。Esc、岛失焦、再点一次按钮退出。
- **岛变大，组件不缩小**：编辑时岛的展开宽度加 80px、高度加 96px（`PANEL_EDIT_GROW`，`custom-panels/panelEditing.ts`，在 `IslandApp` 里加到展开尺寸上），多出来的高度放底部常驻的组件栏。弹出页打开时不加。岛离屏幕左右边不到 40px 时少加宽，按两边里更窄的那边算，贴着屏幕边就不加宽（`editGrowWidth`）。没做成「只往一侧长」：岛在原生窗口里居中，Rust 按居中判断鼠标在不在岛上，只在网页里把岛挪向一侧会让那一侧的点击穿透出去。
- **抖动**：编辑中每个组件 ±0.9° 来回转，一个来回 135ms，各组件起始时间按序号错开、等岛长完（`--motion-slow`）再开始；鼠标停在组件上或键盘聚焦到里面时停住，拖动中的那个不抖；减少动画时不抖。这是表示「正在编辑」的状态动画，编辑结束就停。它会让组件里的文字跟着转，是用户要的效果，属于 motion.md「文字不动位置」的例外。
- **拖动范围**：拿起的组件拖不出组件区：上下在当前的行数之内，左右在整条组件区之内。
- **面板大小和方向**：网格模式按面板宽高自适应（C176，2026-11-22 用户定；2026-11-23 用户定：底部留白多给行数、自适应；自由模式也跟着面板）：格子 120px、间隔 8px，按面板的宽和高算一页几列、几行，整块只在 0.85–1.2 倍之间缩放去贴合面板，在这个范围里挑最填满面板、又最接近原大小的行列数（`stripGeometry.ts` 的 `gridFor`），所以窄而高的面板变成 3、4 列多行，字号基本不变。行数不再封顶（11-22 那版最多 6 行，460 × 1530 的面板只用到上面 849px，下面一大片空白）：上限按面板最高 4320px、格子缩到 0.85 倍算出来是 39 行，面板多高就给多少行，底部剩下的不到一行；网格按列从上到下排，组件会排进多出来的行。有 2×2 的组件时至少 2 行、有 4 格宽的至少 4 列，不够时才整体缩小到更小。放不下一整行的余量留在底部（和别的页一样内容贴着页签开始）；分页时放不下一整列的余量平分到左右并裁掉，不露出下一页（编辑时照旧露出，提示能拖过去）。自由模式不重排（位置是手摆的，存的格式不变），但组件区的行数和缩放跟网格模式算的一样：同一块面板上两种模式的组件一样大，能一直往下放到面板底部，面板大时也跟着放大（之前固定 6 列 × 2 行、最多原大，大面板上组件挤在上面一小块）。面板变矮后落到组件区下面的组件挪到最下面一行，压到别的组件就把它往右推；从网格切到自由时组件留在原位，都在组件区里。之前：窄于 6 列时整体缩小（2026-11-22 早些时候）；C162 2026-11-21 定「宽度跟随」；再之前固定 6 × 2。组件少、一页用不满所有行时，只用够放下它们的行数（至少 2 行），在顶部排成紧凑的一块、横向用满列，空白留在下面，不再在高面板上沿左边一列竖着堆下去；放不下一页时才用满所有行（2026-11-23，用户定：按 Agent 推荐）。组件只往右加：网格模式按列从上到下、从左到右排，压到别的组件时把它往右推。放不下时组件区横向滚动（滚轮上下滚也是横向，不显示滚动条）。编辑时自由模式右边多留一列空位，方便往后放；网格模式编辑时也按页翻，见下面「跨页拖动」。
- **背景和吸附**：编辑时网格模式画出全部虚线空格，自由模式画 16px 的点阵。自由模式拖动和拉伸吸到点阵上；离别的组件的边 8px 以内时改吸到和它对齐（左对左、右对右、上对上、下对下）或贴边隔一格（8px），对齐的那条边画一条强调色的线。
- **每个组件**：底部盖一条半透明标签条（‹ 名字 › 尺寸），不加高卡片，进出编辑不重新排版；1×1 的组件只显示箭头和尺寸。网格模式点 ‹ › 换位置，点尺寸或点组件本身换下一档大小；自由模式只有名字，右下角拉伸。移除是悬停时右上角浮出的 ×，点了直接拿掉，组件栏右侧出现「拿掉了某某 · 撤销」，4 秒后消失。
- **组件栏**：「添加组件」标题、网格 / 自由切换、提示文字一行，下面一排横向滚动的组件（内置在前，插件在后），点一下加到面板，滚轮能直接横向滚。已经在面板上的不列出。
- **拖动**：网格模式拖着组件时，别的组件按指针位置实时让位（指针过了某个组件的中线就插到它后面）；组件栏里的组件也能直接拖进面板，指到哪里先出现一个虚线占位，松手就放在那里，拖回组件栏不加。自由模式拖进来的放在松手的位置。松手后被拖的组件从指针处滑进它的空位（`--motion-medium`）。
- **跨页拖动**（C172，2026-11-22，用户定「全都做」，预览页 [panel-drag-paging-preview.html](../investigations/panel-drag-paging-preview.html)）：网格模式编辑时也分页（不吸附，页与页之间画一条虚线），拖动中：
  - **贴边翻页**：指针进到组件区左右边 36px 以内，那一边亮起强调色渐变和一个圆环，停 450ms 翻一页，不松开每 800ms 再翻一页；甩得快（超过 1.1px/ms）立刻翻；等待时面板往那边探出 28px。最后一页往右是「新的一页」，圆环里是加号，翻过去就多一页。自由模式没有页，贴边时连续往那边滚。
  - **页的缩略图**：拖起来时页头（真刘海时在组件栏标题行）的页码点长成每一页的缩略图（被拖的组件画强调色，会被挤到下一页的画橙色），后面是「新的一页」和「全部」。指针停在一张缩略图上 320ms 跳到那一页；在缩略图上松手是把组件送过去、当前页不动，组件栏出现「已放到第 N 页 · 去看看 · 撤销」。放进满了的页时，放进的组件留在那一页，最后一个挤到下一页。
  - **全部**：指针停在「全部」上 350ms 或按空格，组件区换成所有页的缩略图，指到哪一页、哪个位置就放在那里，松手后跳到那一页。
  - **暂存架**：组件栏最左边一格，拖进去先放着（组件从面板上拿掉，组件栏不列它），翻到想要的页再从暂存架拖出来；退出编辑时还在架上的放回面板最后。
  - **键盘**：拖动中 ← / → 翻页（最后一页往右是新的一页），1–9 跳到第几页，空格开关「全部」，Esc 取消这次拖动、组件回原处。滚轮照旧翻页，组件跟着指针走（滚动时补偿位移）。
  - **提示**：组件栏标题行右边的提示随拖动变：松手会放到第几页、会挤走谁、贴边会翻到哪一页、暂存是什么意思。被挤到下一页的组件描橙色边。
  - 新的一页靠组件上的 `pageBreak` 标记撑住（数据格式见 contracts.md），否则空页上放一个组件会被自动排回前一页的空格里。
  - 参数（450 / 800 / 320 / 350ms、36px 边、28px 探出）是 Agent 推断。
- **自由模式碰到就推开**（用户定）：放下、拉伸或拖进来的组件碰到别的组件（含 8px 的间距），被碰到的往下推到它下面，被推的再碰到别的也一样往下推；拖动和拉伸的过程中就实时推开。
- **默认组件页**（2026-11-20，用户定「照预览页做进岛里」）：没存过布局时 Fuyu 页面是预览页 [panel-default-widgets-preview.html](../investigations/panel-default-widgets-preview.html) 的排法，首屏是今日（2×2）、下一个会议、今天的待办、正在播放、番茄钟、打卡，往右是歌词、Agent 会话、系统状态、电池、专注统计、年进度、月历，再往右是便签、剪贴板、倒数日、世界时钟、喝水、日出日落、习惯，最后是翻译、未读消息、文件中转、网速、快捷启动、最近截图、音量亮度、秒表、计时器。设计依据见 [widget-design.md](../research/widget-design.md)。预览里的 28 个组件都已做进岛里（三批，2026-11-20）。
- **小组件出场动效**（2026-11-21，用户定「都要，放进设置里，默认轮播，每次都不同」）：面板展开到 Fuyu 页面时，当前这一屏的卡片按选的方式出场。设置 → 行为 → 展开与收起 →「开合动画」里的「小组件出场动效」：轮播（默认）、整体淡入（原来的样子）、跟着面板撑开、幕布、光波、涟漪、骨架扫光、描边点亮、逐个通电、落位、水母吐泡泡、对焦、翻牌。轮播每次展开换一种：十一种效果洗成一副牌依次发，发完重洗，重洗后的第一张不和上一张相同，所以不会连着两次一样。下面一行「数据动效」（默认开）可以和任何一种叠加：卡片出现后环形进度扫到位、数字原地跳到真实值（位数不变，文字宽度不动）、进度条填满、打卡格子依次点亮、按钮弹一下。做法：卡片的底色和描边画在格子元素自己身上，直接动它文字会跟着动，所以出场期间在格子层里垫一层只有底板的替身（`entrance/EntranceGhosts.tsx`），真卡片的底色和描边暂时透明，只淡入内容；动效全部用 Web Animations 播，播完替身撤掉、一切还原。岛内容层原有的整体淡入不变，卡片动效叠在它上面。只给当前这一屏的卡片做，翻到后面几屏的不动。不播的情况：「减少动画」、开合动画选「无动画」、正在编辑布局、面板是空的。出场到一半收起，立刻撤掉并把数字还原成真实值。第三方小组件不用改代码也有卡片出场；想要数据动效，在元素上加 `data-enter`：`count`（数字）、`sweep`（环形进度）、`draw`（线条画出来）、`fill-x` / `fill-y`（条形填满）、`cell`（格子依次亮）、`pop`（弹一下）。内置小组件按现有 class 匹配，对照表在 `entrance/entranceData.ts`。预览和各方案的取舍见 [widget-entrance-preview.html](../investigations/widget-entrance-preview.html)；回归页 `widget-entrance.html?effect=<名字>&real=1` 可以对着真实小组件手动看某一种。（用户要求）

## 摄像头刘海一圈（C167，2026-11-22）

刘海模式（Mac 真刘海，或岛屿实验台 / 形态选「刘海」时的模拟刘海）下，沿 Mac 自带的摄像头刘海内侧、隔一段间距画一圈线，画在岛里面；和 C166 的「刘海边框」（画岛和面板的外轮廓）是两件事，两个可以同时开。预览页 [notch-camera-ring-preview.html](../investigations/notch-camera-ring-preview.html)，用户说「按倾向开始做」，下面除标明的外都按页上的倾向。

- **九种样式全留**：关、发丝、辉光、扫描、滴落、进度、律动、刻度、极光。岛屿和面板各一组。岛屿默认「关」；面板在 Mac 上默认「发丝」（用户定 2026-11-22，预览页原本倾向两组都关），其他平台默认「关」。面板的样式因为缺省值跟平台走，不进跨设备同步。面板多一个「面板同岛屿」，默认关。可调颜色（白、强调色、紫、粉、薄荷、自定义）、粗细 0.5–3px、离刘海的间距 0–6px、强度、动效。
- **摄像头、麦克风单独一个开关，默认开**：样式是「关」时也亮。摄像头绿 `#30d158`，麦克风橙 `#ff9f0a`，同时用时摄像头优先。
- **新消息、Agent 等你单独一个开关，默认关**：新消息用来源软件的颜色，Agent 等你橙色闪，完成时绿色亮约 2.6 秒。
- **状态从哪来**：岛的贡献表新增 `glow`（各功能自己推，按 `GLOW_PRIORITY` 取最高的一个）和 `playback`（音乐在放时的起点和时长）。岛壳不 import 功能，C166 的边框也只读 `glow`。
- **样式遇到条件不满足时退一档**：「进度」「律动」没在放音乐时画发丝（亮着时画辉光）；亮起时「关」「发丝」「刻度」临时换成辉光；关了动效时「扫描」「滴落」换成辉光，极光不流动，进度画成静止的那一段。
- **收起时的底边**：收起的岛和刘海一样高，刘海下面没有地方。默认「只画两侧」，两侧画到岛底就截掉；选「岛加高画整圈」时收起的岛往下长 间距 + 粗细 + 2px（`notchRingExtra`，Rust 的 `collapsed_size` 一起加高点击区域，最多 12px），只在样式不是「关」或正亮着时长。贴边收起时不长。
- **设置位置**：岛屿布局 →「显示与刘海」→「刘海」里的「内圈」一行，只在 Mac 上或岛上正有刘海时显示（C168 并组，见下面「刘海设置」）。
- **画法**：`windows/island/notch-ring/` 里一层不接鼠标的 SVG，叠在岛的玻璃层上面，按刘海宽高生成路径（刘海底角圆角 8px、顶部两侧外翻 4px）；顶边 5px 渐隐，刘海本体挖空，所以线只出现在刘海外侧的岛上。贴边收起、侧边、拖离顶边、分离时不画。
- **动效和省电**：辉光呼吸、扫描、滴落、刻度转动、极光流动是用户明知是循环装饰仍要的可选项，由「动效」开关管，和 [motion.md](motion.md)「底线」第 4 条的例外一样只在用户打开时出现。岛窗口隐藏、前台全屏（游戏免打扰）时动画停在当前帧；系统开了「减少动态效果」时按关了动效画。进度条按播放起点用 CSS 动画走，不每秒重画岛。

## 拖动时的中线辅助线（C103，2026-11-15）

起因是用户在 C98 验收后要的：「拖动时屏幕有辅助线，9 宫格的虚线」。第一版做成九宫格（横竖各两条三等分线、1px），真机验收后用户改了：「虚线太细了，另外九宫格实际没啥用，还是改成两条线吧，四分格」（2026-11-16）。

- **画什么**：拖岛（直接拖、修饰键拖）时，在岛中心所在屏的工作区（不含任务栏、菜单栏、Dock）上画横竖两条中线，把工作区分成四格。主题色（`--color-accent`）2px 虚线，段长 12px、间隔 8px，85% 不透明，外加 1px 的暗色晕（浅色系统下是白色晕），高分屏和亮、暗、花的壁纸上都看得清。（用户确认：两条线、四分格、加粗；段长、不透明度和晕为 Agent 推断）
- **中线不吸附**，只是看的参考。（用户确认）
- **四条边中间的轻微吸附**：岛贴着顶边或底边（会吸上去的 16px 以内）时，水平中心离工作区水平正中 12px 以内就对齐到正中；吸在左、右侧时，竖直中心离工作区竖直正中 12px 以内就对齐到正中。吸住时那条边的中线亮起一段：从屏幕边往里 120px、6px 宽、实心不透明的主题色带柔光，压在平常的 2px 虚线上，一眼能分出来；离开就灭。Mac 上拖动中就跟手吸；Windows 的拖动由系统接管，拖动中只亮提示，松手时对齐。原来的贴边吸附和提示线不变。
  - **和贴边吸附怎么配合**：中间对齐只在贴边吸附成立时才看，用的是同一个判断（`drag_hint::hint_for`：离哪条可吸的边 16px 以内，侧边只在收起时、两屏相接的边不算），所以贴边提示线亮着的那条边，才可能再亮中线那一段。顺序是先中间对齐（只挪沿边方向：顶 / 底挪 x，左 / 右挪 y），再贴边吸附（只挪垂直于边的方向），两者各管一个方向，不会互相拉扯。不在任何一条边的 16px 内时，离屏幕正中多近都不吸。（Agent 推断）（用户确认：只吸四边中间、约 12px、吸住要有提示；提示的样子为 Agent 推断）
- **开关**：外观 → 尺寸与位置 →「拖动」组的「拖动时显示中线辅助线」，默认开，只管两条中线；关掉后中间吸附照旧，吸住时只亮那一段。（用户确认）窗口 label `drag-grid`、设置 key `dragGrid`、事件和命令名保留第一版的叫法，没改。
- **出现和消失**：开始拖动时淡入，松手后 120ms 淡出；拖到另一块屏幕时中线跟过去，不重新淡入。系统「减少动态效果」时直接出现、消失。（Agent 推断）
- **窗口**：岛窗口是 820 宽的舞台，盖不住整屏，所以线画在单独的透明窗口 `drag-grid` 里：铺满那块屏的工作区，鼠标穿透、不抢焦点，压在岛下面、其他窗口上面。Mac 上是 level 比岛低一级的 NSPanel，所有桌面和全屏应用里都能出现；Windows 上每次显示都放到岛的正下方。第一次拖岛时创建，之后隐藏常驻。（用户确认：新开透明窗口、压在岛下面；层级做法为 Agent 推断）

## 岛挡住别的程序时让位（C134，2026-11-19，#849 跟进）

### 快捷键切上下层（已做）

- 全局快捷键「切换岛的上下层」，**默认不设**（C144，2026-11-19 起，#1086），在「设置 → 快捷键 → 全局 → 岛屿」里自己设、改或关掉（存 `fuyu-settings` 的 `islandLayerShortcut`，空字符串是没设；`islandLayerShortcutChosen` 为 true 才算数）。0.3.11 默认是 `Ctrl+Alt+B`（Mac 上是 ⌃⌥B），当时以为常见的 IDE 默认不用它，这个判断不对：VS Code / Cursor 里它是开关右侧栏，JetBrains 里是「跳到实现」。用户在 IDE 里按到后岛退到所有窗口下面，没有提示，重启才回来，群里当成「岛莫名其妙消失」反馈。所以这类全局键不再带默认值；0.3.11 存下的默认键没有 `islandLayerShortcutChosen` 标记，升级后失效，当时特意选了键的用户要重新设一次。（用户确认）
- 退到下层要让人看得见、叫得回（C144）：按键后岛上先显示一行「岛退到窗口下面，再按 <键> 回来」，约 1.2 秒后才真正退下去（`layer.rs` 的 `DROP_DELAY`），这期间再按一次就不退；回到最前不等。托盘卡片的岛按钮在岛退到下层时写「在窗口下面」，点一下回到最前（`tray_menu_action` 的 `raise_island`）；从托盘或别的入口显示岛（`show_island`、`show_island_without_focus`）也回到最前。（用户确认做提示和托盘入口；1.2 秒为 Agent 推断）
- 按一次：Windows 上 `SetWindowPos(HWND_NOTOPMOST)` 再 `SetWindowPos(HWND_BOTTOM)`，都带 `SWP_NOACTIVATE`，岛不再置顶、排到所有普通窗口下面；Mac 上面板层级从「菜单栏之上」降到 normal 并 `orderBack`。再按一次：Windows `HWND_TOPMOST`，Mac 回到菜单栏之上并 `orderFrontRegardless`。岛藏在托盘里时只改层级、不让它出现。
- 只改前后层：位置、贴边、露边几何、鼠标穿透都不动；全屏让位、截图选区、贴图这些现有规则各管各的，不进这个开关。上下层只在内存里，重启浮屿后回到最前。
- 状态在 `src-tauri/src/island/layer.rs`：`front`（快捷键切的，默认 true）和 `yielding`（以后自动让位用，默认 false），`allows_raise() = front && !yielding`。C130（#882，别的置顶窗口出现时把岛拉回最前）的守护线程每次置顶前先问 `allows_raise()`，岛被切到下层时不会被它拉上来。
- 岛在下层时，被点到或鼠标悬停拿焦点时会照常排到普通窗口的最前（这是系统行为），之后被别的窗口盖住也正常；要它一直在最前就再按一次快捷键。

### 别的置顶窗口盖住岛时拉回最前（C130，2026-11-21，#882，只有 Windows）

- 搭全屏检测的轮询（`system/fullscreen.rs`，每 0.8 秒）：沿 `GW_HWNDPREV` 往上看岛上面的窗口，有和岛矩形重叠的别家置顶窗口时，`SetWindowPos(HWND_TOPMOST, SWP_NOACTIVATE)` 把岛放回最上面，不抢焦点。代码在 `island/topmost_guard.rs`。
- 不拉的情况：`allows_raise()` 为 false（快捷键切到下层）、前台全屏程序在岛的屏幕上、岛隐藏或挂在任务栏下面（有 owner）；浮屿自己进程的窗口（截图选区、贴图）；另一个浮屿的岛（窗口类名相同）；工具窗口、不激活、鼠标穿透的弹层；开始菜单、通知中心、任务切换、托盘溢出、输入法、右键菜单、提示框这些系统窗口（按类名）。
- 对方也在反复把自己提到最前时，同一个窗口连续拉 5 次后就不再拉，等它不再盖住岛再重新计数，避免两边来回闪。

### 挡住可点区域时自动退后（只评估，待用户定）

用户提的三种自动做法，按成本从低到高：

1. **按前台程序判断**：前台是浏览器（Chrome、Edge、Firefox）或 Office（WINWORD、EXCEL、POWERPNT）且窗口最大化、顶边和岛重叠时，`set_yielding(true)` 退到下层，前台换走时回来。
   - 能拿到：`GetForegroundWindow` + 进程名 + 窗口矩形，岛已经有前台窗口和全屏的检测（`win32/window.rs`），每次前台切换算一次，开销可以忽略。Mac 上用 `NSWorkspace` 的前台应用和窗口列表，同样便宜。
   - 误判：用户就是想在浏览器上面看岛（看歌词、Agent 状态、待办）时岛却没了；名单之外的程序（WPS、飞书、VS Code 的标签栏）照样被挡，名单要一直补；窗口没最大化、标签栏不在岛下面时也会白退。
2. **按岛下面的东西判断（UI Automation 命中测试）**：鼠标靠近岛时，用 `IUIAutomation::ElementFromPoint` 取岛下面那个点的元素（岛自己要先跳过，或按岛矩形四周采样），元素是 `TabItem`、`Button`、`MenuItem`、工具栏子项时退后。
   - 能拿到，但要绕过岛本身：命中测试拿到的是最上面的窗口，岛在上面时拿到的是岛，只能取岛下面那个窗口（`WindowFromPoint` 跳过岛后 `ElementFromHandle` 再往里找），或临时让岛穿透再取。
   - 开销：每次调用跨进程，Chrome、Office 的 UIA 树很大，冷启动一次几十到几百毫秒，Chrome 第一次被 UIA 访问时还会打开整棵无障碍树，浏览器内存和 CPU 都会涨；要放在后台线程、节流（比如鼠标停住 150ms 才查一次）。Mac 上对应 `AXUIElementCopyElementAtPosition`，要「辅助功能」授权。
   - 误判：岛下面有可点元素不等于用户要点它；鼠标路过就退后，岛会频繁闪进闪出；Electron 应用、游戏、自绘界面的元素类型不可靠，Office 的功能区是自绘的，只能拿到粗粒度的 Pane。
3. **只做鼠标穿透**：已有，挡不住「看不见标签页标题」，所以不够（#849 用户补充）。

**推荐**：先不做自动退后，用快捷键 + C117 的缩窄露边条覆盖主要场景，看用户反馈。真要做选第 1 种，做成默认关的开关（「浏览器或 Office 最大化时自动退到后面」），名单可编辑，退后只用 `set_yielding`，不碰用户用快捷键选的 `front`。第 2 种开销和误判都高，不推荐。

待用户定：自动退后做不做；做的话是否按第 1 种、默认开还是关。
