## 内置插件与收起条槽位（2026-11-06）

- 用量环、会话环、中心图案都做成内置插件，在"插件扩展"里开关，不另设功能开关。（用户确认：插件形态）
- 用量环是同心双环：外环 5 小时、内环 7 天。（用户确认）插件叫「Agent 用量环」，Claude Code、Codex、GLM、Kimi 各一个开关，每个打开的 Agent 一个环，可以同时上岛，各有自己的颜色。（用户要求 2026-11-08）会话环是一个分段环，每段一种会话状态，中心可写总数。（用户确认）会话环另有像素格、状态条和信号格三种样式，在插件设置「样式」里选，默认仍是分段环。（用户要求 2026-11-08）
- 收起条有三个槽位，都空着时收起条与现在完全一样（Agent 推断，依据审阅报告）：
  - 中心槽位：只在没有消息预览、翻译、Agent 标题、待办和名称时显示，占摘要的位置，在状态灯与右侧元素之间的剩余空间居中；点它和点小岛一样。
  - 仪表槽位：放在最右侧元素（收起灰点或会话数）紧前面，和音乐、文件中转按钮同一行间距。（2026-11-09 起这是默认位置，用户可以在设置里调，见文末「统一排序」。）
  - 会话槽位：AI Agent 开启时代替蓝色会话数；AI Agent 关闭时不显示，保留收起灰点。
  - 插件声明槽位要占的宽度（`centerWidth`、`sideWidth`），折叠岛按它变宽（最宽 340px），不挤压摘要。
- `MiniRing` 是纯 SVG 小环：同心环或单个分段环，12 点钟方向起顺时针，圆头，默认 20px、线宽 2.5、环距 1.5，底轨白 16%；中心标签用 `--text-1`、600、等宽数字；数值变化 320ms 缓出，减少动效时不动画。值为 0 的环只画底轨，不画弧。（Agent 推断，依据审阅报告）
- 用量双环（内置插件 `claude-usage`，2026-11-16 前是第 2 版的 `focusd.claude-usage`；名称「Agent 用量环」）：每个打开的 Agent 一个环，24px（和会话环的分段环一样大；用户要求 2026-11-08），按 Claude Code、Codex、GLM、Kimi 排列，收起条每多一个环加宽 30px；全部关掉时不显示。外环 5 小时、内环 7 天，没有周限额的套餐（Kimi 新版会员）内环画本月；常态色各家不同：Claude Code `#FFB27A`（橙）、Codex `#E6E6EB`（OpenAI 的黑白取近白）、GLM `#A99BFF`（智谱标志的蓝紫）、Kimi `#6AABFF`（Kimi 品牌蓝），≥70% 统一 `#F5E06E`（黄，和 Claude 的橙分得开），≥90% 统一 `#FF7A7A`（各家常态色为 Agent 推断：官方没有公开色值，按标志取色）。底轨是岛的文字色 12%，跟着岛的深浅。浅色岛另用一套深色：Claude Code `#93400F`、Codex `#3A3A42`、GLM `#5B47E0`、Kimi `#1666D6`、≥70% `#8A6400`、≥90% `#C42B2B`、过期 `#6A6A72`。两套都按 WCAG 算过：相对底轨，Claude 的常态色至少 4.5:1，其余至少 3:1（深色岛按 `#2F2F37`、浅色岛按 `#F2F2F5` 算）。色值在 `tokens.css` 的 `--usage-*`。（issue #42，2026-11-12 起；具体色值为 Agent 选定，用户同意由 Agent 决定）；卡片第一行是 Agent 名和套餐（如「GLM · GLM Coding Pro」），用它的颜色；GLM 的 MCP 月度额度、Kimi 的本月额度列在 7 天之后。以下 Claude Code 的规则对各家通用：数据超过 15 分钟或没有数据时整体变灰（深色岛 `#A3A3AA`），没有数据时只画底轨。数据与 Agent 页顶部的用量相同：Claude Code 经本机 magpie 网关时读 magpie 的用量，否则读 claude-hud 的用量快照（都不联网、不读凭据）；插件设置「直接向 Anthropic 查询」打开时（默认关），两者取较新的一份。直接查询失败但数据仍新鲜时环不变灰，卡片里加一行原因；卡片最后一行写更新时间和来源（claude-hud / Anthropic）。环是按钮，点击立即请求刷新并重读（原生端 60 秒内只放行一次）。（用户确认：配色与过期、直接查询可选且默认关、不直连；点击行为为 Agent 推断）
- 会话环（内置插件 `session-ring`，2026-11-16 前是第 2 版的 `focusd.session-ring`；样式和「显示会话数」在 设置 → AI Agent 的「会话环」分组）：显示的就是 Agent 页列出的会话（含 Codex，跟着「隐藏已退出的会话」「只显示进行中」和 × 移除走，环自己不另设去留规则），列表里有几个、各是什么灯色，环里就是什么。（用户要求 2026-11-08：直接依赖主会话列表，不要和它对不上）AI Agent 开启时代替蓝色会话数，点击打开 Agent 页；AI Agent 关闭时不显示。颜色就是 Agent 页的灯色：等你确认（等审批或等回答，或失败且没看过）`#FF453A`、等你回复（回合结束、最后的回复在问你：回复状态标记 ↩，没有标记时看最后一段是否问句）`#FFD60A`、运行 `#34C759`、可能已停（运行中但很久没动静）半透明绿、完成（含看过的等你确认 / 回复）`#8E8E93`，按这个顺序排。四种样式，分段环和状态条的数字可以用插件的「显示会话数」开关关掉（默认开，关掉后只看颜色比例，环的大小不变）（用户要求 2026-11-08）：
  - 像素格（默认，用户要求 2026-11-15）：每个会话一格，4 个以内 2×2 格（8px），否则 3×3 格（6px），格距 2px、圆角 2px，没用到的格子画成白 10% 暗点，超过 9 个时最后一格画成加号、亮最急的 8 个；亮格带同色 5px 光晕，等你确认 1.4 秒一闪，运行 2.8 秒呼吸，收起条不在屏幕上或减少动效时不动。
  - 分段环：24px，中心写总数（一位数 12px，两位数 10px），从 12 点起顺时针。
  - 状态条：总数（11px）加一条 34×6px 胶囊，每种状态一段，长短按会话数分，段间 1px 断开，最短 3px。
  - 信号格：从左到右灰（完成）、绿（运行，可能已停的画成半透明绿叠在上面）、黄（等你回复）、红（等你确认）各一根 6px 宽的柱子，柱距 3px；没有会话的颜色不画柱子。每根柱子 5 个槽位，每个会话从下往上亮一格，没亮的画成白 10% 暗格（同像素格的空格），所以柱子一样高、在条里居中，亮了几格就是几个会话。横条粗细固定、所有柱子一样：5 个槽位时 3px（共 19px），任一根超过 5 个时每根都加到 6–7 个槽位、2px（共 17–20px），条距 1px；一根最多亮 7 格，再多的只在悬停卡片里计数。亮格光晕 2px（条距只有 1px，像素格的 5px 会把上面的暗格染色）。（用户要求 2026-11-08：柱子、颜色顺序、没有会话不出柱子；粗细固定而非填满高度、暗格槽位为 Agent 建议：填满后柱高不再表示数量，只画亮格时 1 个会话只剩一根 3px 短线，像出错）横条的圆角跟外观 → 圆角：岛屿圆角按收起条 38px 高等比缩到横条高度（最多半个条高，即胶囊），圆角样式（方圆 / 圆角）用同一个 `corner-shape`。（用户要求）
  （样式细节为 Agent 推断，截图检查过 1/3/6/12 个会话，信号格另看过岛屿圆角 16 / 40 和两种圆角样式）没有要显示的会话时整个环不显示，退回蓝色数字。悬停卡片列出各状态计数和前三个等你处理的会话"状态：标题 · 项目"，标题超过 40 字截断。（配色与优先级为用户确认；数据来源改为岛屿自己的会话列表为维护者决定）
  - 打开设置 → AI Agent → 连接 →「回复状态标记」（B9，推荐打开）后，已完成的会话按回复末尾的标记分：`↩` 等你回复为黄（看过也保持黄），`⋯` 等它自己的后台任务算运行（绿），`✓` 做完为灰；没有标记的会话沿用“没看过算等你回复”。Agent 页里等你回复的会话在状态行写「等你回复」。提醒和音效同样细分：等你回复按「等你确认 / 回答」弹出（受那个开关控制）并用「提问」音效，等后台任务不弹不响，后台任务结束、Claude Code 被唤醒接着做时也算同一轮，不弹「开始」、不响「收到」，卡片上的提问和计时仍是你那一条（issue #15）；做完照旧是完成。标记符号自定，不沿用 claude-sessions 的符号与文字。（用户确认做成可选、默认关；符号与文案为 Agent 推断，待用户审阅）
- 悬停详情卡片 `IslandHoverCard`（`src/components/`，用量环、会话环、Agent 页顶部用量行共用；用量行的卡片出现在这一行正下方，只写直接查询失败的原因和「更新时间 · 来源」，和用量环卡片的最后几行一致）：不用原生 `title`。光标停在环上 200ms 后，在胶囊正下方居中出现；会被鼠标指针挡住时整张移到指针左边（左边放不下就移到右边），鼠标在触发区里移动时跟着避让，键盘聚焦（`:focus-visible`）时立即出现；移开、按下、失焦或原生端报告光标离开岛时消失。底色用岛的 `--island-background-color`，1px 白 8% 描边、圆角 12、阴影；文字 12px，数据行 `--text-1`，次要行 `--text-3`，行首可带 6px 色点（环的颜色）。卡片画在 `.stage` 里、岛外面，不接收鼠标，不在原生点击区域内，因此不挡穿透、不抢焦点；环是按钮，按现有规则停在上面不会悬停展开。进场 140ms 淡入下移 4px，减少动效时不动画。（用户确认：卡片形式与位置；样式细节为 Agent 推断）

## 新消息横幅（C10，issue #13，2026-11-09）

- 设置 → 消息 →「新消息提示」选「一行预览 / 横幅」，默认一行预览，老用户不变。（用户确认）
- 横幅时 QQ、微信、邮箱和插件通知（`island.notify`）在收起的岛正下方弹一张卡片，收起条保持原样，不再同时出一行预览。（用户确认：收起条不重复、插件也走横幅）微信读不到内容，卡片标题写「微信」，摘要只写「有新提醒」。（用户确认，2026-11-09：原先微信留在收起条上一行，改为也弹卡片）
- 卡片：宽 320px，岛下方 8px 居中；底色用岛的 `--island-background-color`，1px 白 8% 描边、圆角 16、阴影。左侧 20px 来源图标；第一行发送人 / 群名 / 插件标题（13px、600，单行省略）和右侧到达时间（11px `--text-3`，24 小时制）；下面摘要（12px `--text-2`，最多两行）；同组有多条时再写「另有 N 条」。右上角 22px 关闭按钮。插件通知的按钮排在卡片底部，与文字左对齐。进场 220ms 淡入下落，减少动效时不动画。（Agent 推断）
- 停留 5 秒（插件用它自己的 `durationMs`）；卡片显示期间新到的消息并进同一张，显示最新一条并重新计时。鼠标停在卡片上时不收回，离开后重新计满。点击卡片和点一行预览一样（QQ 打开 QQ，微信打开微信，打不开时回到消息页的那个来源；邮件打开岛内阅读页，插件通知关闭），点插件按钮运行动作，点关闭只收回。展开、贴边收起、托盘隐藏、全屏免打扰时不弹，已弹的立即收回；贴边时开着「有新消息时露出」的，岛滑出后再弹。（规则沿用一行预览，issue 中的要求）
- 卡片在原生点击区域内（`island/banner_hit.rs`，前端交出卡片的矩形），所以能点；但停在卡片上不算停在岛上，不会触发悬停展开。（Agent 推断）

## 新消息展开面板（C11，2026-11-09）

- 「新消息提示」的第三个选项「展开面板」：新消息到达时，收起的岛自己展开到消息页，只列这次弹出期间到达的消息，最新的在上，最多 6 条；QQ、邮箱、微信（一行「你收到了一条消息」）和插件通知都进面板，插件通知的按钮放在它那一行。（用户确认：微信、插件都进）
- 停留时间单独设置：3 / 5 / 8 / 15 / 30 秒，默认 8 秒，只在选了展开面板时显示。（用户确认）
- 仿照 Agent 弹出提醒：面板开着时新到的消息并进来并重新计时；鼠标停在岛上时不收起；在面板里按下就算接管，不再自动收起，按在消息行以外的地方回到完整消息页；点岛外收起。点一行和点一行预览一样：QQ / 微信打开对应程序并收起岛（打不开时回到消息页的那个来源），邮件在岛内打开阅读页，插件通知移走这一行（最后一行移走时收起），点插件按钮运行动作并移走这一行。（Agent 推断，沿用 Agent 弹出提醒）
- 你自己展开着岛、游戏模式、托盘隐藏时不弹；贴边时开着「有新消息时露出」的照常弹。和 Agent 弹出谁先到谁占着，后到的进各自的页面；Agent 的审批卡片会切到 Agent 页，面板随之结束。收起条在这个模式下不出一行预览。（Agent 推断）
- 行的样式和横幅卡片一致（来源图标、发送人 13px 600、时间、两行摘要），每行白 8% 底、圆角 12；岛的高度按这几行的实际高度。（Agent 推断）
- 弹出时不显示岛的顶部栏（页面圆点、设置、翻译等按钮），岛宽 400（完整面板 560），只包住「新消息」标题和卡片；标题右边一个「全部消息 ›」，点它或标题行、面板空白处，岛从中间展开成带顶部栏的完整消息页。宽度固定，不随消息内容变化，免得来一条消息宽度就跳一下。（用户确认：C11b；宽度固定、「全部消息」入口为 Agent 推断、用户同意）
- 「全部消息」左边一个只有图标的「清除提醒」（双勾，悬停说明只清岛上的提醒）：一次清空弹出的面板、收起条预览和横幅，以及 QQ、微信的提醒列表，插件的提示也收起；不打开任何应用，微信、QQ 里的消息不标为已读；弹出页里列出的邮件会在邮箱里标为已读，邮箱里其他未读不动（用户要求 2026-11-13，C55；原先邮件也不标）。只放图标是为了窄窗口下标题行不挤。（issue #45，C46）

## 折叠待办状态

- 没有已开始的任务时，默认显示“剩余 x 个待办”；设置中可单独关闭，开始任务后显示任务标题。（用户确认：本次请求）
- 数量只包含当前待办中的未完成项，包括 0；总文字开关仍控制全部折叠文字，消息预览继续优先显示。（Agent 推断）

## 折叠态中心图案

- 摘要为空时折叠岛中间显示一个图案：内置五款 SVG 动画（跟随光标的眼睛、小鸟、呼吸光点、小猫、水母），或一只 Codex Pets 宠物（petdex 格式，读 `~/.codex/pets` 与应用数据目录 `pets/`，同名时应用数据目录优先）。不做任意单张图片导入。（用户确认）
- 图案按 22px 高画、最宽约是高的 2 倍，白 / 浅灰为主，喙、脚、耳内少量暖色；只动 transform / opacity，循环 5–9 秒，岛展开、贴边收起和"减弱动态"时停住。眼睛跟随窗口外的光标靠原生端约 28Hz 的 `island-cursor-moved` 事件，只在眼睛显示时开启；4 秒没有光标变化就自己缓慢环视。（Agent 推断）
- 宠物按状态播放 petdex 的行：空闲 idle、运行 running、等待确认 waiting、失败 failed、完成 waving；帧数和循环时长照 petdex 渲染器的状态表。图集总是大幅缩小显示，用平滑采样（`image-rendering: auto`），像素风也不用 `pixelated`。v2 的 8×11 图集按前 9 行使用。（Agent 推断）

## 刘海两翼放不下：收进「+N」（C139.2，2026-11-19）

贴合刘海时每侧最宽 100，去掉边距约 80，放两三个项目就满。以前放不下时插件项会一起被挤到看不见，内置项伸进刘海那一段，岛上没有任何提示。

- **谁留下**：按「收起条上的项目」清单的顺序先放，放不下的整项收起来，不把后面更小的项目提到前面；留下的项目完整显示，不再被挤扁。用户 2026-11-19 的预期是「排在上面的先显示」，所以没有按最初方案的「靠屏幕外侧的优先」。
- **「+N」**：有收起来的项目时岛上多一个「+N」，放在更空的一侧（一样空时放左侧），左翼排在最后、右翼排在最前，也就是靠刘海那头。没有内容的项目（比如没有新邮件）不算数、不收起。
- **小面板**：停在或点「+N」，岛正下方出一张卡片，按顺序列出收起来的项目的名字；点一项打开它的页面，没有页面的只列名字。Esc 收起并把焦点还给「+N」，上下键在行之间移动。卡片画在岛外，矩形报给原生层算进可点击区域。没有动画。
- **宽度**：有项目被收起时两翼撑到最宽，不随剩下的内容缩窄，否则刚收起又放得下，会来回跳。最宽默认 100，岛屿布局 →「刘海两侧最宽」能调到 170（只在 Mac 上显示这个滑块）：调宽能多放几个，代价是盖住更多菜单栏。
- **算宽度**：没有内容但占着位置的项目（空的元素）不收起，但它在两翼里仍然占一个间隔，算容量时要扣掉；打开岛的那块按钮按它的内边距算最小宽度。漏算会让留下的项目被轻微挤压。
- **开关**：岛屿布局 →「放不下的项目收进「+N」」，默认开；关掉回到以前的排法。
- 项目都放得下时不渲染任何新东西，收起条的结构和以前一样。
- **清单里的「小面板」一档**：清单每行多一个「⋯」按钮（2026-11-22 起改成拖进「小面板」那一格），把项目一直放在「+N」小面板里，不占岛上的位置（`fuyu-collapsed-items` 的项目多 `shelf: true`）。它在小面板里排在清单里原来的位置；隐藏优先于小面板。有这样的项目时「+N」一直在，刘海形态下照样挑更空的一侧，没有刘海时排在右侧项目之后、贴边收起的圆点之前。把「放不下的项目收进「+N」」关掉后，自动收起停了，但手动放进小面板的项目照旧。
- **设置里的标记**：岛把此刻放不下的项目写进 `fuyu-collapsed-overflow`，清单里对应的行标「刘海旁放不下」，手动放进去的标「在小面板里」。2026-11-22 起改成虚线和「+N」标签，手动放的就在「小面板」那一格。
- **悬停展开**：收起条上的按钮本来就不触发悬停展开，「+N」是按钮，停在上面岛不会展开。
- 还没做：没有刘海时超过 520 的自动收起（仍是右边缘淡出，可以先手动放进小面板）；新装插件放到更空的一侧和安装提示。
