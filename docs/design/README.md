# 界面设计约定

更新：2026-11-06

## 已确认的方向

- 消息区恢复用户截图中的 QQ、微信、邮箱三项品牌导航，操作按钮排列在同一行右侧，沿用现有深色、圆角和紧凑控件风格。（用户确认）
- 微信回到共用导航中，显示简洁提醒状态，接收和打开动作使用图标，不额外抽成常驻卡片。（用户确认）
- QQ 通知与邮件分别显示在各自来源列表中。（用户截图）
- 微信不显示未经获取的联系人、消息正文或准确未读数。（用户确认）
- 点开邮件进入岛内单栏阅读页；返回原列表，内容区域可滚动。（用户确认）
- 来源列表恢复截图中的 350 布局高度，邮件阅读沿用 450 的高度。（截图恢复与现有阅读实现）
- **清空的规则各来源一致**（B70）：来源标签上的提示（QQ 的条数、微信的点、邮箱的未读数）在这一页点清空（垃圾桶）或全部已读（双对勾）后都要消失，之后有新消息才再出现；只是列表空了、提示还亮着算 bug。邮箱标签上的连接状态点只在有问题时显示（连接中黄、出错红），正常连接不显示，免得和未读的薄荷绿混淆。以后接入新平台照这条做。（用户要求 2026-11-16）

## 品牌与组件

- 复用已有品牌图标、系统字体、深色表面、lucide 动作图标、圆角及浅绿提醒色，不另建视觉主题。（用户确认）
- 主要样板为 `src/features/messages/Messages.tsx`、`wechat/WeChatReminders.tsx` 和 `mail/MailPanel.tsx`；样式复用 `qq-notifications/QQNotifications.css`，新增语义样式放在对应模块。（Agent 推断）
- 长主题和发件人不能挤压时间；列表文本截断，阅读页完整换行。（Agent 推断）
- 处理过程中保留返回动作，失败时原地给出重试入口。（Agent 推断）

## 阅读行为

- 正文按需加载，后台只同步邮件头；阅读不自动标记已读。（用户确认）
- HTML 保留可读排版并清理主动内容，远程图片不加载；附件和回复保留网页入口。（用户确认）
- 正文与提醒状态仅保存在内存，现有偏好存储键保持兼容。（Agent 推断）
