# 会话的层级、分组和命名

> 日期：2026-11-15。问题：一个主会话开「任务主 agent」，主 agent 再派子会话，这样形成三层会话，侧边栏里第三层没法展开收起；会话名字也乱。用户想要 5～10 个只用来聊天的主会话，由它们按要求开任务主 agent、再派子会话，不同层级的会话名字也要能区分开。该怎么组织？
> 范围：Claude Code 官方文档（desktop、agent teams）、anthropics/claude-code 的 GitHub issue、同类工具（Conductor、Claude Squad、Vibe Kanban、Cursor subagents）和多 agent 层级的实践文章；本机 app 自带的侧边栏和会话工具（`list_sections`、`move_sessions`、`start_session`）。关键词：nested sessions sidebar、session groups、agent teams lead、orchestrator worker depth。

## 结论

1. **限制来自 app，不在我们的流程里。** 侧边栏按「谁开了谁」把会话挂成一棵树，看截图只有最上面一层能折叠。自定义分组也只有一层：分组里不能再套分组（[#93058](https://github.com/anthropics/claude-code/issues/93058)），这个需求官方还没回应，也没排期。所以「主会话 → 任务主 agent → 子会话」三层的结构，在现在的侧边栏里怎么排，第三层都收不起来。
2. **业内的共识是两层就够。** 一层统筹，一层干活：Anthropic 自己的研究系统、Claude Code 的 agent teams（一个 lead 带若干 teammate，teammate 不能再开下一级）、Cursor 都是这样。Cursor 的 subagent 最多只能嵌套两级，社区经验是平铺派发最稳。层级越深，token、延迟和排查成本越高。
3. **定下来的做法（2026-11-15 用户定）：每个长期领域一个分区，分区里一个总控；总控只聊天、不开发；小事总控直接派任务会话，大事才开组长。**
   - **分区**：按长期领域划分，5 个以上。分区可以整个折叠，领域之间互不干扰。
   - **总控**：每个分区一个，由你自己开，长期存在。只聊天、规划、派会话、检查，不写代码。另有一个「全局」总控（就是现在这个会话），负责分 issue、整批合入、拦发版和跨领域协调。
   - **组长**：总控为一件要分几批、派好几个会话的大事开的统筹会话，规划、派会话、收口，不写代码。做完就归档。
   - **任务会话**：真正改代码的，做完就归档（`fuyu-lead` 收口这一步已经写好了）。
   - **层级**：总控 → 任务会话是两层，大部分时候都是这样；只有开了组长的大事，进行期间才会有第三层（总控 → 组长 → 任务会话）。第三层收不起来的问题没有解决，只是靠「小事不开组长」和「做完就归档」把它压到最少。
4. **命名按角色加固定前缀**：`[总控]`、`<组长>`、`(任务编号)`、`「预览」` 这类，在侧边栏一眼能分出角色（细则见下面「命名」一节）。

## 详细

### 现在的问题出在哪

- 现在的结构是：总控（Issue triage and routing）开主 agent，主 agent 再派子会话，一共三层，第三层收不起来。用户截图里，「消息与小功能主 agent」下面的 C72、C80 等就收不起来。
- 主会话、主 agent、子会话的名字看不出谁是谁。有的写「主 agent：…」，有的写任务编号，有的是一句话，还有英文。
- 做完的会话不归档。2026-11-15 一次清理就归档了 49 个；`fuyu-lead` 收口时归档子会话这一步已经加上，提交是 3af16261。

### app 能做什么（本机工具和文档）

- **分区（section）**：侧边栏现在是分区布局。内置的有「置顶」「定时任务」「会话」三个分区，可以新建自定义分区，用 `create_section`。每个分区能单独折叠、单独设排序（按最近、按名字、按创建时间），会话用 `move_sessions` 归进分区。分区里不能再套分区。
- **会话树**：`start_session` 开出来的会话记着是谁开的，侧边栏把它挂在开它的会话下面。官方文档原话是「侧边栏把开出来的会话列在当前会话下面」（the sidebar lists the started session under the current session），没写能挂几层、能不能折叠。
- **自动归档**：可以设成闲置 N 天后自动归档，现在是 2 天。也可以设成 PR 合入时归档，但我们是整批合入，不按会话开 PR，这个用不上。

### 别人怎么做

| 做法 | 层级 | 怎么分组 | 怎么命名 |
|---|---|---|---|
| Claude Code agent teams（实验功能） | 一个 lead 加若干 teammate，两层；teammate 不能再开下一级 | 一个团队一份共享任务清单 | 团队名，加任务清单里的任务 |
| Anthropic 的研究系统（orchestrator-worker） | 一个 lead agent 并行派多个 subagent，两层 | 不适用 | 不适用 |
| Cursor subagents | 最多到第二级；社区经验是平铺派发最稳 | 不适用 | 不适用 |
| Conductor、Claude Squad | 平铺，每个任务一个工作区（worktree） | 按仓库 | 用任务对应的分支名，例如 `feature-auth`、`bugfix-123` |
| Vibe Kanban | 平铺，一张卡片一个 agent | 看板的列（待做、进行中、完成） | 卡片标题 |
| 侧边栏「分组里再分组」的需求（#93058） | 想要多层分组 | 讨论里的变通做法：标题加路径前缀（`auth/login`），或者按主题建顶层分组 | 路径前缀；有人说这两种分组会互相打架，最后放弃了 |

一篇实践文章建议一个统筹者同时管的任务不超过 8 个，不然统筹者本身就成了瓶颈；这和「全机器同时开 6 个左右改代码的会话」的现行规则对得上。

### 结构

```text
分区「全局」
  [总控] 全局                          ← 分 issue、整批合入、拦发版、跨领域协调
分区「插件平台」
  [总控] 插件平台                      ← 你开的，长期存在，只聊天不开发
    (E36.3.18) 翻译入口不收 baseUrl     ← 小事：总控直接派的任务会话
    <组长> 插槽化                       ← 大事：总控开的组长
      (E36.2.6) 头部按钮走插槽          ← 组长派的任务会话（第三层，做完归档）
      (E36.2.7) 刘海提醒插槽
分区「岛与外观」
  [总控] 岛与外观
    「预览」岛的三种形态                ← 等你挑方案
……（5 个以上的分区）
```

- 分区按长期领域划分，不按一次性的主题划分。例如：全局、插件平台、Agent 页、岛与外观、消息与小功能、剪贴板与媒体、Mac 适配、流程与文档。要几个由你定。
- **什么时候开组长**：一两个任务会话就能做完的，总控直接派；要分几批、派三个以上会话的，才开组长。
- 总控对话变得很长时，在同一个分区里新开一个同名的，把旧的归档。交接靠任务文件和计划文件，不靠对话。
- 只读的调研、查资料，优先用后台子代理（Agent 工具）做，子代理不进侧边栏。要你能看到、能插手的工作才开会话。
- 实测（2026-11-15）：把一个会话移进分区，它下面开出的会话（包括第三层）会一起跟过去。新派出的会话会不会自动进父会话的分区还没验证，派完看一眼，不在就用 `move_sessions` 挪进去。

### 命名

| 角色 | 标题格式 | 例子 | 会话短名（`name`） |
|---|---|---|---|
| 总控 | `[总控] <领域>` | `[总控] 全局`、`[总控] 插件平台` | 你开的会话没有短名 |
| 组长 | `<组长> <主题>` | `<组长> 插槽化` | `<主题>-lead`，例如 `slots-lead` |
| 任务会话 | `(<任务编号>) <一句话>`；还没建任务的写 `(#<issue 号>)` | `(C72) 待办颜色和优先级`、`(#523) 共享模块名单` | 任务编号，点换成短横线，例如 `c72`、`e36-3-18` |
| 其他 | `「预览」`、`「调研」`、`「排查」`、`「长期任务」`加主题 | `「预览」岛的三种形态`、`「排查」Mac 更新后卡在重启` | 例如 `c65-preview`、`mac-restart` |

- 前缀里不加空格，前缀和主题之间也不加「 - 」：侧边栏很窄，标题超出部分会被截掉。
- 括号里优先写任务编号：每个 issue 都会建任务，编号能直接拿去 `pnpm tasks show`。
- 定时任务在侧边栏里有自带的「定时任务」分区，不用前缀。
- 标题都用中文，任务编号和英文专有名词照原样写。

### 迁移

1. 已做：现在这个会话改名为 `[总控] 全局`，移进了「全局」分区，它下面的主 agent 和子会话都跟着进去了。
2. 每个领域开一个总控：在侧边栏新建会话，第一句输入 `/fuyu-lead 总控 <领域>`。它会自己改名为 `[总控] <领域>`、建好同名分区并把自己移进去，读完规则后等你吩咐。
2a. 已做：原来你开的三个顶层会话直接转成总控，改名并移进同名分区，它们下面的会话一起跟过去了：「插件平台第 3 版基线和可行性验证」→ `[总控] 插件平台`，「issue 处理」→ `[总控] Agent 页`，「项目 Skill 体系整理」→ `[总控] 流程与文档`。「beta/正式版本发布」→ `「长期任务」发版`，放进「全局」分区。消息与小功能、岛与外观、剪贴板与媒体、Mac 适配这几个领域还没有总控，要你用 `/fuyu-lead 总控 <领域>` 开。
2b. 已做：哪个总控管哪些任务组、平时只由 `[总控] 全局` 整批合入、总控之间怎么互发消息，都写进了 `fuyu-lead`。实测：正在跑的会话，发消息时直接写标题（`[总控] 插件平台`）就能送到；没在跑的写会话 id。
3. 现在挂在 `[总控] 全局` 下面的几个主 agent（消息与小功能、岛外观、同步调研等）挪不到别的总控下面：会话挂在谁下面由开它的会话决定。它们做完手上的事就归档，以后同类的事交给对应领域的总控。
4. `fuyu-lead` 已经改成这套：开总控的入口、什么时候开组长、三种角色的命名，以及派出的会话不在总控的分区时挪进去。
5. 自动归档从闲置 2 天改成 1 天，兜住漏掉没归档的。
