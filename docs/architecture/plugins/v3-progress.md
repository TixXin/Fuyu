## 基线和实测

每个系统一行，在哪台机器上测的就改哪一行。「基线」是开工前的数，之后每个阶段结尾各量一次。测法写在第一次量的时候，之后都用同一个测法。

### 闲置内存（收起、不放音乐，私有内存）

| 系统 | 机器 | 基线 | 第 1 阶段后 | 第 3 阶段后 | 第 5 阶段后 |
|---|---|---|---|---|---|
| Windows | tixxin-computer | 约 489 MB（2026-11-15，两次 669、671 MB 减去两个第 2 版插件，见下面的测法；2026-11-06 [idle-usage.md](../../investigations/idle-usage.md) 的旧数是约 330 MB，那次没有插件、默认设置）。按私有工作集重量（2026-11-15，`39f2138d`，3 次）：Rust 主进程加 WebView2 约 **353 MB**（318.5–397.1），之后按这个比 | 开着第 3 版比关着多一个 Node 宿主进程，私有工作集 **25.2 MB**（25.0–25.8），在 40 MB 的验收线以内（2026-11-15，`39f2138d`，宿主的线程池在 Windows 上设成 2，关、开交替各 3 次，lane 37）。私有内存口径下宿主 47.8 MB（改线程池前约 64 MB，超线；那次的数据见 [v3-kernel-measurements.md](../../investigations/v3-kernel-measurements.md)）。1 小时长跑（改线程池后，私有工作集，宿主带 10 个空插件和 1 个每秒干活的插件）：25.2–32.2 MB，前 46 分钟慢慢涨，回落约 1 MB 后最后 13 分钟一直是 31.3 MB，没有重启；改之前按私有内存跑的一轮是 63.1–71.9 MB，形状一样 | | |
| macOS | tixxindeair | 约 490 MB（2026-11-14，两次测量在 480–516 MB 之间） | 约 494 MB，开着第 3 版比关着多一个宿主进程 25 MB（2026-11-15，`4170b870`，关、开交替各 3 次；关着 476.5 MB、开着 493.7 MB；见 [v3-kernel-measurements.md](../../investigations/v3-kernel-measurements.md)）。1 小时长跑（宿主带 11 个插件，其中一个每秒干活）：26.5–37 MB 锯齿起伏、到顶会回收，没有持续增长，没有重启 | | |

验收线：没装第三方插件时，比基线多不超过 40 MB；连跑 1 小时不持续增长（原来是 8 小时，用户 2026-11-15 改成 1 小时）。

macOS 的测法（之后每次都这样量）：

- 构建：`pnpm tauri build --debug --no-bundle`，加 `CARGO_PROFILE_DEV_OPT_LEVEL=3`、`CARGO_PROFILE_DEV_DEBUG=0`、`CARGO_TARGET_DIR=src-tauri/target/agents`（和 [idle-usage.md](../../investigations/idle-usage.md) 一样：前端是正式打包的产物，Rust 按 release 优化）。量的是 `2f29022e`（0.3.9-beta.1 之后）。
- 身份：`FOCUSD_DEV_LANE=36`，独立的数据目录，数据是正式数据的一份副本（装了一个插件但没启用；QQ、微信、邮件、推送是关的）。
- 启动：用一个会让进程自成一组的启动器（临时项目里的 `tools/launch-time`），否则 WebKit 的辅助进程会记在终端名下，数不到。
- 统计：岛屿进程加上系统记在它名下的全部进程（WebKit 的 GPU、网络和 6 个网页进程，媒体适配脚本，音频辅助进程）的 `phys_footprint` 之和，就是活动监视器「内存」一栏的数。启动 20 秒后每 10 秒读一次，读 180 秒，取中位数（临时项目里的 `tools/mem.py <pid> 20 180`）。
- 这个数和 Windows 的私有内存不是一个口径，两个系统各比各的。其中 WebKit 的 GPU 进程约 117 MB、主网页进程约 140 MB、Rust 主进程 32–40 MB。
- 测量时本机有一个 Claude Code 会话在跑（就是做测量的那个），岛上在显示它的状态，这 180 秒里 CPU 约占单核的 15%，所以不是完全闲置。之后量的时候也是这个条件。

Windows 的测法（之后每次都这样量）：

- 构建：同 macOS（`pnpm tauri build --debug --no-bundle`，加 `CARGO_PROFILE_DEV_OPT_LEVEL=3`、`CARGO_PROFILE_DEV_DEBUG=0`、`CARGO_TARGET_DIR` 写绝对路径 `$PWD/src-tauri/target/agents`）。写成相对路径 `src-tauri/target/agents` 时 cargo 按 `src-tauri` 解析，产物会落进没被忽略的 `src-tauri/src-tauri/`（2026-11-15 第一次量时就是这样，量完删了）。量的是 `1cad1a01`。
- 身份：`FOCUSD_DEV_LANE=36`，独立的数据目录，数据是正式数据的一份副本（第一次启动复制，41 秒）。副本里 QQ、微信、邮件、推送是关的，但**启用了几个第 2 版插件**：PowerShell 写的插件合计约 162 MB 私有内存，一个 Node 写的插件约 21 MB。开发版默认「正式版优先」，没有影响同时开着的正式版。
- 统计（2026-11-15 起）：岛屿进程和它的全部子孙进程的**私有工作集**（`Win32_PerfRawData_PerfProc_Process` 的 `WorkingSetPrivate`，任务管理器「内存」一栏）之和，和 macOS 的 `phys_footprint` 一样只算真正用到的页。私有内存（`PrivateMemorySize64`）会把只提交、没用到的线程栈也算进去（见 [v3-kernel-measurements.md](../../investigations/v3-kernel-measurements.md)「宿主为什么是 64 MB」），只作参考。下面这条是改口径前第一次量的做法：岛屿进程和它的全部子孙进程的私有内存（`PrivateMemorySize64`）之和。启动 20 秒后每 5 秒读一次，读 60 秒，取中位数，量两次。两次的合计是 671、669 MB（工作集 1230、1232 MB），其中 Rust 主进程 35–36 MB、WebView2 合计 453–454 MB、PowerShell 插件 162 MB（另有 `conhost` 3.5 MB）、Node 插件 21 MB。基线按不带插件算：Rust 主进程加 WebView2 约 **489 MB**。以后每次量都按同样的减法，或者先在副本里关掉插件再量（改了要在这里写明）。
- 测量时本机有 D47 的内存采样（盯着正式版）和做测量的 Claude Code 会话在跑，正式版也开着。比 11-06 的 330 MB 多出的约 160 MB 没有拆开查，那次用的是默认设置、没有插件、0.3.x 早期的代码。

### 冷启动（从启动到岛屿能用）

| 系统 | 机器 | 基线 | 第 1 阶段后 | 第 3 阶段后 | 第 5 阶段后 |

验收线：不比基线慢。

macOS 的测法：同上面的构建和身份；从启动器拉起进程，到屏幕上出现这个进程的第一个窗口为止（每 2 ms 查一次窗口列表）。文件已经在系统缓存里，不是重启电脑后的第一次启动；装好后的第一次启动是 4.3 秒，其中包括复制数据。

Windows 的测法：同上面 Windows 的构建和身份；`Process.Start` 拉起进程，每 2 ms 用 `EnumWindows` 查一次，到出现这个进程可见的、类名是 `Tauri Window` 的 820×460 岛屿窗口为止（单实例插件的那个窗口类名以 `-sic` 结尾，30 ms 就出现，不算）。每次看到窗口 3 秒后结束整棵进程树，隔 8 秒再启动。数据复制那一次不计。
