# 插件的独立窗口（设计稿）

> 状态：**待用户审**（2026-11-13）。任务 [E31](/docs/tasks/E/E31.md)，issue 201。外部产品的做法见 [docs/research/plugin-windows.md](/docs/research/plugin-windows.md)。隔离的原型还没做：要在 Windows 上跑，这份稿子是在 Mac 上写的，见第 9 节。

## 0. 摘要

现在插件的界面都在岛屿自己的窗口里。要做启动台、桌面小组件这类插件，需要岛屿之外的窗口。

推荐的做法：

- **窗口由岛屿建并管理**，插件只在清单里声明、用接口请求显示和隐藏。不把窗口对象交给插件。
- **页面沿用现有 `webview` 模板的隔离**：岛屿自己创建的 WebView2，所有请求和跳转在原生层拦截，页面只能和自己的插件进程通信，不能联网。
- **分两种窗口**：浮层（快捷键唤起、失焦就收，适合启动台）和小组件（常驻、贴在桌面上，适合桌面组件）。
- **位置、层级、透明度这些归用户**，清单只声明种类和尺寸范围。
- **先进实验通道，先只做 Windows**，分四期，合计约 4 到 5 周。

## 1. 窗口由谁建

三种做法：

| 做法 | 说明 | 结论 |
|---|---|---|
| 插件自己建 | `.exe` 插件今天就能这样做，岛屿不参与 | 不算支持：PowerShell 和 Node 插件做不了，窗口不跟随主题，岛屿管不到，用户也没法统一设置 |
| 岛屿用 Tauri 窗口建 | 和设置窗口一样，`WebviewWindowBuilder` | 不行。Tauri 建的 webview 都会注入命令通道，本应用没有应用级权限清单，本地来源的页面能调用全部命令（[p8-webview-validation.md](/docs/investigations/p8-webview-validation.md) 第 2 节） |
| **岛屿用原生窗口建，里面放自己创建的 WebView2** | 一个普通的 Win32 顶层窗口，不经过 Tauri；页面用现有的 `win32::webview_page` | **采用** |

岛屿管窗口的代价是每一种窗口行为都要岛屿实现一遍。好处是插件用什么语言写都一样，窗口随插件停用而关闭，用户有统一的地方管它们。

## 2. 隔离是否还成立

现有页面的隔离全部挂在 WebView2 控制器上，和它的父窗口是谁无关（[webview_page.rs](/src-tauri/src/win32/webview_page.rs)）：

- `WebResourceRequested` 过滤 `*`，只回答页面来源下、`entry` 文件夹里的文件，其余返回 403。
- `NavigationStarting` 和 `FrameNavigationStarting` 取消一切离开页面来源的跳转。
- 新窗口、权限请求、下载全部拒绝；关掉宿主对象、脚本对话框；InPrivate，不落盘。
- Tauri 的命令通道是按 webview 注册的，这个控制器上没有。

`webview_page::create` 本来就只要一个 WebView2 环境和一个父窗口句柄。把父窗口从岛屿窗口换成新建的原生窗口，这些都不变。所以判断是：**隔离成立，但要用原型重新验证一遍**，因为下面几处是新的。

| 新情况 | 现在 | 要做的 |
|---|---|---|
| 键盘焦点 | 页面在岛屿窗口里，焦点由岛屿管 | 浮层要拿焦点才能打字。`AcceleratorKeyPressed` 里处理 Esc 关闭，别的浏览器快捷键继续禁用 |
| 透明和圆角 | 页面背景透明，底下是岛屿 | 顶层窗口要自己透明。WebView2 在分层窗口上的透明有限制，原型里试两条路：窗口用 DWM 圆角加不透明底色；或用合成宿主（`CreateCoreWebView2CompositionController`） |
| 拖动 | 不需要 | 小组件要能拖。页面里的 CSS 拖动区需要较新的 WebView2；保守做法是岛屿在窗口边上留一条原生的拖动把手，或用户按住修饰键拖 |
| 环境 | 从岛屿的 webview 拿 | 不变。岛屿窗口一直在（只会隐藏） |
| 同一插件多个页面共用来源 | 已是如此 | 不变。窗口和岛上页面能互相读对方的 `localStorage` 吗：InPrivate 下各自独立，原型里确认 |
| 页面数量 | 每个插件最多 2 个，只在可见时存在 | 小组件常驻，每个约 25 MB。要有总数上限，见第 4 节 |

原型要重跑 p8 第二轮的全部检查（调用不了岛屿命令、任何请求到不了网络），再加上表里的五项。

## 3. 两种窗口

两种窗口的要求几乎相反，分开做：

| | 浮层 `panel` | 小组件 `widget` |
|---|---|---|
| 用途 | 启动台、快速输入、选择器 | 时钟、天气、监控、便签 |
| 出现 | 用户按快捷键或点命令时，由插件请求显示 | 插件启用后一直在 |
| 位置 | 屏幕中央偏上，在鼠标所在的屏幕 | 用户拖到哪就在哪，岛屿记住 |
| 层级 | 置顶 | 默认贴在桌面上，用户可改成普通或置顶 |
| 焦点 | 拿焦点；失焦、按 Esc 就隐藏 | **不拿键盘焦点**（`WS_EX_NOACTIVATE`），只收鼠标 |
| 任务栏、Alt+Tab | 不出现 | 不出现 |
| 「显示桌面」（Win+D） | 无关 | 仍然可见 |
| 生命周期 | 隐藏后页面销毁，状态靠 `getState` / `setState` | 页面常驻；插件停用、岛屿退出时关闭 |

小组件不拿键盘焦点是特意的：它一直在屏幕上，如果能收键盘输入，就能做成一个仿冒的密码框。要输入的东西去浮层或岛上的表单页。

**清单声明什么，用户管什么**（照 Rainmeter 的分法，见调研）：

- 清单：种类、入口页面、默认尺寸、最小和最大尺寸、能否由用户调整大小。
- 用户：位置、在哪块屏幕、层级（贴桌面 / 普通 / 置顶）、透明度、锁定位置、点击穿透、是否显示。设置在 **设置 → 插件扩展 → 窗口** 里，也在小组件的右键菜单里（菜单由岛屿画，不是页面画）。

多显示器：位置按「哪块屏幕加屏幕内的相对位置」记。屏幕拔掉后小组件回到主屏的对应位置，插回来再回去。

## 4. 清单和协议

以下都放在实验通道里，名字在转正前可以改。

**清单**

```json
"experimentalApis": ["windows"],
"permissions": ["windows"],
"contributes": {
  "windows": [
    { "id": "launcher", "kind": "panel", "entry": "ui/launcher.html",
      "title": { "zh-CN": "启动台", "en": "Launcher" }, "width": 640, "height": 420 },
    { "id": "clock", "kind": "widget", "entry": "ui/clock.html",
      "title": { "zh-CN": "时钟", "en": "Clock" }, "width": 220, "height": 120,
      "minWidth": 160, "minHeight": 80, "maxWidth": 400, "maxHeight": 300, "resizable": true }
  ]
}
```

上限：每个插件 1 个浮层、3 个小组件；整个岛屿同时显示的小组件 12 个，超过时新的不显示并在插件卡片上说明。尺寸 80 到 1200 像素。

**方法和通知**

| 名字 | 方向 | 说明 |
|---|---|---|
| `window.show { windowId }` | 插件 → 岛屿 | 只对浮层。要求用户刚操作过这个插件（15 秒内按过它的快捷键、点过它的命令），和 `island.openView` 用同一条规则（[reveal.rs](/src-tauri/src/plugin_host/reveal.rs)），否则返回 403 |
| `window.hide { windowId }` | 插件 → 岛屿 | 浮层隐藏；小组件不能自己隐藏，由用户管 |
| `window.postMessage { windowId, message }` | 插件 → 岛屿 | 发给页面，上限 256 KB，同 `webview.postMessage` |
| `window.message { windowId, message }` | 岛屿 → 插件 | 页面发来的消息 |
| `window.visible { windowId, visible }` | 岛屿 → 插件 | 显示或隐藏了；小组件被用户关掉时也发 |

- 页面里的接口沿用 `acquireFuyuApi()`，多两个方法：`close()`（浮层隐藏自己）、`resize(width, height)`（在清单的范围内）。主题变量同现在的无边框网页页面。
- 激活事件 `onWindow:<id>`，从 `contributes.windows` 自动推出。有小组件的插件在启用后启动并保持运行，相当于自带 `host.keepAlive`，卡片上写明原因。
- 能力 `windows`，放进 `initialize.experimentalApis`，转正后进 `capabilities`。

没有采用「沿用 `webview.postMessage`、把窗口当成一种页面」：页面的 id 是 `viewId`，可见性跟着岛屿走；窗口的生命周期不同，混在一起会让两边的规则都说不清。

## 5. 权限和告知

- **新权限 `windows`**，普通权限，启用插件时授予。不设为「敏感」：敏感权限保护的是数据（剪贴板、消息），这里没有新数据，问一次就够。
- **市场审核**：新版本第一次带 `contributes.windows` 时暂缓上架，等维护者看，和「第一次加入自定义网页」同一条规则。市场和卡片上标「独立窗口」。
- **防仿冒**，四条一起用：
  1. 浮层顶上有一条岛屿画的原生标题条，写着插件的图标和名字，页面盖不住它。
  2. 小组件不拿键盘焦点（第 3 节）。
  3. 浮层只能在用户刚操作过插件时显示，不能自己弹出来。
  4. 窗口不进任务栏，标题固定为「<插件名> · 浮屿」，页面改不了。
- **权限管不到的地方不变**：`.exe` 插件本来就能自己建任何窗口。这套设计保证的是「经岛屿建的窗口是受管的」，文档里照实写。

## 6. Mac

第一期只做 Windows。Mac 上清单里的 `contributes.windows` 照常解析，窗口不创建，卡片和市场提示「独立窗口暂不支持 Mac」（做法同 G1.16）。

和 G1.15 的关系：G1.15 研究的是把 WKWebView 叠到岛屿窗口上。独立窗口在 Mac 上反而简单一些，一个 `NSPanel` 里放一个 WKWebView，不用解决叠放和跟随位置。建议 G1.15 调研时把两种一起看：自定义 URL scheme 提供文件、`WKScriptMessageHandler` 做消息通道、`WKNavigationDelegate` 拦跳转、`WKContentRuleList` 拦请求。这部分要另起任务，不在本稿的工作量里。

## 7. 不用独立窗口能做到哪一步

启动台的简版今天就能做在岛上：命令加全局快捷键，`island.openView` 展开岛屿并打开插件的列表页，列表模板自带搜索框（`view.search`），回车触发条目动作。

| | 岛上的简版 | 独立窗口版 |
|---|---|---|
| 出现的位置 | 岛屿所在的位置（屏幕顶部） | 屏幕中央 |
| 大小 | 岛屿面板的大小，列表 2 到 8 行 | 清单声明，可以很大 |
| 界面 | 列表模板，风格和岛一致 | 插件自己的网页，网格、图标墙都行 |
| 键盘 | 搜索框和上下选择由岛屿处理 | 页面自己处理 |
| 今天能不能做 | 能，Windows 和 Mac 都行 | 不能 |

建议先用简版做一个官方的启动台插件，既是对照，也能验证「用户到底要不要屏幕中央那个大窗口」。桌面小组件没有对应的简版，只能等独立窗口。

## 9. 原型（还没做）

验收里的「用最小的原型验证隔离」需要 Windows：WebView2、原生窗口和 p8 的测试脚本都只在那边能跑。这份稿子是在 Mac 上的会话写的，所以这一节留空，由 Windows 那台机器上的会话接着做。

做法：在隔离的应用标识下，用 release 程序建一个不经过 Tauri 的顶层窗口，放一个示例页面，按 [p8-webview-validation.md](/docs/investigations/p8-webview-validation.md)「第二轮」的表逐项检查，再加第 2 节表里的五项。

## 10. 新增的对外契约

转正时登记到 [contracts.md](/docs/architecture/contracts.md) 和插件文档；实验期间不算。

- 清单 `contributes.windows`，权限 `windows`，激活事件 `onWindow:<id>`，能力 `windows`。
- 方法 `window.show`、`window.hide`、`window.postMessage`，通知 `window.message`、`window.visible`。
- 页面接口 `close()`、`resize()`。
- `plugins.json` 每个插件多一个 `windows`：每个窗口的位置、屏幕、层级、透明度、是否显示。
- 市场索引条目多一个 `windows: true`，审核规则多一条。

## 11. 要用户定的

1. 窗口由岛屿建并管理、不把窗口对象交给插件（第 1 节），同意吗。
2. 两种窗口都做，还是只做一种。只想要启动台的话，可以先只做第 0、1 期。
3. 小组件不能收键盘输入（第 3 节），接受吗。
4. 先只做 Windows（第 6 节），接受吗。
5. 是否先做岛上的简版启动台插件作为对照（第 7 节）。
