# 浮屿下一阶段路线图（2026-12 至 2027-05）

> 日期：2026-11-27，基于 v0.3.15-beta.1。依据：[competitive-landscape.md](../research/competitive-landscape.md)（四路竞品调研）、[platforms.md](platforms.md)、`pnpm tasks` 现有任务、浮汐群反馈 FB-1 至 FB-35、GitHub issue。
>
> 状态：**草案，等用户定「等你定的事」五项**。定了以后按阶段用 `pnpm tasks add` 建任务（有 issue 的先 `gh issue create`），本文只留阶段、目标和任务编号，进度记在各任务文件里。全部阶段做完后移到 `history/`。

## 一、现状一句话

功能面已经是同类里最宽的（待办、音乐歌词、9 款聊天、邮箱、剪贴板、文件架、翻译、17 家 AI 代理、日历、系统提示、截图录屏、语音、插件与主题市场、加密同步），插件平台第 3 版也已默认开启。**短板不在「缺功能」，在三处：**

1. **验收积压**：「需要你本人」的真机实测有 43 条，很多功能标着「待实测」。这是整个项目的瓶颈，不先解决，新功能越多越积压。
2. **性能与稳定**：主进程收起闲置 CPU 约 20%（D86）、GPU 进程私有内存约 400 MB（#746）、系统文本缩放不是 100% 时内容被裁（D122）、群里反馈文字模糊（FB-22）、回弹失败（FB-25）。
3. **Mac 版还没正式发**：G1 有 15 个子任务在等真机确认，签名公证要用户准备 Apple 开发者账号（G1.12）。

## 二、定位与原则

**一句话定位**：电脑上一切需要你注意的事，在岛上一眼看到、一下处理完；Windows 和 Mac 都一样，免费开源。

调研给出的判断（细节见调研报告「结论」）：

- 系统（苹果真灵动岛、macOS 27.3 菜单栏实时活动、Windows 任务栏 Agent）和官方产品（Claude Agent View、Codex app、GitHub 手机实时活动）在吃掉「显示状态、发通知」这一层。浮屿要做它们不做的：**跨平台、跨多家、中立、能在岛上直接处理完**。
- Windows 上第一次出现成规模的收费对手（NotchNook Windows 版 9.9 美元，11 月上线）。窗口期是现在。

**原则（每个阶段都适用）：**

1. **先收口再扩张**：每个阶段开头先清掉上一阶段的「待实测」，不让积压跨阶段增长。
2. **处理完，不只是看到**：新功能优先做「在岛上把事情做完」（审批、审阅、作答、回复），其次才是「多显示一种信息」。
3. **AI 一律默认关**：按次授权，不常驻扫屏，岛上标明本地还是云端；不做屏幕感知和长期记忆。
4. **永远不锁功能、不限插件数**：商业化只走自愿支持和增值服务。
5. **岛只放「一眼 + 一下」的东西**：长列表、工作台类内容分到侧边翼（[side-docks-plan.md](side-docks-plan.md)），不把主岛塞爆。
6. **开放优先**：新能力先想「能不能做成接口 / 插件槽，让别人也能用」，再做内置。

## 四、各阶段

### 阶段 0：收口（2 周）

**目标**：「需要你本人」从 43 条降到 10 条以内；收起闲置 CPU 降到单核 5% 以下；发 0.4.0 正式版。

| 项 | 内容 | 对应 |
|---|---|---|
| 0.1 实测交给 AI | 用户定了（2026-11-27）：所有测试由 AI 做。43 条按机器分组，Mac 用 computer-use，Windows 经 Tailscale SSH 加桌面会话脚本，结果写回各任务文件；只有密码、代发消息、付款、办账号这几步请用户。分组与顺序见 [ai-manual-test-runbook.md](../investigations/ai-manual-test-runbook.md) | B47 扩展、A6–A19、C1xx、D5、E64.3、E66.14、G1.x |
| 0.2 测试自动化 | 把 AI 实测里能脚本化的部分（安装卸载、CPU 采样、钩子、日志断言）沉淀成可重跑的脚本，下个版本直接跑，不再逐条手测 | 新任务（D 组） |
| 0.3 性能 | D86 主进程 CPU 热点；#746 GPU 私有内存；D47 8 小时长测。每个版本在 [idle-usage.md](../investigations/idle-usage.md) 记一次，退步就挡发版 | D86、D47、D56.1 |
| 0.4 群反馈待处理 | FB-19 卡片跳不到窗口、FB-22 文字模糊、FB-25 回弹失败、FB-31 面板尺寸上限、FB-6 布局导入导出（并入阶段 4 的分享） | 新任务（C / D 组） |
| 0.5 D122 | 系统文本缩放不是 100% 时内容被裁 | D122 |
| 0.6 发 0.4.0 正式版 | 插件平台第 3 版、侧边翼、液态玻璃（C135 验收过的部分）一起转正；没验过的项留在 beta 开关后面 | `fuyu-release` |

**完成标准**：0.4.0 发出；`pnpm tasks` 里「需要你本人」≤10；闲置 CPU 数字写进 idle-usage.md。

### 阶段 1：Agent 中枢 2.0（4 周）

**目标**：Claude Code 和 Codex 的所有「等你」都能在岛上处理完，不用切回终端。这是浮屿对 Mac 独占的 Vibe Island 一类产品、对 NotchNook Windows 版最硬的差异。

| 项 | 内容 | 竞品参照 | 价值 / 难度 |
|---|---|---|---|
| 1.1 计划审阅卡 | `ExitPlanMode` 时岛上渲染完整 Markdown 计划（可展开到侧边翼看长文），按钮：批准 / 批准并自动接受编辑 / 写反馈退回。现在只把计划文本推到手机（`push_detail.rs`） | Vibe Island、Nimbalyst | 高 / 中 |
| 1.2 审批卡看全 | 命令不截断（可展开、可复制）；Edit / Write 显示文件名和 ±行数，展开看 diff 摘要；永不超时自动允许 | Vibe Island、Crest、CodeIsland | 高 / 中 |
| 1.3 按状态分组 | Agent 页加「等你 / 运行中 / 待审阅（刚完成未看）/ 完成」分组视图；全局快捷键「跳到下一个等你的会话」；前台正在看的会话不再弹提醒 | Claude Agent View、cmux | 高 / 低 |
| 1.4 上下文与进度 | 卡片上显示上下文占用、子代理和待办进度（补全现有 `AgentSubagents`） | claude-hud | 中 / 低 |
| 1.5 花费与预算 | 按 5 小时窗口估算花费（ccusage 算法）；日 / 周预算告警；New API、OpenRouter 中转站余额作为额度来源 | ccusage、Atoll | 中 / 低～中 |
| 1.6 跑完之后 | 会话完成时识别「有未推提交 / 有 PR」，提示「开 PR」「看 CI」（调 `gh`，没有就不显示） | Conductor、Claude 桌面版 | 中 / 中 |
| 1.7 更多家能作答 | 按 [agent-harnesses.md](../research/agent-harnesses.md) 逐家把「只能看」升级到「能批 / 能答」，按用户量排序 | 竞品普遍只有 3 家能答 | 高 / 中～高 |

**完成标准**：Claude Code、Codex 两家在 Windows 和 Mac 上走通「计划 → 审批 → 提问 → 完成 → 开 PR」全流程，不碰终端；回归页覆盖新卡片；出一条宣传短片（D33）。

### 阶段 2：开放接口（4 周）

**目标**：让任何程序（CI、下载、编译、脚本、AI 代理）都能把「正在进行的事」放到岛上，并接收用户在岛上的操作。抢先把浮屿的接口做成事实标准。

| 项 | 内容 | 依据 |
|---|---|---|
| 2.1 实时活动接口 v2 | 本机接口新增 `PUT /v1/activities/{id}`（标题、正文、进度 0–1、状态、图标、最多 3 个按钮）、`DELETE`、按钮回调（SSE 订阅或回调 URL）；收起条显示进度。旧 `/v1/notify` 保留不变 | Notchwork `/v1/activity`、ActivityKit、Windows `Shell.Tasks`；现在 `/v1/notify` 只能一次性弹出 |
| 2.2 命令行与插件 API | `fuyu activity start / update / end` 小命令（随安装包）；插件 `ctx.activities`；文档给 GitHub Actions、`aria2`、`cargo` 三个示例 | WinLand `winisland://notify` |
| 2.3 浮屿 MCP 服务 | 本机 MCP（stdio + HTTP）：`notify`、`activity`、`add_todo`、`append_note`、`ask_user`（岛上弹确认 / 选项，等用户答完返回）、只读剪贴板（默认关）；插件可注册自己的 MCP 工具。设置里一键写入 Claude Code、Codex、Cursor 的 MCP 配置（复用钩子安装器，卸载只删自己的） | Raycast 2.13、uTools、ZTools 2.3 |
| 2.4 任意应用通知上岛 | C57：Windows 用现有 `toast_notifications` 监听，用户勾选应用；Mac 评估 boring.notch 的辅助功能读横幅做法 | boring.notch、NotchNook |
| 2.5 契约 | 新接口、MCP 工具名、事件名写进 [contracts.md](contracts.md)；`local-api.md` 加章节 | AGENTS.md「对外契约」 |

**完成标准**：用 `curl` 和 MCP 各跑通一个「带进度 + 按钮」的活动；Claude Code 通过 MCP 让用户在岛上二选一并拿到结果；C57 在 Windows 上默认关、可勾选。

**风险**：本机接口安全。沿用现有令牌 + 「允许弹消息」分开授权；MCP 的 `ask_user` 每个调用方首次要用户在岛上点允许。

### 阶段 3：轻 AI 与统一入口（4 周）

**目标**：用已有零件（翻译的 7 家模型与本机 Ollama、划词翻译、截图 OCR、剪贴板 AI 改写、离线语音、启动器和文件搜索插件）串出两个入口，不新造模型配置。

| 项 | 内容 |
|---|---|
| 3.1 岛上快问 | 快捷键把岛展开成输入条，短对话，答案留在岛上；一键存为待办 / 笔记 / 复制。模型和密钥复用翻译设置（凭据库），**默认关**，岛上标「本地 / 云端」 |
| 3.2 划词动作条 | 现有「翻译选中文字」扩成动作条：翻译、解释、总结、改写、加为待办、搜索；插件可注册文本动作（复用剪贴板 `clipboard.actions` 接缝） |
| 3.3 截图问 AI | 截图工具栏加「问」：带 OCR 文本发给模型，或支持图片的模型直接发图 |
| 3.4 语音交给 AI | 离线语音识别的结果可直接作为快问输入 |
| 3.5 统一搜索 | 一个快捷键，一个输入框，聚合：应用（`@fuyu/launcher`）、文件（`@fuyu/file-search`，Windows 接 Everything，Mac 用 Spotlight）、插件命令、剪贴板、待办、计算与单位换算；全程支持拼音。回应 FB-27 |
| 3.6 本地模型检测 | 检测本机 Ollama / LM Studio 端点，一键选为后端；不随安装包分发模型 |

**完成标准**：三个入口（快问、划词、统一搜索）在两个平台可用，全部默认关；隐私说明写进 [privacy.md](../privacy.md)；不开任何 AI 功能时内存和 CPU 不变。

**不做**：常驻扫屏、屏幕感知、长期记忆、主动建议、会议全程录音（留到阶段 5 评估）。

### 阶段 4：生态（4 周）

**目标**：插件和内容从「官方 12 个」长到「社区 30+」，靠低门槛格式和分享，不靠钱。

| 项 | 内容 | 依据 |
|---|---|---|
| 4.1 「动作」格式 | 不写代码的配置文件：一串步骤（打开网址、运行命令、发 HTTP、文本变换、调 AI、调插件命令、写待办），出现在统一搜索、划词动作条、剪贴板 `Ctrl+K`、岛上按钮。市场里轻审核（静态检查 + 人工看一眼），比插件快 | Quicker 动作、Alfred Workflows、Raycast 脚本命令 |
| 4.2 分享与导入 | 布局、主题、动作打包成一个文件或 `fuyu://` 链接，一键导入（回应 FB-6）；主题市场同样走这条路 | 群反馈 |
| 4.3 插件市场运营 | E60 / E77 收尾；每月精选；「新手友好」任务清单（缺哪些插件、谁来写）；`npm create fuyu-plugin` 加 AI skill 生成草稿，仍走源码构建和审核 | Raycast 冷启动 |
| 4.4 官方样板 | 把高频小功能（防休眠、Wi‑Fi / 蓝牙开关、文件架转格式和压缩、汇率）做成开源官方插件当样板，而不是内置 | Atoll、NotchNook、Droppy |
| 4.5 开发者入口 | 英文文档、tauri-cordis 外发帖（[tauri-cordis-outreach.md](plugins/tauri-cordis-outreach.md)）、Discord / Telegram 频道 | |

**完成标准**：市场上第三方插件 + 动作 ≥ 30；至少 3 个来自非项目成员。

## 五、贯穿所有阶段

- **质量**：每次发版前测一次闲置 CPU 和内存，退步挡发版；回归页随新卡片同步；崩溃和前端错误日志（D112）每月看一次。
- **增长**：每个阶段出一条功能短片（D33 起）；按 [promotion-channels.md](../research/promotion-channels.md) 发帖；英文 README 同步。重点讲「Windows 也有、免费开源、能在岛上审完」。
- **可持续**：D114「支持」页（收款方式、打赏名单、签名经费收支）；Apple 账号、商店费用公开记账。不做买断、不锁功能。
- **社区**：群反馈每周用 `fuxi-fb` 过一遍，高频诉求进当期阶段。

## 六、等你定的事

| # | 问题 | 推荐 | 理由 |
|---|---|---|---|
| 1 | 要不要做通用 AI 入口（阶段 3 的快问、划词问 AI） | 做，默认关 | 零件都在，成本低；竞品和系统都在做，不做会显得缺；默认关能避开 Recall 式反感 |
| 2 | 手机伴侣先做 PWA 还是直接原生 | 先 PWA | 不需要商店审核和推送服务器；用量起来再做原生 |
| 3 | Apple 开发者账号（99 美元 / 年）现在办吗 | 12 月内办 | Mac 正式版和后面的实时活动都卡在它上面 |
| 4 | 商业化 | 全免费 + 自愿支持 | 开源免费是对 NotchNook、Vibe Island 最强的差异；授权服务器是别人差评的来源 |
| 5 | 兼容 uTools / Raycast 插件，还是只做自己的「动作」格式 | 只做自己的动作格式 | 兼容层要跟着别人的 API 变，维护成本高；动作格式更轻、更贴合岛 |

## 七、风险

| 风险 | 应对 |
|---|---|
| 系统和官方继续下沉（Windows 任务栏 Agent 转正、Claude / Codex 自带更全的通知） | 主打跨平台、跨多家、能操作；必要时把浮屿也接成系统实时活动的一个来源，而不是对着干 |
| NotchNook Windows 版口碑起来 | 阶段 1 的 Agent 深度和阶段 0 的稳定性抢在前面；宣传强调免费开源 |
| 主岛越来越挤 | 新功能先问「能不能放侧边翼 / 做成插件」；主岛页数设上限 |
