## 说明

Mac 上汽水音乐放歌时，`media.nowPlaying` 多半是 `{playing:true, title:null, sourceApp:"汽水音乐"}`。原因在 `src-tauri/src/media_control/service_macos.rs` 的 `get_state`：系统媒体接口（adapter）报的不是 playing 时直接返回「正在出声的进程」兜底 `from_audio_process()`，兜底从窗口标题解析不出歌名，adapter 读到的歌名、歌手、封面被丢掉。

要做：兜底找到的播放器和 adapter 快照是同一个应用时合并——曲目信息（歌名、歌手、专辑、封面、时长、随机 / 循环、能否跳过、`source_app`、`sessions`）用 adapter 的，`playing` / `playback_status` / `audio_active` / `audio_peak` 用兜底的，进度按 playing=true 用 `timeline_clock::sample` 重算。不是同一应用、或 adapter 没歌名时照旧返回兜底。

同一应用按顺序判断，任一条成立即可：

1. adapter 快照的 `processIdentifier` 经 `apps::responsible_pid` 等于兜底找到的 pid；
2. `apps::path_for_bundle_id(adapter 的 bundle id)` 的 `outer_app_name` 和兜底的 `apps::display_name(pid)` 对上；
3. 两边 `friendly_app_label` 相同。

判断和合并写成不碰系统接口的纯函数。只改 `service_macos.rs`（测试超 150 行放 `service_macos_tests.rs`），不碰 E72 在改的 `events_macos.rs`、`plugin_kernel/mod.rs`。

不做：`friendly_app_label("com.soda.music")` 认不出（`players.rs`，Windows 共用），等用户定。

## 验收

- 单元测试：同一应用（pid / bundle 路径 / 标签三种）合并后有歌名、playing=true；不同应用返回兜底；adapter 没歌名返回兜底；adapter 本来在播不走兜底
- Rust 单元测试、clippy（本机 + `x86_64-pc-windows-gnu`）、`pnpm build:exe`、`pnpm mq:try` 的 Windows CI 链接
- 用户 Mac 真机：汽水音乐放歌时岛和 `nowPlaying()` 有歌名、在播；换歌岛跟着变（E72 合入后换歌提示会弹）；暂停显示暂停；Apple Music 暂停、汽水音乐在放时显示汽水音乐
