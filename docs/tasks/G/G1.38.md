## 说明

见 issue #1080。Mac 上 ⌘⇧V 打开剪贴板窗口、选中一条后，内容没有粘到原来的应用里。

粘贴链路：`clipboard_history/popup_macos.rs` 的 `toggle` 打开时记下前台应用 pid → `paste` 写剪贴板、收起窗口 → `paste_into` 在 `macos/input.rs` 的 `can_post_keys()`（`CGPreflightPostEventAccess`）通过时激活原应用、等 120ms、用 CGEvent 发 ⌘V。下面任一处不满足都只复制不粘贴，而且没有日志、没有提示：

1. 没有发按键权限：只弹一次系统授权就返回。开发版 `target/debug/fuyu`（`com.tixxin.fuyu.dev`）和正式版 `com.tixxin.fuyu` 各要一份「辅助功能」授权；从终端启动时权限可能算到终端头上。
2. 没记下目标应用：打开窗口时前台是浮屿自己就记成空，`will_send_keys` 直接跳过。
3. 收起或激活失败：`a45e340f8`（2026-11-17）把 `paste_clipboard_history_item` 等命令挪到 `spawn_blocking` 后台线程，`hide`（NSPanel 收起）和 `apps::activate` 从此不在主线程上调用；`hide` 出错会在发 ⌘V 前返回，`activate` 返回假时静默不发键。这次改动之后 Mac 上没有实测过粘贴。

做法：先在粘贴链路每一步补失败原因的记录，没权限时在岛上提示去「隐私与安全性 → 辅助功能」，不再静默只复制；在 Mac 真机上用开发版和 `pnpm build:exe` 的正式身份分别复现，按记录定位再修。是第 3 条的话，收起面板、激活应用这类 AppKit 调用放回主线程（`run_on_main_thread`），重活留在后台线程。

## 验收

- Mac 上 ⌘⇧V 选中文字、图片、文件，都能粘到备忘录、浏览器输入框和终端里；顺序粘贴、「固定」开着时也能粘。
- 没有辅助功能授权时有明确提示，授权后不用重启就能粘。
- Windows 上的粘贴行为不变。
