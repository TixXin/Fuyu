## 说明

G1.8 让插件能在 Mac 上跑起来。下面几处和 Windows 还不一样。

1. **不统计 CPU。** [macos/job.rs](/src-tauri/src/macos/job.rs) 的 `usage()` 固定返回 `cpu_ticks: 0`。插件卡片上 CPU 一直是 0，「连续 1 分钟超过 25%」的提醒永远不会出现。按进程组把各进程的 CPU 时间加起来（`proc_pidinfo` 的 `PROC_PIDTASKINFO` 有用户态和内核态时间），换算成和 Windows 一致的 100 纳秒单位。Apple 芯片上这两个值的单位是 mach 时间而不是纳秒，要用 `mach_timebase_info` 换算，实现时在真机上核对。
2. **内存上限把运行时也算进去。** [baseline.rs](/src-tauri/src/plugin_host/baseline.rs) 的 `runtime_for` 只认 `powershell.exe` 和 `node.exe`。Mac 上进程名是 `pwsh` 和 `node`，量不到运行时空闲时的大小，卡片上显示的、和 512 MB 上限比较的都是整个进程组。让它认 Mac 上的名字，`idle_command` 在 Mac 上用 `pwsh` 和找到的 `node`。
3. **版本管理器装的 Node 找不到。** [manifest.rs](/src-tauri/src/plugin_host/manifest.rs) 的 `find_unix_program` 只找 PATH、`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin`。从访达或程序坞启动的应用拿不到终端的 PATH，用 nvm、fnm、volta、asdf、mise 装的 Node 就找不到。卡片会提示去装 Node.js，而用户其实装了。可以在启动时用登录 shell 取一次 PATH（要设超时），或者再查这些工具的默认目录；另外在插件扩展里留一个「Node.js 路径」的设置兜底。
4. **报错文案。** [storage.rs](/src-tauri/src/plugin_host/storage.rs) 里 `secrets.*` 的错误写死了 "Windows Credential Manager"，Mac 上存的是钥匙串。

## 验收

- Mac 上跑一个忙循环的插件，卡片上的 CPU 接近一个核的占比，1 分钟后出现高占用提醒；空闲的插件接近 0。
- Mac 上 Node 插件卡片显示的内存是减去运行时之后的数；`baseline` 的测试覆盖 Mac 的进程名。
- 只用 nvm 装了 Node、从访达启动浮屿，Node 插件能启动。
- Mac 上 `secrets.set` 失败时的文案不提 Windows。
- Mac 上 `cargo clippy --all-targets -- -D warnings`、`cargo test` 通过；Windows 的交叉 clippy 通过。
