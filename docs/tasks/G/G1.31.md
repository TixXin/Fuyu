## 说明

见 issue #632。不激活的 NSPanel 不是 key window 时 WKWebView 多半收不到鼠标移动；修好后悬停展开的面板里 hover 样式直接生效，点面板里的东西不会把面板收起，也不抢前台焦点。

## 提交

- `fix(macos): hovering the island shows hover styles without taking the keyboard from the front app (G1.31)`

## 备注

- 原因：「悬停时拿键盘」默认关，Mac 上悬停时岛不是 key window，WKWebView 不处理鼠标移动，`:hover` 不生效；点一下让岛真成为 key 后才有。
- 原型（非激活 NSPanel + WKWebView，别的应用在前台）：activeAlways 的 NSTrackingArea 转发鼠标移动没用，WebKit 自己丢掉；只覆写 `isKeyWindow` 也不够，WebKit 的「窗口活跃」状态是缓存的，要再发一次 NSWindowDidBecomeKeyNotification 刷新；两者都做了才有 hover，前台应用和键盘不变。
- 选了计划里的 ①（不靠真 key），没选「悬停真拿 key」：后者会拿走别的应用的键盘，正是 #631 的另一半。
- 做法：`macos/island_panel.rs` 把岛面板的类换成子类 `FuyuHoveredIslandPanel`（只有类不对或大小不同时放弃并打一行日志），悬停时 `isKeyWindow` 报 true，开始悬停且不是真 key 时补发 didBecomeKey；结束时不发 resign，否则 tao 发 Focused(false)，前端会当成失焦把面板收起。tao 的 `is_focused` 因此在悬停时为 true，`useCollapseOnBlur` 在鼠标还在岛上时不收起，正合适；`take/release_island_hover_focus` 改用真 key 判断（`fuyuHasRealKey`），「悬停时拿键盘」开着时照旧真拿。监听在 `focus_macos.rs` 启动显示时装一次，没改 `lib.rs`（有别的会话没提交的改动）和前端。
- 开发版实测（代理用 CGEvent 移动鼠标、截图对比）：悬停展开后停在齿轮按钮上按钮变亮、移开恢复；全程前台应用（微信）不变；悬停展开后点面板，面板不收起，移开按悬停展开的延迟收起。
