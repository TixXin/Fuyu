## 说明

见 issue #725。刘海形态本身没问题：岛画在刘海下面，是因为存的形态是「贴顶」，按 C65 的设计，有真刘海的屏上贴顶会让到菜单栏下面。新装的 Mac 默认就是贴顶；开发版在 C65 和 G1.29 之间第一次保存，也存成了 top。

用户 2026-11-16 定：形态加一项「自动」，作为 Mac 的默认。岛所在的屏有真刘海（含开发用的模拟刘海 `dev_notch`）就用刘海，没有就贴顶。

1. 设置数据（`src/lib/settings/`）：`IslandForm` 加 `"auto"`，Mac 默认 auto、Windows 照旧 top。Mac 上存的设置里没有形态的迁成 auto（取代 G1.29 查主屏刘海的做法），已经存了形态的不动；Windows 不变。
2. Rust（`island/notch.rs`、`state.rs`、`mod.rs`、`geometry.rs`）：auto 时按岛所在的屏决定，有刘海和 fit_notch 一样，没有就按贴顶算（菜单栏设置照旧）；岛换屏、刘海变化时重新判断；把实际生效的形态（notch / top）用新事件告诉前端，写进 contracts.md。「按屏决定形态」写成纯函数并测试。
3. 岛前端：`islandFormLayout`、`data-island-form`、`marginY` 按实际生效的形态算。
4. 设置界面：加「自动」，只在 Mac 上显示，说明「有刘海的屏幕用刘海，其他屏幕贴顶」，中英文。
5. 文档：`docs/design/macos.md`「刘海」、`docs/design/island.md`「岛的形态」、`platforms.md` 岛那一行、`contracts.md`；真机验收项写进 `macos-port-plan.md`「待人工验收」的 G1.3 组。

## 验收

- 新装的 Mac 和没存形态的老设置是「自动」；存了贴顶、药丸、刘海的不变；Windows 默认贴顶、看不到「自动」。
- 自动：有刘海的屏上和刘海连成一块，外接屏上贴顶，拖过去拖回来跟着变。
- 迁移和按屏决定形态有单元测试。

## 备注

- 等的是用户在真机上验收，清单在 [macos-port-plan.md](/docs/architecture/macos-port-plan.md)「待人工验收」G1.3 组的「自动形态（G1.33 #725）」：MacBook 屏上自动 = 刘海；拖到外接屏变贴顶、拖回来变刘海；贴顶、药丸、刘海不变；Windows 看不到「自动」。
- 选了「放在菜单栏下面」而没存形态的老设置读成贴顶，不读成自动：自动在刘海屏上会压到菜单栏上，违背用户原来的选择（Agent 推断）。
- G1.29 的命令 `primary_screen_has_notch` 删掉了：老设置直接读成自动，不再需要查主屏。
- 自动形态下前端先按贴顶传布局（`autoForm: true`），Rust 每次摆岛时按所在屏换成刘海（`fitNotch` 真、`underMenuBar` 假、`marginY` 0），所以换屏、插拔外接屏、合盖都跟着屏幕监视和跟随的重摆走，不用前端来回传。
