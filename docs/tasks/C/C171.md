## 说明

C161（#1163）的「外设电量」组件在 Windows 和 macOS 上都读不到任何设备。前端（`src/features/peripheral-battery/`）的读取、订阅和空状态都没问题，问题在后端 `src-tauri/src/device_events/` 的读法覆盖太窄。排查和开源工具（BlueGauge、BleBatterySubscribe、AirBattery、BatteryBoi）的做法见 [调研](/docs/research/peripheral-battery.md) 的「2026-11-22」一节。

### 分工（三个子任务并行，改的文件不重叠）

| 子任务 | 平台 | 独占的文件 |
|---|---|---|
| C171.1 | Windows | `src-tauri/src/win32/ble_battery.rs`、`win32/devnode.rs`、`device_events/readers.rs`、`device_events/mod.rs`、`device_events/batteries.rs` |
| C171.2 | macOS，不要权限 | 新文件 `src-tauri/src/macos/hid_battery.rs`、`macos/bluetooth.rs`、`device_events/readers_macos.rs` |
| C171.3 | macOS，要蓝牙权限 | 新文件 `src-tauri/src/macos/bluetooth_access.rs`（名字可调）、`src-tauri/Info.plist`、`src/features/peripheral-battery/`、`src/i18n/sections/islandWidgets.ts`；最后接入 `readers_macos.rs` 时要等 C171.2 提交 |

大家都改的热点文件（`platforms.md`、`contracts.md`、`Cargo.toml`、`lib.rs`、`macos/mod.rs`）改完就单独提交，用 `pnpm mq:commit-part` 只带自己的改动。

### 共同约定

- 列表格式不变：`PeripheralBattery { id, name, kind, battery }`，`kind` 仍是 headphones / headset / speaker / mouse / keyboard / trackpad，前端不用跟着改（C171.3 的按钮除外）。
- 外设的 `id` 用 12 位大写十六进制蓝牙地址（`macos/bluetooth.rs` 的 `address_key` 的格式），这样同一台设备从不同读法来时能按地址去重，`PeripheralTracker` 的提醒也不会因为换了读法而重复弹。
- 同一台设备几条读法都有电量时：系统自己的数字优先（Windows 的设备节点属性、macOS 的 `system_profiler` / IOKit），GATT / CoreBluetooth 只补缺。
- 读不到、出错一律当作没有，不报错、不弹框；不往岛上加新的提醒类型。
- 每条读法都要能在只读的探测测试（`#[ignore]`，真机上手动跑）里单独打印结果，方便用户在自己的机器上贴输出。
- 解析和合并写成纯函数配单元测试；平台调用薄薄一层。

### 用户的决定（2026-11-22）

- 三块都做，包括 macOS 上要蓝牙权限的两条读法。
- 权限交互由 C171.3 实现：不在启动时弹框，用户在组件里点「读取第三方蓝牙设备」才申请。

- `platforms.md` 的「设备插拔、电源」一行写清两个平台各用哪几条读法、哪条要权限
