## 说明

任务 [C102](/docs/tasks/0-archive/C/C102.md)（[#642](https://github.com/TixXin/fuyu/issues/642)，方案见 [im-message-sources.md](/docs/research/im-message-sources.md)，功能说明见 [im-sources.md](/docs/features/im-sources.md)）已完成共享监听底座（[C102.1](/docs/tasks/0-archive/C/C102.1.md)）、7 款客户端原生接入与三级应用唤起（[C102.2](/docs/tasks/0-archive/C/C102.2.md)）以及品牌图标、通用面板与设置页接入（[C102.3](/docs/tasks/0-archive/C/C102.3.md)），并通过双端单元测试、回归页及 CI 检查。

由于自动化环境无登录态桌面聊天客户端会话，需在安装了真实软件并登录账号的 Windows 11 与 macOS 真机上逐项实测确认。

## 验收

- Windows 11：运行 `cargo run --manifest-path src-tauri/Cargo.toml --example im_notification_probe -- --watch-seconds 30` 核对本机已安装客户端的真实 `AppUserModelId` 与任务栏闪烁事件命中情况
- Windows 11：「设置 → 消息 → 即时通讯」中已安装应用排在未安装应用前面并带「已安装」标识，默认均为关闭；开启后展开「看过后从岛上去掉」与自绘弹窗说明
- Windows 11：真实收消息时，发系统 Toast 的客户端（及开启「Use Windows notifications」后的 Telegram）正常展示品牌图标 + 发送人 + 消息摘要；仅自绘弹窗闪任务栏的客户端兜底展示「有新提醒」，且 2 秒内伴随系统 Toast 到达时原位合并升级、不重复计数
- Windows 11：点击收起条预览、横幅或消息面板条目能唤起对应已登录客户端窗口（不双开新登录框）；切到客户端前台时按设置自动清除岛上此前提醒；同时开启 5 个以上来源时 350px 窄面板顶部来源栏横向滚动无溢出
- macOS：「设置 → 消息 → 即时通讯」在未装 `com.tencent.tim` 时不展示 TIM，已安装应用排在前面；授予辅助功能权限后程序坞角标上升触发提醒并同步未读数，点击 `open -b` 唤起对应应用，切入前台或角标清零后自动清除
