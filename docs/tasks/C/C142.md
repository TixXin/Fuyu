## 说明

用户 2026-11-19 提：其他软件和开发者要能调岛屿的功能，比如弹一条消息。脚本跑完、CI 挂了、下载好了、智能家居的事件，都能用一行 `curl` 在岛上说一声。

现状：[本机接口](/docs/features/local-api.md)开放了待办、每日笔记、AI Agent 状态灯和只读的剪贴板历史，没有弹消息。正式版里唯一能让岛弹东西的路由是开发版专用的 `/v1/dev/island/emit`。插件那边已经有 `messages/v1` 的 `notify`（`packages/plugin-services/src/services/messages.d.mts`）。

做法（用户同意了方向，下面的数字和默认值是 Agent 推断，做的时候拿不准的问用户）：

- **路由**：`POST /v1/notify`，请求体 `{ "source": "ci", "title": "...", "body"?: "...", "name"?: "CI", "durationMs"?: 5000 }`，回 `{ shown, receivedAt }`。`source` 的规则和 `/v1/agent-status/{source}` 一样（1–32 个小写字母、数字或 `-`），在岛上的来源 id 是 `local-api/<source>`；`name` 是显示名，省略时沿用上次的，第一次默认用 `source`。
- **走现有的消息通道**：和插件的 `messages/v1` `notify` 同一条路，照常进消息页，显示来源名。不另写一套弹出。
- **只收纯文本**：标题最长 120 个字，正文最长 500 个字，超了回 400。第一版不带按钮，不收图标地址（不让岛去拉外面的图片）。
- **开关**：设置的本机接口页（C141）加「允许弹消息」，独立于「允许修改」，默认关；关着时回 403。`/v1/health` 多回一个 `allowNotify`。
- **防滥用**：每个来源每分钟最多 10 条，超了回 429；最多 16 个来源。免打扰、游戏模式、全屏时和别的消息一样处理。设置页列出弹过消息的来源，能按来源静音；静音的来源照常回 200，`shown` 是 `false`。
- **对应功能关着时**：照 `src-tauri/src/local_api/switches.rs` 现有的做法回 503。消息没有总开关，做的时候核实该看哪个开关。
- 同一批改：[local-api.md](/docs/features/local-api.md) 的路由表和示例、`docs/architecture/contracts.md`（新路由、`local-api.json` 或设置里新增的字段）、`docs/architecture/platforms.md`（Windows 和 Mac 都支持）、C141 那页上的示例换成弹消息。

这次不做，以后另建任务：按钮和点击回调、命令行里的 `notify`、MCP 的 `notify` 工具（并进 E59）、把计时器和媒体控制这些服务也开放出来、事件流。

预计改动：`src-tauri/src/local_api/`（`routes.rs`、`switches.rs`、`config.rs`、`settings.rs`、`tests.rs`，限频另开一个文件）、`src/features/local-api/`、`src/features/island-bridge/`、`src/i18n/sections/settings/localApi.ts`、`tests/regression/settings.tsx`。

## 验收

- 开着「允许弹消息」时，一条 `curl` 让岛弹出消息；消息页里有这条，显示来源名
- 开关关着回 403，没带令牌回 401，同一来源一分钟内第 11 条回 429，标题或正文超长回 400
- 在设置页把某个来源静音后，它再发的消息不弹，接口回 `shown: false`
- 免打扰、游戏模式下的表现和别的消息一致
- 路由校验和限频有 Rust 单元测试
- `local-api.md`、`contracts.md`、`platforms.md` 已更新
- `pnpm check`、`cargo test --manifest-path src-tauri/Cargo.toml`、`pnpm build:exe` 通过；在真岛上用 `curl` 弹过一次
