## 说明

计划第 2 批。插件 `cc-connect`；第 2 版 `focusd.cc-connect` 的启用状态和设置迁过来；插件详情页里的设置改成 `settings.section/v1`；和 Agent 推送之间改走服务。只有 Windows，Mac 上写实测清单。

计划见 [v3-phase3-plan.md](/docs/architecture/plugins/v3-phase3-plan.md)。

## 验收

- 按计划「每个功能任务都按这个标准算做完」的 8 条：插件清单里有它、通用的三层「关掉」检查都过；插槽项都在 `src/features/<领域>/plugin/`、拥有者是它的 id；后台登记进开关表、关掉就真停；旧开关迁进 `plugins.yml` 并兼容旧值；不 import 别的功能；回归页快照不变或写明为什么变；插件页能开关；两个系统的待人工验收列好
- 新的插件 id 不带 `focusd`（`focusd.cc-connect` 改成和 `timer` 一样的短名）；前端常量（`src/features/` 里用到它的地方、`useCollapsedGauges.tsx`、`CollapsedItemsSection.tsx`、`PluginDetailPage.tsx`）和 `src/AGENTS.md`、`src-tauri/AGENTS.md` 里提到这个 id 的地方一起换掉。`v2_builtins.rs` 里从旧 id 迁设置的映射留到 E36.6（D81 的 C 类，见 [old-names-cleanup.md](/docs/investigations/old-names-cleanup.md)）
- Agent 推送和 cc-connect 之间的双向引用由本任务拆（2026-11-16 组长定，原写在 E36.3.37）：cc-connect 提供服务（发推送、列推送目标），`agent-status/push` 改调服务；`cc-connect/useRemoteCcConnect` 改调 `agents/v1` 的 `remoteHosts`（E36.3.37 提供）。白名单里这 6 条（`agent-status/push/*` → `cc-connect` 4 条、`push/useAgentPush` → `plugins/useBuiltinPlugin`、`cc-connect/useRemoteCcConnect` → `agent-status/api`）清零
