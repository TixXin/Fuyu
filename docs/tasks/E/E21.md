## 说明

[updates.rs](/src-tauri/src/plugin_host/updates.rs) 的 `check()` 在一个循环里依次下载并安装可以自动更新的插件，`fetch_package` 和 `install_entry` 后面都用 `?`。其中一个失败，整个 `check()` 就返回，排在后面的不再处理。

待更新的列表按插件 id 排序，顺序是固定的。所以一个一直装不上的包（下载地址 404、哈希不对、文件被占用）会在每次检查时挡住排在它后面的所有插件，直到用户手动更新。

改成每个插件单独处理：失败的记下原因、继续下一个，全部处理完再汇总。失败原因现在只进 `eprintln!`，最好能在那个插件的卡片上看到。

## 验收

- 把逐个安装的循环抽成能单测的函数，测试覆盖：两个待自动更新的插件，第一个失败时第二个照常安装。
- 失败的插件不会被标成「已更新到 x.y.z」，下一次检查会再试。
- `cargo test --manifest-path src-tauri/Cargo.toml`、`pnpm build:exe` 通过。
