## 说明

现在插件的界面只能放在岛屿自己的窗口里：展开后的页面（每个插件最多 2 个）、收起条状态项、岛上提示、右键菜单和设置项。插件没有办法让岛屿替它开一个独立窗口，所以启动台、桌面小组件这类插件做不出来。

自定义网页（`webview` 模板）不是独立窗口：它是叠在岛屿窗口里一个占位框上的 WebView2 页面，大小跟着岛屿的面板走，切页或收起时就销毁，而且只在 Windows 上有（Mac 见 G1.15）。

`.exe` 插件可以自己用系统接口建窗口，但那个窗口和岛屿没有关系：岛屿不管它的位置、置顶和主题，它拿不到岛屿的外观变量，PowerShell 和 Node 插件也基本做不了。

用户 2026-11-13 决定往这个方向走，先调研。要回答的问题：

1. **窗口由谁建。** 岛屿建并管理（位置记忆、随插件停用关闭、跟随主题），还是只给插件一个约定、让它自己建。倾向前者，说明理由和代价。
2. **页面怎么隔离。** Windows 上已有的独立 WebView2 页面（[webviews.rs](/src-tauri/src/plugin_host/webviews.rs)、[webview_page.rs](/src-tauri/src/win32/webview_page.rs)）在原生层拦截请求和跳转、只能和自己的插件进程通信、不能联网。确认这一套换一个宿主窗口后还成立，列出要改的地方。
3. **窗口的种类。** 至少分开看两种：快捷键唤起、失焦就收的浮层（启动台）；常驻、贴在桌面层的小组件。各自需要哪些窗口属性（置顶或贴桌面、是否抢焦点、是否进任务栏、透明和圆角、多显示器、开机恢复位置），哪些由清单声明，哪些归用户设。
4. **清单和协议。** 新贡献点怎么写（例如 `contributes.windows`），插件怎么打开、关闭、移动窗口，窗口和插件进程之间沿用 `webview.postMessage` 还是另起一组方法；数量和尺寸的上限。
5. **权限和告知。** 能在屏幕上任意位置画东西比在岛上放一页敏感得多（可以仿冒系统对话框）。需要什么新权限、是否算敏感权限、窗口上要不要有来自哪个插件的标识、市场审核要看什么。
6. **Mac。** 依赖 G1.15 的结论：没有 Mac 的网页页面，这又是一个只有 Windows 能用的能力。说明 Mac 上的做法或明确先只做 Windows。
7. **不用独立窗口能做到哪一步。** 启动台的简版可以用现有的列表模板加命令快捷键做在岛上，写清楚它和独立窗口版的差别，作为对照。
8. **别的产品怎么做。** 看 Raycast、uTools、Rainmeter、Übersicht、Stream Deck 等让插件拥有窗口或桌面组件的做法，尤其是隔离和权限。

按 E30 的结论决定它是否先进实验通道；E30 还没定时，方案里按「先进实验通道」写。
