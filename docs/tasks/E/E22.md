## 说明

[store.rs](/src-tauri/src/plugin_host/store.rs) 的 `load_state` 在文件读不到或解析失败时一律返回默认值，不区分这两种情况。

文件存在但内容坏了（手动改错、磁盘问题）时，结果是：「允许运行第三方插件」被关掉，每个插件的启用状态、授权、设置、敏感权限的回答、记下的作者密钥，以及信任的发布者、离线也生效的下架名单全部丢失。下一次保存还会把坏文件覆盖掉，用户得不到任何提示。

要做的：

- 区分「文件不存在」（第一次启动，正常）和「存在但解析失败」。后者先把原文件另存为 `plugins.broken-<时间>.json`，再用默认值启动。
- 在设置 → 插件扩展里显示一行说明：插件设置读取失败，原文件备份在哪里。
- `save_state` 自己写临时文件再改名。换成 [fs_write.rs](/src-tauri/src/fs_write.rs)，文件被别的程序暂时占用时它会重试。

## 验收

- 单元测试：内容不是合法 JSON 的 `plugins.json` 被另存，原内容还在；文件不存在时不产生备份。
- 插件扩展页能看到那行说明，中英文都有。
- `cargo test --manifest-path src-tauri/Cargo.toml`、`pnpm build:exe`；改了设置页再跑 `pnpm check`、`pnpm build`、`pnpm test:regression`。
