## 说明

2026-11-13 市场上的 8 个插件（6 个官方、2 个第三方）运行时全是 PowerShell。Mac 上要先装 PowerShell 7 才能跑其中任何一个，带自定义网页的还显示不出页面（G1.15、G1.16）。

Node 写的插件两个系统都能跑，脚手架也有 Node 模板，但市场上一个示范都没有。浮屿的用户多数在用 Claude Code、Codex 这类工具，电脑上大多已经有 Node.js。

2026-11-04 定官方示例用 PowerShell，是因为 Windows 自带、用户不用装东西（[v1-design.md](/docs/architecture/plugins/v1-design.md) 第 13 节第 5 条）。Mac 版发布后，这个前提只对 Windows 成立。

要做的：用 `fuyu-plugin` 的 Node SDK 写两到三个官方插件。可以重写现有示例里不依赖 Windows 接口的（待办摘要、番茄钟、GitHub 待办 issue 都只用岛屿接口和网络），也可以写新的。重写的用新 id，旧的 PowerShell 版保留给没装 Node 的 Windows 用户，名字上要能区分。清单写 `"platforms": ["windows", "macos"]`，界面用岛屿的模板（list、status），不用自定义网页。

## 验收

- 两到三个 Node 插件在 Windows 和 Mac 的真岛上各跑通一次，Mac 上不装 PowerShell。
- 每个都有模拟宿主的测试，随 `pnpm test` 跑。
- 上架后，市场里能看出它们需要 Node.js；没装 Node 的电脑上卡片给出安装提示。

## 备注

- Mac 上用 nvm 这类工具装的 Node 现在找不到（G1.17 第 3 条），这些插件在 Mac 上好不好用取决于它。
- Mac 上现在没有免安装的插件运行方式：`.exe` 不能跑，`.ps1` 要 PowerShell 7，`.js` 要 Node.js。要支持 Mac 的原生程序，清单得能按平台写不同的命令，解压时还要保留可执行位，这两样现在都没有。要不要做另行决定。
- `pnpm plugins:index` 要用的签名私钥在 Windows 那台机器上。
