## 说明

**第 3 版默认打开之前必须完成**（[进度](/docs/architecture/plugins/v3-progress.md)「当前状态」里记着）。issue #550 写了全文。

E36.3.18 定了规则：宿主这条路上的 `translator/v1` 不收调用方给的地址，因为 Rust 会带上用户给自定义引擎存的密钥去请求。所以自定义引擎在这条路上报 `translation.customUnavailable`（`src-tauri/src/translation/mod.rs` 的 `host_provider`）。自定义地址现在只存在前端 `fuyu-translation-settings` 的 `customBaseUrl` 里，Rust 不知道它。

要做的：

1. 用户在设置里保存自定义地址时，由窗口交给 Rust 存下（系统凭据或数据目录里的文件，由做的人定），Rust 自己读，不从插件或服务调用方收。旧版本已经填过的地址要迁过来，用户不用重填。
2. `translator.translate` / `translator.rewrite` 的宿主入口在自定义引擎时用 Rust 存的地址；没设地址时报一个新的、清楚的错误。
3. 宿主入口照旧不收地址参数。
4. 文档：`v3-services.md` 去掉「自定义引擎暂不开放」，`v3-secrets.md` 记地址存在哪，`data-storage.md`、`contracts.md` 记新位置、新命令（热点文件，各自单独提交）。

## 验收

- 在设置里填了自定义地址和密钥后，经 `translator/v1` 翻译能用上，地址改了马上生效
- Rust 测试：宿主入口传不进地址；没设地址时报新的错误码，错误里没有密钥
- 已经在 localStorage 里填过地址的用户，升级后不用重填
- v3-progress「当前状态」里这条改成已完成
