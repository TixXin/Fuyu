## 说明

设置 → 插件页，来源是「本地开发」（`plugins.yml` 里 `source: dev`）的插件，在 ⋯ 菜单和详情弹窗里加「从浮屿移除」（英文 Remove from Fuyu）：

- 只从 `plugins.yml` 删掉这条 dev 登记，**不碰开发文件夹**（`path` 指向的目录和构建产物都不动）。
- 「同时删除本插件的数据目录」勾选框沿用卸载时的那个。
- 确认框写明不会删除插件文件夹，再次运行 `fuyu-plugin dev` 会重新出现。中英都有。
- 「重启」和启用开关的行为不变（仍只对 market / manual 显示）；`source: file` 不在这次范围内。

### 现状（2026-11-19 核对）

- 前端：`src/windows/settings/pluginEntries.ts` 的 `managed` 只认 market / manual；`InstalledPluginRow.tsx`（⋯ 菜单的卸载、重启、启用开关）和 `PluginDetailModal.tsx`（重启、卸载按钮）都看 `entry.managed`。弹窗调 `marketClient.uninstall({ id, removeData })`。
- 宿主：`src/features/updater/host/market.mjs` 的 `uninstall` 调 `packages/plugin-cli/src/installer.mjs` 的 `uninstallPackage`，不看来源：删 `packages/@scope/name`、删 `plugins.yml` 条目、可选删 `data/@scope/name`。
- CLI `--clean`：`packages/plugin-cli/src/dev.mjs` 的 `unregisterDevEntry`，逻辑和 `installer.mjs` 的 `removeInstalledFromYml` 完全一样（两份拷贝）。
- 插件数据目录：宿主用 `packages/plugin-base/src/host/data.mjs` 的 `dataDirOf(join(dir, "data"), id)`，dev 插件也在 `data/<id>`。
- Rust 读写 `plugins.yml` 时没有针对 `source: dev` 的校验，Rust 不用改。

### 直接拿现有 uninstall 处理 dev 的两个坑

1. **误删市场包**：同一个 id 从市场装过、又在用 `fuyu-plugin dev` 开发时，`packages/@scope/name` 还在，现在的 uninstall 会把它删掉。dev 来源不能碰 `packages/`。
2. **非 scoped id 报错**：`hello` 这类 id 在 `installer.mjs` 的 `packageDirFor` 里抛 `bad-name`，勾删数据就失败。dev 来源删数据用 `dataDirOf`。

### 做法

1. `dev.mjs` 的 `unregisterDevEntry` 改成调用 `installer.mjs` 的 `removeInstalledFromYml`，删掉重复的 `stripPluginBlock`；`--clean` 行为不变。
2. 宿主 `uninstall` 按来源分支：用 `readYmlEntries` 读出原始 `source`（现在它只区分 manual / market，要能保留 `dev`）；dev 只删登记，`removeData` 时用 `dataDirOf` 删 `data/<id>`；其余照旧走 `uninstallPackage`。`market.mjs` 现 369 行（上限 400），放不下就在 `installer.mjs` 加一个函数。`market/v1` 的方法名和参数不变，`packages/plugin-services` 不改。
3. 前端：`InstalledEntry` 加 `removable`（market / manual / `plugin.source === "dev"`），⋯ 菜单和详情弹窗的移除入口看 `removable`，`managed` 不动；dev 插件用「从浮屿移除」一组文案，加在 `src/i18n/sections/settings/` 对应文件。
4. 测试：单元测试覆盖 dev 条目移除后登记没了、开发文件夹还在、同 id 市场包还在、勾 removeData 删掉 `data/hello`、不勾保留；`packages/plugin-cli/test` 覆盖 `dev --clean` 仍只删这一条；`pluginEntries` 的 dev → removable 但不 managed。回归页 mock 加一个 `source: "dev"` 的 `hello`，中英快照按需更新。

### 认领范围

`--scope src/windows/settings/pluginEntries.ts,src/windows/settings/InstalledPluginRow.tsx,src/windows/settings/PluginDetailModal.tsx,src/i18n/sections/settings/,src/features/updater/host/market.mjs,src/features/updater/host/marketStore.mjs,packages/plugin-cli/src/dev.mjs,packages/plugin-cli/src/installer.mjs,packages/plugin-cli/test/,tests/unit/,tests/regression/plugin-page.tsx,tests/regression/pluginPageMocks.ts`（快照目录按实际补上）。

## 验收

- dev 插件的 ⋯ 菜单和详情弹窗都有「从浮屿移除」；确认后这条从 `plugins.yml` 消失、列表里不再出现，开发文件夹原封不动。
- 勾「删除数据目录」删 `data/<id>`，不勾不删；非 scoped id 也能删。
- 同 id 的市场包不被误删；market / manual 的卸载、重启、启用开关行为不变。
- `fuyu-plugin dev --clean` 行为不变，和宿主共用一份删条目逻辑。
- 验证：`pnpm check`、`pnpm build`、`pnpm test:regression plugin-page`（含英文页）、`pnpm build:exe`。不改 Rust，不跑 `cargo test`。
- 用户手动验收：拿 `fuyu-plugin dev --once` 留下的 `hello` 点一次「从浮屿移除」。

## 备注

用户 2026-11-19 同意组长的计划，三个待定问题都按建议：开发进程还在跑时点移除不额外处理（dev 只在启动时登记一次，移除后下次运行 `fuyu-plugin dev` 才回来），只在确认框里说明；`source: file` 这次不做；dev 插件这次不加启用开关。
