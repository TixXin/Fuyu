## 说明

[方案](/docs/architecture/plugins/v3-everything-plugin.md)「分阶段」的第 0 阶段，预计 1 周。在仓库之外的临时项目（一个最小的 Tauri 应用）里，在 Windows 和 macOS 上实测方案的几项关键假设。前 3 项决定架构能不能成立。

要做的：

- Node 和 Bun 各当一次宿主：Cordis 的内核、加载器、热重载能不能跑；空载和加载后的内存、启动时间、安装包增量
- 附带程序在 Mac 上的签名、公证和即时编译授权，Windows 上的打包
- 窗口到宿主的本机 WebSocket 在 WebView2 和 WKWebView 上通不通；不通时 `invoke` 长轮询的并发表现
- 自定义协议上的 `import()` 和共用 React 的转接模块
- 宿主崩溃、卡死后的重启和窗口重连
- 睡眠唤醒、所有窗口隐藏时宿主的定时器
- 对照：隐藏 WebView 当宿主时的内存
- 花一天做 rutis 的小样，看它「标记即服务」和进程恢复是怎么做的

开工前读 [进度](/docs/architecture/plugins/v3-progress.md) 和 [流程](/docs/architecture/plugins/v3-workflow.md)；开工时把上面拆成步骤写进下面的验收，做完一步勾一步。
