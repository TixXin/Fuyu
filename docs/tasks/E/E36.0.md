## 说明

[方案](/docs/architecture/plugins/v3-everything-plugin.md)「分阶段」的第 0 阶段，预计 1 周。在仓库之外的临时项目（一个最小的 Tauri 应用）里，在 Windows 和 macOS 上实测方案的几项关键假设。前 3 项决定架构能不能成立。

要做的：

- Node 和 Bun 各当一次宿主：Cordis 的内核、加载器、热重载能不能跑；空载和加载后的内存、启动时间、安装包增量
- 附带程序在 Mac 上的签名、公证和即时编译授权，Windows 上的打包
- 窗口到宿主的本机 WebSocket 在 WebView2 和 WKWebView 上通不通；不通时 `invoke` 长轮询的并发表现
- 自定义协议上的 `import()` 和共用 React 的转接模块
- 宿主崩溃、卡死后的重启和窗口重连
- 睡眠唤醒、所有窗口隐藏时宿主的定时器
- 对照：隐藏 WebView 当宿主时的内存
- 花一天做 rutis 的小样，看它「标记即服务」和进程恢复是怎么做的

开工前读 [进度](/docs/architecture/plugins/v3-progress.md) 和 [流程](/docs/architecture/plugins/v3-workflow.md)；开工时把上面拆成步骤写进下面的验收，做完一步勾一步。

## 验收

- 实测报告 `docs/investigations/v3-feasibility.md`：每一项写怎么测的、在哪个系统上、数字、结论（成立 / 有条件成立 / 不成立）、对方案的影响
- 一周到点就出报告，没测完的如实写「未测」和原因
- 前 3 项有不成立的，先改方案再做第 1 阶段；用户定继续、改方案还是停，以及用 Node 还是 Bun

## 备注

- 等用户定的三件事和报告的建议见[报告](/docs/investigations/v3-feasibility.md)「要你定的」。
- 临时项目在这台 Mac 的 `~/Desktop/projects/fuyu-v3-spike`，不在仓库里。Windows 上补测时把 `app/` 和 `host/` 拷过去：`app/` 里 `node build.mjs` 之后 `npx tauri build`，附带的 Node 放在 `app/src-tauri/binaries/node-<目标三元组>`；运行时设 `SPIKE_SCENARIO=suite`，结果写到 `SPIKE_OUT` 指的目录下的 `results.jsonl`。Rust 一侧取令牌读的是 `/dev/urandom`、宿主靠标准输入关闭来退出，这两处在 Windows 上要先改。
