## 说明

E63.2 让 `market/v1` 的六个会改磁盘的方法（refresh、installMarket、installFile、setManualAllowed、setEnabled、uninstall）只回应设置窗口（`src/features/updater/host/market.mjs` 的 `assertSettingsWindow`）。但窗口是谁，是连接自己在握手时报的（`packages/plugin-base/src/host/sockets.mjs` 第 54 行 `message.window`）。跑在设置窗口里的插件界面代码（插件的设置页）和设置窗口共用同一条宿主连接，调用时 `caller` 也是 `{ window: "settings" }`、没有 `plugin`，所以这道检查挡不住它：设置窗口里的插件代码能装、卸、开关别的插件。发版前审查（[`docs/investigations/plugin-release-readiness.md`](/docs/investigations/plugin-release-readiness.md) 的 S1）记过这一条，不挡 0.3.11。

考虑过的改法：

- 插件界面代码各用一条自己的连接，握手时由宿主发给它带插件 id 的凭据，宿主按凭据给 `caller.plugin` 赋值，设置窗口本身的连接不发凭据给插件代码。
- 或者把插件设置页放进单独的 iframe / 窗口，和设置窗口不在同一个 JS 环境里，连接自然分开。
- 只靠在前端过滤调用不够：插件代码和设置窗口同一个 JS 环境，能直接拿到连接。

## 验收

- 设置窗口里的插件代码调用 `market/v1` 的六个方法被拒，错误里写出插件 id
- 设置窗口自己的调用照常
- 单元测试覆盖握手凭据或隔离后的 `caller`
