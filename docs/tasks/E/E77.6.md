### 市场仓库要改的地方（没推、没开 PR）

生成 `index.v3.json` 的脚本在 `TixXin/fuyu-plugins`，不在本仓库。改好的一份在本机 `/Users/tixxin/Desktop/projects/fuyu-plugins` 的本地分支 `e77-6-index-keywords-docs`（提交 `a3db943`）和共享笔记的 `e77-6-market-repo.patch`，没有的话照下面改：

- `scripts/v3/lib/listing.mjs`
  - 新函数 `keywordsOf(built)`：取构建出的 `package.json` 顶层 `keywords`，只留字符串，去首尾空格，去空的和重复的（不分大小写），最多 32 个。
  - `manifestSummary` 里：`const keywords = keywordsOf(built); if (keywords.length > 0) summary.keywords = keywords;`
  - 新函数 `docHashes(builtDir)`：列出构建产物文件夹顶层名字匹配 `/^(?:README|CHANGELOG)(?:\.[A-Za-z]{2,3}(?:-[A-Za-z0-9]{2,8})*)?\.md$/i` 的文件，按名字排序，名字不分大小写去重，最多 16 个，返回 `{ 文件名: 文件字节的 SHA-256（小写十六进制） }`。
- `scripts/v3/build.mjs`：构建完一个版本、拼 listing 时加 `docs: docHashes(packed.outDir)`。
- `scripts/v3/lib/market-index.mjs` 的 `versionEntry`：`listing.docs` 非空时把它写进版本条目的 `docs`。
- `market/v3/tools.json`：`commit` 换成本批合入后的 `TixXin/fuyu` `main` 提交号。
- 测试：`test/v3/listing.test.mjs`（新，测上面两个函数）、`test/v3/pipeline.test.mjs`（索引条目带 `keywords` 和 `docs`）。

哈希按构建产物里的文件算，岛从 `raw.githubusercontent.com/<仓库>/<提交>/<路径>/<文件名>` 取同一个文件来比，所以仓库里存的字节和检出的字节要一样（用 `.gitattributes` 把这些文件转成 CRLF 的仓库会对不上，详情页就不显示文档）。

### 第 6 项的契约（已写进 contracts.md 和 v3-market.md）

- 版本条目可选 `docs: { "<文件名>": "<sha256>" }`，只收包顶层的 `README*.md`、`CHANGELOG*.md`，最多 16 个；`manifest.keywords` 可选，最多 32 个非空字符串。两个字段旧岛都忽略。
- 详情页（没装的插件）：有 `docs` 的版本只取列出的文件，可以走下载镜像，字节的哈希不符、404 或超过 1 MB 就换下一个源，都不对就不显示；没有 `docs` 的版本只从 GitHub 直连，不走镜像。
- 副作用：这批合入后、重新上架前，已上架的旧版本在连不上 GitHub 的机器上详情页没有 README 和更新记录（原来 E77.1 让它们不校验地走镜像）。
