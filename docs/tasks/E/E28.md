## 说明

插件文档让新作者去看 `plugins/examples/` 的源码，但示例是全仓库最旧的写法：

- 7 个示例的清单都叫 `focusd-plugin.json`，文档教的是 `fuyu-plugin.json`。[build-plugin-index.mjs](/scripts/plugins/build-plugin-index.mjs) 里清单名写死成旧名字，要先让它认新名字。
- 6 个旧示例各自带着 `lib/focusd.ps1`，一共 5 个不同的版本（82、87、88、200、235 行），函数名是改名前的 `*-Focusd*`。只有天气用了现行的 `lib/fuyu.ps1`，和 `plugins/sdk/powershell/fuyu.ps1` 相同。
- `plugins/market/` 里 5 个文件的 `repo` 还是 `TixXin/fly-island`，并且缺 `dev.focusd.system-monitor.json`，所以本仓库的旧索引里系统监控没有分类和仓库。

每个示例升一个版本：清单改名，换上现行的 SDK 和 `*-Fuyu*` 函数名，忽略文件改成 `.fuyuignore`，再 `pnpm plugins:index` 重新打包签名。

插件 id（`dev.focusd.*`）不改。它是已安装用户的插件目录名、数据目录名和授权记录的键。

## 验收

- 每个示例用模拟宿主跑通，`tests/scripts/` 里已有的示例测试照常通过；`pnpm test` 里「索引和 zip 与源码一致」的检查通过。
- `plugins/examples/` 里搜不到 `focusd.ps1` 和 `-Focusd`；`fuyu-plugin validate` 对每个示例没有错误。
- 改名前发布的岛屿仍能从本仓库的旧索引装上新版本：zip 里同时有 `fuyu-plugin.json` 和一份同内容的 `focusd-plugin.json`，和 `fuyu-plugin pack` 的做法一样。
- 新版本在市场上架。官方插件 land 之后由 fuyu-plugins 的 CI 自动跟上，见 [market-ops.md](/docs/architecture/plugins/market-ops.md)。

## 备注

- 已发布的版本不能改，只能发新版本。`pnpm plugins:index` 要用旧索引的签名私钥和官方作者密钥，都在 Windows 那台机器上，Mac 上的会话做不完这一步。
- E11 还开着，范围也是这些示例（旧库的读取超时）。这个任务做完，E11 里示例的部分就不用再做，只剩 PowerShell Gallery 发布。
- fuyu-plugins 里官方插件的提交文件 `repo` 也还是 `TixXin/fly-island`，下载地址靠 GitHub 的改名跳转。顺手改成 `TixXin/fuyu`。
