## 说明

官方插件要在空状态里放「去设置」按钮（天气没填城市、GitHub Issue 没填仓库），需要插件能打开自己的设置。接口由插件系统总控 2026-11-19 定下，已告诉官方插件完善组长。不挡发版，排在 E60.9、E60.10 之后。

- `ctx.settings.open()`：不带参数。客户端（任何窗口里的插件代码）和宿主（例如点通知时）都能调。
- 效果：打开或聚焦设置窗口，落到本插件详情弹窗的「设置」标签，和插件行上 ⚙ 的落点一样。
- 只能打开自己的设置：插件 id 由宿主或运行时按调用方填，插件不能传别人的 id。
- 实现可以复用 `src/windows/settings/pluginPageHandoff.ts` 的 detailRequest，再加一个跨窗口入口（例如 `openSettingsWindow` 带插件详情参数，见 `src/windows/settings/api.ts`）。宿主那一路走 Rust 命令还是窗口转发，由做的会话定；新增或改 Tauri 命令时按 `src-tauri/AGENTS.md` 同步前后端和权限配置。
- 类型声明（`packages/plugin-base` 的 `*.d.mts`）加 JSDoc，`docs/plugins/services-and-slots.md`（或对应的接口文档）写清用法。

## 验收

- 岛上的插件调 `ctx.settings.open()` 后，设置窗口打开（或已开时聚焦）到这个插件的详情「设置」标签
- 宿主调用同样能打开；插件没法打开别的插件的设置
- 单元测试或回归页覆盖上面的落点；接口文档和类型声明同步
- `pnpm check`、`pnpm build`、`pnpm test:regression` 通过；改了 Rust 时加 `cargo test` + `pnpm build:exe`，附 `mq:try` 的 Windows CI
- 做完告诉插件系统总控和官方插件完善组长
