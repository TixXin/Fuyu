## 说明

第 2 版插件宿主删除时（E36.6.5，fcf96486），`fuyu://` 链接的处理整套跟着删掉了：Windows 上的协议注册（原 `win32/url_protocol.rs`）、`fuyu://plugin/<id>/…` 与 `fuyu://market/install/<id>` 的解析和分发、macOS 上 `RunEvent::Opened` 的处理。第 3 版没有接手，现在点链接只会唤起浮屿，链接被忽略；`src-tauri/Info.plist` 仍声明 `fuyu`、`focusd` 两个协议，老用户的注册表项也还在（指向 exe，无害）。

2026-11-18 用户决定 E36 收口时不做，单开本任务。要做的：

1. 至少支持 `fuyu://market/install/<作用域>/<名字>`：唤起岛屿，打开第 3 版市场的详情或安装确认，签名校验和确认都不跳过。
2. 是否给插件开放 `fuyu://plugin/<名字>/…`（如 OAuth 回调），先定权限和格式。
3. Windows 重新注册协议（只用 HKCU），Mac 继续用 `Info.plist`；冷启动时等宿主就绪再处理。
4. 旧名 `focusd://` 按 `contracts.md`「改名兼容（D17）」的期限决定留不留。

## 验收

- 两个系统上点 `fuyu://market/install/<名字>` 能唤起岛屿并出现安装确认
- `contracts.md`、`platforms.md` 写明新的链接格式和支持情况
- 单元测试覆盖链接解析（长度、非法字符、未知作用域）
