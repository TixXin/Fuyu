## 说明

1. **拼错的字段没人提醒。** 清单的 schema 顶层不禁止多余字段，岛屿的 `PluginManifest` 也不拒绝未知字段。2026-11-13 实测：把 `activationEvents` 写成 `activationEvent`、`optionalPermissions` 写成 `optionalPermission`，`fuyu-plugin validate` 返回 ok，岛屿静默忽略。结果是插件变成随岛常驻，可选权限消失，作者不知道为什么。`validate` 对顶层和 `contributes` 下不认识的字段给告警。只告警、不报错：新版岛屿加的字段，旧 SDK 还不认识。
2. **复制进插件的 SDK 会过期。** PowerShell 和单文件 Node SDK 是复制进每个插件的（`lib/fuyu.ps1`、`fuyu.mjs`）。SDK 修了 bug，每个插件都要重新复制再发版，作者得不到提示。E10 修读取超时时就遇到了；现在 6 个旧官方示例里有 5 个不同版本的 `lib/focusd.ps1`。[validate.mjs](/packages/fuyu-plugin/src/validate.mjs) 已经认识这些文件名（`SDK_FILES`），发现插件里的副本不是 CLI 自带的现行版本时给告警，并写明怎么换。两种做法选一种：和 CLI 自带的文件比内容哈希；或者给单文件 SDK 加一个版本变量再比版本。仓库规则是代码不写注释，版本标记不能用注释。
3. **市场 CI 用的 SDK 落后。** `TixXin/fuyu-plugins` 的依赖锁在 `fuyu-plugin` 0.5.0，npm 已经是 0.6.0。新加的校验要等有人手动升级才在市场生效。把「发版后升级 fuyu-plugins 的依赖」写进 [sdk-release.md](/docs/architecture/plugins/sdk-release.md) 的步骤，这次发版后升上去。

## 验收

- 上面两种拼错的清单各得到一条告警，退出码仍是 0；正确的清单没有新告警。
- 带旧版 `lib/focusd.ps1` 的插件得到一条「SDK 文件不是现行版本」的告警；脚手架新建的插件没有。
- 两项告警各有测试；`pnpm check`、`pnpm build` 通过。
- 发了带这两项的 SDK 新版本，fuyu-plugins 的 `package.json` 升到同一版本，sdk-release.md 多了这一步。
