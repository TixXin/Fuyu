## 说明

1. **上架时间。** fuyu-plugins 的索引构建设的是每小时一次（`cron: "17 * * * *"`），但 GitHub 的定时触发不保证准点。2026-11-05 到 11-13 这 7.8 天里，定时构建只跑了 29 次：平均 6.7 小时一次，最长 10.9 小时，没有一次间隔短于 3 小时。岛屿自己每 6 小时查一次市场，所以第三方作者发新版本到用户看到，最坏约 17 小时。合并 PR 和修改 `revoked.json` 由推送触发，不受影响。

   写着「一小时内」或「每小时」的地方：[publish.md](/docs/plugins/publish.md)、[market-ops.md](/docs/architecture/plugins/market-ops.md)、[cli.mjs](/packages/fuyu-plugin/src/cli.mjs) 里 `publish` 的输出，以及 fuyu-plugins 的 CONTRIBUTING.md（README 里如果也写了，一起改）。先把文字改成实际情况，例如「通常几小时内」。

   要不要换更可靠的触发另行决定。可以让作者的发布工作流在发完 Release 后请求一次构建，或者用外部定时器调用 `workflow_dispatch`。

2. **数据目录。** 浮屿的数据目录默认已经是 `~/.fuyu`（[home_dir.rs](/src-tauri/src/home_dir.rs)，也可能被 `FUYU_HOME` 或 `home.json` 指到别处）。插件在 `~/.fuyu/plugins/<id>/`，插件数据在 `~/.fuyu/plugins-data/<id>/`。插件文档里还有 5 处写着 `%APPDATA%\com.tixxin.fuyu\plugins\`：`manifest.md`、`runtime.md` 的环境变量表、`quickstart.md`、`publish.md`、`vscode.md`。改成现在的位置，并说明最稳妥的办法是在设置 → 插件扩展里打开插件目录。

## 验收

- 上面列出的文件里搜不到「一小时内」「within an hour」和 `%APPDATA%\com.tixxin.fuyu\plugins`（讲旧版本迁移的地方除外）。
- `fuyu-plugin publish` 的输出改了以后，`pnpm check` 通过；有测试断言这段输出的话一起改。
- fuyu-plugins 的 CONTRIBUTING.md 同步改。
