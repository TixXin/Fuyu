## 备注

### 市场仓库要改的地方

前提：岛屿侧的两个提交（`a1ff7630d`、`a2cdc55a4`）已经在 `TixXin/fuyu` 的 `main` 上。

1. **换工具版本**：`market/v3/tools.json` 的 `commit` 现在是 `e2dfc07e…`，那个提交的 `validateIndex` 不认识 `bundles`（会当成不认识的字段放过，不校验）。换成含 `a1ff7630d` 的 `main` 提交号，单独一个 PR 先合。
2. **套装文件**：新目录 `bundles/`，一个套装一个文件 `bundles/<id>.json`，文件名去掉 `.json` 必须等于里面的 `id`。内容就是索引里的一个 `bundles` 条目。第一个文件 `bundles/pomodoro-flow.json`：

   ```json
   {
     "id": "pomodoro-flow",
     "displayName": { "zh-CN": "番茄工作法", "en": "Pomodoro flow" },
     "description": {
       "zh-CN": "番茄钟计时，收起条上看今天的待办进度，每天给一份待办小结",
       "en": "A pomodoro timer, today's to-do progress on the bar, and a daily to-do digest"
     },
     "plugins": ["@fuyu/pomodoro", "@fuyu/todo-ring", "@fuyu/todo-digest"],
     "onboarding": true
   }
   ```

   上架前核对：三个插件都已经在线上的 `index.v3.json` 里（少一个，`validateIndex` 就会让这次发布失败），说明文字和三个插件现在的功能对得上。
3. **拼索引**：`scripts/v3/lib/market-index.mjs` 的 `assembleIndex` 多收一个参数 `bundles`（默认空数组），拼 `doc` 时在 `plugins` 后面加 `...(bundles.length > 0 ? { bundles } : {})`，没有套装时索引和现在逐字节一样。后面已有的 `market.validateIndex(doc)` 会查格式和「成员都在这份索引里」，不过就抛错，这一次发布失败，不会出一份坏索引。新增 `scripts/v3/lib/bundles.mjs`：`readBundles(root)` 读 `bundles/*.json`，按 `id` 排序，查文件名等于 `id`、成员都是 `@fuyu/*`（第一批只收官方，以后放开改这里）。`scripts/v3/release.mjs` 的 `releaseAll` 调 `assembleIndex` 时传 `bundles: readBundles(root)`。每天重签的那条路如果也走 `assembleIndex`，一样传；只重签不重拼的话不用动。
4. **触发**：`.github/workflows/publish-v3.yml` 的 `paths` 现在只有 `plugins/v3/**`，加上 `bundles/**`，不然只改套装的 PR 合入后不会重出索引。
5. **PR 检查**：`scripts/v3/plan.mjs`（`check-submission.yml` 的 `v3-plan` job）对改到的 `bundles/*.json` 跑 `readBundles` 的检查，并用现有的索引加上这次 PR 的套装调一次 `validateIndex`，问题写进报告。套装只由维护者合入：`CODEOWNERS` 给 `bundles/` 指定维护者，或者在 `plan.mjs` 里沿用「谁能改什么」的那段判断。
6. **测试**：`test/v3/` 加一个文件，至少覆盖：没有 `bundles/` 时索引不变；有套装时进索引；成员不在索引里、成员不是 `@fuyu/*`、文件名和 `id` 不一致时失败。
7. **文档**：本仓库的 `docs/architecture/plugins/v3-market-ci.md` 加一节「套装」，写文件位置、谁能合、检查了什么；市场仓库的 `CONTRIBUTING.md` 写一句套装目前不收第三方。

### 上线后怎么验

1. 开发版（`pnpm tauri dev`，用户自己跑）打开设置 → 插件市场，等索引刷新，「套装」一行出现「番茄工作法」，写着 3 个插件。
2. 点「全部安装」，确认框列出三个插件都是「将安装」；确认后三个都装上，插件页能看到。
3. 已经装了其中一个的机器上，按钮是「安装其余 2 个」。
4. 装一个 0.3.10 的正式版，市场页照常打开、能装插件，没有「套装」一行也不报错。
