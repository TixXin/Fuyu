## 说明

第 3 版插件平台没有「插件把密钥存进系统凭据」的接口：第 2 版的 `secrets.*` 随 E36.6 删掉了，[v3-secrets.md](https://github.com/TixXin/fuyu/blob/main/docs/architecture/plugins/v3-secrets.md) 只管内置功能的密钥。要连自己服务的插件（第一个是 C150.12 的截图图床示例插件，要存对象存储的 Access Key 和 Secret）只能把密钥写进数据目录的明文文件。

补一个内核服务 `secrets/v1`：

- 方法 `list()`、`get({ name })`、`set({ name, value })`、`remove({ name })`；每个插件只能读写自己的条目，按调用方的插件 id 隔离，参数里不收插件 id。
- `get` 只给插件的宿主部分（Node）；插件的界面经窗口调这个服务一律回 `forbidden`，设置页要存密钥就交给自己的宿主部分去存。
- 存在系统凭据里：Windows 凭据管理器 / macOS 钥匙串，服务名 `com.tixxin.fuyu.plugin.<插件 id>`、账户是条目名（和第 2 版同一个命名空间）；条目名的索引记在数据目录的 `plugin-secrets.json`（沿用第 2 版的格式，只有名字没有值），卸载浮屿时的清理本来就读它。
- 在插件市场卸载插件并勾了「删数据」时，连它的凭据条目一起清掉；没勾时留着，重新装上还能用。
- 值不进日志、不进前端，错误信息里不带值；`check:secrets` 要过。

## 验收

- `secrets/v1` 的类型在 `@fuyu/plugin-services` 里，接口写进第 3 版服务文档、`contracts.md`、`data-storage.md` 和 v3-secrets.md 的例外名单
- 单元测试：插件之间互相读不到；窗口调用回 `forbidden`；卸载时删数据会清条目
- Rust 单元测试、Mac 本机验证；Windows 凭据管理器写实测清单
- `pnpm check`、`pnpm build`、Rust 测试和 clippy
