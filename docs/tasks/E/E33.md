## 说明

[设计稿](/docs/architecture/plugins/plugin-windows.md)第 7 节。启动台的简版用现有的接口就能做：命令加全局快捷键，`island.openView` 展开岛屿并打开插件的列表页，列表模板自带搜索框（`view.search`），回车触发条目动作。

用户 2026-11-13 同意先做它：它是独立窗口版的对照，也能看出用户是否真的需要屏幕中央的大窗口。

要做的：

- 按快捷键展开岛屿并打开启动台页面，焦点在搜索框里。
- 列出本机的应用（Windows 的开始菜单快捷方式，Mac 的 `/Applications`），输入时过滤，回车或点击启动。最近启动过的排前面，用 `storage` 记。
- 用 Node 写，清单声明 `"platforms": ["windows", "macos"]`，两个系统都能用。可以算作 E29 要的 Node 官方插件之一。

## 验收

- Windows 和 Mac 的真岛上各跑通一次：快捷键唤起、搜索、启动。
- 有模拟宿主的测试，随 `pnpm test` 跑；`fuyu-plugin validate` 没有错误。
- 做的过程中发现现有接口不够用的地方（例如搜索框的焦点、列表的图标、键盘选择），记在这个任务的备注里，供 E34 参考。

## 备注

- 上架要用 Windows 那台机器上的签名私钥。
- Mac 上用 nvm 这类工具装的 Node 现在找不到，见 G1.17。
- 现有接口不够用的地方（给 E34 和列表模板参考）：打开页面后搜索框不会自动拿到焦点，要先点一下；列表没有键盘上下选择，回车也不会打开第一项；打开应用后插件没有办法让岛屿收起；条目图标只能从固定的 47 个里选，显示不了应用自己的图标；本地搜索只按字面包含匹配，没有拼音和模糊匹配。
- Mac 上显示的是应用包的文件名，系统应用是英文名（访达显示为 Finder）；要本地化名字得读每个应用的 InfoPlist.strings，这版没做。
