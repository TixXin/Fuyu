## 说明

[方案](/docs/architecture/plugins/v3-everything-plugin.md)「分阶段」的第 1 阶段，预计 2–3 周。把插件内核搭起来，默认关闭，对用户没有可见变化。

要做的：

- 基座的包结构：独立的包和 crate，不依赖浮屿的业务代码
- Cordis 拷进 `vendor/`，包成 `fuyu-plugin` 的接口
- Node 附带程序的打包和签名；Rust 看管宿主进程（启动、心跳、重启）
- 宿主和 Rust 之间的管道；窗口和宿主之间的本机 WebSocket；跨进程的边界规则
- 窗口里的小加载器和客户端上下文；插槽注册表
- `plugins.yml`（按配置调和）；状态视图；出错处理；安全模式；CPU 和资源数统计
- 内核的保证清单和对应的测试

开工前读 [进度](/docs/architecture/plugins/v3-progress.md) 和 [流程](/docs/architecture/plugins/v3-workflow.md)；开工时把上面拆成步骤写进下面的验收，做完一步勾一步。

## 验收

- 一个演示插件在宿主注册服务、往岛屿插槽放一个组件；关掉它两样都撤掉；改代码能重载
- 杀掉宿主进程后几秒内恢复
- 保证清单里的每一条都有测试；反复加载卸载演示插件 1000 次后内存、句柄、定时器数回到原样
- 插件页看得到它的状态和占用
- 没装第三方插件时私有内存比基线多不超过 40 MB，连跑 1 小时不持续增长（用户 2026-11-15 把 8 小时改成 1 小时）；冷启动不比基线慢
- Windows 和 macOS 真岛各验收一次

步骤（2026-11-15 开工时拆的；做完一步勾一步）：

- [x] 1. Cordis 拷进 `vendor/cordis/`（6 个包，npm 的构建产物），记版本、哈希、上游提交和本地改动；pnpm 的 overrides 保证全仓只有这一份
- [x] 2. 基座的 TS 包 `packages/plugin-base`：宿主启动内核、按 `plugins.yml` 加载、共享内核给装在别处的插件、收集日志、插件状态视图（运行中 / 等哪个服务 / 失败原因 / 停用）；保证清单的前 9 条有测试
- [x] 3. 宿主进程的入口：标准输入输出上的 JSON-RPC（和 Rust）、心跳、标准输入关闭就退出；跨进程的边界规则写成一页（[v3-boundary.md](/docs/architecture/plugins/v3-boundary.md)）
- [x] 4. Rust 一侧：`src-tauri/crates/plugin-base`（Cargo 工作区成员）找电脑上的 Node、拉起宿主、等就绪、心跳、崩溃和卡死后按退避重启；`src-tauri/src/plugin_kernel` 用作业对象 / 进程组管住它。开发版里设 `FUYU_PLUGINS_V3=1` 才启动
- [x] 4b. 决定 16 的后半：电脑上没有能用的 Node 时下载（写死的版本和 SHA-256、官方加两个国内镜像、放进数据目录的 `runtime/`），找 Node 和下载都在后台线程，不卡启动；宿主能打包成随正式版带上的文件夹（`scripts/plugins-v3/bundle-host.mjs`）。设计和实测见 [v3-node-runtime.md](/docs/architecture/plugins/v3-node-runtime.md)（会话 v3-node-download 做的，接线在这边）
- [ ] 4c. 正式版里打开时再做：构建时带上打包好的宿主（方案在 v3-node-runtime.md「让正式构建带上它」）、Rust 从资源目录找宿主脚本、岛上显示下载进度和可重试的失败、发版冒烟测试检查宿主文件
- [x] 5. 窗口和宿主之间的本机 WebSocket：令牌、来源核对、握手、序号、快照（宿主一侧和 `@fuyu/plugin-base/client`；窗口向 Rust 要端口和令牌的命令放在第 6 步，那时窗口第一次真的连上）
