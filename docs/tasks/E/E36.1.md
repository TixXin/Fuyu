## 说明

[方案](/docs/architecture/plugins/v3-everything-plugin.md)「分阶段」的第 1 阶段，预计 2–3 周。把插件内核搭起来，默认关闭，对用户没有可见变化。

要做的：

- 基座的包结构：独立的包和 crate，不依赖浮屿的业务代码
- Cordis 拷进 `vendor/`，包成 `fuyu-plugin` 的接口
- Node 附带程序的打包和签名；Rust 看管宿主进程（启动、心跳、重启）
- 宿主和 Rust 之间的管道；窗口和宿主之间的本机 WebSocket；跨进程的边界规则
- 窗口里的小加载器和客户端上下文；插槽注册表
- `plugins.yml`（按配置调和）；状态视图；出错处理；安全模式；CPU 和资源数统计
- 内核的保证清单和对应的测试

开工前读 [进度](/docs/architecture/plugins/v3-progress.md) 和 [流程](/docs/architecture/plugins/v3-workflow.md)；开工时把上面拆成步骤写进下面的验收，做完一步勾一步。

## 验收

- 一个演示插件在宿主注册服务、往岛屿插槽放一个组件；关掉它两样都撤掉；改代码能重载
- 杀掉宿主进程后几秒内恢复
- 保证清单里的每一条都有测试；反复加载卸载演示插件 1000 次后内存、句柄、定时器数回到原样
- 插件页看得到它的状态和占用
- 没装第三方插件时私有内存比基线多不超过 40 MB，连跑 8 小时不持续增长；冷启动不比基线慢
- Windows 和 macOS 真岛各验收一次

- [x] 1. Cordis 拷进 `vendor/cordis/`（6 个包，npm 的构建产物），记版本、哈希、上游提交和本地改动；pnpm 的 overrides 保证全仓只有这一份
- [x] 2. 基座的 TS 包 `packages/plugin-base`：宿主启动内核、按 `plugins.yml` 加载、共享内核给装在别处的插件、收集日志、插件状态视图（运行中 / 等哪个服务 / 失败原因 / 停用）；保证清单的前 9 条有测试
