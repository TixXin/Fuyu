## 说明

`src/` 里 44 个文件有 `setInterval`，只有 7 个文件看 `visibilitychange` / `document.hidden`。隐藏的 WebView 里定时器和动画照样在跑，占 CPU，也带来无效的渲染。Tauri 的 `background_throttling` 在 Windows 上不支持，`window.hide()` 之后页面是否算 hidden、定时器是否被 Chromium 自动节流，没有找到可靠说明，要实测。

做法：先实测：窗口 `hide()` 之后 `document.visibilityState` 是什么，定时器的实际频率是多少。然后逐个过 `setInterval`：隐藏的翻译、剪贴板窗口里的全部停掉，显示时立即补一次；主岛上只在展开态才看得见的面板，收起时停掉。优先复用已有的 `usePageHidden`。全屏应用盖住岛屿时（已有 `system/fullscreen.rs` 的检测）也可以停掉动画。

来源见[调研](/docs/research/memory-and-performance.md)。

## 验收

- 有一份 `setInterval` 清单，每个写明看不见时是否停、为什么。
- 翻译、剪贴板窗口隐藏时页面里没有在跑的定时器。
- 按 idle-usage.md 的测法，收起闲置时的 CPU 有前后对比。
- 窗口显示或面板展开时数据是新的，不出现先显示旧数据再跳变。
