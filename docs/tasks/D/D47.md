## 说明

收起闲置时私有内存约 330 MB，几乎都在 WebView2，但不知道浏览器进程、GPU 进程和各个渲染进程各占多少，也没有长时间运行的数据。上游有两个没修的泄漏和浮屿的用法对得上：Tauri 的 `emit` 每发一个内容不同的事件留下约 0.75 KB（tauri-apps/tauri#12724），鼠标在 WebView2 表面移动泄漏 GDI 对象（MicrosoftEdge/WebView2Feedback#5536）。这一项只测量、不改行为，结果决定 D48–D50 先做哪项、要不要做。

做法：写一个采样脚本（沿用 idle-usage.md 的测法：独立数据目录、正式打包的前端），每分钟记录岛屿和它全部子进程的私有内存、工作集、GDI 句柄数，并按 `msedgewebview2.exe` 的 `--type` 分类；分别跑「放着不动」和「正常使用（鼠标经常经过岛屿、放音乐、有 Agent 会话）」两种情况。

来源见[调研](/docs/research/memory-and-performance.md)。

## 验收

- `docs/investigations/` 里有一份记录：各类进程的内存占比，8 小时以上私有内存和 GDI 句柄数的走势，两种情况都有。
- 写明两个上游泄漏在浮屿上有没有出现、增长速度是多少。
- 有几个渲染进程、翻译 / 剪贴板 / 截图选区窗口是否各占一个，有实测结论。
- 采样脚本放在 `scripts/` 里，能重复跑。
