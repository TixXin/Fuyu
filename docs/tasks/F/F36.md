## 说明

pnpm mq:land 现在把整个本地 main 推上去，并且在共用的工作区里合 origin/main。多个会话、两个平台同时开发时，一个 PR 会把所有人卡住：2026-11-14 合 README 的链接改动（PR 235）时，先被别的会话没提交的文件挡住合并，又被同一批里 E34 在 macOS 上的编译错误拖住，期间别的会话还往同一个 PR 加了提交。Mac 上的编译错误在 Windows 上查不出来（试过对 aarch64-apple-darwin 跑 clippy：objc2-exception-helper、aws-lc-sys 要面向 macOS 的 C 编译器和苹果 SDK，走不通），只能靠 CI 发现，所以要让它只挡住写那段代码的会话。改两处：一、land 用 git merge-tree --write-tree 算合并结果，直接生成合并提交推到 land 分支，不在工作区里 git merge；真有内容冲突时照旧报出来。二、支持只带指定的提交（--only <提交…> 或 --mine --as <会话名>，写法实现时定），叠到 origin/main 上开 PR，叠不上时拒绝并说明原因，不自动带上别的提交。

## 验收

- 工作区里有别的会话没提交、且 origin/main 也改了的文件时，pnpm mq:land 仍能开出 PR，那些文件原样不动。
- 本地 main 上有 A（别的会话的功能提交）和 B（独立的文档提交）时，可以只把 B 开 PR 合入；之后 A 照常 land，不冲突，B 不出现两次。
- 指定的提交依赖没带上的提交时，land 拒绝并说清楚缺哪个。
- pre-push 检查（land-check.mjs）和 tasks landing 的核对照常生效。
- tests/scripts/ 里有覆盖这两条路径的测试；[workflow.md](/docs/architecture/workflow.md) 和 AGENTS.md 的「合入 main」写了新用法。
