## 说明

pnpm mq:land 推的是整个本地 main，一批里任何一个提交让 CI 没过，整批都合不进去。多个会话、两个平台同时开发时这很常见：2026-11-14 合 README 的四处链接改动（PR 235）时，同一批里 E34 在 macOS 上有 3 处死代码，rust-macos 失败，一行文档改动等了几轮，期间别的会话又往同一个 PR 加了提交。Mac 上的编译错误在 Windows 上查不出来（见 src-tauri/AGENTS.md），只能靠 CI 发现，所以要让它只挡住写那段代码的会话。

改两处：

- 只带指定的提交：`pnpm mq:land --only <提交…>`（或 `--mine --as <会话名>`，写法实现时定），在仓库内部把这些提交叠到 origin/main 上开 PR，不碰工作区。叠不上（依赖没带上的提交、有冲突）时拒绝并说明原因，不自动带上别的提交。合入后本地 main 里对应的提交要能被 mq:sync 认出来，不重复、不冲突。
- 冲突时说清楚：普通合并被没提交的文件挡住、仓库内部合并（F34）又因为内容冲突失败时，land 现在只说「冲突，已撤回」，上面还留着 git 那句「local changes would be overwritten」，容易被读成「被别人没提交的文件挡住」而去等别的会话。改成列出冲突的文件（merge-tree 的输出里有），并说明这是内容冲突。

## 验收

- 本地 main 上有 A（别的会话的功能提交）和 B（独立的文档提交）时，可以只把 B 开 PR 合入；之后 A 照常 land，不冲突，B 不出现两次。
- 指定的提交依赖没带上的提交时，land 拒绝并说清楚缺哪个。
- 工作区里有没提交的文件、两边的提交又有内容冲突时，land 的输出列出冲突的文件名。
- pre-push 检查（land-check.mjs）和 tasks landing 的核对照常生效。
- tests/scripts/ 里有覆盖这两处的测试；[workflow.md](/docs/architecture/workflow.md) 和 AGENTS.md 的「合入 main」写了新用法。
