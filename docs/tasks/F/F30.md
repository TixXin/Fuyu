## 说明

现在的 land 直接推 `main`，只有仓库管理员能用，而且管理员的提交不经过 CI（`b9590bd5` 因此让 `main` 红了一晚）。改成推分支、开 PR、开自动合并，协作者和代理会话走同一条路。分步计划见 [land-via-pr-plan.md](/docs/architecture/land-via-pr-plan.md)。

## 验收

- `pnpm mq:land` 在 lane 里推 `land/<用户名>/lane-<N>`、开 PR 并开启自动合并，CI 通过后 GitHub 合入；`pnpm mq:wait` 合入后快进主工作区。
- 同时开着多个 PR 时，落后的 PR 按开启自动合并的先后一个个被更新、合入。
- 只改 Markdown 的 PR 走 CI 快速路径，`check` 照常报告。
- `dev` 由工作流跟着 `main`。
- AGENTS.md、`lanes.md`、`docs/tasks/README.md` 只写一套流程，有 `CONTRIBUTING.md` 和 PR 模板。
- 规则集里管理员的绕过方式改成 `pull_request`（用户确认后）。

## 备注

- 2026-11-12 用户定：先用自己的工作流把落后的 PR 依次更新，给 merge queue 留好接口，仓库转到组织名下后再换。
- 第 1 步（打开 auto-merge、建 `PR_UPDATER_TOKEN`）和第 8 步（收紧规则集）要用户本人在 GitHub 上做。
