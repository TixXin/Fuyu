## 说明

全网调研与开源项目对比见 [agent-harnesses.md](/docs/research/agent-harnesses.md#五家代理岛上审批复查与开源项目横向对比2026-11-17-追加issue-737)。

浮屿目前通过官方实验桥接包 `@deepseek-ai/dsh-hooks-claude-code` 拦 `PreToolUse` 做 DeepSeek Harness（DSH）的岛上审批，存在两个问题：
1. `dsh-hooks-claude-code` 监听的是 `tools/pre-execute`，源码只处理 `deny` 和 `ask`、忽略 `allow`，导致岛上审批只能点「拒绝」或「交回 DSH」，无法点「允许」；且只能靠猜工具名正则拦截。
2. DSH `v0.2.1-alpha.1` 起已不再默认内置 `dsh-hooks-claude-code`，用户还需手动安装两个实验包。

参照 `clawd-on-desk`（`dsh-clawd-bridge`）和 `dsh-island` 验证过的做法，改由浮屿在 `~/.fuyu/dsh-plugin/` 生成一个零外部依赖的原生 Cordis 插件：
- 通过 `ctx.inject(['approval'], ...)` 在 `approval/request` waterfall 上注册前置监听器（`prepend: true`），只在 DSH 真正发起审批请求时触发，携带 `toolName`、`callId`、`reason`、`session.id`、`cwd` 并联动 `req.signal` 取消信号；
- 岛上点「允许」返回 `'allowed-once'`，点「拒绝」返回 `'rejected'`，点「交回 DSH」、超时或未开启岛上审批时调 `next()` 交回 DSH 原生审批弹窗；
- 同时监听 `session/created`、`session/event`（`turn/start`、`tool/call`、`turn/end`）、`session/disposed` 驱动岛上状态灯；
- 前端审批卡放开 `dsh` 的「允许」按钮。

## 验收

- 「安装/修复」在 DSH 目录存在时生成原生 Cordis 插件，并给出挂载说明（或自动检查挂载状态）
- `/dsh/pre-tool-use`（或 `/dsh/permission`）及前端审批卡支持 DSH 的允许（`allowed-once`）、拒绝（`rejected`）和交回 DSH
- `req.signal` 取消时能及时关闭岛上挂起的审批卡
- Rust 与前端单测覆盖，平台支持表与文档同步更新，真机验证项记入 #179
