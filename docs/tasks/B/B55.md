## 说明

把 GitHub Copilot CLI（npm `@github/copilot`，命令 `copilot`）接进 Agent 页。调研见 [global-coding-agents.md](/docs/research/global-coding-agents.md) 的 Copilot 一节。VS Code 里的 Copilot 不在范围内。

核实（2026-11-15；本机没装 CLI，`~/.copilot` 只有 VS Code 集成留下的空目录）：

- 事件类型以官方 `github/copilot-sdk` 的 `nodejs/src/generated/session-events.ts` 为准：每行 `{type, id, parentId, timestamp(ISO), data, ephemeral?}`。`session.title_changed`、`session.idle`、`user_input.requested`、`elicitation.requested` 是 `ephemeral: true`，不落盘，所以标题和「等你」不能从文件读。
- 落盘的：`session.start`（`sessionId`、`selectedModel`、`reasoningEffort`、`context.cwd`）、`user.message`（`content`，系统注入的以 `<` 开头）、`assistant.message`（`content`、`model`、`toolRequests[]`、子代理带 `parentToolCallId`）、`assistant.turn_start/turn_end`（每次调模型一对，不是每次提问一对）、`tool.execution_start/complete`、`abort`、`session.error`、`session.task_complete`（`summary`）、`session.shutdown`（会话退出）、`session.model_change`（`newModel`）。
- 标题读 `workspace.yaml` 的 `summary`（第三方 recall-cli 的读法，官方没写这个文件），没有就用第一句提问、目录名。
- 钩子：`~/.copilot/hooks/*.json`，`{"version":1,"hooks":{事件:[{type,bash,powershell,timeoutSec,matcher}]}}`。事件名写 PascalCase（`UserPromptSubmit`、`PermissionRequest`、`Stop`……）时 stdin 是 Claude 兼容格式（`session_id`、`hook_event_name`、`tool_name`、`tool_input`）。`permissionRequest` 回 `{"behavior":"allow|deny","message","interrupt"}`，`{}` 交回 Copilot 自己的提示；`notification` 的 `notification_type` 有 `permission_prompt`、`elicitation_dialog`、`agent_idle`。超时默认 30 秒，超时放行。
- 全局提示词文件：`~/.copilot/copilot-instructions.md`（官方目录说明）。
- Copilot 也执行 `.claude/settings.json` 里的钩子，岛给 Claude Code 装的钩子会把 Copilot 会话当成 Claude Code 再报一次，靠 claude_compat 的「按来源去重」解决（doubao 在做）。

做法：会话读取在 `copilot.rs`；钩子、审批回包、去重等 claude_compat 扩展提交后再接。用量环不做（只有非官方接口）。

## 验收

- Rust 读 `events.jsonl` 和 `workspace.yaml`，带按 SDK 类型构造的样本测试（运行中、完成、打断、出错、退出、子代理、系统注入的提问）
- 「安装/修复」在 `~/.copilot/hooks/` 放岛自己的 JSON，状态检查分得出没装、过期、最新
- 状态灯、等你、岛上允许 / 拒绝；Copilot 会话不再被当成 Claude Code 重复报
- Agent 页图标和名字、设置里能显示 / 隐藏
- 本机没装 CLI，真机项进实测清单
