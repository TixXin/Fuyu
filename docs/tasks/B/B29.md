## 说明

用户群反馈希望 Agent 页支持豆包。先调研豆包有哪些能当 harness 接入的形态（豆包桌面版、Trae / Trae CLI 等），各自的会话文件、钩子、审批和用量，结果补进 docs/research/agent-harnesses.md；再按 `fuyu-agent-harness` skill 的清单接入能接的那一种。

## 验收

- 调研写清楚每种形态能拿到什么（会话列表、运行状态、等你、审批、用量）
- 至少一种形态在 Agent 页显示会话并亮灯，带品牌图标
- 平台支持表和功能文档同步更新

## 结论

调研 2026-11-15 做完，详见 [agent-harnesses.md「豆包」](/docs/research/agent-harnesses.md#豆包2026-11-15-追加) 和 [china-coding-agents.md](/docs/research/china-coding-agents.md)。结论按形态：

| 形态 | 接不接 | 原因 |
|---|---|---|
| 豆包桌面版（含网页版） | 不接 | 是云端对话的 Chromium 外壳，不在本机跑代码，没有钩子；本地数据在 macOS 沙盒容器里，别的程序读不了（Windows 版未实测，按同类判断同样没有可读的会话文件）。岛上能显示的东西它都不提供 |
| TRAE / TRAE CN（字节的 IDE，模型里有豆包） | 接，作为「豆包」这一项的落地形态 | 支持 Claude Code 格式的钩子（会话开始、提交、工具前后、结束、等授权），能做会话列表、三态、等你和岛上审批；「允许」受 TRAE 自己的确认模式限制，可能只能做「拒绝」和「去 TRAE 处理」。国际版和 CN 版建议算一家、两个配置目录都装（和 Qoder 的做法一样） |
| TRAE CLI 2.0 | 暂不接 | 只给企业旗舰版，普通用户装不上，本机没法实测 |
| 扣子空间等其他字节产品 | 不接 | 都是云端 Agent，本机没有会话和钩子 |

做法：不单独写一套，等 B48 的「Claude Code 兼容」声明层合入后，TRAE 作为第二批的第一家，只写一份声明（配置目录、会话位置、记录格式、提示词文件），约 1 天。显示名用「TRAE」，不叫「豆包」（用户在 TRAE 里也可能选别的模型），#312 回复里说明「豆包桌面版接不了，豆包家能接的是 TRAE」。

还要用户定的：TRAE 的「允许」做不做（要实测它的确认模式）；TRAE 和 TRAE CN 算一家还是两家（推荐一家）。
