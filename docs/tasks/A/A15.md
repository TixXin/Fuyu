## 说明

用户反馈在 Windows 上使用 WorkBuddy 时，在岛上 Agent 页点击会话行或右键点击「跳到窗口」，均提示「没找到对应的窗口」，无法唤醒 WorkBuddy 界面。

排查 [session_process.rs](/src-tauri/src/agent_status/session_process.rs)、[focus.rs](/src-tauri/src/agent_status/focus.rs)、[workbuddy.rs](/src-tauri/src/agent_status/workbuddy.rs) 与 [window_focus.rs](/src-tauri/src/agent_status/window_focus.rs) 的跳转链路，定位到以下根因：

1. **`session_process_chain` 漏查了 WorkBuddy 的活动进程登记目录**：
   - WorkBuddy 运行时在 `~/.workbuddy/sessions/<pid>.json` 与 `~/.workbuddy-ai/sessions/<pid>.json`（及 `$WORKBUDDY_CONFIG_DIR/sessions`）登记活动会话 `pid` 与 `sessionId`（[session_scan.rs](/src-tauri/src/agent_status/session_scan.rs) 退出检测已读取该目录）。
   - 但 [session_process.rs](/src-tauri/src/agent_status/session_process.rs) 的 `running_sessions(home_dir)` 仅读取 `~/.claude/sessions`，导致 [focus.rs](/src-tauri/src/agent_status/focus.rs) 的 `process_chain` 对 WorkBuddy 会话恒返回空链，无法顺着父进程链直接定位承载该会话的 WorkBuddy 主窗口进程。
2. **进程名 / Bundle 兜底与编辑器宿主表不全**：
   - Windows 侧 `workbuddy::EXES` 仅硬编码匹配 `WorkBuddy.exe`、`WorkBuddyAI.exe`（未覆盖带空格的 `WorkBuddy AI.exe` 或国内版客户端变体）；macOS 侧 `BUNDLES` 仅列了 `("com.workbuddy.workbuddy-ai", "workbuddy ai")`（缺国内版 Mac bundle id 及 `"workbuddy"` 应用名）。
   - [window_focus.rs](/src-tauri/src/agent_status/window_focus.rs) 的 `EDITORS` 未包含 `"workbuddy"` / `"workbuddy ai"` / `"workbuddyai"`，导致多窗口时 `best_window` 得分为 `0`、无法按工作区目录或会话标题挑对窗口。
3. **无标题窗口过滤与最小化 / 托盘隐藏唤醒缺失**：
   - Windows 侧 `focus_session_window` 直接跳过了 `title.is_empty()` 或收起到系统托盘（`!is_visible`）的窗口；当 WorkBuddy 自绘窗口无原生标题文本或最小化隐藏到托盘时，直接返回 `not found`（「没找到对应的窗口」），无法恢复并唤醒界面。

改法：
- 在 [session_process.rs](/src-tauri/src/agent_status/session_process.rs) / [focus.rs](/src-tauri/src/agent_status/focus.rs) 补齐 WorkBuddy 各配置目录下 `sessions/*.json` 的 `pid` 查找与 `ancestor_chain` 构造；
- 核实并补全双端 WorkBuddy 国内版与国际版的进程名 / Bundle ID，加入 [workbuddy.rs](/src-tauri/src/agent_status/workbuddy.rs) 与 [window_focus.rs](/src-tauri/src/agent_status/window_focus.rs) 的 `EDITORS` 列表，支持多窗口按目录与标题选窗；
- 对已命中的目标桌面进程放宽空标题顶层主窗口过滤，并在主窗口最小化或隐藏至托盘时恢复显示并前置激活；未命中时在 `agent-focus.log` 补充候选窗口诊断摘要。

## 验收

- Windows 与 macOS 上打开 WorkBuddy（国内版 / WorkBuddy AI），点击岛上会话行或右键「跳到窗口」可稳定唤起并前置对应的 WorkBuddy 窗口（多窗口时优先选中对应项目窗口），不再误报「没找到对应的窗口」
- WorkBuddy 最小化或收起到托盘后，点击「跳到窗口」能够重新唤出界面
- 补充 `session_process`、`window_focus` 与 `workbuddy` 单元测试，同步更新 [harnesses.md](/docs/architecture/agent/harnesses.md) 与 [agent-harnesses.md](/docs/research/agent-harnesses.md)
- `pnpm check`、`pnpm build`、`pnpm heavy -- cargo test --manifest-path src-tauri/Cargo.toml` 与双端 CI 全部通过
