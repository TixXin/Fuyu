## 说明

用户群反馈「优化下 agent 打开相应对话窗口吧」「WorkBuddy 还是不太行」。A16（#862）已经能在 Agent 页点 WorkBuddy 会话时找到窗口、从托盘唤出、找不到时说明原因，但窗口里停在哪条对话由 WorkBuddy 自己决定。这项要做到点哪条会话就打开 WorkBuddy 里的那一条。

1. 查 WorkBuddy（国内版和 WorkBuddy AI，Electron）能否从外部打开指定会话：URL scheme / deep link（Info.plist、注册表里的协议，安装包 asar 里 open-url / second-instance 的处理）、启动参数、本地 IPC / HTTP；会话 id 和我们读的 `~/.workbuddy*` 会话记录怎么对应。A16 读过 WorkBuddy AI 5.11.4 Mac 安装包，从那里接着看。
2. 有办法：点会话先唤出窗口，再打开那条会话。没办法：行内说明只能到窗口（沿用 `agent-focus-window-only`），调研结论写进 `docs/research/`。
3. 顺带看 Antigravity、Cursor 等图形界面代理有没有同样的办法，有就列成后续任务，这次不做。
4. 按 `fuyu-agent-harness` skill 走；`platforms.md` 的 WorkBuddy 行写清实测情况，Windows 测不了留实测清单，和 A16 的清单合在一起。

## 验收

- Mac 上 WorkBuddy AI 开着两条以上会话时，点其中一条，WorkBuddy 切到那一条
- 做不到时有 `docs/research/` 结论，行内说明只能到窗口
