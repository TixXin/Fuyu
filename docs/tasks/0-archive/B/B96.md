## 说明

B74 Windows 实测（2026-11-27）第 2 条不过：退出浮屿、删掉 `%USERPROFILE%\.fuyu\fuyu-agent-*.{cmd,ps1}` 后 `claude -p … --include-hook-events`，Claude Code 的 5 个浮屿钩子全部 `exit_code=127, outcome=error`（bash 报 No such file，PowerShell 报 -File 文件不存在，中文报错在 Claude 里还是 GBK 乱码）。`src-tauri/src/agent_status/claude_hooks.rs` 的 Windows 版 `claude_code_running_command` / `claude_code_powershell_command` 没有存在性守卫，Mac/Linux 版有 `[ -f … ] && exec … || exit 0`。Codex、Cursor、Gemini/Antigravity、Grok、Copilot（PowerShell 那条）都有守卫，实测静默返回 0。浮屿运行时约 1 分钟内会自动写回脚本，所以只影响浮屿已卸载或家目录被删、配置还在的情况。

改法：Windows 上 Claude Code 经 Git Bash 执行钩子，两种命令都包一层 `[ -f "<脚本>" ] && <原命令> || exit 0`，并确认没有 Git Bash 时的执行方式；识别受管条目的逻辑要同时认新旧写法，「自动更新旧版钩子」能把旧命令换掉。

## 验收

- Windows 上删掉钩子脚本后 `claude -p "hi" --output-format stream-json --verbose --include-hook-events` 里所有浮屿钩子 `exit_code=0`、无 stderr
- 脚本在时状态灯、审批、会话照常工作
- 旧写法的钩子在升级后被自动换成新写法，移除钩子时新旧写法都能删干净

## 备注

- 2026-11-27 定做法：B83 要求同一条命令在 Git Bash、PowerShell（Cursor 读 `~/.claude/settings.json` 时用它执行）、cmd.exe 下都能跑，所以不能用 bash 的 `[ -f … ]`。cmd 的 `if exist` 在 Git Bash 下会被 MSYS 改写 `/c` 和内层引号，实测不通。最后用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "if (Test-Path -LiteralPath '<脚本>') { & '<脚本>' claudeCode … }"`：三种 shell 原样交给 PowerShell，stdin 和参数都到脚本。代价是运行钩子多约 140 ms（Git Bash 下 5 次平均：直接调 .cmd 约 50 ms，经 PowerShell 约 190 ms）。退出码只剩 0 / 1，脚本本来就不用 2。路径含 `$` 或反引号时退回旧的 `-File` 写法。
- 2026-11-27 Windows 实测（tixxin-computer，Claude Code，Git Bash）：把 `settings.json` 里浮屿钩子换成新写法后 `claude -p … --include-hook-events`，脚本在、脚本不在两种情况下 5 个钩子都是 `exit=0 outcome=success`、stderr 为空，回复正常；`settings.json` 已原样恢复（哈希一致）。Windows 上 `agent_status::claude_` 的 Rust 单元测试 31 个全过，含新加的 `windows_hooks_are_guarded_and_fail_open_when_the_script_is_missing`。
- 旧写法：启动时 `has_unguarded_windows_hooks` 发现就整套重写；识别受管条目靠脚本名，新旧写法移除钩子时都能删掉（`unguarded_windows_hooks_from_older_versions_are_found`）。
- 没测：没装 Git Bash 的 Claude Code（PowerShell 跑钩子），按上面三种 shell 的实测推断可用。
