## 说明

把月之暗面的 Kimi Code CLI（新版 TypeScript 的 `kimi`，仓库 `MoonshotAI/kimi-code`）接进 Agent 页。调研见 [china-coding-agents.md](/docs/research/china-coding-agents.md) 的 Kimi Code 一节和下面的核实结果。

核实（2026-11-15，按 `MoonshotAI/kimi-code` 源码；本机没装 CLI）：

- 会话以 `<KIMI_CODE_HOME 或 ~/.kimi-code>/sessions/<工作区>/<会话>/state.json` 为准（旧版在 `session-meta/state.json`）。`session_index.jsonl` 在当前版本只由旧版迁移器（`packages/migration-legacy`）写，新会话不一定在里面，所以扫目录、索引只作补充。
- `state.json` 有 `title`、`titleKind`（custom 是用户改的名）、`lastPrompt`、`cwd`、`archived`、`custom.child_session_kind`、`lastTurnReason`（completed / cancelled / failed）。
- 进行中看 `agents/main/wire.jsonl`：最后一个 `turn.prompt` 之后没有 `turn.ended` / `turn.cancel` 就是在跑；最近回复是 assistant 的 `context.append_message`，模型在 `usage.record.model`。
- 钩子是 `config.toml` 的 `[[hooks]]`，每条只认 `event`、`matcher`、`command`、`timeout`；Windows 上经 Node `shell: true`（cmd.exe）执行。`PermissionRequest` 只通知不等结果；能挡的 `PreToolUse` 在权限检查之前、对每次工具调用都触发，只认 deny。
- 旧版 `~/.kimi/`（Python kimi-cli）不读：仓库已归档，新版第一次启动会把配置和会话迁到 `~/.kimi-code/`。
- Kimi 桌面版（本机 3.2.21）内嵌的运行时用自己的目录 `~/Library/Application Support/kimi-desktop/daimon-share/daimon/runtime/kimi-code/home/`，`config.toml` 由桌面写入、没有 `[[hooks]]`，会话索引在桌面自己的 sqlite 里。不往里装钩子：没法确认桌面会不会覆盖这份配置、内嵌运行时会不会执行外部钩子。

做法：

- 会话列表：上面那些字段，子会话和已归档的不列。
- 钩子：在 `config.toml` 末尾写一段 `# BEGIN/END Fuyu Agent Status Hooks (Kimi Code)` 包住的 `[[hooks]]`：UserPromptSubmit 亮灯，Stop / Interrupt 记完成，StopFailure 记失败，PermissionRequest 存输入算「等你」。只在目录存在时装；用户把 `hooks` 写成行内数组时报错不改。改完要开新会话才生效。
- 岛上审批不做：`PermissionRequest` 不能回结果，挂 `PreToolUse` 会让连自动放行的工具调用都要在岛上点，而且「允许」也只是交回 Kimi 再问一次。岛上只亮「等你」，点进去跳到终端。
- 用量环复用已有的 Kimi（`/coding/v1/usages`，填 API key）；不读 CLI 的 OAuth 凭据（`credentials/<name>.json`，刷新归 CLI 管，本机也没法核对格式）。
- 回复标记写 `~/.kimi-code/AGENTS.md`。
