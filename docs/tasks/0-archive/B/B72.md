## 说明

针对 #737 提出的五家代理岛上审批诉求，完成上游源码（`deepseek-ai/deepseek-harness`、`MoonshotAI/kimi-code`）、官方文档（`docs.factory.com`、`docs.trae.ai`、Grok CLI `1.0.77`）以及五个主流开源项目（`CodeIsland`、`Open Island`、`Ping Island`、`Clawd on Desk`、`dsh-island`）的横向调研，详见 [agent-harnesses.md](/docs/research/agent-harnesses.md#五家代理岛上审批复查与开源项目横向对比2026-11-17-追加issue-737)。

按调研结论拆为三个独立子任务推进，Grok CLI 与 Kimi Code 因上游钩子机制不支持外部代批维持现状：

- **B72.1（DeepSeek Harness）**：放弃只认 `deny`/`ask` 且在 DSH 0.2.1+ 已不再默认内置的 `@deepseek-ai/dsh-hooks-claude-code` 桥接包，改由浮屿在 `~/.fuyu/dsh-plugin/` 生成原生 Cordis 插件监听 `approval/request` waterfall（`prepend: true`），完整支持 `allowed-once`（允许）/ `rejected`（拒绝）/ `next()`（交回 DSH），并联动 `req.signal` 取消。
- **B72.2（Factory Droid）**：启用 `claude_compat.rs` 预留的 `Reply::PreToolUse`，对命令与写文件类工具挂 `PreToolUse` 审批钩子（`/droid/pre-tool-use`），支持 `allow` / `deny` / `ask`（交回终端）。
- **B72.3（TRAE / TRAE CN）**：将 `trae.rs` 的 `APPROVED_TOOLS` 从 `RunCommand` 扩充到写改删文件与 MCP 工具（不拦只读工具），忽略 TRAE 主会话自带的 `agent_id`（避免误判为子代理），并在设置与文档中说明配合 TRAE「自动执行」模式免去二次点击的用法。

## 结论（2026-11-17）

- **Grok CLI（B57）不做岛上审批**：无阻塞式 `PermissionRequest`；`PreToolUse` 在权限流水线第 1 步执行，文档写明回 `allow` 仅代表「钩子不拦截」，不会跳过第 5 步的终端确认框；且 `ls`、`git status` 等只读命令也走 `run_terminal_command`（在第 4 步才按白名单免确认），挂阻塞 `PreToolUse` 会把每次只读命令都卡在岛上。五家开源项目一致只做状态与通知。
- **Kimi Code（B52）不做岛上审批**：`agentExternalHooksService.ts` 中 `PermissionRequest` 为 `fireAndForget`；`runHook.ts` 的 `structuredOutput()` 只将 `permissionDecision === 'deny'`（或退出码 2）判为拦截，返回 `allow` 只算未拦截、照常进入 `AgentPermissionGate` 弹终端确认框；插件系统无进程内权限拦截接口。五家开源项目一致只做状态与通知。
