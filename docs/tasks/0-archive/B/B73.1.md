## 说明

方案见 [agent-hooks-uninstall-cleanup.md](/docs/research/agent-hooks-uninstall-cleanup.md) 第 1、4 步。

在 `src-tauri/src/agent_status/` 补齐统一的钩子与外部配置卸载能力、SSH 远端移除、应用卸载清理接口及脚本缺失 Fail-Open 守卫：

1. 在 `harness::Hooks` 中增加 `uninstall: fn(&HookEnv) -> Result<(), String>`，为全部 18 家内置代理实现无损卸载（JSON 事件数组剥离并在变空时移除空 `hooks` 键、Antigravity 移除 `"fuyu"` 键、Codex / Kimi TOML 标记块剥离、`grok` / `copilot` / `opencode` / `mimo` / `pi` 独占钩子与插件文件删除、DSH `dsh-plugin/` 与受管 `cordis.patch.yml` 挂载清理），保留用户自己的其他 hooks 与配置。
2. 实现 `remote_setup::uninstall_hooks` 清理已启用 SSH 远程主机上的 Claude Code / Antigravity 钩子，并在 `agent_status/mod.rs` 暴露 Tauri 命令 `uninstall_agent_status_hooks(app: AppHandle) -> Result<AgentHooksUninstallResult, String>`（返回 `{ removedAt: i64, remotes: Vec<RemoteResult> }`；仅卸载钩子与脚本，不动应用内单独开关的回复标记）。
3. 暴露 `pub(crate) fn cleanup_for_app_uninstall(app_dir: &Path, delete_data: bool)` 供 `B73.3` 调用：清理全部 18 家本机钩子/插件与全部本机提示词回复标记（含清空后的 `~/.grok/rules/fuyu-island.md`）；`!delete_data` 时在 `app_dir` 记录 `uninstalled-hooks.json` 并在下次启动时自动恢复钩子与回复标记；`delete_data` 时顺带删除 7 款 VS Code 系编辑器 `extensions/` 下的 `tixxin.fuyu-*` 副本。
4. 钩子命令包裹脚本存在性守卫（Windows `if exist`、Unix `[ -f ... ]`，缺失时静默 `exit 0`）；`fuyu-opencode-plugin.js`、`fuyu-pi-extension.js`、`fuyu-dsh-plugin.js` 在 `FUYU_DIR` 不存在时不再调用 `mkdir` 重建顶层目录。

## 验收

- `harness::Hooks` 强制 18 家代理全部提供 `uninstall`，单测覆盖各配置形态只删浮屿受管项且保留用户自有项
- Tauri 命令 `uninstall_agent_status_hooks` 可移除本机与已启用 SSH 远程主机的钩子及脚本文件
- `cleanup_for_app_uninstall` 支持保留数据记录恢复标记及启动自动恢复、彻底删除时同步清理回复标记与编辑器扩展
- 生成的 Windows / Unix 钩子命令在脚本缺失时退出码为 `0`；外部 JS 插件在 `FUYU_DIR` 被删后不重建顶层目录
- `cargo test`、双平台 `clippy`（含 `x86_64-pc-windows-gnu`）、`pnpm check:size` 与 `pnpm check:secrets` 全部通过
