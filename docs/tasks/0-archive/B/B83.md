## 说明

外部用户反馈（#889）：在岛上安装或修复 AI 钩子后，所有 agent 都报 `Hook blocked with message: curl: try 'curl --help' for more information`，用不了。

`curl: try 'curl --help'` 是 curl 没拿到参数或参数不认时的输出，退出码 2；Claude Code 系的 agent 把退出码 2 当成「钩子拦截」。最可疑的是 `src-tauri/src/agent_status/claude_hooks.rs` 的活动钩子：`claude_code_hook_entry` 写的是 `{"command": "curl.exe", "args": [...]}`（Mac 上是 `/usr/bin/curl`）。不认 `args` 字段的 agent 或旧版 Claude Code 只会执行一个光秃秃的 `curl`，正好是这个报错；Claude Code 的分支（WorkBuddy、CodeBuddy、Qoder 等）可能都不认。另一个可能是 Mac 审批脚本 `fuyu-agent-approval.sh` 里 `--connect-timeout 0.3` 这类参数在旧 curl 上不认，但脚本把 curl 的 stderr 扔掉了，可能性小。做之前先加载 `fuyu-agent-harness` skill，并在 issue 里等报告人回系统、浮屿版本、出错的 agent 和版本。

## 验收

- 找到并修好原因：钩子在报告人用的 agent 和版本上不再拦截，也不再输出 curl 的用法提示
- 写给某家 agent 的钩子格式，只用它确实支持的字段；不支持 `args` 的改回单条命令字符串
- 钩子出任何错都不拦 agent（退出码不是 2），单元测试覆盖
- issue 里告诉报告人临时解法（设置 → Agent →「移除钩子」）和修复所在的版本

## 备注

**为什么拿 `CURSOR_VERSION` 判断「是 Cursor 在执行钩子」**（2026-11-19 核对，本机 Cursor 3.30.14，`/Applications/Cursor.app`）：

- 在安装包里所有 `.js`、`.cjs`、`.mjs` 中搜 `CURSOR_VERSION`，只有三处把它设成环境变量，而且都在拼钩子环境的函数里：`out/vs/workbench/workbench.desktop.main.js`（以及同样内容的 `workbench.glass.main.js`）的 `_buildHookEnvironment`，`extensions/cursor-agent-host/dist/4098.js` 的 `buildHookEnvironment`，`extensions/cursor-agent-host/dist/agent-host-daemon/dist/bin/daemon.cjs` 的 `buildHookEnvironment`。它们都和 `CURSOR_PROJECT_DIR`、`CLAUDE_PROJECT_DIR` 写在同一个对象里。`daemon.cjs` 里另一处是遥测标签名 `cursor_version`，不是环境变量。
- 内置终端那条路上没有：主进程 `out/main.js`、终端宿主 `out/vs/platform/terminal/node/ptyHostMain.js`、终端的 shell 集成脚本（`out/vs/workbench/contrib/terminal/common/scripts/shellIntegration*`）里都没有 `CURSOR_VERSION`。非 JS 文件和 `MacOS/`、`Frameworks/` 下的二进制里也搜不到。
- 所以在 Cursor 终端里跑的 Claude Code，它的钩子不带 `CURSOR_VERSION`，照常计入 Claude Code；只有 Cursor 自己执行 `~/.claude/settings.json` 里的钩子时才带。以后 Cursor 如果把它加进终端环境，就要改成看钩子 stdin 里 Cursor 特有的字段（例如 `cursor_version`、`conversation_id`）。实测清单第 2 条顺带确认：在 Cursor 终端里开 Claude Code，岛上照常亮灯。
