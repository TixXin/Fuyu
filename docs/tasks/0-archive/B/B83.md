## 说明

外部用户反馈（#889）：在岛上安装或修复 AI 钩子后，所有 agent 都报 `Hook blocked with message: curl: try 'curl --help' for more information`，用不了。

`curl: try 'curl --help'` 是 curl 没拿到参数或参数不认时的输出，退出码 2；Claude Code 系的 agent 把退出码 2 当成「钩子拦截」。最可疑的是 `src-tauri/src/agent_status/claude_hooks.rs` 的活动钩子：`claude_code_hook_entry` 写的是 `{"command": "curl.exe", "args": [...]}`（Mac 上是 `/usr/bin/curl`）。不认 `args` 字段的 agent 或旧版 Claude Code 只会执行一个光秃秃的 `curl`，正好是这个报错；Claude Code 的分支（WorkBuddy、CodeBuddy、Qoder 等）可能都不认。另一个可能是 Mac 审批脚本 `fuyu-agent-approval.sh` 里 `--connect-timeout 0.3` 这类参数在旧 curl 上不认，但脚本把 curl 的 stderr 扔掉了，可能性小。做之前先加载 `fuyu-agent-harness` skill，并在 issue 里等报告人回系统、浮屿版本、出错的 agent 和版本。

## 验收

- 找到并修好原因：钩子在报告人用的 agent 和版本上不再拦截，也不再输出 curl 的用法提示
- 写给某家 agent 的钩子格式，只用它确实支持的字段；不支持 `args` 的改回单条命令字符串
- 钩子出任何错都不拦 agent（退出码不是 2），单元测试覆盖
- issue 里告诉报告人临时解法（设置 → Agent →「移除钩子」）和修复所在的版本
