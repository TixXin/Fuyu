## 说明

全网调研见 [agent-harnesses.md](/docs/research/agent-harnesses.md#五家代理岛上审批复查与开源项目横向对比2026-11-17-追加issue-737)。

针对 TRAE 和 TRAE CN（B29）的岛上审批补齐三件事：
1. **扩充拦截工具**：目前 `src-tauri/src/agent_status/trae.rs` 的 `APPROVED_TOOLS` 只拦 `"RunCommand"`，将其扩充为覆盖命令执行、文件写改删与 MCP 工具的正则（如 `"^(RunCommand|Bash|Write|Edit|MultiEdit|StrReplace|CreateFile|DeleteFile|WriteToFile|ReplaceInFile|mcp__.*)$"`），同时不拦只读工具（避免每次读文件都弹窗）。
2. **忽略 TRAE 主会话自带的 `agent_id`**：CodeIsland PR #341 实测发现 TRAE / TRAE CN 的主会话在每个钩子事件里都会附带 `agent_id`（如 `"solo_agent"`、`"builder_v3"`），在 `HookInput::parse_for` 等处对 `Trae` / `TraeCn` 忽略 `agent_id`，避免主会话被当成子代理处理。
3. **手动确认模式的配对用法说明**：TRAE 官方文档规定工具处于「手动确认」模式时钩子回 `allow` 不会跳过 IDE 确认框；在设置说明与文档（`agent-status-hooks.md`、`harnesses.md`、`platforms.md`）中写明：将 TRAE 设为「自动执行」并开启岛上审批，即可在岛上点允许直接执行（无需回 TRAE 再点一次）、点拒绝拦截、点交回 TRAE（回 `ask`）才在 IDE 弹窗。

## 验收

- `trae.rs` 的 `PreToolUse` 审批 matcher 覆盖命令、写改删文件与 MCP 工具，旧 `RunCommand` 钩子显示为过期可升级
- TRAE / TRAE CN 的钩子输入带 `agent_id` 时不会被误标为子代理审批
- 文档与设置提示写清配合 TRAE「自动执行」免二次点击的用法，单测通过
