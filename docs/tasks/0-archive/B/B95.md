## 说明

B92 Windows 实测（2026-11-27）发现：Claude Code 在 Windows 上经 Git Bash 运行 `statusLine.command`，调用链是 `claude.exe → bash.exe → bash.exe → powershell（fuyu-claude-statusline.ps1）→ cmd.exe → 原状态栏命令`。脚本找 bash 时用 `Get-Command git.exe` 上退两级拼 `bin\bash.exe`，而 Git Bash 里 `git.exe` 解析到 `Git\ucrt64\bin\git.exe`（老版本 `mingw64\bin`），拼出的 `Git\ucrt64\bin\bash.exe` 不存在，于是退回 cmd.exe。bash 语法的原状态栏（claude-hud、`~/.claude/statusline.sh`、带 `$(...)` 或单引号的命令）显示为空或报错；cmd 能跑的命令正常，中文、✓ 编码和行数都对。

改法：往上找到含 `bin\bash.exe` 的 Git 根（兼容 `cmd\`、`ucrt64\bin\`、`mingw64\bin\`、`clang64\bin\`），优先用 `$env:EXEPATH` 等 Git Bash 已给出的线索；同步看 `.sh` 版有没有类似假设。

## 验收

- Windows 上 Claude Code 配 bash 语法的原状态栏（例如 `bash -c '…$(…)…'`）照常显示，调用链里原命令由 bash.exe 执行
- 从 cmd、PowerShell、Git Bash 三处调用脚本结果一致
- 单元测试覆盖 git.exe 在 `cmd\`、`ucrt64\bin\`、`mingw64\bin\` 三种位置

## 备注

- 2026-11-27 改法：`Find-GitBash` 依次看 `CLAUDE_CODE_GIT_BASH_PATH`、`EXEPATH`（`bin\bash.exe` 或 `bash.exe`）、从 `git.exe` 所在目录往上最多 4 级找 `bin\bash.exe`。`.sh` 版直接用 `/bin/sh`，没有同类假设。
- 2026-11-27 Windows 实测（tixxin-computer）：原状态栏设为 `echo "x=$(echo hi) 中文"`，新脚本经 B96 的守卫命令从 Git Bash、PowerShell、cmd 三处调用，都输出 `x=hi 中文`，退出码 0。Windows 上单元测试 `the_script_finds_git_bash_from_any_git_exe_location` 覆盖 `cmd\`、`ucrt64\bin\`、`mingw64\bin\` 三种位置，通过。
