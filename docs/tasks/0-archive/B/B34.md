## 说明

B30 让 opencode 2.x 的会话在岛上显示「等你」并能在岛上审批，靠的是后台服务的 `service.json` 和 HTTP 接口。opencode 1.x 没有后台服务，`opencode --standalone` 的私有服务不写 `service.json`，这两种都拿不到待批请求。1.x 要做得写一个 1.x 插件（`event` + `permission.ask` 钩子）写事件文件、挂起等岛的结果，接口和 2.x 不兼容。调研见 [agent-harnesses.md](/docs/research/agent-harnesses.md)「opencode」一节。

## 验收

- 1.x 的会话能显示「等你」，能在岛上允许 / 拒绝；或者决定不做，在 `docs/architecture/agent/harnesses.md` 写明原因
- `--standalone` 能支持就支持，不能就在文档里写明

## 提交

- `feat(agent-status): opencode 1.x shows waiting and is approved on the island through a plugin`

## 结论

- 对照上游 v1.19.5 源码：插件类型里有 `permission.ask`，但权限模块（`packages/opencode/src/permission/index.ts`）从不调用它，只发 `permission.asked` / `permission.replied` 事件。所以插件只用 `event` 钩子：收到 `permission.asked` 写等待文件 `agent-notifications/opencode-plugin-<id>.json`，同时 POST 到岛的审批接口 `/opencode/permission` 等结果；岛上点了，插件用自己拿到的 `client`（连本进程的服务）回复 opencode。TUI 照样弹框，谁先回谁算；TUI 先回时插件断开对岛的请求、删等待文件，岛上的卡片跟着关。
- 插件文件 `src-tauri/src/agent_status/hooks/fuyu-opencode-plugin.js`，`include_str!` 编进岛，「安装/修复」把岛数据目录写进去，装到 opencode 配置目录的 `plugin/fuyu-island.js`（认 `XDG_CONFIG_HOME`）；没装 opencode（配置目录和数据目录都没有）时不装。默认导出 `{ id, server, setup }`：1.x 用 `server`，2.x 也扫这个目录，按源码会把空的 `setup` 当成什么都不做的插件加载（2.x 未实测）。
- `--standalone`（2.x）不做：TUI 起子进程 `opencode serve --stdio --port 0`，随机密码只在子进程的环境变量 `OPENCODE_PASSWORD` 里，地址只写到和 TUI 之间的管道，不写 `service.json`。岛要拿到只能读别的进程的环境变量，不做。以后要支持就写 2.x 服务端插件（`setup` 里订阅权限事件、回复），另开任务。
- 实测：Mac 上用 1.19.5（装在临时目录、隔离的 XDG 目录、假的模型和假的岛审批接口）跑通了允许、拒绝带理由、TUI 先回三种情况。真岛、真 TUI、Windows、2.x 加载这个插件没测，列进实测清单。
