## 说明

新手引导在「连接 AI 代理」之后加一幕「推送到手机」，基于 cc-connect：

1. 安装 cc-connect：本机和 SSH 远程页打开的每台电脑，已装的跳过；远程由岛在本机下载 Linux 版、校验 sha256 后经 SSH 传上去。
2. 建项目：先问用户是否同意给每台电脑上的每个 AI 代理各建一个 cc-connect 项目（默认名 `<电脑>-<代理>`，可以去掉不要的）。
3. 建机器人：推荐飞书（扫码就能建好），也可用 Telegram、Discord；微信标成「只能用来对话、不推荐」。每个平台附建机器人的网页和官方教程链接，提示机器人名字和项目名一致。
4. 同一页里，每个项目后面直接接机器人：飞书扫码、Telegram / Discord 贴 token，建一个接一个。
5. 测试：每个项目显示是否已收到手机发来的消息，可以发一条测试消息。

远程电脑需要新的原生能力：远程装 cc-connect、远程写 `~/.cc-connect/config.toml` 加项目并重启远程的 cc-connect、远程跑飞书扫码。

起因：用户要求（2026-11-15），第一次用的人不知道手机推送要先装 cc-connect、建项目、建机器人。issue #474 起初标成 B50，和 #461 的 B50 撞号，2026-11-15 改成 B59。

## 验收

- 引导里能走完上面五步，本机和远程都能建项目并接上机器人
- 远程写配置前备份，失败时还原
- 回归页覆盖这一幕，Rust 单元测试覆盖远程脚本

### 现状（读代码得出）

- **新手引导**（`src/windows/onboarding/`）现在有 6 幕：hello → shape → outfit → play → permissions（只在 Mac）→ release。**没有「连接 AI 代理」这一幕**，只在最后一幕 release 里有个「连接 AI 编程工具」按钮跳设置。所以新的一幕放在 release 之前（permissions 之后），只在用户选了「AI Agent」模块时出现，可以跳过。
- **本机 cc-connect 已经有大半**（`src-tauri/src/cc_connect/`，`src/features/cc-connect/`）：
  - 下载 Windows 版、校验 sha256（`install.rs`）；岛自己托管运行和重启（`runner.rs`）
  - 加项目：写 `~/.cc-connect/config.toml`，写前备份、失败还原（`config_file.rs`）；Telegram / Discord 贴 token 并检查、Telegram 自动找到发消息的人（`bots.rs`）
  - 飞书扫码建机器人（`feishu.rs`，跑 `cc-connect feishu new --qr-image`，失败还原配置）
  - 读每个项目收到过哪些聊天（`chats.rs`）、发消息（`send`）
  - 设置里已有一个「新建项目」表单（`CcConnectSetup.tsx`、`FeishuSetup.tsx`）
- **远程只有只读**（`cc_connect/remote.rs`）：经 SSH 读状态（程序在哪、在不在跑、项目和聊天）、发消息。**没有**远程安装、远程加项目、远程飞书扫码、远程启动 / 重启。
- **两处限制**：
  1. 整个 `cc_connect` 模块只在 Windows 编译（`lib.rs` 里 `cfg_attr(not(windows), path = "cc_connect/unsupported.rs")`），Mac 上全部是「不支持」。G1.8 把它留下了没做。
  2. 能建项目的代理只有 Claude Code 和 Codex（`config_file.rs` 的 `AGENTS`、`api.ts` 的 `CC_CONNECT_SETUP_AGENTS`）。

### 新的 Rust 原生能力（都放在 `src-tauri/src/cc_connect/`）

| 能力 | 做法 |
|---|---|
| 检测每台电脑装了哪些代理 | 本机按 PATH 找、远程 `command -v`（经登录 shell）；只列 cc-connect 支持、岛也认识的代理（名单由任务会话对照 cc-connect 文档定，至少 Claude Code、Codex） |
| 远程装 cc-connect | 远程先 `uname -m`；岛在本机下载对应的 Linux 包，按 `checksums.txt` 校验 sha256，再用现有的 `run_ssh`（脚本走 stdin）把 base64 包进脚本传上去，装到 `~/.local/bin/cc-connect`；已装的跳过 |
| 远程加项目 | 脚本里先把 `~/.cc-connect/config.toml` 复制成带时间戳的备份，追加项目块（复用 `config_file::project_block`，文本走 base64 不进 shell），失败时用备份还原；token 不出现在命令行 |
| 远程启动 / 重启 cc-connect | 默认 `pkill -x cc-connect` 后 `setsid nohup cc-connect --config … >~/.cc-connect/fuyu.log 2>&1 &`；状态读取已能判断在不在跑 |
| 远程飞书扫码 | 一条长 SSH 会话跑 `cc-connect feishu new --qr-image <远程临时文件> --set-allow-from-empty`，逐行读输出（URL、allow_from、✅ / Error）；二维码图片另用一次 `run_ssh` 以 base64 取回；取消或失败时结束远程进程并还原配置。前端沿用 `FeishuProgress` 的形状 |

都配 Rust 单元测试：脚本内容（引号、base64、备份和还原的分支）、输出解析。**不改 `src-tauri/src/agent_status/`**（B50 正在改那里），只调用它已公开的 `run_ssh` 和 `remote_hosts`。

### 前端这一幕怎么拆

新目录 `src/windows/onboarding/push/`，一个 `PushAct` 带五个小步骤，上方一条小进度：

1. **安装**：列出本机和 SSH 远程页里开着的每台电脑，各显示「已装 / 未装 → 安装」。
2. **建项目**：先一句话问是否同意给每台电脑每个代理各建一个项目；列出 `<电脑>-<代理>` 的勾选列表（名字可改，可去掉）。这一步只定名单，不写配置。
3. **选平台**：飞书（推荐，扫码即可）、Telegram、Discord；微信标「只能对话、不推荐」、不可选。每个附建机器人的网页和官方教程链接，提示机器人名字和项目名一致。
4. **接机器人**：同一页里每个项目一行，后面直接接：飞书扫码 / Telegram、Discord 贴 token（复用 `bots.rs` 的检查和找发消息的人），接好一个才真正写配置，建一个接一个。
5. **测试**：每个项目显示「已收到手机发来的消息」与否（复用状态里的 chats），可以发一条测试消息。

本机和远程走同一个「一台电脑」的接口（`push/targets.ts`：本机调现有命令，远程调新命令），界面不分两套。文案中英文都有（新文件 `src/i18n/sections/onboarding-push.ts`），窄窗口不溢出。回归页 `tests/regression/onboarding-push.tsx` 覆盖五步，mock 一台本机加一台远程。
