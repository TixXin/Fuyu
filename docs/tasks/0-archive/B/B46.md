## 备注

核对结果（2026-11-15，Mac，只读）：

- Code 页：`claude-code-sessions` 里 84 个 `local_*.json`，`cliSessionId` 在 `~/.claude/projects/` 下 84 个都有对应的 jsonl（`entrypoint: claude-desktop`，jsonl 里也写了 `custom-title`）。#180 里 Windows 上 6–7 月的旧会话对不上，当前 Windows 版本要复测（实测清单）。
- Cowork：本机 `local-agent-mode-sessions` 里没有会话，只有 `scheduled-tasks.json`。
- Codex：`threads` 610 个，其中 251 个归档、334 个是子代理线程；`thread_history_1.sqlite` 是 WAL 模式、旁边没有 `-shm` / `-wal`，普通只读打开会失败，所以用 `immutable`。本机 Codex 最后一次用是 2026-11-12，岛的时间窗最长 24 小时，所以现在 Agent 页本来就不会有 Codex 会话；放开时间窗的探测结果见下。
- 放开时间窗的探测（临时的 ignored 测试，没有提交）：`threads` 里不归档、不是子代理的 92 个会话，91 个的 rollout 已经不在；这 91 个现在都能从 sqlite 拿到标题（Codex 起的名字）、模型、档位、最后一句提问和回复，例如「追踪并提交 .agents 文件夹」/ `claude/claude-opus-5-5` / `xhigh` / 提问「.agents 文件夹也需要追踪和提交」。Claude 桌面 App 时间窗内 96 个 Code 页会话，Agent 页 24 小时窗口里的 12 条都是 `claudeCode`、标题取自桌面 App，没有重复。

## 结论

- Codex：新文件 `codex_threads.rs` 只读打开 `~/.codex/state_5.sqlite`，按时间窗列 `threads`（跳过归档、子代理和 guardian 线程）。rollout 还在的照旧读 rollout，并且不再限于最近两天的日期目录；rollout 不在的（2026-11-12 迁移进 `thread_history_1.sqlite` 的）用 `threads` 的标题、目录、模型、档位，加上 `thread_items` 里最后一条提问和回复、`thread_turns` 最后一轮的状态。库不在或缺 `id` / `rollout_path` / `updated_at` 列时退回只扫 rollout。旁边没有 `-wal` 的库用 `immutable=1` 打开，不建 `-shm`、不加锁。
- Claude 桌面 App 的 Code 页：新文件 `claude_desktop.rs` 读 `claude-code-sessions/<组织>/<账号>/local_*.json`，按 `cliSessionId` 把桌面 App 里的标题、模型、档位并进 `~/.claude/projects` 里同一条会话，不另列。
- Cowork 不列，原因写给主 agent 收口进 `platforms.md` 和 `agent-status-hooks.md`。
