## 说明

#646：Windows 上的 Antigravity IDE（报告里写 2.7.0）里的会话岛上能看到，点会话却提示「没有找到对应窗口」。跳转时 Antigravity 按程序名 `antigravity` 找窗口（`src-tauri/src/agent_status/focus.rs` 的 `prefer_app`、`antigravity::APP`），新版改了可执行文件名或窗口标题的话可能对不上；先看报告人的 `agent-focus.log` 再定。

## 验收

- 用报告人的 `agent-focus.log` 或在装了 Antigravity IDE 2.x 的 Windows 上复现，确认没找到窗口的那一步
- 修好后 Antigravity IDE 2.x 的会话能跳到它的窗口，旧版 Antigravity 不受影响
- 回复并关闭 #646

## 提交

- `fix(agent-status): clicking an Antigravity IDE 2.x session finds its window by program name, product and folder (A10)`

## 结论（2026-11-16）

原因是 Antigravity IDE 2.x 的程序改名为 `Antigravity IDE.exe`，和写死的 `antigravity` 对不上；进程链也一直拿不到。别的开源项目的做法和建议修法见 [Antigravity 窗口调研](/docs/research/antigravity-window-focus.md)。

## 交接

- 2026-11-16 01:53：2026-11-16 issue 和 PR 总控：原因已确认，exe 是 Antigravity IDE.exe，浮屿 0.3.10-beta.2。报告人的 agent-focus.log：49 次里 48 次是 process=unknown, prefer=antigravity | not found，即进程链、程序名、标题匹配三步都没找到；1 次 focused 很可能切到了开着的 2.0（Antigravity.exe）。别的项目怎么做和建议修法见 docs/research/antigravity-window-focus.md：认一组程序名（antigravity / antigravity ide / antigravity-ide），用 transcriptPath 区分 IDE / 2.0 / CLI，用 workspacePaths 的文件夹名挑窗口；macOS 上同样对不上（Antigravity IDE.app）。顺带改 docs/features/agent-status-hooks.md 里 agent-focus.log 的位置（0.3.7 起在 %USERPROFILE%\.fuyu）。
- 2026-11-16 02:33 a10：进程链（process=unknown）没修：Antigravity 的钩子（fuyu-agent-running.cmd/.sh）只存事件输入，不写 agent-sessions/<id>.json，没有进程号；Claude 的 sessions 注册表也没有它。要修得在钩子脚本里记父进程号（.cmd 拿不到父进程号，得改走 ps1），且跑钩子的是 language_server 还是 node、能不能沿它找到 IDE 主窗口都没核实，没有 Windows 机器上的 IDE 2.x 没法验证。现在靠程序名 + transcriptPath + 文件夹名挑窗口，不依赖进程链。另：IDE 窗口名不在编辑器名单里，是按文件夹名比标题那步也失败的原因，已补。实测清单（本机 Mac 没装 IDE 2.x、没有 Windows）：1) Windows 上 IDE 2.x 的会话点了能跳到对应窗口；2) IDE 和 2.0 同时开时跳到 IDE；3) IDE 开两个项目窗口时跳到会话所在的那个；4) Mac 上 Antigravity IDE.app 能被激活
