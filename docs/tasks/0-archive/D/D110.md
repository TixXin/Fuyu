## 说明

issue 984：2d13584e9 改插件页时把 `.settings-stage--light :is(.plugins-v3__card)` 的右括号删掉了，打包后这条规则后面的样式都被吞掉，设置窗口不能滚动、底色丢失。esbuild 只报 warning，`pnpm check` 和构建都照常通过，所以漏进了 main。补上括号，再加一条检查拦住同类错误。

## 验收

- `PluginsV3SettingsPage.css` 的 `:is(` 配对，`pnpm build` 不再报 `css-syntax-error`
- 打包出的 `SettingsWindow-*.css` 括号配对，`.settings-stage` 的规则没被吞
- `pnpm check:css` 在 `pnpm check` 里，把这个括号删回去时它报出文件和行列
- Windows 真机上设置窗口能滚动、有底色（实测清单）

## 提交

- `fix(settings): close the :is( in PluginsV3SettingsPage.css so the settings window scrolls again (D110)`
- `chore(check): add check:css to catch unbalanced brackets in stylesheets (D110)`

## 备注

- 检查是手写的括号扫描（`scripts/check-css-syntax.mjs`），不用 esbuild：esbuild 只是 vite 的间接依赖，根目录 import 不到。它跳过注释、字符串、转义和不带引号的 `url()`，一个文件只报第一处；扫 `src/`、`packages/`、`plugins/v3/`、`scripts/`、`tests/`。
- 没修时它报 `src/windows/settings/PluginsV3SettingsPage.css:92:27  this "(" has no ")" before the "{" at 92:46`，其余 240 个文件没有误报。
- 回归页拦不住这类错误：开发服务器一个文件一个 `<style>`，坏的规则只废掉自己这一条；打包合成一个文件后才吞掉后面的规则。
- 实测清单的第 1、2 条，报告人在 issue 984 里已经用同样的改法在 Windows 11 上量过（`main` 高度 624px、底色 `rgb(19, 20, 23)`、滚轮 `scrollTop` 0 → 674）；本机没有重测。
