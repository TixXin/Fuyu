## 说明

针对 `flyl1u/fly-island#75` 在多音频端点与虚拟声卡环境下播放音乐持续占用 ~25% CPU（约 4 核）、线程数持续膨胀的同源问题排查（详见 [调研与修复计划](/docs/research/windows-media-audio-cpu.md)）：

虽然 [D52](/docs/tasks/0-archive/D/D52.md)（`24cbe95c`）已将 `on_media_thread` 改为常驻单线程并放宽前端定时轮询，但 Windows 原生侧仍存在三处高频高开销路径：
1. `read_system_audio_peak()`（播放时 500 ms、闲置时 `events.rs` 1.2 s、切歌 `sound_onset` 最高 15 ms）和 `read_master_volume()` 每次都重新调 `CoCreateInstance(MMDeviceEnumerator, CLSCTX_ALL)` 并遍历 3 个音频角色激活 `IAudioMeterInformation` / `IAudioEndpointVolume`；`system_levels` 每 5 秒强制重建音量回调订阅，`device_events` 每 1 秒枚举全部活跃音频端点属性库。
2. `events.rs` 将 `TimelinePropertiesChanged` 直接映射为无节流、无去重的 `Signal::Playback`，前端收到即调全量 `get_media_state`。
3. `get_media_state` 每次都重新调 `MediaSessionManager::RequestAsync()`、`TryGetMediaPropertiesAsync()`，且即使已有 SMTC 会话正在播放，仍无条件运行 `discover_fallback_sessions()`（遍历进程音频会话 + `CreateToolhelp32Snapshot` 全系统进程快照 + `EnumWindows` 全桌面窗口枚举）。

做法（对外命令与事件契约零变更，前端 1 行收口等 [D97.4](/docs/tasks/D/D97.4.md) 合入后衔接）：
1. **WASAPI 常驻端点缓存与 `IMMNotificationClient` 事件化**：在 `win32::audio` 改用 `CLSCTX_INPROC_SERVER`，封装无锁回调的 `IMMNotificationClient`（回调内仅递增原子代数，不加锁、不调 COM、不在回调内注销）；常驻缓存默认 `Multimedia`（回退 `Console`）端点的 `PeakMeter` 与 `OutputVolume`，平时轮询仅调微秒级的 `GetPeakValue()`；去掉 `system_levels` 5 秒强制重开与 `device_events` 1 秒盲扫端点。
2. **GSMTC 会话管理器常驻、进度事件节流与非 SMTC 兜底短路**：`media-com-worker` 线程局部常驻缓存 `MediaSessionManager`（带错误重连冷却）；`events.rs` 拆分 `TimelinePropertiesChanged`（匀速推进 ≥1.5s 节流、seek 跳变即时放行）并增加 80ms 会话事件突发合并；有活跃 SMTC 会话时 `get_media_state` 跳过重复读峰值、按会话代数缓存元数据，并在已有 SMTC 会话播放时短路跳过 `discover_fallback_sessions()`（非 SMTC 兜底加短 TTL 快照缓存）。

## 验收

- `win32::audio` 使用 `CLSCTX_INPROC_SERVER` 并通过无锁 `IMMNotificationClient` 感知设备变化，峰值与音量读取在设备未变时不重新 `CoCreateInstance` 或 `Activate`
- `system_levels` 去掉 5 秒强制重建订阅，`device_events` 仅在音频设备通知变化（或蓝牙电量周期到期）时重新枚举音频端点
- `media-com-worker` 常驻缓存 `MediaSessionManager`；`events.rs` 对匀速 `TimelinePropertiesChanged` 节流并保留 seek 跳变即时响应；SMTC 播放时短路跳过 `discover_fallback_sessions` 全系统进程/窗口扫描，非 SMTC 兜底带 TTL 快照缓存
- 纯逻辑（事件合并与进度跳变节流、元数据缓存失效、兜底快照 TTL）有单元测试覆盖
- Mac 本机 `cargo test`、`cargo clippy`（含 `x86_64-pc-windows-gnu` 交叉检查）、`pnpm build:exe` 及 Windows CI（`pnpm mq:try --wait`）通过，并留下 Windows 多端点真机实测清单
