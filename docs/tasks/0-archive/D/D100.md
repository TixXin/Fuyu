## 说明

源自 [fly-island-issue-76.md](/docs/research/fly-island-issue-76.md)（对应 6-5 与 6-3 日志可观测性缺口）：

1. **WebView2 GPU 进程崩溃日志与恢复**：
   - [src-tauri/src/win32/webview_crash.rs](/src-tauri/src/win32/webview_crash.rs)（D66）目前仅处理 `RENDER_PROCESS_EXITED` 与 `RENDER_PROCESS_UNRESPONSIVE`，忽略了系统睡眠唤醒、显卡驱动重置时在透明合成窗口上高发的 `COREWEBVIEW2_PROCESS_FAILED_KIND_GPU_PROCESS_EXITED`。
   - 补齐对 `GPU_PROCESS_EXITED` 的日志记录（写入 `webview-crashes.log`），并在限流保护下触发受影响窗口自愈刷新，避免透明窗口在 GPU 进程退出后画面冻结死锁。
2. **宿主原生 Rust panic 落盘日志**：
   - 目前原生侧若发生未捕获 `panic` 闪退，家目录下没有任何崩溃记录文件。
   - 在 [src-tauri/src/webview_recovery.rs](/src-tauri/src/webview_recovery.rs)（或同级模块）安装非阻塞的 `std::panic::set_hook`（保留原 hook 调用链），将崩溃时间、版本号、线程名、源码位置（`file:line:col`）与脱敏摘要追加写入 `<家目录>/crash.log`（同样做 64 KB 滚动截断，严禁写入环境变量或用户剪贴板/消息原文）。
3. **设置页一键定位日志与文档同步**：
   - 在「设置 → 通用 → 数据文件夹」（[DataHomeSection.tsx](/src/windows/settings/sections/DataHomeSection.tsx)）补充简洁提示或打开最新崩溃日志的辅助入口（有日志时可直接定位，无日志时说明日志存放位置），并在 [data-storage.md](/docs/architecture/data-storage.md) 登记 `crash.log`。

## 验收

- Windows 下 WebView2 `GPU_PROCESS_EXITED` 被记录进 `webview-crashes.log` 并走限流恢复逻辑
- 原生 `panic` 钩子可将时间、线程与位置写入 `<家目录>/crash.log` 且自动限制文件大小上限（含单元测试）
- 「设置 → 通用 → 数据文件夹」中英文界面可清晰指引或定位日志，更新 [data-storage.md](/docs/architecture/data-storage.md)，通过 `pnpm check`、`pnpm heavy -- cargo test --manifest-path src-tauri/Cargo.toml` 与 Windows CI
