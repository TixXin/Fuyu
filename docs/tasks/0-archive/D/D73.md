## 说明

`pnpm test:regression`（`scripts/run-regression.mjs`、`scripts/regression/`）的两个问题，核实结果和体检数据在 issue #531。

1. **运行器被杀掉时留下无头 Chrome 和 Vite。** 浏览器和 Vite 只在 `finally` 里收；运行器被信号杀掉（工具超时、停后台任务、Ctrl-C）时 `finally` 不执行，两个子进程变成孤儿一直不退。留下的无头 Chrome 在 LaunchServices 里是 `com.google.Chrome` 的另一个实例，`open` 的页面可能被它接走（这一半没能复现）。
   - 改法：Chrome 用 `--remote-debugging-pipe`（管道断了自己退，`kill -9` 也一样）；Vite 在运行器进程里起；收到 SIGINT / SIGTERM / SIGHUP 时收尾再退；调试连接断开时等待中的请求立刻失败；启动时删一天前留下的 `fly-regression-*` 目录；`open` 的事写进文档。
2. **`side-island` 的快照偶尔抓在摘要行切换中途。** 这一页做完 `set({ preview: null })` 就报通过；吸在侧边时 `.island__collapsed` 是 `display: none`，旧摘要层只靠 720ms 定时器去掉；抓快照前只等 CSS 动画和过渡，平时被波形条没完没了的 100ms 过渡拖满 20 轮（约 2 秒）碰巧盖过，某一轮没有过渡在跑时就抓早了。浅色一轮的「0 changed lines 仍不一致」是 `compareSnapshot` 在没有浅色快照文件时拿本次的深色结果比、而不是拿深色快照文件比。
   - 改法：`side-island.tsx` 等切换结束再报通过；`compareSnapshot` 没有浅色文件时和深色快照文件比；不一致时等 1 秒重抓一次，一致就过并打印提示；`--update-snapshots` 写入前隔 1.5 秒复抓，还在变就不写。
3. **体检发现另有 5 页存的是会自己变回去的状态**（`plugin-info`、`list-pages`、`settings-search`、`music-lyrics`、`timer`，见 issue）。`timer` 在快照规则里抹数字；另外 4 页放不放进这一项等用户定。

## 验收

- 运行器被 SIGTERM、SIGKILL 杀掉后不留 `fly-regression` 的 Chrome 和 Vite 进程。
- `side-island` 连跑多次快照一致；浅色一轮不再出现「0 changed lines 却不一致」。
- `pnpm check`、`pnpm build`、`pnpm test:regression` 通过。
- Windows 上由 CI 的 `regression` 验证（管道连调试口、信号处理在 Windows 上本机测不了）。
