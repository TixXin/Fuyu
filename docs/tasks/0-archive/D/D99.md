## 说明

源自上游议题排查与开源对比报告 [fly-island-issue-76.md](/docs/research/fly-island-issue-76.md)（对应 6-4 项）。

当用户将剪贴板或快捷翻译的打开方式设为「岛上页面」（`OpenIn::Island`），且主岛当前不在焦点、鼠标光标也不在岛上时，按下全局快捷键唤起岛展开后一旦松开按键，岛会立即失焦并自动收起：

1. [src-tauri/src/island/focus.rs](/src-tauri/src/island/focus.rs) 的 `focus_island_for_shortcut` 将原前台窗口句柄存入了与鼠标悬停借焦点共用的 `PREVIOUS_FOREGROUND`，而不是点击展开专用的 `CLICK_PREVIOUS_FOREGROUND`；
2. 主岛切到 `expanded` 时鼠标不在岛上（`hovering = false`）且无输入框自动聚焦，前端 `useHoverFocus` 立即调用 `releaseIslandHoverFocus()`，取出 `PREVIOUS_FOREGROUND` 把焦点切回原外部窗口，触发 [useCollapseOnBlur.ts](/src/windows/island/useCollapseOnBlur.ts) 自动收起主岛；
3. 此外，主岛折叠态带有 `WS_EX_NOACTIVATE`，`focus_island_for_shortcut` 在清除 `WS_EX_NOACTIVATE` 之前直接调 `window.set_focus()`，也缺少 `win32::window::activate_from_background` 安全激活步骤。

修复方式：
- 在 `src-tauri/src/island/focus.rs` 中让 `focus_island_for_shortcut` 先开启点击激活（临时移除 `WS_EX_NOACTIVATE`），经 `win32::window::activate_from_background` 切到前台并聚焦 WebView，把原前台窗口记入 `CLICK_PREVIOUS_FOREGROUND`（同时清掉可能残留的 `PREVIOUS_FOREGROUND`），使悬停释放逻辑不再误还快捷键焦点，而在主岛收起同步（`island_mode_synced(..., false)`）时正常把焦点归还给原窗口。
- 核查 macOS 侧以「岛上页面」响应全局快捷键时是否存在同类失焦自收起问题。

## 验收

- Windows 下将剪贴板或翻译设为「岛上页面」，在其他窗口聚焦且鼠标不在岛上时短按一次全局快捷键立即松手，主岛稳定展开并保持焦点，不会自动收起
- 按 `Esc` 或再次按快捷键收起主岛后，键盘焦点正确归还给唤起前的外部窗口
- 补充单元或状态机测试覆盖快捷键聚焦与悬停释放互不干扰，`pnpm heavy -- cargo test --manifest-path src-tauri/Cargo.toml` 与 Windows CI（`pnpm mq:try --wait`）通过
