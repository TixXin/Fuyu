## 说明

D56 的一部分。用户反映岛有时卡顿感明显。在正式版 0.3.10 上接调试端口实测，岛收起、闲着、没放音乐时：

- 主界面每秒重排 70 次、重算样式 70 次（其他窗口都是 0），渲染进程约 20% 单核，GPU 进程约 20%。
- 逐组暂停动画对比：只暂停中间的 Agent 状态标记（`src/features/center-pattern`，SVG 里 `circle` 上的 `center-mark-breathe` / `center-mark-typing`），重排降到每秒 1 次、渲染进程降到 6%。Chromium 里 SVG 子元素的动画不走合成，每帧都要主线程重排。
- GPU 进程的 20% 来自「任何一个无限循环动画都让透明置顶窗口每帧重新合成」：液态玻璃流动色块、会话格子呼吸，单独暂停哪组都不降，全部暂停才降到 0。

做法：
1. 标记的循环动画改成能合成的：动画作用到 HTML 元素或整个 `svg` 上，不再动 SVG 子元素。
2. 收起且闲着时，纯装饰的无限循环动画（玻璃流动、光泽、边框旋转）暂停，展开或有状态变化时再跑。表达状态的动画（等你、运行中）保留。

## 验收

- 收起闲置时主界面每秒重排降到个位数。
- 渲染进程和 GPU 进程的 CPU 有前后对比（同样的接调试端口测法）。
- 标记和玻璃的观感不变：展开时照常流动，状态动画照常。
- `pnpm check`、`pnpm build`、`pnpm test:regression` 通过。

## 备注

- 标记改成三层 HTML `span`（胶囊、灯、右边的横线 / 打字点 / 勾），每层包一个只画一样东西的 `svg`，动画作用在 `span` 或整个 `svg` 的 `opacity` 上。Chromium 里 SVG 子元素和 `svg` 元素自身的 `transform` 动画都不走合成，`span` 上的 `transform` / `opacity` 走合成。
- 无头 Edge（`--force-device-scale-factor=2`）逐帧量：旧写法每秒重排 61 次、重算样式 61 次，新写法都是 0。逐帧截图对比：大多数帧 0 像素差异，缩放的那几帧有 200–400 像素的抗锯齿差异（最大通道差 47），肉眼看不出。
- 第 2 条「收起时暂停装饰循环」：外观设置里已有「玻璃流动：一直 / 只在展开时」，CSS 里强行暂停会盖掉用户的选择，所以改的是默认值，从「一直」改成「只在展开时」（用户定）。已保存过设置的用户保留原来的值，要自己在外观设置里切换。会话格子的呼吸表示状态，保留。
- 真岛上渲染进程和 GPU 进程的前后对比要等发版后测，`pnpm check` 里 4 个失败与本改动无关（Windows 不许普通账户建符号链接、插件索引待签名、两个真宿主压测在高负载下超时）。
