## 说明

落实性能审查报告（[fuyu-performance-audit.md](/docs/research/fuyu-performance-audit.md)）的 **M3（`setup()` 启动链优化）** 与 **M4（合并常驻 OS 线程）**：

1. **M4**：将主岛原本独立的 4 条常驻看护线程（`start_monitor_follow_loop` 300ms、`keep_in_top_space` 2s、`start_notch_watch` 2s、`watch_installed_island` 3s）合并进单一 `"island-watch"` 线程（`src-tauri/src/island/watch.rs`）。默认 `MonitorFollow::Primary` 下不再每 300ms 空唤醒，而是按周期任务到期时长休眠（Windows 正式版无周期任务时 `park()` 挂起），并在切换显示器跟随时通过 `Thread::unpark()` 立即唤醒。
2. **M3**：在 `src-tauri/src/lib.rs` 的 `setup()` 中将主岛窗口面板化与初始几何计算移至 `coexist::init` 之后立即执行；将 `src-tauri/src/file_shelf/mod.rs` 的 `items` 改为互斥锁保护的按需懒加载并在后台短线程预热，避免在 `setup()` 主线程同步读取 `file-shelf.json`。

## 验收

- 主岛看护逻辑收敛至单条 `"island-watch"` 线程，`watch.rs` 内联单元测试覆盖不同模式与截止时间的休眠计算。
- `lib.rs` 主岛窗口初始化位于各后台服务之前，`file_shelf` 启动不在主线程同步读盘。
- macOS 与 `x86_64-pc-windows-gnu` 双端 `cargo clippy --all-targets -- -D warnings` 零告警，`cargo test` 通过。
