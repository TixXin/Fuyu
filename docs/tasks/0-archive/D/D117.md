## 说明

Tauri 的 `window.hide()` 只对外层窗口调 `ShowWindow(SW_HIDE)`，不会把 WebView2 控制器的 `IsVisible` 设为 false（tauri-runtime-wry 2.12.3 里只有 `WebviewMessage::Hide` 走 wry 的 `set_visible`，它才调 `SetIsVisible`）。所以隐藏窗口里的页面一直是 `visible`：`requestAnimationFrame` 照跑、定时器不节流、渲染缓存不释放；D51 按 `document.hidden` 暂停定时器的做法对隐藏窗口在 Windows 上没有生效，D48 想用的 `TrySuspend` 也要求先 `IsVisible = false`。

探测程序（`src-tauri/target/perf/visibility-probe`，不进仓库）在 Tauri 2.12.5、WebView2 157 上的数字见[调研](/docs/research/memory-and-performance.md)「隐藏窗口的 WebView 其实没隐藏」。

做法：`win32/webview_visibility.rs` 给窗口挂子类，显示前（`WM_WINDOWPOSCHANGING` 带 `SWP_SHOWWINDOW`）设 `IsVisible(true)`，隐藏后（`WM_WINDOWPOSCHANGED` 带 `SWP_HIDEWINDOW`）设 `IsVisible(false)`；`webview_visibility.rs` 在 `on_page_load` 里挂上。主岛 `main` 第一步不接：它只在用户藏到托盘时隐藏，页面里有 Agent 审批、提醒这类逻辑，定时器被节流的影响要先核实。

## 验收

- 剪贴板、剪贴板预览、翻译、托盘卡片、截图选区、贴图、插件窗口隐藏后页面是 hidden，显示后是 visible。
- 唤起剪贴板、翻译窗口没有变慢、没有闪一下。
- 收起闲置时 WebView2 私有内存有前后对比。
- clippy、Rust 单元测试和 `pnpm build:exe` 通过。

## 备注

### 本机 dev 版的数字（2026-11-20，debug 构建，启动后 16 分钟，收起闲置）

| 进程 | 改之前（04:09） | 改之后（04:50） |
|---|---:|---:|
| 隐藏的剪贴板窗口的渲染进程 | 69 MB | 57 MB，60 秒内 CPU 0 ms |
| 主岛的渲染进程（没接） | 158 MB | 169 MB |
| GPU 进程 | 167 MB | 169–207 MB（来回跳） |

- 确认生效的办法：隐藏的剪贴板窗口里 WebView2 的 `Chrome_WidgetWin_0` 子窗口没有 `WS_VISIBLE`，主岛里有（`src-tauri/target/perf/list-windows.ps1` 枚举，不进仓库）。
- 收益比探测程序小：剪贴板页面本来就轻。主要的作用是隐藏窗口里的动画帧和定时器真的停下，D51 按 `document.hidden` 暂停的逻辑在 Windows 上开始生效。
- 顺带看到：dev 版收起闲置时主岛渲染进程 60 秒用了约 7.6 秒 CPU（约 13% 单核），GPU 进程约 8 秒、浏览器进程约 7 秒。dev 版跑的是 Vite 开发模式的前端，不能直接当正式版的数字，要在正式构建上复核（D86 管主进程，这三项在 WebView2 侧）。
- Rust 单元测试在这台机器的代理环境里有 254 个因为构建目录带低完整性标记、写不了目录而失败（`docs/investigations/windows-build-env.md`），和这次改动无关；试跑 CI（run 44737191282）的 Windows `rust` 和 `rust-macos` 都通过。
