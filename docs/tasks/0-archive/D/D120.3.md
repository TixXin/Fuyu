## 说明

全量跑回归页时（`mq:verify`、CI）通过 CDP 打开 Chrome 的精确覆盖率，记下每页实际执行的源文件，存成「文件 → 页面」表；`test:changed` 用它挑页，代替按 import 关系挑。表里没有的新文件、新页面或表太旧时，退回 import 关系。漏挑由推 PR 前的全量验证兜底。见[调研](/docs/research/pre-commit-test-speed.md)「结论」第 3 条。

## 验收

- 全量运行时顺带生成或更新覆盖率表，不明显变慢；写明表放在哪、怎么刷新。
- 几次典型改动（一个设置页组件、岛壳、i18n 文案）挑出的页数比现在少，数字写进备注。
- 拿历史上真挂过的几个提交回放，按新表仍然挑得到挂的那一页。

## 提交

- `feat(test-changed): pick regression pages by the lines each page ran`

## 备注

**表放哪、怎么刷新**：git 公共目录的 `fuyu-regression-coverage.json`（主工作区和 `../Fuyu-verify` 共用），不进仓库。全量跑回归页（不带页面名、不分片、不在 CI）时生成，`mq:verify` 每次推前都跑，所以每次推完都是新的；只在代码没有没提交的改动、HEAD 没动时写，主工作区里的全量一般不写。不进仓库的理由：每次全量都变（这次的样本 4–6 MB），进仓库各会话一推就冲突；CI 产物要下载，`test:changed` 不该联网。另一台机器第一次 `mq:verify` 之前按 import 关系挑。细节写在 `docs/architecture/workflow.md`「开发中：`pnpm test:changed`」下面。CI 不收（分片、表也用不上）。

**粒度**：先试了按文件，岛壳、i18n 这类每页都加载，几乎省不了，所以记到行：每页执行过的函数换回源码行号（Vite 内联 source map）。块覆盖和函数覆盖在下面所有例子里挑出的页一样，函数覆盖便宜，用函数覆盖。文案文件按「快照或页面源码里有没有这段文字」挑，因为文案是模块顶层的对象，所有加载它的页都算执行过。

**慢不慢**（2026-11-22，本机 10 核 Mac，同时有别的会话在跑；`island settings` 16 页、3 个浏览器，开关各跑两次）：
- 函数覆盖：每页用时合计开 146 / 148 秒，关 147 / 167 秒；整次 60 / 85 秒对 59 / 101 秒，量不出差别（每页中位数比 1.17，几秒的小页噪声大）。
- 块覆盖（先试的）：每页中位数慢约 20%，所以没用。
- 收完一页取覆盖率约 0.1–0.3 秒；全量 100 页、3 个浏览器带块覆盖的样本跑了 217 秒。
