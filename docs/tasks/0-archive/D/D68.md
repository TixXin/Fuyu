## 说明

排查记录见 docs/investigations/dev-island-issues.md 第 3 节。src/devReload.ts：页面加载几秒后仍没挂载就自己重载，间隔逐次加长、次数有上限；只在 dev 构建生效。验收：模拟 import 失败，修好文件后不做别的改动，岛也会自己出来。

## 提交

- `fix(dev): reload a window that has not mounted a few seconds after loading`

## 备注

- 做法：`src/devReload.ts` 在页面加载后按 3、6、12、24、48 秒的间隔检查，没挂载就 `location.reload()`，最多 5 次，次数记在 `sessionStorage` 的 `fuyuDevRemountAttempts`，挂载成功后清掉。重载前先看最近 1.5 秒内还有没有模块在加载（冷启动慢时不打断），再 GET 一下 Vite 开发服务器，连不上就不重载、等下一轮，不消耗次数。下一次 Vite 更新时重载没挂载的页面（并把次数清零），渲染崩溃后清掉挂载标记，这两条照旧。页面挂载过一次后计时就停：崩溃后的空白仍然等下一次代码改动再重载，不自动刷新，免得冲掉控制台里的崩溃信息。算间隔和判断的部分在 `src/lib/devRemount.ts`，测试在 `tests/unit/dev-remount.test.mjs`。正式版构建里 `import.meta.hot` 是 `undefined`，这段逻辑被摇树去掉（构建产物里搜不到这些字符串）。
- 浏览器模拟（2026-11-15）：另起一个 Vite（端口 5468，临时配置放在 `node_modules/.cache/`，没改仓库文件），用插件让 `IslandApp.tsx` 加载失败。页面不挂载，按间隔自己重载；去掉故障后不做别的改动，下一轮重载就挂载了，次数清零，之后不再重载。
- 用户在 `pnpm tauri dev` 下要实测的：
  1. 岛正常显示时，改一个 `src-tauri/` 文件让应用重新编译重启，岛能照常出来。
  2. 在重启过程中让一个岛用到的前端文件有语法错误（例如在 `src/windows/island/IslandApp.tsx` 末尾临时加一个 `{`），等应用重启完：岛不显示，devtools 控制台每隔 3、6、12… 秒出现 `The window did not mount, reloading`。
  3. 把那个文件改回去后什么都不动：最多等一个间隔，岛自己出来，不用点托盘。
  4. 连续 5 次都失败后不再自己刷新；之后改任何前端文件仍会重载一次。
