## 备注

### 做了什么

- 拥有者：`plugin/owner.ts` 导出 `OWNER = "todos"`。岛上的待办页、收起条的待办标题和数量（`island.line/v1`）、侧栏的待办格（`island.side/v1`）、runner、收起条贡献（`useIslandContributions` 的拥有者从 `builtin` 改成 `todos`）、设置窗口的保存目录 runner 都挂在它名下。
- 设置 → 待办这一页的代码还在 `src/windows/settings/`（`TodosSettingsPage`、两个分节）：项目分节用了 `plugin-views` 的样式（`plugin-pages`、`plugin-card__button`），搬进 `features/todos` 会多一条跨功能引用，白名单只减不增。这次只在 `windows/settings/slots/categories.tsx` 注册分类时把拥有者给成 `todos`，关掉待办时分类跟着撤掉。要搬，先把那两个样式类上提到 `components/`。
- 旧开关：`todoEnabled` 在 `LEGACY_SWITCHES` 加一行，备份经镜像带上；设置概览、引导的「装扮」写这个字段就是开关插件。
- 后台：待办在 Rust 里没有线程，`background` 照旧是 `[]`，加了测试核对。
- 服务 `todos/v1`：`list`、`days`、`add`、`update`、`remove`、`note`、`setNote`，事件 `changed`（`{ date }`）。形状同本机接口的 `todos.*`、`note.*`；`add` 多了可选的 `project`（日历的输入框要保留「#项目 标题」的写法，Rust 和窗口两边的 `todos.add` 都加了，本机接口因此也能传）。
  - 窗口那份：`plugin/services.ts`，只在岛窗口登记，走 runner 交出来的 `useTodoApiHandlers`（`plugin/todoApi.ts` 的 runner store），runner 在今天的待办、排期、笔记变了时发 `changed`。
  - 宿主那份：`host/index.mjs` 调 Rust 方法 `todos.*`（`todos/host.rs`），两边的错误都经 `host/index.mjs` 规整：400 → `bad-params`、404 → `not-found`、待办存在窗口里时 `unavailable`、`inactive` → `peer-gone`。宿主那份不发 `changed`：Rust 往宿主发事件还没有。
  - **Rust 方法体里不碰 `AppHandle`**：`todos/service.rs` 原来把 `AppHandle` 存在状态里，给主窗口发 `todos-changed`、给第 2 版插件发 `todos.changed` / `note.changed` 都从状态里拿。改成 `init` 时登记两个闭包（`ANNOUNCE`、`PUBLISH`），状态里不再有 `AppHandle`。`sync::notify_local_change` 只往通道里送一个值，没碰 `AppHandle` 的方法。
- 去掉的跨功能引用（白名单清零 4 条）：
  - 日历读待办的 store（两条）改成 `calendar/useTodoLink.ts` 经 `todos/v1` 读今天的待办和排期、在某天加待办，`changed` 时重读；runner 读一次放进 `todoLinkState`，日历页读它。「#项目 标题」的拆法（`splitProjectPrefix`、`readProject`）上提到 `src/lib/todo-projects/prefix.ts`，`todos/project.ts` 转出，原来的引用不变。
  - todos→local-api：本机接口转给岛的请求改由本机接口自己的 runner（`local-api.bridge`）接，`local-api/todoHandlers.ts` 把方法名映射到 `todos/v1`，错误码再转回 HTTP 状态（400/404/503），原来的错误文字放在服务错误的 `data.error` 里原样带回。
  - todos→plugins：第 2 版宿主事件改用待办自己的 `useTodoHostEvent` 和 `api.ts` 的 `emitTodoHostEvent`（同一个事件名 `plugin-host-event`）。
- 关掉待办后岛的退路：默认页、收起条本来就按插槽走（`resolveIslandPage` 退到下一个开着的页面，收起条没有待办的行就显示别的），引导的「装扮」「试一试」里没有写死待办。新回归页 `todos-off` 覆盖：开着时默认打开待办页、收起条有待办的行；关掉后待办页和行都没了、收起的岛照常、展开退到下一页；引导演示中关着待办展开也退到下一页。
- 本机接口在待办关掉时照旧可用（`local-api.md` 的约定），没有像文件中转那样回 503；只有这次运行待办在 `localStorage` 里时（`todos.json` 用不了）会回 503，那时只有岛上的待办能答。认领时在 issue 里写的「关掉后回 503」没有做。
