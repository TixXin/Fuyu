## 说明

插件平台第 3 版第 5 阶段（#295）：第 3 版的命令行 `fuyu-plugin` 2.0，新包 `packages/plugin-cli`（开发期叫 `@fuyu/plugin-cli`，命令名 `fuyu-plugin`，正式发 npm 时再改名）。命令行参考见 [v3-cli.md](/docs/architecture/plugins/v3-cli.md)。

- `build`：esbuild 0.28.1。源码入口按约定从清单的产物路径推出（`dist/host.js` ← `src/host.ts` 等）；宿主部分按 Node 打包、npm 依赖打进去、`fuyu-plugin` 和 `@fuyu/plugin-base` 留作外部，从 metafile 扫出 Node 内置模块写进 `fuyu.nodeApis`，再写 `builtWith`；界面部分按浏览器打包，共享模块（名单读 `@fuyu/plugin-base/protocol` 的 `SHARED_MODULES`）默认改写成根路径 `/__shared/…`，给了层数参数时改写成相对路径，样式打进 JS；声明和代码对照给告警；产物确定
- `pack`（`.fuyu`，可加作者签名）、`check`（清单、试构建、审核分析器的单版本扫描）、`review`（两边是文件夹或 git 提交）、`keygen` / `sign`（签 `fuyu-plugin-commit/1` 或给包签名，密钥沿用第 2 版的位置、环境变量和格式）
- `publish`、`dev` 不在这个任务里

## 验收

- 示例 `test/fixtures/hello`（`plugin-base/examples/hello` 按新结构重写）`build` → `pack` → 用 `@fuyu/plugin-manifest` 读回并校验通过
- 同一份源码放在两个不同路径下构建，`.fuyu` 逐字节相同
- `review` 对 E36.5.3 的夹具给出和分析器一样的分档和发现，文件夹和 git 提交两种输入都测
- 手动验证（2026-11-15，Mac）：hello 打出的 `.fuyu` 解包到 `plugins/@someone/fuyu-hello/`，用现在的 `startHost` 加载，状态 running，窗口文件登记成 `@someone/fuyu-hello/dist/island.js`，`greet` 方法能调；界面部分（相对路径的构建）用 `client/shims` 的转接文件在 Node 里加载，组件能渲染，样式插入后随停用撤掉。根路径 `/__shared/…` 在两个系统 WebView 里的真机验证归 E36.3.9
- `pnpm check` + `pnpm build` 通过

- 2026-11-15 08:49：共享模块名单的形状（第 3 阶段地基定，2026-11-15）：@fuyu/plugin-base/protocol 将导出 SHARED_MODULES = { react: "__shared/react.js", "react/jsx-runtime": "__shared/react-jsx-runtime.js" }（.d.mts 用字面量类型）。路径相对 fuyu-plugin://localhost/ 根（Rust 的 plugin_kernel/protocol.rs 在这两个路径提供转接文件），build 按输出文件所在目录算出 ../__shared/react.js 这样的相对路径。react-dom、fuyu-plugin 的转接还没有，加了再进名单，所以现在 fuyu-plugin 不改写。常量合入前，build 先把名单作为参数、默认值用这两项；合入后主 agent 转告，改成从 protocol 读。
- 2026-11-15 08:58 E36.5.4 fuyu-plugin 2.0 命令行：共享模块的引用改用根路径（经理和第 3 阶段地基定，2026-11-15）：build 默认写 /__shared/react.js，和安装布局、内置插件前缀无关；相对路径（../ 按传入的层数算）留作可选参数。之前「包根最多 2 层、写 ../../../」的做法算错了：地址是 fuyu-plugin://localhost/plugins/@a/b/dist/island.js，前面还有 plugins/。根路径在两个系统上的真机验证由 E36.3.9 做，有问题再切回相对路径。
