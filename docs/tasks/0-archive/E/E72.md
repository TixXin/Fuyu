## 说明

插件收不到换歌通知，只能自己轮询（E66.8 换歌提示 #985 现在每 2.5 秒问一次 `nowPlaying()`）：

- `packages/plugin-services/src/services/media.mjs` 的 `mediaV1` 只声明了 methods，没有 `events`。
- 宿主的媒体模块 `src/features/media/host/index.mjs` 的 provider 也只提供方法；同一个文件里的歌词 provider 已经会 `emit("changed")`，可以照着写。
- Rust 换歌只发 Tauri 事件 `media-session-changed` 给窗口（`src-tauri/src/media_control/events.rs` 第 29 行、`events_macos.rs`），宿主收不到。宿主这边已经有 `ctx.rust.on(event, listener)`（`packages/plugin-base/src/host/rust.mjs`），Rust 侧要把换歌和播放状态变化也发给宿主；要补通路的话，理由写进备注。

要做：

1. `mediaV1` 加 `events: { changed: true }`。
2. 宿主的媒体模块订阅 Rust 的换歌和播放状态变化，经 provider `emit("changed", NowPlaying)`。载荷和 `nowPlaying()` 的返回值同一个形状，带 `playing`。短时间里连续来好几条时合并或去重，不刷屏。
3. 类型声明（`media.d.mts`）、`docs/plugins/` 的服务文档更新；`pnpm check:rust-types` 涉及时一起更新。
4. 一起修一个平台漏洞：插件可以自己写 `defineService("media/v1", { events: {...} })`，绕过服务清单里的声明，`on("changed")` 不报错却永远不会触发。改成订阅提供方没声明的事件时直接报错（至少记一条告警），补测试。

顺带评估一项，只写结论，不改：岛不在收起状态时，插件发的通知会被直接丢掉，不排队（现在在 `src/features/messages/island/useIslandNotices.ts`）。要不要排队，等岛收起后再显示？官方插件组长希望做成选项，让插件选「岛展开时也显示」或「收起后再弹」，评估时一并考虑。结论写进备注。

## 验收

- 连续快速换几首时，事件被合并或去重

## 备注

- **通路**：Rust 到宿主的事件通路本来就有（`Supervisor::emit` → 宿主 `event` 通知 → `ctx.rust.on`），只是没人用，所以没新开通路。`plugin_kernel::emit_to_host(name, data)` 包了一层：宿主没就绪就丢掉，不阻塞（发进 rpc 的发件队列）。媒体会话事件（Windows 的 `events.rs`、Mac 的 `events_macos.rs`）在发窗口事件 `media-session-changed` 的同时发 `media.changed`，载荷同一份。事件线程是 `music` 的后台（`background.rs`），关掉音乐就不发。
- **合并和去重**：`src/features/media/host/nowPlayingFeed.mjs`。收到 `media.changed` 后等 150 ms 把一串合成一次，再读一次 `media.nowPlaying`，和上次发出的比较（曲目、艺人、专辑、播放器、播放状态、可用、时长、能否跳转 / 上下曲），变了才 `emit("changed")`，所以只跳进度不发。读的时候又来事件，读完再排一次。Rust 那边本来也在 `COALESCE_MS` 内合并过一轮。
- **没声明的事件**：`ctx.services.get(def).on(event)` 现在还对照当前提供方的定义，提供方没声明就抛 `no-event`（`data` 带 `provider`）；订阅时还没有提供方的，提供方上来时在订阅方名下记一条告警（`Services.listening` 记着订阅，插件停用时撤掉）。
- **插件通知要不要排队（只评估，没改）**：结论是**不做默认排队**；真要做，做成单条通知的可选项，默认仍是丢掉。
  - 现状：岛不在收起状态（展开、贴边且没开「新消息时探出」、玩游戏时的安静模式）时 `usePluginNotifications` 直接丢，`messages/v1` 的 `notify()` 回 `{ shown: false }`，插件知道没显示，可以自己决定重发或改在自己的页面里显示。
  - 不默认排队的理由：插件通知多半有时效（换歌提示、计时到点），展开岛可能停留几分钟，收起后再弹的是过时内容；排队还会在收起那一刻一次涌出好几条；安静模式下排队等于游戏一退出就补弹一串。
  - 如果官方插件确实需要「收起后再弹」：给 `notify()` 加可选字段（例如 `whenBusy: "drop" | "later"`，默认 `drop`），`later` 每个插件只留最新一条（后来的替换先前的，不累积），带过期时间（不超过一两分钟），只在岛回到可预览的收起状态时弹，安静模式期间到期就丢。改动在 `usePluginNotifications.ts` 和 `messages/v1` 的类型、文档，`shown` 对 `later` 回 `false` 加一个 `queued: true`。
  - 「岛展开时也显示」不建议：展开时用户正在用某个页面，插件通知盖上去会打断；展开态也没有收起条预览这个位置，要新做展开态的横幅。需要的插件看 `shown: false` 后在自己的岛页面里显示即可。
