## 说明

插件平台第 3 版第 5 阶段（#295）：第 3 版的项目模板，新包 `packages/create-plugin`。

- 包名：开发期私有名 `@fuyu/create-plugin`，命令名 `create-fuyu-plugin`。发 npm 时用 `create-fuyu-plugin` 2.0，和 `fuyu-plugin` 2.0（`@fuyu/plugin-cli`）对齐，这样 `npm create fuyu-plugin@latest` 拿到的就是第 3 版。第 2 版的 `create-fuyu-plugin` 留在 0.x，`packages/create-fuyu-plugin` 不动。
- 生成的 TypeScript 项目包名是 `@<GitHub 所有者>/<名字>`，带三个示例：
  - `src/host.ts`：宿主部分，用计时器服务 `timers/v1`，有计时器在走时每秒用 `ctx.setInterval` 推给窗口；
  - `src/island.tsx`：岛屿页面，插槽 `island.page/v1`；
  - `src/settings.tsx`：设置分节，插槽 `settings.section/v1`，分类写的是 `pluginsV3`。
- 两边共用 `src/timers.ts`，样式在 `src/styles.css`，只用插槽的主题变量。窗口文件靠清单的 `fuyu.client` 登记，宿主部分不调 `ctx.clients.add`。
- 生成的项目带 `tsconfig.json` 和 `eslint.config.mjs`（typescript-eslint 的 recommended 加三组规则）：
  - 不许直接用 `setTimeout` / `setInterval` / `setImmediate`（包括 `window.`、`globalThis.` 前缀）；
  - 不许用 `addEventListener`；
  - 不许插样式：`document.head`、`createElement("style" | "link")`、`adoptedStyleSheets`、`insertRule`、`new CSSStyleSheet`。
  - 每条提示都写了改用哪个受管的接口。
- 用到的接口（`clients`、`timers/v1`、两个插槽）都写进 `fuyu.experimental`。在 `fuyu-plugin` 2.0 发 npm 之前，`devDependencies` 用 `file:` 链到浮屿仓库里的 `@fuyu/plugin-base`、`@fuyu/plugin-services`、`@fuyu/plugin-cli`：从仓库里运行时默认链本仓库，`--fuyu <文件夹>` 改别的克隆。

## 验收

- 测试把模板生成到临时目录，模拟 `npm install`（把依赖链进 `node_modules`），然后：
  - 跑 `tsc` 和 `eslint` 都通过；
  - 用 workspace 里的 `@fuyu/plugin-cli` 跑 `build` 和 `check` 都通过；
  - 按市场规则跑 `check`（不许实验接口）失败。
- lint 规则对 9 种违规写法逐条报错，并给出受管接口的提示；`ctx.setTimeout` 这类成员调用不误报。
- 构建产物用真的 `startHost` 从开发文件夹加载，配一个假的 `timers/v1`：
  - 插件状态是 running，岛和设置两个窗口各登记一个文件；
  - `list`、`start`、`dismiss` 三个窗口方法都能调；
  - 有计时器在走时开定时器、每秒推送，没有时撤掉。
- 边界测试：`src/`、`bin/` 只 import `node:`、相对路径和 `@fuyu/plugin-manifest`；模板只 import 自己的文件、`react`、`typescript-eslint`、`@fuyu/plugin-base`、`@fuyu/plugin-services`。
- 模板用的接口都在清单的 `experimental` 里。
- `pnpm check` + `pnpm build` 通过。

## 备注

- 做的过程中修了 `plugin-cli` 的 `check`：不加 `--market` 时，审核分析器给实验接口的那条红档以前也算错误，模板标了实验就过不了。现在只在 `--market` 时算。主 agent 定的，单独一个提交，`plugin-review` 没改。
- 有 `package.json` 的插件，内核按清单的 `fuyu.client` 自动登记窗口文件，宿主再调 `ctx.clients.add` 会把同一个文件登记两次。模板只靠清单登记。`packages/plugin-cli/test/fixtures/hello` 两样都做，没改它。
- 新生成的项目跑 `check` 有 8 条依赖告警（每个 `devDependencies` 一条「新增依赖」，加一条「没有锁文件」）。只是告警，不影响通过；要不要对单版本扫描省掉 `devDependencies`，归 `plugin-cli`。
- `file:` 链进来的包，esbuild 在产物的注释里写的是到仓库的相对路径，所以产物和机器有关。发 npm 后依赖装在 `node_modules` 里，就没有这个问题。
- E36.3.17 会把 `defineService` 挪到 `@fuyu/plugin-base/services`。模板只用服务，不声明服务，不受影响；以后模板加「提供一个服务」的示例时从新位置拿。
- 模板现在只 `import type` 不带子路径的 `@fuyu/plugin-base`（E36.3.16 的宿主共享名单只认确切的模块名），测试断言宿主产物里的 import 都在 `HOST_SHARED_MODULES` 里。E36.3.17 改完后，`@fuyu/plugin-services` 从 `@fuyu/plugin-base/services` 转出定义，产物会多一条这个 import；它在共享名单里，运行时找得到。
- 真岛上看不到这两个界面：窗口还没渲染第三方的 `island.page/v1`、`settings.section/v1` 项，开发文件夹的窗口文件 Rust 也还没映射（E36.5.10 `fuyu-plugin dev`）。插槽接入第三方项、接口定下后，模板再改一次，到时在真岛上看。
