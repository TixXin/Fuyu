## 说明

排在 E60.5、E60.9 之后（都改 `src/windows/island/`，不和 E60.9 同时开工）；和 C124（#897）共用收起条的宽度上限。

用户 2026-11-19 在开发版装了系统监控插件，收起条最右只显示「CPU 86% ·」，后面的内存占用被截掉。


- 现在收起宽度（`src/windows/island/collapsedWidth.ts`）= 文字宽 + `slots.sideWidth` + 行的 extra；`sideWidth` 是各个 `island.collapsed/v1` 声明的固定 `width` 之和（`useCollapsedGauges.tsx`）。系统监控没声明 `width`，按 0 算；内容是动态文字的插件收起项都会被截断。
- 改成量收起项实际渲染出来的宽度（例如 ResizeObserver），和岛自己的内容一起算收起宽度；声明的 `width` 留作初始值或下限，兼容旧插件。
- 要有上限：到屏幕宽度或设置里的上限就省略。和 C124（#897，收起条长消息先加宽、到上限后换行）共用同一个上限，不各做一套：谁先做谁定下上限的取法，后做的复用。
- 宽度变化配合窗口同步（`windowSync.ts`、`useIslandResize.ts`），不抖：内容频繁变化（每秒刷新的读数）时不来回改窗口大小，例如只增不减、或变化超过阈值再改。
- 插件接口文档写清新的规则（`docs/plugins/services-and-slots.md`、`*.d.mts` 的 JSDoc）。
- 回归页覆盖：声明宽度的、没声明宽度的动态文字收起项，超过上限的。

## 验收

- 系统监控这类没声明宽度、内容会变的收起项完整显示，不被截断（到上限才省略）
- 每秒刷新时收起条不抖
- 老插件声明的 `width` 照样生效
- `pnpm check`、`pnpm build`、`pnpm test:regression` 通过；改了 Rust 或窗口同步时 `cargo test` + `pnpm build:exe`，附 Windows CI
- 用户在开发版装系统监控后，收起条显示完整的 CPU 和内存（另记待人工验收）
