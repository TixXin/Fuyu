## 说明

在同步（`src/features/sync/`、`src-tauri/src/sync/`）和设置备份（`src/lib/settings-backup/`）的代码里没搜到 `plugins.yml` 或 `plugins-v3`，只有内置插件的开关经 `registerBackupSwitches` 进了备份。如果确实不进，换电脑后要把市场插件重装、重配一遍。

先核实现状写进「结论」，再补：建议同步和备份「装了哪些市场插件（名字、是否启用）」和「插件的设置」；不带插件的数据文件、密钥、从文件装的插件包。另一台设备拿到名单后从市场装，不直接传包。

## 备注

- 做法和格式写在 [contracts.md](/docs/architecture/contracts.md)「市场插件的名单」、[data-storage.md](/docs/architecture/data-storage.md) 和 [cross-device-sync-plan.md](/docs/architecture/cross-device-sync-plan.md) 文末「市场插件的名单」；给插件作者的说明在 [services-and-slots.md](/docs/plugins/services-and-slots.md)。`docs/features/sync.md` 不存在，同步文档是 `cross-device-sync-plan.md`。
- 数据格式上的决定：
  - 新的设置 key `fuyu-market-plugins`，数组 `[{ id, source, enabled, config?, configOmitted? }]`，进 `BACKUP_KEYS`，所以设置导出、家目录的 `settings.json`、升级前的备份和跨设备同步走的是同一条路；同步白名单里是 `byId`，每个插件一条，带墓碑。
  - 本机 key `fuyu-market-plugins-local`（`{ seen, dismissed }`）不进备份和同步。`seen` 记主窗口上次看到的本机状态，本机变了才改写自己那条，所以两台设置不同的设备不会来回覆盖。
  - `config` 是插件数据目录里 `config.json` 的内容：字段名含 `password`、`passwd`、`token`、`secret`、`authcode`、`apikey`、`credential` 的去掉（和同步里设置的规则是同一份），整份超过 16 KB 就不带、记 `configOmitted: "tooLarge"`，横幅里说明。写进 localStorage 之前清一遍，Rust 推出和并入前再清一遍。
  - 从文件安装的只记名字和开关，不带设置，另一台设备上只提示。
  - 启用状态只在从横幅安装时照名单设一次；两台都装着的插件各自开关。
- 同步或备份来的名单不会让本机安装、启停插件或改插件设置（用户定的方向）。主窗口只做只读调用（`market/v1` 的 `catalog`、`plugin-config/v1` 的 `get`）；安装、启停、写设置都在设置窗口里，用户点了横幅上的按钮才做，安装走 `market/v1` 的 `installMarket`，签名和 SHA-256 校验没动。
- 比原方案多的一条横幅：两台都装着、设置不一样时提示「用那边的设置 / 保留本机的」。声明了 `fuyu.config` 的插件按字段写，没声明的整份写进 `config.json` 后重启一次。
- 市场里未审核、作者密钥变了、带警告的插件不进「全部装上」，横幅给「去市场看看」，到市场页逐个确认。
- 已知的取舍：在本机卸载过的插件记在 `dismissed` 里，之后在同一台设备上恢复一份带着它的备份也不会再提示，要自己去市场装。
- 没改的：插件的其他数据文件、插件包、内置插件的开关（原来就经 `registerBackupSwitches` 进备份）。
- 实测清单（本机只有一台 Mac，代理不跑 `pnpm tauri dev`，两台设备、真同步文件夹和真市场安装都测不了）：
  1. 两台设备开着同步，A 从市场装两个插件（一个带设置表单，一个是天气这类自己存设置的），改它们的设置，停用其中一个。B 同步完先不开设置窗口：`plugins-v3/packages` 里不该多出任何东西。再打开设置 → 插件：应看到「另一台设备上还装了 2 个插件」，点「全部装上」后两个都装好，设置和 A 一样，A 上停用的那个在 B 上也是停用的。
  2. 两台都装着同一个插件，在 B 上改它的设置。A 的插件页应出现「1 个插件的设置和另一台设备上的不一样」。点「用那边的设置」：带表单的插件设置页显示新值、不重启；天气这类插件重启一次后按新设置显示。点「保留本机的」：横幅消失，之后 B 上出现同样的提示。
  3. A 导出设置，在一台没装这些插件的设备上导入：插件页出现缺失提示，能一键装回。升级前的备份恢复同样看一遍。
  4. A 卸载一个插件：A 不再提示它；B 还装着，B 不受影响，A 上不会因为 B 把它补回名单而再提示。
  5. A 从文件装一个插件：B 的横幅只列它的名字和「要用安装包自己再装一次」，没有安装它的按钮。
  6. 给一个插件的 `config.json` 加一个叫 `token` 的字段：看家目录 `settings.json` 里的 `fuyu-market-plugins` 和同步文件夹里的记录，都不含这个字段。再把 `config.json` 写到 16 KB 以上：名单里那条没有 `config`、有 `configOmitted`，另一台设备的横幅说明设置没带过来。
  7. 名单里有一个市场已下架或这台设备装不了的插件：横幅说明装不了，「全部装上」不含它，点「不用了」后不再提示。
  8. 一台 0.3.10（不认识这个 key）和一台新版同步：旧设备不报错，新设备的名单不被清掉。读代码的结论是旧设备会原样留着 `item:fuyu-market-plugins:*` 记录（`drop_closed` 只筛 `key:` / `field:`），没有用真的旧版本测过。
  9. 上面第 1、2 步在 Windows 上再走一遍；Windows CI 这次没跑（简报要求不推送）。

## 结论（2026-11-19）

改之前（读代码核实，没有实测）：

- 市场插件的名单和启用状态只在应用数据目录的 `plugins-v3/plugins.yml`（`source: market/manual`、`disabled`），插件设置只在 `plugins-v3/data/<id>/config.json`。声明了 `fuyu.config` 的插件经 `plugin-config/v1` 写这个文件；官方插件里天气、GitHub Issues、正在播放、系统监视不声明表单，自己读写同名文件。
- 这两样都不在 `BACKUP_KEYS` 和 `sync/settings_whitelist.json` 里，所以不进跨设备同步、设置导出和 `settings.json`；升级前的备份只带 `plugins.yml`，不带插件设置。
- 第 3 版插件没有密钥接口，密钥只可能在插件数据目录里，不出本机。
- 进设置备份的只有内置插件的开关（`registerBackupSwitches`）；`fuyu-plugin-pages`、`fuyu-plugin-market-favorites` 是第 2 版留下的，E71 已经从备份和白名单里删掉。

改之后：名单、启用状态和插件设置随 `fuyu-market-plugins` 进备份和同步，另一台设备在插件页提示后由用户装上；插件的数据文件、密钥、从文件安装的包仍不出本机。
