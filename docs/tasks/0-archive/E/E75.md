## 说明

E73 给 `timers/v1` 的计时记下了 `owner`（宿主按调用方填写），但任何插件都还能暂停、继续、延长、删除别的插件或用户建的计时。插件系统总控定了收紧规则（E73 的评估见 `docs/tasks/0-archive/E/E73.md` 的备注）：

- 调用方是插件时，`pause`、`resume`、`extend`、`remove` 只能动 `owner` 是它自己的计时，别的计时按 `not-found` 处理，不透露它们存在。`dismissRinging` 只删它自己在响的计时。
- 用户本人（窗口调用）不受限，能动所有不隐藏的计时。
- `list` 不收窄。
- `adopt` 怎么算由做的会话定，理由写进备注。

代码在 `src/features/timer/host/index.mjs` 和 `rules.mjs`。`caller` 里有 `plugin` 就是插件调用。

范围：这一项只管宿主那边的调用。插件的窗口部分调用服务时只带窗口、不带插件身份，会被当成用户本人，这半边要等 E68 让窗口调用带上插件身份。E68 的验收里加了一条，到时同时覆盖计时。

## 验收

- 插件 pause、resume、extend、remove 别人的计时，返回 `not-found`，计时不变
- 插件 `dismissRinging` 只删自己在响的计时
- 用户在岛上的操作、待办专注计时、旧数据迁移不受影响
- `timers.d.mts`、`docs/plugins/` 的服务文档写明规则，单元测试覆盖以上几条

## 提交

- `feat(timers): plugins can only change the timers they started (E75)`

## 备注

- 做法：`rules.mjs` 加 `reachable(timer, plugin)`，调用方没有 `plugin`（窗口调用）时都能动，有时只认 `owner` 等于它的。`changeTimer` 找计时时带上这一条，所以别人的计时和不存在的 id 走同一条路，报一样的 `not-found`（消息也一样）。
- `remove` 别人的计时返回 `{ removed: false }` 而不是报错：删一个不存在的 id 本来就返回它，报错反而透露计时存在。
- `dismissRinging`：插件调用只删 `owner` 是它、在响的计时，隐藏的也删（插件自己的隐藏计时只有它自己会清）；窗口调用照旧只删在响且不隐藏的。
- `adopt` 不另加限制：它只加进新 id，记成调用方的；id 已经存在的计时原样保留（`normalizeTimers` 去重时先到的赢），`owner` 不变，所以插件靠 `adopt` 拿不到别人的计时。返回的 `timers` 和 `list()` 一样是全部计时，不多透露什么。旧数据迁移是窗口调用，不受影响。
- 不受影响的核对：计时器页、提醒按钮、待办专注计时（`useTodoFocusTimer.ts`）、旧数据迁移都是窗口调用；官方番茄钟只动自己建的计时（`sweepOrphans` 也先看 `owner === name`）；插件模板的 `dismissRinging()` 收紧后只删模板自己的倒计时。
- 插件窗口部分直接调服务时不带插件身份、被当成用户的那半边仍挂在 E68。
