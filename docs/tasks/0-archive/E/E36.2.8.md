## 说明

categories.ts 的分类、分组、子页、功能开关、平台可用性、旧名合并和侧栏图标改由 settings.category/v1 提供，SettingsWindow 按注册表渲染页面，纯搬迁。

分步计划见 [v3-phase2-plan.md](/docs/architecture/plugins/v3-phase2-plan.md)。

- 回归页和 DOM 快照一致

- `refactor(settings): the settings sidebar, tabs and pages read their categories from settings.category/v1 (E36.2.8)`

## 备注

- 分类的元数据在 `src/windows/settings/slots/categorySlot.ts`（不带组件，node 测试能直接加载），页面和注册在 `slots/categories.tsx`；`categories.ts` 只剩从注册表算的函数，`settingsGroups(items)` 和 `pagesOfFeaturesOff(on, items)` 可以传一份列表，其余的单个分类查询只读注册表（免得被 `.map(sidebarItemOf)` 把下标当成列表传进去）。
- 功能开关只藏开关表里有的功能的页面，插件带自己的 `feature` 时照常显示。
- `SETTINGS_FEATURES`、`FEATURE_PAGES`、`CATEGORY_ICONS` 还是从内置项算出的常量，给概览页、`OverviewStage`、`FeatureHeader` 和回归页用；插件分类的标题还没有元数据，侧栏和页头的名字仍从 i18n 取。
- 页面的 import 从 SettingsWindow 挪走后 CSS 的拼接顺序会变；把注册的 import 放在 LayoutEditor 后面，构建出的设置、岛、引导三个窗口的 CSS 按加载顺序拼起来逐条比过，没有同优先级、同属性、会落在同一元素上的规则换了先后。
- 子页切换本来就会重挂页面：LayoutEditor 的面板是 `key={category}`。
- 搜索索引：拷一份 `scripts/settings-search-index.mjs` 只改输出路径，从仓库根目录跑，输出和已提交的 `searchIndex.json` 逐字节相同（253 条）。
- 验证：`pnpm check`（1346 个单元测试通过）、`pnpm build`、`pnpm test:regression` 53 页通过、105 个快照不变；`todo-island` 在两次整轮里各挂过一次、单独跑也挂过一次，每次挂在不同的检查上，再跑就过，它不引用这次改的文件。
