## 说明

宿主把哪些模块名解析到自己的内核接口写在两处、还不一致：宿主 `kernel.mjs` 的 `shareModules` 只认不带子路径的 `@fuyu/plugin-base`（加 Rust `--api` 传的别名），`build-builtins.mjs` 却把 `@fuyu/plugin-base`、`fuyu-plugin` 和它们的子路径（`/*`）都标成 external。内置插件只要 import 一个 plugin-base 子路径（如 `@fuyu/plugin-base/protocol`），打包后运行时就找不到模块、插件 `failed`（E36.3.2 踩到过，当时绕开）。`fuyu-plugin` 同理：Rust 还没传 `--api fuyu-plugin`（E36.3.10 的 R3）。

改法：`@fuyu/plugin-base/protocol` 导出 `HOST_SHARED_MODULES`（和窗口用的 `SHARED_MODULES` 并列），宿主 `shareModules` 和 `build-builtins` 的 `external` 都从它取；`external` 只写名单里的名字、不加 `/*`，名单外的子路径照常打进包里。名单放 `@fuyu/plugin-base` 和 `fuyu-plugin`（第 5 阶段同意），宿主默认共享这两个，E36.3.10 的 R3 因此不用 Rust 传 `--api fuyu-plugin`。只改 JS，不编译 Rust。

同类的坑：`packages/plugin-cli`（E36.5.4）的 `HOST_EXTERNALS` 也把子路径标成 external，是第 5 阶段的代码，这里不改，合入后转告那边改成读 `HOST_SHARED_MODULES`。

分步计划：[v3-phase3-foundation-plan.md](/docs/architecture/plugins/v3-phase3-foundation-plan.md)。
