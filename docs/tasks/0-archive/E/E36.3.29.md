## 备注

### 样板定下的写法（后面的功能任务照抄）

| 要做的事 | 怎么写 | 翻译里的例子 |
|---|---|---|
| 拥有者 id | `src/features/<领域>/plugin/owner.ts` 只导出 `OWNER = "<插件 id>"`（和 `builtins.json` 的 `id` 一样，不是目录名）；`plugin/` 下每个 `.add(...)`、`addSettingsCategory(...)` 都把它当最后一个参数传 | `plugin/owner.ts` |
| 插槽项 | 岛的在 `plugin/island.tsx`，设置窗口的在 `plugin/settings.tsx`，无界面的接线在 `plugin/runners.tsx`（`island.runner/v1`）。插件关掉时注册表会把这些项全拿掉，所以 runner 里不用再判断开关；runner 卸下就该撤监听和定时器 | `plugin/runners.tsx` 只剩设翻译目标和快捷键 |
| 窗口服务 | `plugin/services.ts` 里 `windowServices.provide(<定义>, 实现, { owner: OWNER })`；`src/main.tsx` 的 glob 收集，每个窗口一份。错误按宿主那份的码（翻译借用 `host/index.mjs` 的 `fromRust`），原生的 code、args、detail 放进 `data`，调用方用 `data.reason` 还能显示原来的中英文提示；`not-ready` 显示「这个功能已关闭」。回归页不经过 `main.tsx`，要用服务的回归页自己 import 那个 `services.ts` | `plugin/services.ts`、`ClipboardAiList.tsx` |
| 后台登记 | Rust 里在 `<模块>/background.rs` 实现 `plugin_kernel::builtins::Background`（`start`、`stop`、`running`），`init` 里 `builtins::register(PLUGIN_ID, 名字, Arc)`；名字写进 `builtins.json` 自己那一行的 `background`，再加一条测试核对两边一样。开关表在启动和开关变化时调 `start` / `stop`，所以模块自己不再存「开没开」，要问就用 `builtins::is_enabled(PLUGIN_ID)` | `translation/background.rs`，后台 `shortcuts`、`window` |
| 线程真停 | Windows 的消息循环线程：`stop` 给消息窗口发 `WM_QUIT` 再 `join`；线程退出前撤快捷键、销毁窗口、`unregister_class`（不然下次 `start` 注册不了同名的窗口类）；`start` 时线程还没把窗口句柄放好，`stop` 最多等 2 秒。Mac 的 `global-hotkey`：在主线程上注册和撤销，`start` 排进主线程的闭包里先看一眼还在不在开着 | `translation/hotkey.rs`、`hotkey_macos.rs` |
| 开机就建的窗口 | `tauri.conf.json` 里改成 `"create": false`，`start` 时 `WebviewWindowBuilder::from_config` 建（Mac 上接着在主线程变成 NSPanel，原来写在 `lib.rs` setup 里的那条去掉），`stop` 时 `destroy`；Mac 上先在主线程 `forget_panel` 再销毁 | `background.rs` 的 `Window` |
| 关着时改设置 | 改快捷键这类命令在关着时只记下来，下次 `start` 用记下的值，不报错 | `hotkey::want` |
| 旧开关 | `fuyu-settings` 里的字段：在 `features/plugin-kernel/legacySwitches.ts` 的 `LEGACY_SWITCHES` 加一行（字段 → 插件 id），别的不用改；岛、设置窗口、引导页已经套了 `useLegacySwitches`。各自存储里的开关（剪贴板、语音、QQ、微信）和第 2 版 `plugins.json` 的不走这张表，各任务自己写一次性迁移 | `translationEnabled: "translation"` |
| 只交接数据 | 两个功能之间只是交接数据的，读写函数上提到 `src/lib/<主题>/storage.ts`，不加服务方法 | `lib/translation-handoff/storage.ts` |
| 老命令 | 只有自己前端用的「开 / 关」命令（`set_<功能>_enabled`）删掉，前后端同一个提交，记进 `contracts.md` | `set_translation_enabled` |

### 迁移标准建议改的地方

- 第 4 条「备份带上」：走 `LEGACY_SWITCHES` 的字段因为有镜像，自动带上；只有自己存储里的开关要另外核对。
- 第 6 条：`builtins-off` 回归页默认只查拥有插槽项的插件，拥有者一改它就开始查这个插件，所以第 2 条做完就要跑它。
- 第 1 条的「Rust 一层」：通用测试用的是假后台，真后台的 `running()` 没有自动检查，只能靠「待人工验收」；建议每个任务都像翻译这样加一条核对 `builtins.json` 名字的测试。
- 外壳里还剩翻译的选中文字提示（`useQuickTranslation`、`useIslandTranslation`），它按开关表的值关掉，不会留监听；搬走它们要等 E36.3.51。
