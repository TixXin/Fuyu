## 备注

### 做了什么

- 拥有者：三个插件各有 `plugin/owner.ts`（`device-events`、`system-levels`、`device-use`）。刘海提醒（`island.alert/v1`）、收起条的设备占用项（`island.collapsed/v1`）、侧边岛的摄像头和麦克风两行（`island.side/v1`）、三个 runner（`island.runner/v1`）和它们交给外壳的贡献（`useIslandContributions`）都挂在插件 id 名下，关掉插件时一起撤掉。
- 旧开关：`deviceAlerts`、`levelPopup`、`deviceUseIndicator` 在 `LEGACY_SWITCHES` 各加一行（单独提交 426264d2），备份经镜像带上。设置 → 系统提示里那三个开关不用改，拨它就是开关插件。runner 不再读这三个字段：插件关着时 runner 本来就不挂。
- 后台：两条读数线程改用新的 `plugin_kernel/worker.rs`。`Worker` 实现 `Background`：`start` 起线程，`stop` 断开通道叫醒线程并 `join`，`running` 看线程还在不在；线程里用 `Stop::wait(间隔)` 代替 `sleep`，所以关掉时最多等完手上这一轮读数。`device-events`、`system-levels` 各登记一个 `watcher`，`builtins.json` 写上 `background`，加了核对名字的测试；`device-use` 的 `background` 照旧是 `[]`，也加了测试（Windows、Mac 两份实现各一条）。各 tracker 的 `reset()` 原来只在空转时用，去掉了。
- 删掉 `set_device_alerts_enabled`、`set_level_popup_enabled` 两个命令（前后端同一个提交）。线程开着就发事件，不再等岛先打开开关。
- 服务：三个功能都没有别人调，按计划第 5 条不加服务，宿主部分是空插件；没有服务标记，`v3-services.md` 不用改。`platforms.md` 核对过，支持情况没变。
- 边界：三个功能不 import 别的功能，白名单里没有它们的条目。

### 给别的任务

- `Worker`（`plugin_kernel/worker.rs`）是通用的：功能有一条「循环读、隔一会儿再读」的线程时，`builtins::register(PLUGIN_ID, 名字, Arc::new(Worker::new(线程名, move |stop| …)))`，循环里用 `stop.wait(间隔)` 返回 `true` 就退出。媒体（E36.3.33）、消息（E36.3.44）的轮询线程可以用它。
- 文档：`contracts.md` 里本任务那一条被 C101.4 的 d2315fe4 一起提交了（它整份提交了这个文件）；`data-storage.md` 那一行里同时有 E36.3.33 加的 `musicEnabled`，同一行拆不开，随本任务的功能提交带上。
