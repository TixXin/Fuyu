## 说明

M7：宿主代码按不带版本号的地址 `import()`（`packages/plugin-base/src/host/sources.mjs`），装完、更新完只刷新配置，不重启宿主（`src/features/updater/host/market.mjs`）；窗口部分带 `?v=版本`，会加载新版。结果新旧两半一起跑，安全修复要等下次启动浮屿才生效。

## 验收

- 更新一个插件后，宿主里跑的是新版代码（单元测试或宿主集成测试验证），其他插件不受影响

## 提交

- `fix(plugins-v3): run the new host code after a plugin is installed or updated (E63.7)`

## 备注

- 核实：除了宿主按不带版本的地址 `import()`（Node 的 ESM 缓存按 URL 存），更新通常不改 `plugins.yml`，Include 的 `refresh()` 见文件内容没变就直接跳过，旧实例原样继续跑。
- 选的办法：已安装插件（market、manual）的宿主入口地址带 `?fuyu-v=<版本>-<包目录摘要>`（摘要由包里文件的路径、大小、修改时间和包目录算出，跳过 `node_modules` 和点开头的目录），`versioned.mjs` 的解析钩子把参数传给包内部的导入；`PluginsFile.reapply()` 在文件没变时也重新应用，市场装完、更新完调它。地址变了的插件由加载器先停用旧实例（effect、定时器、服务释放）再加载新地址，其他插件地址不变、不重启。
- 没选重启宿主：会让所有插件和内置功能一起中断。代价：旧模块留在 Node 的模块缓存里（每次更新一份插件代码），下次启动浮屿或宿主重启时回收。`dev` 来源照旧不带参数，由热重载处理。
- 替换了内置服务的插件（E63.6）更新时：旧版离开时内置服务同步接回，新版进来时同步让位，测试里更新全程不停调用，没有一次失败。
- 测试：`packages/plugin-base/test/update-reload.test.mjs`（装 v1 → 换成 v2 → 宿主跑 v2、旧实例已停用、另一个插件同一个实例；没变时不重启；替换内置服务的插件更新不丢调用），`tests/unit/market-v3-update-reload.test.mjs`（经 market/v1 的 `installFile` 装 v1 再装 v2）。去掉修复时两个更新用例都失败（宿主仍是 v1）。
