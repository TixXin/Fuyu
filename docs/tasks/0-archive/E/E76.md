## 说明

插件在宿主代码里调用 `messages/v1.notify()` 发的通知到不了岛，插件却收到 `shown: true`。发版前要修。

- 宿主的 messages 提供方（`src/features/messages/host/index.mjs` 第 13–16 行的 `onArrive`）只 `emit("arrived")`，然后写死返回 `true`，经 `sources.mjs` 变成 `shown: true`。
- 宿主那边的 `arrived` 在 `src/` 里没人订阅。岛窗口有自己的提供方（`src/features/messages/plugin/services.ts`），走 `deliverNotice` → `usePluginNotifications` 才会显示，但宿主插件调不到它：`packages/plugin-base/src/host/services.mjs` 只有窗口调宿主（`callFromWindow`）和宿主事件发给窗口，没有宿主调窗口提供方这条路。
- 影响：所有在宿主里发通知的官方插件，包括闹钟、番茄钟、待办摘要、天气、GitHub 新 issue、倒数日、换歌提示，其中几个已经上架。证据和插件侧的情况见 E66.11（#1018）。

修法（组长定）：宿主的 `notify` 转给岛窗口，由岛窗口调 `deliverNotice`，等它回话后把真实的 `shown` 返回给插件。E60.16 刚做了「宿主请求、岛窗口回答」的通道（`packages/plugin-base/src/host/island.mjs` 的 `island.request` / `island.result`，带超时和窗口离开时的收尾），优先复用或照着做，不再新开一套。不选「岛窗口订阅宿主的 `arrived`」，因为那样 `shown` 还是假的，插件没法按它决定要不要换别的方式提醒。

- 岛窗口没连上、超时或中途离开时，`notify` 返回 `shown: false`（或 `not-ready` 错误，选哪种写进备注），不能再假装成功。
- 注意别和岛窗口自己提供方的 `emit("arrived")` 形成回环。
- 一起查 `islandNotices/v1` 的宿主调用有没有同样的问题，有就一起修；没有就在备注里写明查过。

## 验收

- 宿主插件 `notify` 一次，岛上收到并显示一次，返回值是岛窗口给的真实 `shown`
- 岛窗口不在、超时或中途离开时返回 `shown: false`（或 `not-ready`），不卡住插件
- `islandNotices/v1` 查过，结论写进备注
- 单元测试覆盖以上几条（`tests/unit/messages-host.test.mjs` 等）；改了 Rust 附 Windows CI
- `docs/plugins/` 里 `notify` 返回值的说明和实际一致

## 备注

- **失败时回 `shown: false`，不报 `not-ready`**：岛窗口没连上、3 秒（`ISLAND_NOTICE_TIMEOUT_MS`，比服务调用的 30 秒短，插件不会先等到服务超时）内没回话、回了错误或中途离开，宿主的 `notify` 都回 `{ shown: false, receivedAt }`。官方插件都不 catch `notify` 的错误，`shown: false` 也是 E72 起岛展开时就有的结果，插件已经会按它处理。
- **通道**：复用 E60.16 的 `IslandControl`（`packages/plugin-base/src/host/island.mjs`），`island.request` 加 `action: "notify"`；岛窗口 `islandControl.ts` 交给 `messages/plugin/services.ts` 登记的处理函数，它调 `deliverNotice` 并回真实的 `shown`。`ctx.island.notify` / `onNoticeAction` 只给内置插件（`kind` 不是 `third-party`），第三方的 `ctx.island` 仍只有 `open`。
- **不形成回环**：宿主提供方照旧发 `arrived`；岛窗口显示宿主转来的通知时不再本地发 `arrived`，岛窗口里订阅的人只经宿主收到一次。
- **按钮回传（顺带修）**：番茄钟在宿主里监听 `messages/v1` 的 `action`，原来岛上点按钮只在岛窗口本地发，宿主收不到。现在宿主转来的通知上的按钮经 `island.noticeAction` 回宿主，由宿主提供方发 `action`。
- **`island-notices/v1` 查过**：宿主里没有它的提供方，宿主代码调它直接回 `not-ready`，是如实失败而不是假装成功；官方插件都没用它，所以不转发。
- **另一个问题（没修，不在本任务）**：岛上消息页（`Messages.tsx`）只读岛窗口自己的来源表，宿主里 `ctx.messageSources.register` 登记的来源和宿主 `notify` 累计的未读数在岛上看不到。
- 测试：`tests/unit/messages-host.test.mjs` 新加的端到端用例在旧的 `host/index.mjs` 上失败、修后通过；`packages/plugin-base/test/island-control.test.mjs`、`tests/unit/plugin-island-control.test.mjs` 覆盖超时、离开、拒绝、第三方拿不到、按钮回传。
- 实测清单（本机不跑 `pnpm tauri dev`，要真岛）：1) 岛收起时，闹钟到点或换歌提示，岛上弹出通知；2) 岛展开时同样触发，不弹，插件日志里 `shown=false`；3) 番茄钟的通知上点按钮，番茄钟有反应；4) 换歌提示的诊断日志里 `shown` 和岛上是否出现一致。
