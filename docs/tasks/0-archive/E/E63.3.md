## 说明

插件市场的安装、更新和撤销有几处缺口（[排查](/docs/investigations/plugin-release-readiness.md) M5、M6、M8、M10、M9 后端）：

- M5：安装目录按包自己清单里的名字定，不和索引条目比对；市场来源一律按官方身份校验，第三方包也能叫 `@fuyu/*`。
- M8：先删旧目录再逐个写文件，依赖先装；装到一半失败会留下半装的包。
- M6：撤销名单过期、取不到或被拒时 `market.mjs` 直接抛错，索引不更新，自动更新和撤销都不执行；设计写的是只提示。
- M10：自动更新只排除换了作者密钥的版本，新版多要 `nodeApis`、`network`、`replaces` 也会静默装上。
- M9 后端：被撤销停用的插件，拨一下开关就能重新打开；「提示」级撤销没有传给界面。

## 验收

- 包名、版本和索引条目不一致的拒装；非官方来源不能用 `@fuyu/*`
- 安装、更新先写临时目录再改名，中途失败旧版原样还在，单元测试模拟失败
- 撤销名单出问题时索引照常合并、给出提示，单元测试覆盖过期、取不到、被拒
- 新版本比已装版本多要权限的不自动更新，标出来等用户确认
- 被撤销停用的插件 `setEnabled(true)` 被拒；撤销级别和原因能从服务拿到

## 备注

核实（2026-11-19，e63-3）：排查文档对 M5、M6、M8、M9、M10 的说法都属实，行号因 E63.2 的改动有小偏移。另外发现 `openRevoked` 对过期名单返回 `expired`，旧代码也当失败抛错，一并改成合并加提示。

结论和改法（五个提交，正文写了行为变化；第四个是 M10 改名）：

- M5 + M8：安装器只在调用方明确 `official: true` 时按官方校验（市场按索引的 `publisher.official` 传）；市场安装核对包名、版本和索引条目（`name-mismatch` / `version-mismatch`）。安装先写 `packages/.staging/`，一次安装的依赖和插件全部写好后一起换上再写 `plugins.yml`，任何一步失败都换回旧版、还原 `plugins.yml`；崩溃留下的残留在下次安装时清掉，被挪开的旧版放回原处。Windows 上改名遇到 `EPERM` / `EBUSY` 短暂重试。
- M6：撤销名单取不到、被拒、序号倒退、过期都不再让刷新失败；索引照常保存，沿用本机的撤销状态，快照带 `revocationWarning`（`network`、`bad-signature`、`bad-trust`、`invalid`、`older-serial`、`expired`、`behind`），下一次正常刷新清掉。过期的照样合并并执行。
- M10：自动更新比较已装版本和新版本清单里的 `nodeApis`、`network`、`replaces`，新版本会做更多事（用新的 Node 模块、连新的网站、替换内置功能）就不自动装，等用户确认后手动更新：先比索引里的清单，下载后再比包里的清单，带上的依赖也比。目录里这个插件 `autoUpdate` 为 `null`，带 `autoUpdateHeld { version, reason: "new-capabilities", newCapabilities: { nodeApis, network, replaces } }`；升级用的候选版本带 `newCapabilities`。用户定：界面里不出现「权限」的说法（浮屿没有权限系统，不能暗示会拦截插件），字段名、错误码（`new-capabilities`）和文案都按「新版本会做更多事」写。
- M9 后端：`disable` 级撤销的插件 `setEnabled({ enabled: true })` 抛 `revoked`（`data.reasons` 是原因）；`catalog` 的 `plugins[]` 和 `installed[]` 都带 `revocation: { level: "disable" | "warn", reasons: 本地化原因[] } | null`。

给 E63.8 和后续界面任务（类型在 `packages/plugin-services/src/services/market.d.mts`，新字段在类型里都是可选的，免得动回归页的 mock；服务总会给出）：

- 已装插件行：`installed[i].revocation`（`level` 为 `disable` 时开关锁住，`warn` 时提示），原因取 `reasons` 里对应语言；拨开关被拒时错误码是 `revoked`。
- 市场页：快照的 `revocationWarning` 不为 `null` 时提示「撤销名单没更新」；`plugins[i].autoUpdateHeld` 不为 `null` 时提示类似「新版本会做更多事（例如连接新的网站、替换内置功能），需要你确认后再更新」，列出 `newCapabilities` 里新增的 Node 模块、网站和替换的功能；手动更新的确认框可以用 `manual.newCapabilities` 标出新增的项。不写「权限」，不暗示浮屿会拦截插件。界面没有做，留给 E63.8 或后续任务。

没做、留给别的任务的：

- `packages/plugin-base/src/host/sources.mjs` 加载已装插件时仍按 `official: source === "market"` 读清单；安装器已经挡住冒名的包，宿主这边的判断仍然宽松（不在本任务 scope，E63.6 / E63.7 在改 plugin-base）。
- 被 `disable` 撤销而停用的插件不会自动更新到修复版（自动更新只看开着的插件）；设计写「有修复版时优先推」，用户可以手动更新，更新后插件重新打开。
