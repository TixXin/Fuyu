## 备注

### 做了什么

- 拥有者：`plugin/owner.ts` 导出 `OWNER = "file-shelf"`；岛上的「文件中转」页、收起条上的数量（`island.collapsed/v1` 的 `shelf`）和设置 → 文件中转都挂在它名下。
- 旧开关：`shelfEnabled` 在 `LEGACY_SWITCHES` 加一行，备份经镜像带上。外壳里的 `useIslandShelf`、`useFileShelfDrop`、收起条和侧栏的数量照旧读镜像出的 `shelfEnabled`，关掉时不调 `get_file_shelf`、不听 `file-shelf-changed`；挪进 `plugin/` 归 E36.3.51（组长 2026-11-15 定）。
- 后台：文件中转在 Rust 里没有常驻线程（网络盘的可达探测是按次起、按次结束的线程），`background` 照旧是 `[]`，加了测试核对。第 2 版插件的 `shelf.list` / `shelf.add` / `shelf.remove` 在文件中转关着时回 503。
- 服务：**名字是 `file-shelf/v1`，不是简报里的 `fileShelf/v1`**，基座的 `SERVICE_NAME` 只收小写和短横线；JS 导出名是 `fileShelfV1`，Rust 方法名是 `fileShelf.list`、`fileShelf.add`。宿主那份调 Rust，窗口那份（`plugin/services.ts`）调原来的 Tauri 命令，两边都经 `host/index.mjs` 的 `pathsOf`、`serviceItems` 出结果。
- 服务标记不 `inject(app)`（E36.3.30 发现它让 Windows 的测试 exe 起不来）：文件中转的路径在 `init` 时就定了，宿主方法不用求目录；`fileShelf.add` 加完要让岛刷新，用的是 `init` 时存进服务的 `AppHandle` 发 `file-shelf-changed`（和第 2 版 `shelf.add` 一样）。
- ts-rs：`FileShelfItem` 被 `#[serde(flatten)]` 摊进 `FileShelfEntry`，生成的类型里没有单独的 `FileShelfItem`，服务的声明只重新导出 `FileShelfEntry`、`FileShelfSnapshot`；`size: u64`、`addedAt: i64` 都加了 `ts(type = "number")`。

### 没做、留给别的任务

- 截图、录屏还直接 import `addFileShelfPaths`（边界白名单里的两条），改调 `file-shelf/v1` 归 E36.3.35。
- 托盘卡片（C99.2）的「文件中转」入口、设置 → 收起条项目里的「文件中转数量」在文件中转关掉后还在，属于外壳和设置窗口。
