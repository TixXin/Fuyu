## 说明

安全加固，第 3 阶段地基收口时发现的。issue #552 写了全文。

**现在**：Rust 的 `fuyu-plugin` 协议（`src-tauri/src/plugin_kernel/protocol.rs`）以数据目录的整个 `plugins-v3/` 为根。路径解析后还在目录里、是个文件，就原样返回，带 `Access-Control-Allow-Origin: *`，不分窗口也不分插件。窗口因此能读到：

- 每个插件的 `data/<插件 id>/`（`ctx.dataDir`，例如 `data/timer/timers.json`）
- `plugins.yml`、`plugins.yml.bak`（全部插件的配置和选项）
- `safe-mode.json`、`bisect.json`（Rust 的状态文件）
- `packages/` 下已安装的包和放在 `plugins-v3/` 里的开发文件夹（这两类是该给的）

所有窗口的脚本都能读，包括第三方插件的界面部分：它跑在窗口的 JS 里、和窗口同源，一个 `fetch` 就能读到别的插件的数据和全部配置。`ctx.dataDir` 在宿主一侧按插件分开，在窗口这一侧等于没分。

**改完以后**：

- 窗口只能读加载界面要用的：`__shared/` 转接模块、`packages/` 下已安装的包、开发文件夹里的插件代码，以及以后的 `dev/<id>/`、`builtin/<id>/` 映射（[v3-sources.md](/docs/architecture/plugins/v3-sources.md)「安装目录和界面地址」，Rust 一侧还没做）。
- `data/`、`plugins.yml*`、状态文件和其他没登记的路径一律 404。倾向白名单：只放行 `packages/` 和宿主登记过的界面目录（宿主经协议 2 告诉 Rust，或 Rust 读 `plugins.yml` 里的开发文件夹），新加的文件默认不给。
- 插件界面要读自己的数据，经 `ctx.host.call` 让自己的宿主部分读。
- 另外单独评估 `Access-Control-Allow-Origin: *` 能不能收窄。

## 验收

- Rust 测试：`data/…`、`plugins.yml`、`safe-mode.json`、`bisect.json` 返回 404；`packages/…`、`__shared/…`、开发文件夹的界面代码照常 200；符号链接指到外面照旧拒绝
- 演示插件（`node scripts/plugins-v3/install-demo.mjs`）在 Mac 上照常加载；Windows 写进 v3-progress 待人工验收
- `v3-boundary.md`、`v3-sources.md` 写明窗口能读什么；`contracts.md` 里 `fuyu-plugin` 协议的说明跟着改（单独提交）

## 备注

**做法**：宿主在 `ready` 之前和每次界面登记变化时发协议 2 的通知 `clients`（`{ paths }`，就是发给窗口的那份列表里的 `path`），Rust 存下来；`fuyu-plugin` 协议先查拒绝名单（`data/`、`plugins.yml*`、`safe-mode.json`、`bisect.json`，不分大小写，不管 `clients` 写了什么都生效），再查白名单：`__shared/`、`packages/**`、`clients` 里路径所在的顶层目录（数据目录根上的单个文件只放行那一个）。`clients` 来自跑着第三方插件代码的宿主进程，当不可信输入：带 `..`、绝对路径、反斜杠的条目直接丢掉，`data`、`packages`、`__shared`、`dev`、`builtin` 不能当顶层目录登记。路径按符号链接解析后再过一遍同样的检查。规则写在 `v3-boundary.md`「窗口能读的文件」。

**宿主重启的那几秒**：Rust 在宿主 `Starting`、`Down`、`Stopped` 时清空名单，新宿主发来 `clients` 之前，除了 `__shared/` 和 `packages/**` 都是 404。窗口这时也连不上宿主（拿不到端口），宿主就绪后重新拿到界面列表再加载，所以只是重启期间读不到，可以接受。

**`Access-Control-Allow-Origin: *` 能不能收窄**（评估，没改）：

- 必须有 ACAO：窗口用 `import()` 加载插件代码，模块脚本按 CORS 取，窗口的源（Mac `tauri://localhost`、Windows `http://tauri.localhost`，开发版另有 dev 服务器的地址）和 `fuyu-plugin` 不同源。
- 能收窄：可以只回显和宿主 WebSocket 同一份允许的源（`plugin_kernel::host_origins`），加 `Vary: Origin`，别的源不给 ACAO。
- 收益小：自定义协议只在浮屿自己的 WebView 里能用，外面的浏览器访问不到；浮屿的窗口不加载远程网页，也没有 iframe（`src/` 里搜不到），`*` 只在远程页面跑进浮屿的 WebView 时才有影响。白名单之后能读到的也只剩插件代码。
- 风险：源字符串差一点（WebView2 的 http / https、开发版地址），所有插件界面都加载不出来，而这只能在两个系统的真机上验。
- 建议：先不改；做 `dev/<id>/`、`builtin/<id>/` 映射或第 5 阶段开放第三方插件之前，再一起收窄并在两个系统上实测。
