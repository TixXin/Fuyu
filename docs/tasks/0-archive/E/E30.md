## 说明

[v2-platform.md](/docs/architecture/plugins/v2-platform.md) 3.1 节定的规则是「新 API 先进入实验通道，稳定后再转正」。通道在 P10 建好了：清单的 `experimentalApis` 只对开发模式的插件开放，市场拒收。

但 [dev.rs](/src-tauri/src/plugin_host/dev.rs) 的 `EXPERIMENTAL_APIS` 一直是空的。0.3.0 之后加的 7 项能力（`openView`、`permissions`、`statusCells`、`notifyStyle`、`notifyControls`、`statusBatteries`、`statusPie`）都直接进了稳定面。同一个 API 版本内「只增不改」，加进去就撤不回来。

背景：插件宿主从 2026-11-04 第一次提交到 11-13 共 10 天，对外已有 14 项能力、14 个权限、27 个需要权限的方法。市场上的第三方插件是 2 个，都来自本仓库的协作者。接口面比用过它的外部作者多得多。

要用户定的是下面两条选哪条：

- 之后的新能力一律先进实验通道，等有插件用过一轮再转正，最好是第三方的插件。
- 维持现状，官方示例需要什么就直接加。那就把 3.1 节的规则改掉，免得文档和做法不一致。

## 验收

- 用户的决定记在备注里。
- v2-platform.md 3.1 节、[changelog.md](/docs/plugins/changelog.md) 开头的说明和实际做法一致。
