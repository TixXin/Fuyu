## 说明

复查 4744a73a（E36.3.8）时发现：translator/v1 把调用方给的 engine.baseUrl 交给 Rust，自定义引擎会带着用户的密钥请求这个地址；ctx.rust 对宿主里所有插件开放，第三方插件能绕过服务直接调 Rust。修法：ctx.rust 只给来源是 builtin 的插件（来源取宿主加载时记下的，其他来源报 forbidden）；宿主这条路的 translator.translate / rewrite 不收地址，自定义引擎报 translation.customUnavailable，engine 只收 engine、model；v3-services.md、v3-secrets.md、v3-boundary.md 跟着改。4744a73a 合入前修好。

- 2026-11-15 12:53 v3-rust-channel：实测清单（本机是 Mac，Windows 没测）：1) Windows 上跑全部 Rust 测试，加上默认跳过的 plugin_kernel 真宿主测试（--ignored）；2) Windows 上 pnpm build:exe；3) FUYU_PLUGINS_V3=1 的开发版里，市场或开发来源的插件调 ctx.rust.call 得到 forbidden，内置翻译插件照常翻译；translator/v1 传 engine custom 得到 bad-params（data.reason 是 translation.customUnavailable），翻译窗口里的自定义接口照常能用。已知限制：Rust 的事件经根上下文的 ctx.emit("rust:<名字>") 转给插件，第三方插件仍能 ctx.on("rust:…") 听到；按规则事件里不带密钥。
- 2026-11-15 12:54 v3-rust-channel：custom 引擎在宿主这条路上暂不开放：translator/v1 传 engine custom 回 bad-params（data.reason 是 translation.customUnavailable），Rust 的 translator.translate / translator.rewrite 不收地址。第 3 版默认打开之前，要改成由 Rust 从用户设置里读自定义地址，再开放 custom；v3-progress 已把它列为发版和默认打开前必须做完的事（dd81f6a0）。
