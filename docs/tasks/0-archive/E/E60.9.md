## 说明

系统监控插件要用警告色、跟随岛的深浅色，以及点收起项打开自己的岛页面；接口由插件系统总控 2026-11-19 定下。和 E60.8 都改 `src/windows/island/`，不同时开工：先做本任务（系统监控在等），E60.8 排在后面。

插槽主题变量（`src/features/plugin-kernel/PluginSlot.css`）：

- 加 `--fuyu-plugin-warning` 和 `--fuyu-plugin-danger`，深浅两套。参照 `tokens.css` 的 `--color-warning`、`--color-danger`、`--usage-danger`，浅色写在 `.island-light` 下。
- `.plugin-slot` 加 `color-scheme: dark`，`.island-light .plugin-slot` 加 `color-scheme: light`，让插件里的 `light-dark()` 能用。`.plugin-slot` 是 `display: contents`，要核实 `color-scheme` 能不能传给子元素；传不过去就换别的写法，插件里看到的效果要一样。
- 插件独立窗口（`PluginWindowApp.css` 已经设了 color-scheme）和设置窗口里的插槽也要一致。
- 文档：`docs/plugins/services-and-slots.md`「插槽主题变量（`SLOT_THEME`）」那一节，以及 `packages/plugin-base` 里的 `SLOT_THEME` 清单和类型声明。

`island.collapsed/v1` 加 `opens`：

- 写法 `opens: "<页面 id>"`，只能指向同一个插件注册的 `island.page/v1`。宿主让整项可以点，有键盘焦点，Enter 和空格也能触发，点了调 `onOpenPage(id)`。不写 `opens` 时行为完全不变。
- 指向别的插件或内置页时忽略，并记一条告警。
- 改 `packages/plugin-base/src/protocol.mjs` 的 `SLOTS`、类型声明、`src/windows/island/collapsedBarItems.tsx`。点击要阻止冒泡，和收起条的拖动、`OPENS_BAR` 不冲突。
- 顺手核实：外部插件的收起项拿到的 props 里有宿主内部的 `onOpenPage`、`t`、`slots`。第三方插件拿到这些会不会出问题、要不要只给它们精简过的上下文，结论写进本任务。

## 备注

- `color-scheme` 是继承属性，继承按 DOM 树走，`display: contents` 只是不生成盒子，不挡继承。回归页 `plugin-slot` 实测：插件元素算出的 `color-scheme` 深色岛是 `dark`、浅色岛是 `light`，`light-dark()` 跟着取值。设置窗口和插件独立窗口的插槽也经 `SlotView` 包 `.plugin-slot`，深浅只看祖先上的 `.island-light`，三个窗口用的是同一条规则。
- 状态色取 `tokens.css` 里能当文字色的值：深色岛 `--color-warning` / `--usage-danger`，浅色岛 `--warning-text` / `--usage-danger`（浅色值由 `.island-light` 自己换）。`--color-danger` 是底色用的深红，深色岛上当文字太暗，没用它。
- `opens` 只在同一个拥有者（插件 id）的 `island.page/v1` 里找；内置页的拥有者是内置插件，所以指向内置页也算「别人的」。告警按内容去重，同一条只记一次。外壳是 `role="button"` 的 `span`，不是 `<button>`：插件的收起项里可能本来就有按钮，按钮套按钮不合法；点到项里插件自己的按钮、链接、输入框时不打开页面，Enter / 空格只在外壳本身有焦点时响应。
- 收起项的 props（宿主内部的 `CollapsedBarContext`：`t`、`statusLight`、`hints`、`slots`、`onOpenPage`、`onOpenSettings`）核实结论：不是安全问题。插件的窗口代码由 `client/loader.mjs` 动态 `import` 进岛的同一个 JS 环境，本来就能碰到 DOM 和全局对象，这几个 props 不多给权限，`onOpenPage` / `onOpenSettings` 也只是用户自己点得到的界面动作。问题在契约：这些字段没写进文档、随宿主重构会改名，插件依赖了就会悄悄坏；`index.d.mts` 也写明 slot 传给组件的 props 在第 5 期之前是实验性的。本任务不改（改成空 props 会让已经用了 `onOpenPage` 的第三方插件立刻失效），有了 `opens` 以后插件也没有理由再用 `onOpenPage`。建议定插槽 v2 或第 5 期定 props 契约时，给外部插件只传一份文档写明的精简上下文。
