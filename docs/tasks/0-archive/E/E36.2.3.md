## 说明

createSlots 拆成不 import Cordis 的纯模块并补规则（名字带 /vN、按 category 分组、replaces 列表、builtin 拥有者、元数据透传）；每个窗口同步建的注册表；第 2 阶段全部插槽定义；内置用的渲染组件（不加包裹层、每项错误边界）；runtime.ts 改成往已有注册表里加；插槽登记进 v3-boundary.md 和 contracts.md。

分步计划见 [v3-phase2-plan.md](/docs/architecture/plugins/v3-phase2-plan.md)。

## 验收

- 包里的测试覆盖每条规则
- 岛的首屏 JS 不含 Cordis，体积和冷启动前后对比记进任务
- plugin-slot 回归页照过，第 1 阶段演示插件照常出现

## 备注

- 和计划的出入：每插件上限只管第三方项（`external`），内置项不计。第 3 阶段内置功能改传插件 id 后照样不受限（设置的一页有 4 个以上分节、收起条一个功能有 2 项以上都正常）；`island.alert/v1` 的「只显示一个」由窗口按 `active` 挑，注册表不设 `max: 1`，否则排第一的那项没内容时后面的上不来。
- 「是不是第三方」不按 owner 判断，单独记在项上（`external`）：经宿主加载的一律是，岛里代码注册的（`defineSlot(...).add`）一律不是，第 3 阶段内置插件传自己的 id 时也照样平铺。
- 顺手修了第 1 阶段替换的一个 bug：A 被 B 盖住、B 又被 C 盖住时，先撤 B 再撤 C，以前会把已经撤掉的 B 放回来。现在是栈，`replaces` 是被盖住的拥有者列表。
- 宿主启用、插槽里没有项时，以前岛里留一个空的 `.plugin-slot`（`display: contents`），现在什么都不渲染；不设 `FUYU_PLUGINS_V3` 时 DOM 不变。
- `src/AGENTS.md` 的目录地图里 `plugin-kernel/` 那行还写着 `PLUGIN_SLOTS`，留给阶段 D 统一改。

## 结论（2026-11-15）

**首屏 JS**（`vite build` 产物里岛的入口加 `IslandApp` 的全部静态依赖，29 个 chunk）。同一棵代码树构建两次，改动前那次用 Vite 的 `load` 钩子把本任务改的 6 个文件换回改动前的版本，其余文件一样：

| | 改动前 | 改动后 |
|---|---|---|
| 首屏 JS | 1205.6 KB（gzip 411.3 KB） | 1174.7 KB（gzip 399.6 KB），少 30.9 KB（gzip 少 11.7 KB） |
| `IslandApp` chunk | 447.8 KB，含 Cordis | 418.3 KB，不含 Cordis |
| Cordis 在哪 | `IslandApp` chunk 里 | 单独的 chunk（35.3 KB，gzip 12.5 KB），只有 `FUYU_PLUGINS_V3=1` 时由 `runtime.ts` 的 `import()` 加载 |

查法：在产物里搜 `Symbol.for("cordis.`。

**冷启动**：无头 Chrome 打开两份产物（关掉缓存，Tauri 的 `invoke` 一律失败，岛照样渲染），量从开始导航到 `#root` 里出现第一个元素，两份交替各 60 次。改动前中位数 162.0 ms（四分位 153.9–172.0），改动后 157.1 ms（150.8–169.4）；`DOMContentLoaded` 到出现元素 101.3 → 98.5 ms。差别在噪声范围内，没有变慢。测的时候机器负载 30–60（别的会话在编译），只看相对差。
