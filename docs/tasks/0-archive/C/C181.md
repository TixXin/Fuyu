## 说明

公司内网等需要走网络代理的环境里，软件此前缺少用户可配置的全局代理设置：仅更新器等部分 Rust 模块隐式读取环境变量 / Windows 系统代理（macOS 侧未读系统代理），而插件市场及 v3 插件（Node.js 宿主 `fetch`）、日历 ICS 订阅、邮箱 IMAP/SMTP、AI 翻译、Bark 推送等均不走代理，导致无法使用（#1245）。

补齐统一的「网络代理」能力：
- Rust 侧新建 `system/proxy/` 模块，持久化于家目录 `network-proxy.json`，代理密码存入系统凭据库（`com.tixxin.fuyu.network-proxy`），不向前端回显明文、不在错误与日志里泄露凭据。
- 支持「跟随系统 / 手动代理 / 不使用代理」三种模式；手动模式支持 HTTP 与 SOCKS5 协议、地址、端口、可选认证、免代理列表，并补齐 Windows 与 macOS 系统代理检测。
- 统一所有 Rust `reqwest` 客户端、邮箱 IMAP/SMTP 底层 TCP 隧道（HTTP CONNECT / SOCKS5），以及 Node.js 插件宿主（经 JSON-RPC 启动同步与改设置热更新），打通插件市场、日历、邮箱与全局联网。
- 在「设置 → 通用」新增「网络代理」分组与「测试连接」按钮。

## 验收

- 设置 → 通用提供「网络代理」设置：跟随系统（展示脱敏后的检测结果）/ 手动代理（HTTP、SOCKS5、主机、端口、可选用户名与密码、免代理列表）/ 不使用代理，支持保存与「测试连接」。
- 代理密码存入系统凭据库，命令返回值与错误信息不泄露密码；卸载清理同步清理凭据与配置文件。
- Rust 侧所有 HTTP 出网模块（更新器、下载镜像、主题市场、CalDAV & ICS 日历、WebDAV 同步、AI 翻译、Bark 推送、歌词、Node 下载、`claude_usage` 回退等）均遵循全局代理设置与免代理规则。
- 邮箱 IMAP 收信与 SMTP 发信在启用代理时支持 HTTP CONNECT 与 SOCKS5 隧道连接，直连时保持原行为。
- Node.js 插件宿主（插件市场与 v3 插件 `ctx.http.fetch`）在启动及保存代理后自动同步配置，支持 HTTP / SOCKS5 代理与免代理规则，无需重启软件。
- 补齐 Rust 单元测试、Node 宿主代理单元测试、设置回归 mock、搜索索引与 `docs/architecture/contracts.md` 契约记录，`pnpm test:changed` 通过。
