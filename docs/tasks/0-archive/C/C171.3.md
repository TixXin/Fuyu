## 说明

现状和原因见 [调研](/docs/research/peripheral-battery.md)「2026-11-22」和 [C171](/docs/tasks/C/C171.md) 的共同约定。第三方蓝牙耳机（走 HFP 上报电量的）和第三方 BLE 鼠标、键盘，在 macOS 上只有蓝牙接口读得到电量，两条都会触发系统的蓝牙权限框。参考 AirBattery 的 `getIOBTBattery` 和 `BLEBattery.swift`（AGPL，只看思路不抄代码）。

1. **IOBluetooth**：`IOBluetoothDevice.pairedDevices()` 里已连接、`isAppleDevice` 为假的设备，先确认响应 `batteryPercentSingle`（私有属性，用 `respondsToSelector` 判断，不响应就跳过，不能崩），取到 1–100 的值。耳机按地址（`address_key`）和 CoreAudio 输出对上，进 `read_batteries` 的结果；键鼠按 C171.2 的合并规则进外设。
2. **CoreBluetooth**：`retrieveConnectedPeripheralsWithServices([0x180F])` 取已连接的带电池服务的外设，连上读 0x2A19（不扫描广播，不连没连着的设备）；CoreBluetooth 给的是 UUID 不是地址，按名字和 IOBluetooth / `system_profiler` 的设备对上，对不上的作为独立外设（类型按名字或 HID 外观值，不确定就不列）。CoreBluetooth 要在有 run loop 或 dispatch 队列的线程上跑，自己开一个专门的线程或队列，别阻塞 `device_events` 的轮询线程。
3. **权限**：`src-tauri/Info.plist` 加 `NSBluetoothAlwaysUsageDescription`（中英文说明）；检查 `Entitlements.plist` 和签名是否另外要蓝牙的 entitlement。**没授权（`CBManager.authorization` 不是 allowedAlways）时两条读法都不碰**，保证启动和平时不会弹框。新增命令（例如 `get_bluetooth_battery_access` / `request_bluetooth_battery_access`，返回 notDetermined / denied / allowed / unsupported），Windows 上返回 unsupported；写进 `contracts.md`。
4. **前端**（`src/features/peripheral-battery/`）：只在 macOS、状态是 notDetermined 时，组件底部（空状态和有数据时都显示）出现「读取第三方蓝牙设备」按钮，点了申请权限，允许后立刻重读一次；denied 时换成一行提示和「打开系统设置」（隐私与安全性 → 蓝牙）。中英文文案，窄宽度不溢出；改 `api.ts` 后同步回归页 mock。
5. **接入 `readers_macos.rs`**：这个文件归 C171.2，等它提交后再接（看 `git log -- src-tauri/src/device_events/readers_macos.rs` 和 C171.2 的交接），按它的合并规则把两条读法的结果加进去。先把读法模块、权限和前端做完。
6. **探测测试**：`probe_this_computer` 打印两条读法的结果和授权状态。
7. **文档**：`platforms.md`、`contracts.md`、`data-storage.md`（如果有新存的东西）。热点文件改完单独提交。

## 验收

- 没授权时完全不碰蓝牙接口，启动和平时不弹框
- 点按钮弹系统权限框；允许后第三方耳机、BLE 键鼠显示电量；拒绝后有去系统设置的提示，不报错
- 私有属性不存在时不崩，只是没有这条读数
- 中英文文案，窄宽度不溢出，回归页跟上
