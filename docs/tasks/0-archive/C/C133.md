## 说明

用户复制了 GLM 的 API key，想在剪贴板历史里删掉时，删除按钮出现在窗口可见范围之外，点不到（#863，用户群里有录屏）。可能和 #847（行菜单二次确认点击失效）有关，也可能是菜单或按钮被窗口边界裁掉。

另外，系统的「不要记录」标记已经认了（`src-tauri/src/win32/clipboard.rs`），但从网页或终端复制的 key 不带这个标记。要给出结论：长得像密钥的内容（`sk-…`、长 hex / base64 串等）是不记录还是打码显示、默认开还是关、有没有开关。

## 验收

- 剪贴板条目的删除入口在列表底部、窗口边缘等任何位置都能完整显示并点到；录屏里的操作能删掉那条记录
- 对密钥类内容给出结论并实现，中英文文案齐全
- 回归页覆盖最后一行的菜单位置

## 备注

- 原因：`RowMenu` 按整个窗口（`window.innerHeight`）判断上下，岛的窗口是比面板大的透明窗口，面板外的透明区域点击穿透；最后几行的菜单往下弹，落在面板下面，看得见点不到。改成按最近的 `.island__surface`（没有时用视口）的边界定位：下面放不下往上翻，上下都放不下贴边并限高可滚，横向也收在面板里。文件中转、待办、Agent 会话共用，一起受益。
- 独立剪贴板窗口的删除是行内的垃圾桶按钮，不经过 `RowMenu`，窗口不穿透，没改。
- 密钥（方案 A）：设置和默认打码不变，文案已经写「API Key」，没改。新认：智谱 `<32 位 hex>.<16 位字母数字>`；前缀 `LTAI`（阿里云 AccessKey）、`AKID`（腾讯云 SecretId）、`AKLT`（火山引擎 AccessKey）、`bce-v3/ALTAK-`（百度千帆）。DeepSeek、Kimi、通义、硅基流动、百川都是 `sk-`，原来就认。纯 hex 仍不算；火山方舟的 UUID 格式 key 太常见，不认。
