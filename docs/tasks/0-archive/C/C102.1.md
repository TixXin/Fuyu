## 说明

[C102](/docs/tasks/C/C102.md) 第 1 步（方案见 [im-message-sources.md](/docs/research/im-message-sources.md)）。在接入 7 个新聊天软件之前，把双端底层监听抽成单实例共享层，零用户可见行为变化：

- **Windows 共享 Toast 监听与 `AppInfo` 缓存**：从 [listener.rs](/src-tauri/src/qq_notifications/listener.rs) 抽出公共 `UserNotificationListener` 单线程轮询模块；按通知 `Id` 缓存跨进程 `AppInfo()`（`AppUserModelId` 与 `DisplayInfo.DisplayName`），仅保留仍在当前通知集合中的条目；支持按规则分发给多个已开启来源，并预留只读接口供 [C57](/docs/tasks/C/C57.md) 列出最近发过通知的应用。QQ 独有的 `0x80070490` 注册表自动修复仍只留在 QQ 来源逻辑中。
- **Windows 任务栏闪烁与窗口激活多来源复用**：把 [source.rs](/src-tauri/src/wechat_reminders/source.rs) 里按可执行文件名匹配 `HSHELL_FLASH` 和 `HSHELL_WINDOWACTIVATED` 的能力抽成多来源可复用接口，供后续 `C102.2` 给默认不发 Toast 的客户端做无正文提醒兜底。
- **macOS 单线程批量 Dock 角标轮询**：扩展 [dock_badges.rs](/src-tauri/src/macos/dock_badges.rs)，支持单线程每 3 秒一次遍历 Dock 树并读一次前台应用，一次性匹配所有已启用来源候选 Bundle ID 的角标变化；全部来源关闭时线程退出。

## 验收

- QQ（Windows Toast + macOS Dock 角标）与微信（Windows ShellHook + macOS Dock 角标）迁到共享底座上，对外 Tauri 命令、事件名和行为完全不变
- 所有相关来源关闭或 `messages` 插件停用时，后台监听线程真停
- 新增共享底座单元测试（通知 `Id` 缓存命中与淘汰、多来源规则分发、macOS 批量角标匹配）
- `cargo test`、`pnpm check` 通过，Windows CI（`pnpm mq:try --wait`）的 `rust` 任务通过
