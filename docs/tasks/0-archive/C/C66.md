## 说明

用户定（2026-11-15）：自动清除默认开，只清应用被切到前台或岛上点开之前到的消息。

用户群反馈微信弹出的消息没法清空，希望看过之后自动去掉。C46 已有手动的「清除提醒」。要先核实能拿到什么信号：微信 / QQ 提醒靠通知和托盘闪烁，可能拿不到「在微信里已读」，能做到的可能是「对应应用到前台或托盘停止闪烁后清掉它的消息」，以及岛上点开过就算已读。

## 验收

- 核实结论写进任务：能拿到哪些已读信号
- 按能拿到的信号自动移除已读消息，有开关
- 没看的消息不会被误清

## 提交

- `feat(messages): drop WeChat and QQ reminders from the island once they have been seen (C66)`

## 结论（2026-11-15）

能拿到的「看过」信号（都拿不到「在微信 / QQ 里某个聊天已读」）：

| 信号 | Windows | macOS |
|---|---|---|
| 应用被切到前台 | 微信：shell hook 的 `HSHELL_WINDOWACTIVATED`，已有 `ReminderSignal::Activated`（`ActivatedElsewhere` 是别的窗口，不算）。QQ：没有现成的，通知监听每秒一轮时看前台窗口是不是 `QQ.exe`（`win32::window::foreground_window`） | 两个都靠每秒看 `NSWorkspace.frontmostApplication`（`macos::apps::frontmost_path`），只认从后台到前台的那一刻 |
| 托盘 / 角标 | 微信的任务栏闪烁（`HSHELL_FLASH`）只说明有新消息，停止闪烁没有事件；QQ 的托盘图标闪烁读不到（不走 shell hook）。通知中心里的 QQ 通知被移走也不能当信号：每个应用最多留 20 条，旧的会被挤掉，会误清 | 程序坞角标（`AXStatusLabel`，每 3 秒读一次）：消失 = 全看过了，算信号；变少不算（不知道是哪几条）；应用退出、读不到不算 |
| 岛上点开 | `open_wechat` / `open_qq` 成功后 | 同左 |

Mac 实测（macOS 27.2，微信 4.1.34 开着，QQ 没开）：`lsappinfo` 读到微信没有角标时 `StatusLabel` 为空，前台应用能读到；角标从有到无、QQ 的信号要有人发消息才能测，列进实测清单。Windows 的两个前台信号只读了代码，列进实测清单。

做法：信号出现时去掉列表里时间不晚于信号的条目（微信按 `at`，QQ 按通知创建时间），之后到的留着；开关「看过后从岛上去掉」在消息设置的微信、QQ 两组里，默认开，Rust 默认关、等前端按设置告诉它。
