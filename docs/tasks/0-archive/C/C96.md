## 说明

用户提到有人在局域网里 Mac + Windows 混用。第一版靠同步文件夹（Syncthing、NAS 共享）和 NAS 的 WebDAV 覆盖；这项是以后单做的局域网直连，定位「局域网剪贴板互传，并能立即触发同步」，设计见 [cross-device-sync.md](/docs/research/cross-device-sync.md)「三、局域网」。

- 自签证书（rcgen），设备 id 取公钥 SHA-256；mDNS `_fuyu._tcp`（mdns-sd）加手填 IP
- 6 位配对码 + SPAKE2 绑定双方证书指纹（或核对校验串）；双向 TLS 1.3 只认配对时的指纹
- 传同一套按设备的记录（按序号拉增量）；可选剪贴板实时推送，敏感条目不推
- Windows 防火墙弹窗、公用网络、AP 隔离的提示；Mac 本地网络权限（`NSLocalNetworkUsageDescription`、`NSBonjourServices`）

排在同步引擎之后，并且要等 Mac 有正式签名的包（G1.12）才能验收本地网络权限。

## 验收

- Windows ↔ Mac 在家用路由器上互相发现、配对、传输；休眠唤醒后重连
- 拒绝防火墙 / 本地网络权限后的提示

## 备注

**方案（2026-11-25 草案，待总会话 / 用户确认方向后再动手）**


**做法：把「局域网对端」做成同步引擎的又一个后端**，不另起一套记录格式。

1. **身份**：首次开启时 `rcgen` 生成 Ed25519 自签证书，私钥进凭据管理器 / 钥匙串（`keyring`，和其他凭据同一个服务名），设备 id = 公钥 SHA-256 的前 16 字节（base32）。证书不出本机，窗口只拿指纹的短串。
2. **发现**：`mdns-sd` 注册 `_fuyu._tcp.local.`，TXT 只放设备 id 和协议版本，不放设备名以外的信息；同时支持手填 `IP:端口`。默认端口 47321，被占用就随机，mDNS 里报实际端口。
3. **配对**：一台显示 6 位码（2 分钟有效、只用一次、输错 5 次作废），另一台输入；双方用 `spake2`（Ed25519 组）以配对码派生共享密钥，再用它对「双方证书指纹 + 设备 id」做 HMAC 确认，两边都对上才各自记下对方指纹（`sync-lan-peers.json`，只存指纹、设备 id、名字、最近地址）。配对走一条临时的、不校验证书的 TLS 连接，安全性全靠 SPAKE2 绑定指纹，不靠 TLS。
4. **传输**：`rustls`（已在依赖树里）双向 TLS 1.3，服务端和客户端都只认配对表里的指纹（自定义 `ClientCertVerifier` / `ServerCertVerifier`）。协议是长度前缀的 JSON 帧，三种请求：`list <目录>`、`read <路径>`、`push-clip <条目>`；只读，对端不能写本机任何东西（剪贴板推送只进「来自其他设备」的历史，不直接改系统剪贴板，除非用户开了「收到就放进剪贴板」）。
5. **接进同步引擎**：新增 `sync/backend_lan.rs` 实现现有 `Backend` trait：写本机记录到数据目录 `sync-lan/<本机设备 id>/`（和同步文件夹同一种按设备的布局），`list` / `read` 别的设备目录时向对应对端取。于是增量、合并、端到端加密都复用现有引擎；对端上线（mDNS 出现、休眠唤醒）就触发一轮同步。
6. **剪贴板实时推送**：可选，默认关；只推文字和小图（≤ 2 MB），`skip_sensitive` 命中的、密码管理器来源的一律不推；收到的条目标「来自 <设备名>」。
7. **系统提示**：Windows 第一次监听前在设置页说明会弹防火墙框、要点「允许」并勾专用网络；监听失败或对端连不上时提示检查「公用网络 / AP 隔离」。Mac 加 `NSLocalNetworkUsageDescription` 和 `NSBonjourServices`（`_fuyu._tcp`），被拒时提示去「隐私与安全性 → 本地网络」打开。
8. **开关**：整个功能在「同步」设置里，默认关；关着时不监听端口、不注册 mDNS。

**新依赖**：`rcgen`、`mdns-sd`、`spake2`、`tokio-rustls`（`rustls` 已有）。估计 Rust 1500–2000 行、设置页加配对弹窗约 500 行，拆 4 个提交：身份与配对表 → 传输与校验 → 同步后端 → 设置页与剪贴板推送。
