## 说明

[C102](/docs/tasks/C/C102.md) 第 2 步（方案与各应用标识矩阵见 [im-message-sources.md](/docs/research/im-message-sources.md)）。基于 `C102.1` 的共享底座，用一套参数化服务接入 7 个聊天软件的原生后端、三级窗口唤起、本机已安装检测与只读探测工具：

- **声明式来源规格表与后台注册**：统一登记 `telegram`、`discord`、`whatsapp`、`tim`、`feishu`、`dingtalk`、`wecom` 七个来源到 [messages_plugin.rs](/src-tauri/src/messages_plugin.rs) 与 [builtins.json](/src/features/builtins.json)（与 `qq`、`wechat`、`mail` 并列），单个来源关闭或 `messages` 插件关闭时立即停止对应分发。
- **Windows「Toast 优先 + 任务栏闪烁兜底」**：
  - 匹配多安装渠道 AUMID（含 Telegram `Telegram.TelegramDesktop` 及便携版动态哈希后缀、商店版前缀，Discord Stable/PTB/Canary，WhatsApp 商店版 `5319275A.WhatsAppDesktop` 前缀，TIM、飞书/Lark、钉钉、企业微信 `WXWork.exe`）；
  - 当客户端处于默认自绘弹窗未发系统 Toast 但触发 `HSHELL_FLASH` 时，自动退化产生无正文「有新提醒」，与短时间窗口内到达的同来源 Toast 去重合并；企业微信与微信严格隔离，绝不复用微信 4.x 专用的 `gate.rs`。
- **双端应用唤起与本机安装检测**：
  - Windows 三级唤起：已运行可交互顶层主窗口前置 → URL 协议（`tg://`、`discord://`、`whatsapp://`、`feishu://`/`lark://`、`dingtalk://`、`wxwork://`）或商店 MSIX 包公开接口 `IApplicationActivationManager::ActivateApplication`；绝不强行 `ShowWindow` 隐藏窗口或双开登录框；
  - macOS：按候选 Bundle ID 列表（覆盖 Telegram `ru.keepcoder.Telegram` 与 `com.tdesktop.Telegram`、飞书与 Lark 等）读取角标并用 `open -b` 唤起；TIM 仅在检测到本机装有历史 `com.tencent.tim` 时报告可用；
  - 提供统一的按 `source` 参数调用的 Tauri 命令（查询快照、清空、设置自动清除、打开应用、查询本机已安装来源列表）。
- **只读探测程序**：新增 `src-tauri/examples/im_notification_probe.rs`，在 Windows 真机一键打印通知中心各应用真实 `AppUserModelId`、显示名与闪烁事件（不输出聊天正文）。

## 验收

- 7 个来源在 `messages` 插件配置下可独立启停，「看过后从岛上去掉」（前台切入或点击打开后清除此前条目）双端生效
- 参数化 Tauri 命令与本机安装检测命令就绪，若需要宿主暴露则同步运行 `pnpm gen:rust-types`
- `im_notification_probe` 示例程序在 Windows 构建通过
- 覆盖多渠道 AUMID 匹配、Toast 与闪烁合并去重、状态与自动清除流转的单元测试通过，Windows CI（`pnpm mq:try --wait`）的 `rust` 任务通过
