## 说明

方案见 [计划](/docs/architecture/skills-batch1-plan.md) 第 3 节。

## 验收

- --list、--take、--match、--as、-- <整个文件>、--dry-run、-m、-F 都在
- 编号按内容算；这次提交相对 HEAD 的每一行增删都必须是工作区里已有的
- commit-tree 加带旧值核对的 update-ref；HEAD 中途推进时重来，最多 3 次，不冲掉别人的提交
- 提交后对涉及的路径 git reset -q，对齐共用索引；提交说明经 git hook run commit-msg
- 临时仓库里的测试覆盖计划第 3 节列的各种情况，开头去掉 GIT_* 变量
- pre-commit 的提示指向这个命令；workflow.md 补说明；在真实仓库里用它提交一次

## 交接

- 2026-11-15 10:40 commit-part：实测清单（这台 Mac 上测不了，要在 Windows 那台机器上试，进 F46）：1) core.autocrlf=true 加 CRLF 文件，pnpm mq:commit-part --take 只带一处：提交里的内容仍是 LF、工作区仍是 CRLF、git status 不把整个文件显示成改动；2) Git for Windows 上 git hook run commit-msg 可用，带 Claude 署名行的说明被拒绝；3) 索引被别的 git 进程锁着时的重试和最后打印的 git reset 命令（Mac 上只用手放的 index.lock 测过）；4) 从 PowerShell 里跑 pnpm mq:commit-part … -- <文件>，确认 -- 和带中文的 -m 原样传到脚本；5) pre-commit 在 Windows 上看到自定义 GIT_INDEX_FILE（反斜杠路径、盘符大小写）时提醒打得出来，普通的 git commit -- <文件> 不误报。
