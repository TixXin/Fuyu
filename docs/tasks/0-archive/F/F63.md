## 说明

v0.3.12-beta.4 的发版复盘（[release-timing.md](/docs/investigations/release-timing.md)）里，每轮 PR CI 的关键路径都是 `regression` 这一个 job（8.5–9 分钟），本机 `mq:verify` 里回归页也最长（6.5–7.5 分钟）。把回归页拆成并行分片。

## 验收

- `scripts/run-regression.mjs` 支持 `--shard <i>/<n>`，按历史耗时均分。
- CI 的 regression 是矩阵，`check` 照样要全部分片通过，挂的页在各分片里都能看到。
- 本机 `mq:verify` 的回归页并行跑，不多占 `pnpm heavy` 的名额。
- `pnpm mq:try` 实测 regression 关键路径降到 5 分钟左右，前后数字写进本文件和 release-timing.md。

## 提交

- `ci(regression): split the regression pages into parallel shards`
- `docs(investigations): record regression shard timings`

## 备注

- `pnpm mq:commit-part` 拆 `run-regression.mjs` 时把相邻的几处改动拼错了（只带走一部分删除），提交出来的文件是半新半旧的；当时 HEAD 是自己的提交，改成整份文件去掉别人那一行再 amend。

## 结论（2026-11-22）

| | 改之前 | 改之后 |
|---|---|---|
| CI 的 regression | 1 个 job，8 分 37 秒 – 9 分 02 秒 | 3 个分片：3 分 15、4 分 05、4 分 21 秒（`mq:try` run 45038576092） |
| 整轮 CI 关键路径 | regression 约 9 分钟 | rust-macos 4 分 53 秒 |
| 本机 79 页（Mac 单独跑） | 1 个浏览器 6 分 36 秒 | 3 个浏览器 2 分 16 秒 |

- 分片按 `tests/regression/timings.json` 均分（两次 CI 日志的平均），没记的页按中位数算；`node scripts/regression/timings.mjs <run id…>` 从 CI 日志重写。
- 本机 3 个浏览器和 1 个浏览器的结果一致：只有 C168 正在改、还没提交的 `notch-settings` 快照不一致，单独串行跑也一样，不是并行造成的。
- 那次 `mq:try` 的 frontend 挂在 `tests/unit/reduced-motion.test.mjs`：本地 main 上还没推的 `ea6242566`（刘海光环）和 `8f4b19f13`（刘海边框）里的 notch-rim / notch-ring 动画没有减少动效的处理，不是这个任务的改动。
- 下一步可做：`builtins-off` 一页在 CI 上要 90–100 秒，是 regression 的下限。
