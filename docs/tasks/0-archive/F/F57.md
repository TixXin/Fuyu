- 场景验证：开一个没看过这次对话的子代理，只带 skill 草稿（不让读 D74、D76 任务文件和 workflow.md 里讲它们的那几条），按当时报上来的样子给三个场景，让它说照 skill 会怎么做：
  - D74（4 页快照存了「已复制」、高亮这类会自己变回去的状态，有人提议加 `UNSETTLED_PAGES` 放行）：判断对，不加名单，让页面等状态回落再报通过、重存快照，和 D74 的实际修法一致。它指出「不加放行名单」没写原因、换个名字（跳过参数）就拦不住，已补「换了名字也一样，进了名单的页再也没人查」，并写明改的是 `tests/regression/<页名>.tsx`。
  - D76（todo-island 偶尔失败、每次挂不同的检查项、有人提议加重试或把等待调到 1 秒）：判断对，不加重试、不调超时，连跑看失败率和挂在哪一步，改成每 50 毫秒轮询就绪信号，查不清就开任务，和 D76 的实际修法一致。它指出没讲怎么排除自己的改动、没给连跑命令，已补「先看失败的测试用到的文件自己改没改过」和连跑的 `for` 循环。
  - CRLF（新测试读 workflow YAML 匹配带 `\n` 的一行，Mac 过、Windows CI `frontend` 挂）：判断对，先把 `\r\n` 换成 `\n` 或匹配不带换行的片段，报验前跑 `pnpm mq:try --wait`，并认出这种读文本匹配字符串的测试本身写法有问题。它指出「读源码」不明确包不包括配置文件、没给替代做法，已改成「读源码或配置（含 `.github/workflows/`）」，补「配置解析成结构再断言字段，要守 CI 跑了某个脚本这类事实就直接跑那个脚本」。
